## Session 4.0.4.3.1 — Signature parsing, lifecycle and stub nodes

**Sub-version:** 4.0.4.3
**Master plan:** `docs/VERSION_4_0_PLAN.md` §4.0.4.3
**UX gate:** No
**Execution profile:** Frontier autonomous coding agent
**Delivery unit:** One agent session, one shared sub-version branch, one PR per session
**Roadmap coverage:** §4.0.4.3 signatures — the scanner paste parser, the signature lifecycle with equality-skipping and undo, ghosted stub nodes, the lifetime ceiling, and the two additional collapse triggers
**Internal phases:** 1. Parse scanner output into signatures and anomalies and populate the list; 2. Land the lifecycle rules for re-paste updating, removal with an undo window, and debounced last-seen bookkeeping; 3. Spawn ghosted stub nodes for known wormhole signatures, drive the lifetime ceiling, and route the two new triggers into the shipped collapse pathway
**Split triggers:** Scanner output varies by client language or partial-scan state in a way the parser cannot resolve without an operator decision about which formats are supported

## 1. Objective

Turn a pasted scan into map state: parsed signatures, lifecycle rules that update
in place without churn, ghosted stub nodes so the map draws holes rather than
paperwork, and the two remaining collapse triggers routed into the single
pathway. This is the first session of sub-version 4.0.4.3; the inference engine,
provenance model and observation emissions follow in the second. The sub-version
ships one pull request per session because its combined diff would otherwise be
too large to review as one change.

## 2. Current context and dependencies

- **DEP-1:** Sub-version 4.0.4.1 shipped the single collapse pathway, explicitly designed for the two additional triggers this session adds.
- **DEP-2:** Sub-version 4.0.3.3 shipped the window primitive the signature list lives in.
- **DEP-3:** Sub-version 4.0.1.3 shipped the wormhole codex that supplies each type's maximum lifetime.
- **DEP-4:** Sub-version 4.0.2.2 shipped the signature document's soft-deletion shape and the debounce threshold for last-seen bookkeeping.
- **DEP-5:** Sub-version 4.0.3.2 shipped the surfacing vocabulary a stub node uses when it appears.
- **DEP-6:** The inference engine, which needs the statics dataset, belongs to this sub-version's second session; this session must leave the list and stubs coherent without any inference.
- **DEP-7:** A signature identifier is an ephemeral key within one wormhole's lifetime and is never an identity; a collapsed static respawns under a new identifier.

## 3. Done conditions

- **DC-1:** Pasting scanner output parses its signatures and anomalies and populates the signature list.
- **DC-2:** A signature whose group is not recognised stays in the list only, while a signature known to be a wormhole spawns a ghosted stub node on the canvas.
- **DC-3:** A jump that resolves a stub converts it into the real system rather than leaving a duplicate.
- **DC-4:** Re-pasting updates signatures in place, and a signature whose content is unchanged produces no write.
- **DC-5:** A signature missing from a re-paste is removed immediately but within an undo window that restores it.
- **DC-6:** Last-seen bookkeeping is written only when it passes the shipped debounce threshold, so ordinary re-pastes do not churn the chain payload.
- **DC-7:** Entering a wormhole type populates its maximum lifetime, and the resulting ceiling counts down; because first-seen is a lower bound on age, ceiling expiry can never remove a connection that is still alive.
- **DC-8:** Re-paste disappearance and ceiling expiry both route into the collapse pathway shipped in sub-version 4.0.4.1, with no second implementation.

## 6. Hard constraints

- **HC-1:** One collapse pathway serves all three triggers; no second implementation may appear.
- **HC-2:** Ceiling expiry may never remove a connection that is still alive, because first-seen bounds age from below rather than fixing it.
- **HC-3:** A signature identifier is an ephemeral key within one wormhole's lifetime and is never treated as an identity across lifetimes.
- **HC-4:** An unchanged signature on re-paste produces no write, and last-seen bookkeeping respects the shipped debounce so it cannot invalidate the chain payload read set.
- **HC-5:** The map draws holes rather than paperwork: an unrecognised signature does not clutter the canvas.

## 7. Decisions the session plan must resolve

- **PD-1:** Paste-format edge cases — partial scans, the anomalies section, and client language variants — resolved against live samples rather than assumption.
- **PD-2:** The undo window's duration and how a removal is presented while it remains reversible.
- **PD-3:** How a stub node is matched to the system a jump resolves, so resolution never produces a duplicate.
- **PD-4:** How the signature list surface composes inside the shipped window primitive without extending that primitive.

## 8. Acceptance criteria

- **AC-1:** Pasting a representative scan populates the list with its signatures and anomalies correctly parsed — proving DC-1.
- **AC-2:** An unrecognised-group signature appears only in the list while a known wormhole signature spawns a ghosted stub on the canvas — proving DC-2 and HC-5.
- **AC-3:** Jumping through a hole predicted by a stub converts that stub into the real system with no duplicate remaining — proving DC-3.
- **AC-4:** Re-pasting an unchanged scan produces no writes, verified deterministically — proving DC-4 and HC-4.
- **AC-5:** A signature absent from a re-paste is removed and can be restored within the undo window — proving DC-5.
- **AC-6:** Last-seen bookkeeping writes only past the debounce threshold, and a chain payload document is unchanged by an ordinary re-paste — proving DC-6.
- **AC-7:** Entering a type populates its maximum lifetime and starts the ceiling countdown, and a connection whose first-seen is recent is never removed by ceiling expiry — proving DC-7 and HC-2.
- **AC-8:** Both a re-paste disappearance and a ceiling expiry drive the collapse pathway shipped previously, confirmed to be the same code path as the manual trigger — proving DC-8 and HC-1.
