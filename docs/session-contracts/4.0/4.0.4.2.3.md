## Session 4.0.4.2.3 — Fog and activity promotion

**Sub-version:** 4.0.4.2
**Master plan:** `docs/VERSION_4_0_PLAN.md` §4.0.4.2
**UX gate:** Yes
**Execution profile:** Frontier autonomous coding agent
**Delivery unit:** One agent session, one shared sub-version branch, one PR per session
**Roadmap coverage:** §4.0.4.2 zero-document fog halo, live-pilot presentation and activity promotion
**Internal phases:** 1. Derive the bounded fog halo from synchronized facts; 2. Render its controls and provisional state; 3. Land promotion and tune the live behavior
**Split triggers:** Fog cannot remain deterministic and document-free without changing the shipped layout or tracked-location contracts

## 1. Objective

Show where tracked pilots can reach without turning every visited system into
shared fact, and promote a fog system only when meaningful activity occurs.

## 2. Current context and dependencies

- **DEP-1:** Sessions 4.0.4.2.1 and 4.0.4.2.2 shipped tracking, classification and wormhole-exit authoring.
- **DEP-2:** Decisions D1 and D11 make fog derived presentation with a narrow activity-promotion exception.
- **DEP-3:** The static adjacency asset and deterministic layout are the only graph inputs.

## 3. Done conditions

- **DC-1:** A bounded breadth-first halo is on by default outside wormhole space, with a depth dial and toggle.
- **DC-2:** Fog writes no collaborative document and two clients derive the same halo from the same facts.
- **DC-3:** Fog systems and live pilots are visibly provisional and unmistakable from authored fact.
- **DC-4:** Defined meaningful activity promotes a fog system for every subscriber while preserving its fog context.
- **DC-5:** Promotion uses the shipped surfacing vocabulary.

## 4. In scope

- **IS-1:** Halo derivation, controls, fog rendering and live-pilot presentation.
- **IS-2:** The activity-promotion rule and its trigger set.

## 5. Out of scope

- **OOS-1:** Route halos, region rendering, notifications and observation scoring.
- **OOS-2:** Signature parsing and inference.

## 6. Hard constraints

- **HC-1:** Fog is deterministic derived presentation and stores zero documents.
- **HC-2:** Authoring every visited system remains forbidden.
- **HC-3:** Only the approved activity triggers promote fog to shared fact.

## 7. Decisions the session plan must resolve

- **PD-1:** The exact promotion triggers and preserved fog context.
- **PD-2:** The default halo depth, dial range and placement style.
- **PD-3:** The large-chain cost boundary for halo recomputation.

## 8. Acceptance criteria

- **AC-1:** A tracked pilot produces the bounded halo and its extent follows the dial — proving DC-1.
- **AC-2:** Two clients derive identical fog and no fog document is written — proving DC-2 and HC-1.
- **AC-3:** Operator inspection distinguishes every fog state from authored fact — proving DC-3.
- **AC-4:** A note in fog promotes the system on a second client with its context preserved — proving DC-4 and HC-3.
- **AC-5:** The promoted system surfaces through the shipped motion vocabulary — proving DC-5.

## 9. Verification

- **V-1:** Determinism and zero-document evidence.
- **V-2:** Two-client promotion and surfacing demonstration.
- **V-3:** Operator visual review and the repository's standing definition-of-done gate.

## 10. UX/operator gates

- **G-1:** The operator reviews halo depth, fog/fact distinction, live-pilot presentation and promotion against live mapping before the pull request opens.

## 11. Baseline/hotspot boundary

Expected baseline effect is Neutral. Planning must prevent the breadth-first
derivation from becoming per-render work that regresses large-chain performance.

## 12. Close-out behavior

This is the final session of sub-version 4.0.4.2 and ships through its own pull
request. It may become `Complete` after external review and merge, completing
the sub-version and advancing the resolver to 4.0.4.3.
