## Session 4.0.2.3.1 — Reactive read path

**Sub-version:** 4.0.2.3
**Master plan:** `docs/VERSION_4_0_PLAN.md` §4.0.2.3
**UX gate:** Yes
**Execution profile:** Frontier autonomous coding agent
**Delivery unit:** One agent session, one shared sub-version branch, one sub-version PR
**Roadmap coverage:** §4.0.2.3 reactive read path, kept separate from the data model by the approved delivery topology so an authorization or projection defect cannot ship under a review focused on live presentation
**Internal phases:** 1. Land the two split subscriptions against the shipped chain schema; 2. Build the reconciler that owns the merge and emits the motion intents later work consumes; 3. Label nodes from the versioned directory, place them provisionally, and prove the live two-client behavior
**Split triggers:** The reconciler's event contract cannot be settled without a motion-layer decision that belongs to sub-version 4.0.3.2, requiring operator direction before the intent vocabulary is fixed

## 1. Objective

Make two browsers watch the same map change live: split subscriptions, a
reconciler that owns the merge, and nodes labelled from the versioned client
directory — with no refresh control anywhere. This belongs in sub-version 4.0.2.3
because it is the first live picture of shared chain data and the point at which
the version's central bet, that the server owns existence while each client owns
placement, becomes observable.

## 2. Current context and dependencies

- **DEP-1:** Sub-version 4.0.2.2 shipped the chain schema, its indexes, the authorization gate and the access projection, all proven independently of any interface.
- **DEP-2:** Sub-version 4.0.2.1 shipped the map shell, the host layer and the development wall this renders inside.
- **DEP-3:** Sub-version 4.0.1.3 shipped the versioned system directory this session labels nodes from.
- **DEP-4:** Decision D1 fixes the product bet: facts are shared and presentation is derived. Positions, layout and animation are local and are never synchronized.
- **DEP-5:** The prior version's subscription-split lesson is binding: a connection change must not cause the systems read set to be re-read.
- **DEP-6:** The reconciler's output events are the motion intents sub-version 4.0.3.2 consumes, so their vocabulary is established here even though no motion ships in this session.
- **DEP-7:** Decision D11's consequence for live surfaces is that no manual refresh control exists anywhere in the map.

## 3. Done conditions

- **DC-1:** A document inserted on one client appears on the other with no refresh, and a removed document leaves both.
- **DC-2:** A node moved locally holds its position through an unrelated subscription update, and a node being dragged is never repositioned by an incoming update.
- **DC-3:** Nodes display real system names and classes resolved from the versioned client directory.
- **DC-4:** Revoked access resolves to a calm state explaining access is no longer held, rather than an error screen.
- **DC-5:** No loading spinner exists anywhere on the canvas: the canvas renders immediately and nodes arrive when their data does, with reconnection handled silently.
- **DC-6:** The two subscriptions remain split so a connection change does not re-read the systems range.
- **DC-7:** The reconciler owns the merge and emits a named set of intents describing what arrived, what left and what moved.

## 4. In scope

- **IS-1:** The two split subscriptions over the shipped chain schema.
- **IS-2:** The reconciler, its merge ownership, and its named intent vocabulary.
- **IS-3:** Directory-driven node labelling.
- **IS-4:** Provisional node placement sufficient to observe live behavior.
- **IS-5:** The calm revoked-access state and silent reconnection behavior.

## 5. Out of scope

- **OOS-1:** The deterministic layout engine, which belongs to sub-version 4.0.3.1; placement here is provisional and may be arbitrary.
- **OOS-2:** Any motion or animation, which belongs to sub-version 4.0.3.2.
- **OOS-3:** Any mutation interface; this session reads only.
- **OOS-4:** Signature subscriptions, which belong to sub-version 4.0.4.3.
- **OOS-5:** A connection-state indicator with a permanent home, which requires the window framework from sub-version 4.0.3.3.
- **OOS-6:** Any loading spinner or manual refresh control, which decision D11 forbids on a live surface.

## 6. Hard constraints

- **HC-1:** The server owns existence and the client owns placement. The reconciler must never overwrite a local position on an incoming update.
- **HC-2:** The subscriptions stay split between the rarely-changing systems set and the frequently-changing connections set, so a connection change does not re-read the systems range.
- **HC-3:** The client subscribes directly; the route stays static and no server-side preloaded query is introduced.
- **HC-4:** No manual refresh control ships anywhere on the map.
- **HC-5:** Loading is not modelled as a distinct visual state; nodes simply arrive, so the same vocabulary later carries the surfacing animation.

## 7. Decisions the session plan must resolve

- **PD-1:** The reconciler's exact event contract — the intents for a node arriving, leaving and being repositioned — given sub-version 4.0.3.2 consumes them as motion intents.
- **PD-2:** How a locally moved or actively dragged node is identified so an incoming update provably cannot disturb it.
- **PD-3:** The provisional placement approach, chosen so it can be replaced by the deterministic layout engine without reworking the reconciler.
- **PD-4:** How the revoked-access state is distinguished from an ordinary empty map so the calm state is correct rather than merely quiet.

## 8. Acceptance criteria

- **AC-1:** With two clients open on one map, inserting a document makes it appear on both without a refresh, and removing it makes it leave both — proving DC-1.
- **AC-2:** A node moved locally retains its position across an unrelated update, and a node held under an active drag is never repositioned — proving DC-2 and HC-1.
- **AC-3:** Nodes render the correct system names and classes for known systems — proving DC-3.
- **AC-4:** Revoking access while a client watches resolves that client to the calm no-access state rather than an error screen — proving DC-4.
- **AC-5:** An inspection of the map surface finds no spinner and no refresh control, and a forced disconnection recovers without user action — proving DC-5 and HC-4.
- **AC-6:** A connection change leaves the systems read set untouched, shown deterministically rather than by observation — proving DC-6 and HC-2.
- **AC-7:** The reconciler emits its named intents for arrival, departure and repositioning, and those intents are the only merge output the canvas consumes — proving DC-7.

## 9. Verification

- **V-2:** Deterministic evidence that a connection change does not re-read the systems range.
- **V-3:** Reconciler intent coverage for arrival, departure and repositioning.

- **V-5:** The repository's standing definition-of-done gate.

changes.

## 12. Close-out behavior

This session is the only session of sub-version 4.0.2.3, so it completes the
sub-version: it commits on the shared lifecycle branch, pauses for the operator
browser review named above, then opens the sub-version pull request. It may
become `Complete` only once that pull request passes the external review gate and
merges. The map remains behind the development wall. On merge, the resolver
advances to sub-version 4.0.3.1.
