## Session 4.0.3.1.2 — Layout integration and tuning

**Sub-version:** 4.0.3.1
**Master plan:** `docs/VERSION_4_0_PLAN.md` §4.0.3.1
**UX gate:** Yes
**Execution profile:** Frontier autonomous coding agent
**Delivery unit:** One agent session, one shared sub-version branch, one sub-version PR
**Roadmap coverage:** §4.0.3.1 selected layout engine integration, worker execution, local pinning and operator tuning
**Internal phases:** 1. Run the selected engine off the main thread and load it only on the map route; 2. Integrate computed positions and local-only pinning; 3. Expose the dials and iterate to operator sign-off
**Split triggers:** Integration disproves a determinism or stability claim accepted in 4.0.3.1.1, requiring the engine decision to reopen

## 1. Objective

Integrate the approved deterministic layout engine into the live canvas without
synchronizing presentation, then tune its drawing feel to operator sign-off.

## 2. Current context and dependencies

- **DEP-1:** Session 4.0.3.1.1 selected the engine behind a pure graph-to-positions seam and proved its deterministic properties.
- **DEP-2:** Sub-version 4.0.2.3 shipped the reconciler this session supplies with positions.
- **DEP-3:** Decisions D1, D2 and D8 keep layout local and prevent motion from feeding back into its targets.

## 3. Done conditions

- **DC-1:** Layout runs off the main thread and its library is absent from non-map routes.
- **DC-2:** The canvas consumes only the shipped pure layout seam, and identical clients retain identical computed positions.
- **DC-3:** Unlock, drag and re-lock pins a node locally, excludes it from layout while pinned, never synchronizes the pin and returns it to its computed position.
- **DC-4:** The ring, sector, sibling and direction dials are exposed and the operator signs off the live drawing feel.

## 4. In scope

- **IS-1:** Worker and route-scoped loading integration.
- **IS-2:** Canvas position consumption, local pinning and tuning controls.

## 5. Out of scope

- **OOS-1:** Motion and animation, which belong to 4.0.3.2.
- **OOS-2:** Fog and non-wormhole placement, which belong to 4.0.4.2.

## 6. Hard constraints

- **HC-1:** The shipped pure seam remains the only position-computing path.
- **HC-2:** Pins and tuning state are local presentation and are never synchronized.
- **HC-3:** Integration may not weaken the deterministic and stability properties proved in the first session.

## 7. Decisions the session plan must resolve

- **PD-1:** Worker mounting, cancellation and stale-result handling.
- **PD-2:** The tuning dial ranges and operator-review fixture.
- **PD-3:** How a pinned node rejoins its deterministic target without changing shared layout.

## 8. Acceptance criteria

- **AC-1:** Profiling shows the main thread remains responsive during a layout pass and route evidence excludes the library elsewhere — proving DC-1.
- **AC-2:** Two integrated clients retain identical positions for the same graph — proving DC-2.
- **AC-3:** The full pin round trip remains local and returns to the computed position — proving DC-3.
- **AC-4:** The operator records sign-off after tuning against live mapping — proving DC-4.

## 9. Verification

- **V-1:** Worker responsiveness and route-scoped loading evidence.
- **V-2:** Integrated determinism and pinning demonstrations.
- **V-3:** Operator sign-off and the repository's standing definition-of-done gate.

## 10. UX/operator gates

- **G-1:** The operator tunes the exposed dials against live mapping and approves the drawing feel before the pull request opens.

## 11. Baseline/hotspot boundary

Expected baseline effect is Neutral. Planning must keep worker orchestration and
canvas integration separate enough that neither arrives near a universal
complexity cap.

## 12. Close-out behavior

This is the final session of sub-version 4.0.3.1. It completes the shared branch,
pauses for operator review, and opens the single sub-version pull request.
