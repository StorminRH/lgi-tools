## 1. Objective

Create a valid empty map atomically and open it at the shipped home prompt
without partial state or a bespoke abuse-control mechanism.

## 2. Current context and dependencies

- **DEP-1:** Sub-version 4.0.1.1 shipped durable map/access tables.
- **DEP-2:** Sub-version 4.0.2.2 shipped the one-way collaborative access projection.
- **DEP-3:** Sub-version 4.0.4.1 shipped the first-run home prompt.
- **DEP-4:** The repository already owns reusable rate-limiting mechanisms.

## 3. Done conditions

- **DC-1:** One small dialog accepts a name and private/corp visibility.
- **DC-2:** One durable transaction writes the map and owner access row, then the one-way projection is written and the map opens at the home prompt.
- **DC-3:** A new map contains zero collaborative chain documents.
- **DC-4:** No map-count cap exists, while the existing rate guard blocks a scripted burst and not human use.

## 4. In scope

- **IS-1:** Creation dialog, durable transaction, owner projection and first-run handoff.
- **IS-2:** Creation rate limiting through an existing repository mechanism.

## 5. Out of scope

- **OOS-1:** Switching and access editing, owned by 4.0.4.4.2.
- **OOS-2:** Archive and purge, owned by 4.0.4.4.3.

## 6. Hard constraints

- **HC-1:** Partial durable map creation is impossible.
- **HC-2:** A new map holds no chain documents.
- **HC-3:** The guard is invisible to normal users and is not a bespoke counter.

## 7. Decisions the session plan must resolve

- **PD-1:** Transaction-to-projection sequencing and recovery if projection delivery fails.
- **PD-2:** Which existing rate-limiter owner matches the durable creation boundary.

## 8. Acceptance criteria

- **AC-1:** The dialog creates private and corp maps with their owner row — proving DC-1 and DC-2.
- **AC-2:** Failure injection cannot leave a partial durable map, and projection retry remains one-directional — proving DC-2 and HC-1.
- **AC-3:** A created map has zero chain documents — proving DC-3.
- **AC-4:** A scripted burst trips the guard while ordinary use does not — proving DC-4 and HC-3.

## 9. Verification

- **V-1:** Atomicity and projection-recovery evidence.
- **V-2:** Empty-map and rate-guard coverage.
- **V-3:** Operator review and the repository's standing definition-of-done gate.
