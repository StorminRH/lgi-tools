## Session 4.0.4.4.1 — Maps and access management

**Sub-version:** 4.0.4.4
**Master plan:** `docs/VERSION_4_0_PLAN.md` §4.0.4.4
**UX gate:** Yes
**Execution profile:** Frontier autonomous coding agent
**Delivery unit:** One agent session, one shared sub-version branch, one sub-version PR
**Roadmap coverage:** §4.0.4.4 maps and access — creation, the switcher, the access editor, the archive lifecycle, and the creation rate guard
**Internal phases:** 1. Land map creation as one durable transaction with its projection write and first-run handoff; 2. Land the switcher and the owner-only access editor; 3. Land the archive, grace and purge lifecycle with its bounded sweep and the creation rate guard
**Split triggers:** The purge sweep cannot delete a large map's documents within the collaborative platform's per-operation limits without a batching design that changes the shipped schema, requiring operator direction

## 1. Objective

Make maps manageable and closable: create one, switch between them, grant and
revoke access, and archive one safely with no path that instantly destroys a
living chain. This belongs in sub-version 4.0.4.4 because it is the last slice of
the roadmap and because map lifecycle management is a distinct durable-side domain
from the chain behavior that precedes it.

## 2. Current context and dependencies

- **DEP-1:** Sub-version 4.0.1.1 shipped the durable map and access tables, the authorization helper, and the corp-membership resolver this session's access editor uses.
- **DEP-2:** Sub-version 4.0.2.2 shipped the access projection that gates collaborative reads, written one-directionally from the durable side.
- **DEP-3:** Sub-version 4.0.4.1 shipped the first-run home prompt a newly created map opens to.
- **DEP-4:** Decision D9 makes the switcher the fourth floating chrome element, composed at the application layer alongside the menu, the reserved search slot and the account control.
- **DEP-5:** The account control already exposes a dynamic per-page settings section, which is the mechanism the access editor occupies rather than a new surface.
- **DEP-6:** The repository already provides a rate-limiting component that the creation guard uses rather than a bespoke counter.
- **DEP-7:** An idle map costs nothing: with no viewer there is no subscription, and per-map document volume is small, which is why no cap on the number of maps is imposed.

## 3. Done conditions

- **DC-1:** Creating a map is one small dialog taking a name and a visibility of private or corp, which performs one durable transaction writing the map and its owner access row, plus the projection write, and opens the map at the home prompt.
- **DC-2:** A newly created map holds zero collaborative documents.
- **DC-3:** The switcher is a dropdown whose trigger is the current map's name, and switching retargets every subscription to the new map so the canvas repopulates through the normal reconciler and surfacing behavior.
- **DC-4:** The switcher's list is read from the durable side on the server; the collaborative projection serves only the access gate.
- **DC-5:** No cap is placed on the number of maps, while a soft creation rate guard trips under a scripted burst and never under human use.
- **DC-6:** Access editing is owner-only, lives in the account control's per-page settings section, and accepts both character and corp principals with roles of viewer, editor or owner.
- **DC-7:** Revoking access evicts a live viewer, re-verified end to end.
- **DC-8:** A corp member can open a corp-visible map and a non-member cannot.
- **DC-9:** Archiving removes a map from every switcher immediately and is restorable by its owner; after a grace period a sweep purges the map's collaborative documents completely in bounded batches and tombstones the durable row. No path instantly hard-deletes a living chain.

## 4. In scope

- **IS-1:** The creation dialog and its single durable transaction with the projection write.
- **IS-2:** The dropdown switcher and subscription retargeting.
- **IS-3:** The owner-only access editor in the account control's settings section.
- **IS-4:** The archive, grace and purge lifecycle with its bounded sweep.
- **IS-5:** The creation rate guard built on the existing rate-limiting component.

## 5. Out of scope

- **OOS-1:** Finer role tiers beyond viewer, editor and owner, which remain deliberately deferred rather than rejected.
- **OOS-2:** Map settings beyond access management.
- **OOS-3:** Removing the development wall, which is the release act and happens only after the version's audit completes.
- **OOS-4:** Any content belonging to a later version.
- **OOS-5:** Changing the chain schema or the authorization gate shipped earlier.

## 6. Hard constraints

- **HC-1:** Purge happens only after the grace period, and no instant hard-delete path for a living chain may exist.
- **HC-2:** The switcher's list never reads the collaborative projection; that projection serves the access gate only.
- **HC-3:** Map creation is one durable transaction so a partially created map cannot exist.
- **HC-4:** The purge sweep deletes in bounded batches that respect the collaborative platform's per-operation limits.
- **HC-5:** The creation guard is invisible to real users and is built on the existing rate-limiting component rather than a new mechanism.

## 7. Decisions the session plan must resolve

- **PD-1:** The grace period's length, with a shorter-than-a-season default as the recorded lean.
- **PD-2:** The purge sweep's batching strategy under the platform's per-operation delete limits, including how it resumes if interrupted.
- **PD-3:** How subscription retargeting on a switch avoids a flash of the previous map's contents.
- **PD-4:** How the access editor presents corp principals given membership resolves through the shipped helper.

## 8. Acceptance criteria

- **AC-1:** Creating a map writes the map row and owner access row in one transaction, writes the projection, and opens the map at the home prompt — proving DC-1 and HC-3.
- **AC-2:** A newly created map contains no collaborative documents — proving DC-2.
- **AC-3:** Switching maps retargets every subscription and repopulates the canvas through the normal reconciler and surfacing behavior — proving DC-3.
- **AC-4:** The switcher's list is served from the durable side, and an inspection confirms it never reads the collaborative projection — proving DC-4 and HC-2.
- **AC-5:** A scripted creation burst trips the rate guard while an ordinary human creation rate does not — proving DC-5 and HC-5.
- **AC-6:** An owner can grant and change access for character and corp principals while a non-owner cannot reach the editor — proving DC-6.
- **AC-7:** Revoking access evicts a live viewer end to end — proving DC-7.
- **AC-8:** A corp member opens a corp-visible map and a non-member is refused — proving DC-8.
- **AC-9:** Archiving removes a map from switchers and is restorable, and after the grace period the sweep purges its collaborative documents in bounded batches and tombstones the durable row, with no instant hard-delete path present — proving DC-9, HC-1 and HC-4.
