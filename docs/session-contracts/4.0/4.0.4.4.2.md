## Session 4.0.4.4.2 — Map switching and access management

**Sub-version:** 4.0.4.4
**Master plan:** `docs/VERSION_4_0_PLAN.md` §4.0.4.4
**UX gate:** Yes
**Execution profile:** Frontier autonomous coding agent
**Delivery unit:** One agent session, one shared sub-version branch, one sub-version PR
**Roadmap coverage:** §4.0.4.4 durable map switcher, subscription retargeting, owner-only access editing, corp access and live revocation
**Internal phases:** 1. Land the durable server-read switcher; 2. Retarget subscriptions without stale-map flashes; 3. Land access editing and prove revocation and corp membership
**Split triggers:** Access editing requires a second authority path or switching requires reading the collaborative projection as a map list

## 1. Objective

Let authorized users switch maps and owners manage character and corp access
without widening the sole authorization path.

## 2. Current context and dependencies

- **DEP-1:** Session 4.0.4.4.1 shipped atomic map creation.
- **DEP-2:** Sub-version 4.0.2.2 owns the one-way access projection and revocation behavior.
- **DEP-3:** The switcher belongs in application chrome and the access editor in the existing per-page settings section.

## 3. Done conditions

- **DC-1:** The current map name opens a durable server-read switcher.
- **DC-2:** Switching retargets every subscription without flashing the previous map.
- **DC-3:** Owners can grant character and corp principals viewer, editor or owner access; non-owners cannot edit access.
- **DC-4:** Revocation evicts a live viewer end to end.
- **DC-5:** A corp member can open a corp-visible map and a non-member cannot.

## 4. In scope

- **IS-1:** Switcher, durable map listing and subscription retargeting.
- **IS-2:** Owner-only access editing, corp membership and revocation.

## 5. Out of scope

- **OOS-1:** Map creation and rate limiting, shipped in 4.0.4.4.1.
- **OOS-2:** Archive and purge, which belong to 4.0.4.4.3.

## 6. Hard constraints

- **HC-1:** The switcher never reads the collaborative access projection.
- **HC-2:** The access editor uses the existing settings slot and sole authority path.
- **HC-3:** Switching cannot expose stale content from the prior map.

## 7. Decisions the session plan must resolve

- **PD-1:** The subscription-retarget sequence that prevents stale flashes.
- **PD-2:** Character and corp principal presentation in the existing settings surface.

## 8. Acceptance criteria

- **AC-1:** The switcher lists only durable authorized maps — proving DC-1 and HC-1.
- **AC-2:** Switching repopulates through the reconciler without showing prior-map data — proving DC-2.
- **AC-3:** Owner and non-owner access-edit attempts produce the required outcomes — proving DC-3.
- **AC-4:** Revocation removes a live viewer — proving DC-4.
- **AC-5:** Corp member and non-member access cases diverge correctly — proving DC-5.

## 9. Verification

- **V-1:** Switch and stale-content demonstration.
- **V-2:** Character/corp authorization and live revocation evidence.
- **V-3:** Operator review and the repository's standing definition-of-done gate.

## 10. UX/operator gates

- **G-1:** The operator reviews switching, access editing and revocation in local browsers before the sub-version pull request opens.

## 11. Baseline/hotspot boundary

Expected baseline effect is Neutral. Planning must consume the page-settings
composition and avoid widening the AF-008 authorization-contract surface.

## 12. Close-out behavior

This is the second of three sessions in sub-version 4.0.4.4. It verifies and
commits on the shared branch without opening the sub-version pull request, then
hands off to 4.0.4.4.3.
