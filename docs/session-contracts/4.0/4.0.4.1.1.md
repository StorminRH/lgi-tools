**Split triggers:** The collapse pathway cannot be designed to serve its two later triggers without a decision about signature lifecycle that belongs to sub-version 4.0.4.3, requiring operator direction before the pathway is fixed

## 1. Objective

Make the chain hand-authorable and unobtrusive: additions always grow from
somewhere, the wormhole type is the only thing a user types, every destructive
action is undoable, and severing a connection never silently destroys a branch.
This belongs in sub-version 4.0.4.1 because it is the first mutation surface, and
because the collapse pathway it establishes must be designed once for three
eventual triggers rather than reimplemented later.

## 2. Current context and dependencies

- **DEP-1:** Sub-version 4.0.2.2 shipped the chain schema and the authorization gate every mutation here passes through.
- **DEP-2:** Sub-version 4.0.2.3 shipped the reactive read path these mutations fan out through.
- **DEP-3:** Sub-version 4.0.3.3 shipped the window and popover surfaces this session's editing affordances live in.
- **DEP-4:** Sub-version 4.0.1.3 shipped the wormhole codex that auto-fills a connection's mass budget, per-jump limit, regeneration, size class and lifetime from its type alone.
- **DEP-5:** Decision D11 requires removing chores rather than adding controls: where the codex can fill a field, no manual control for it exists, and where the type determines ship size, no ship-size control exists except for an unidentified far-side wormhole.
- **DEP-6:** Decision D3 places all of this session's writes on the collaborative side as shared chain data.
- **DEP-7:** The mass model ships two of its three layers here — the type's budget from the codex, and clamping from observed shake states — while the layer driven by observed jumps arrives with sub-version 4.0.4.2.
- **DEP-8:** The collapse pathway established here must serve two further triggers added by sub-version 4.0.4.3: a signature vanishing from a re-paste, and a lifetime ceiling expiring.

## 3. Done conditions

- **DC-1:** A connection is added from an existing node by choosing a destination through a type-ahead against the versioned directory, so a floating system cannot be created and the one-root rule holds by construction.
- **DC-2:** Entering a wormhole type auto-fills its mass budget, per-jump limit, regeneration, size class and lifetime from the codex, visibly, with no manual control offered for any field the codex fills.
- **DC-3:** Marking a connection end-of-life is one action that stores an absolute moment and produces a countdown on every client, alongside a separately presented honest ceiling derived from the type's lifetime and the connection's first-seen time.
- **DC-4:** The mass estimate reflects the type's budget and is clamped by observed shake states, and is presented as an estimate with its variance rather than as truth.
- **DC-5:** Deleting a system or connection is undoable, and a connection's type, mass and end-of-life are editable from a small surface anchored to it.
- **DC-6:** Severing a connection routes through one computed pathway that never destroys silently: a genuinely dead and empty branch is marked severed and offered for one-click undoable removal, while a branch retaining exits, pilots or another route home is kept and marked severed without prompting, and ambiguity keeps the branch.
- **DC-7:** A blank map presents exactly one affordance — a centred prompt to set a home system — and the first system chosen becomes the root.
- **DC-8:** Every mutation requires the editor role and is rejected for a viewer, while applying optimistically for the acting client and fanning out reactively to others.

## 6. Hard constraints

- **HC-1:** Every destructive operation is undoable, and the collapse pathway never destroys a branch silently.
- **HC-2:** The collapse pathway is designed once for three triggers — the manual one shipped here, plus re-paste disappearance and ceiling expiry added later — and no second implementation may appear.
- **HC-3:** Mutations are field-scoped and skip writes that would not change a value, so unchanged data produces no write.
- **HC-4:** No manual control exists for any field the codex can fill, and no ship-size control exists where the type determines it.
- **HC-5:** Additions grow from an existing node, so a disconnected system cannot be created.
- **HC-6:** Mass and remaining-life figures are presented as estimates with their honest bounds and never as certainties.

## 7. Decisions the session plan must resolve

- **PD-1:** The placement declaration restated for this session's writes — all authoring is collaborative chain data and therefore lands on the collaborative side per decision D3 — confirmed against the shipped schema.
- **PD-2:** How the context affordance and the anchored editing surface compose against the shipped window primitive without introducing a second window implementation.
- **PD-3:** The collapse pathway's decision inputs, chosen so the two later triggers can drive it without changing its shape.
- **PD-4:** How an observed shake state is recorded and how it clamps the mass estimate.
- **PD-5:** How optimistic local application is reconciled if a mutation is rejected by the gate.

## 8. Acceptance criteria

- **AC-1:** Adding a connection from a node creates the system and connection on every client, and no affordance exists that would create a disconnected system — proving DC-1 and HC-5.
- **AC-2:** Entering a type visibly fills every codex-derived field, and an inspection finds no manual control for any of them — proving DC-2 and HC-4.
- **AC-3:** Marking end-of-life produces a countdown on a second client and a separately presented ceiling derived from lifetime and first-seen — proving DC-3.
- **AC-4:** The mass estimate reflects the type budget, tightens when a shake state is observed, and displays its variance — proving DC-4 and HC-6.
- **AC-5:** Deleting a system or connection can be undone to the prior state, and connection fields are editable from the anchored surface — proving DC-5 and HC-1.
- **AC-6:** Severing a connection to a dead empty branch offers undoable removal, severing one to a branch with an exit keeps it marked severed without prompting, and an ambiguous case keeps the branch — proving DC-6.
- **AC-7:** A blank map shows only the home prompt, and the first chosen system becomes the root — proving DC-7.
- **AC-8:** A viewer's mutation attempt is rejected while an editor's succeeds, and an edit that changes nothing produces no write — proving DC-8 and HC-3.
