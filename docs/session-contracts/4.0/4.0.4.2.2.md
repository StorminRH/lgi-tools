## Session 4.0.4.2.2 — Fog of war, promotion and hole matching

**Sub-version:** 4.0.4.2
**Master plan:** `docs/VERSION_4_0_PLAN.md` §4.0.4.2
**UX gate:** Yes
**Execution profile:** Frontier autonomous coding agent
**Delivery unit:** One agent session, one shared sub-version branch, one PR per session
**Roadmap coverage:** §4.0.4.2 auto-mapping on jump — the derived fog halo, the activity promotion rule, and connection-to-signature hole matching
**Internal phases:** 1. Derive and render the fog halo from already-synchronized facts with zero stored documents; 2. Land the activity promotion rule that turns a fog system into shared fact; 3. Match a resolved connection against unresolved wormhole signatures where exactly one candidate fits
**Split triggers:** Fog placement cannot be made to read clearly against the deterministic layout without a layout change that belongs to sub-version 4.0.3.1, requiring operator direction

## 1. Objective

Show what is known, what is merely seen, and let activity turn the second into
the first: a derived fog halo around tracked pilots, a promotion rule that
authors a fog system when something meaningful happens there, and automatic
linking of a resolved connection to the signature that predicted it. This is the
second session of sub-version 4.0.4.2 and carries its visual review.

## 2. Current context and dependencies

- **DEP-1:** The first session of this sub-version shipped tracking, classification, wormhole-exit authoring, the mass decrement and the first observation emissions, and merged through its own pull request.
- **DEP-2:** Sub-version 4.0.1.3 shipped the stargate adjacency asset the fog halo walks.
- **DEP-3:** Sub-version 4.0.3.2 shipped the surfacing vocabulary that a promoted system uses when it becomes fact.
- **DEP-4:** Decision D1 makes fog derived presentation: it is computed identically by every client from already-synchronized facts and stores nothing.
- **DEP-5:** The authoring boundary established in the first session stands — wormhole exits are authored, travel beyond an exit is fog — and this session adds the single documented exception, promotion by activity.
- **DEP-6:** Signature data does not exist until sub-version 4.0.4.3, so hole matching here operates against whatever unresolved wormhole signatures exist and degrades cleanly when there are none.

## 3. Done conditions

- **DC-1:** Fog of war is on by default outside wormhole space: a bounded breadth-first halo around tracked pilots, computed over the static adjacency asset, with its depth exposed as a dial and a toggle available.
- **DC-2:** Fog is pure derived presentation and stores no collaborative document; two clients compute the same halo from the same synchronized facts.
- **DC-3:** Fog systems render as clearly provisional — ghosted and dimmed — and are visually unmistakable from authored fact.
- **DC-4:** Meaningful activity in a fog system promotes it into the shared map for every subscriber, carrying its own fog context; a note made in a fog system promotes it.
- **DC-5:** When a resolved connection's origin system has several unresolved wormhole signatures and the destination's class matches exactly one candidate, the connection links to that signature automatically; ambiguity links nothing and waits.
- **DC-6:** A promoted system surfaces using the shipped motion vocabulary rather than appearing abruptly.

## 4. In scope

- **IS-1:** The derived fog halo, its depth dial, its toggle and its rendering.
- **IS-2:** The promotion rule and its trigger set.
- **IS-3:** Connection-to-signature hole matching and its ambiguity behavior.
- **IS-4:** The live pilot indicator within fog.

## 5. Out of scope

- **OOS-1:** Route halos, which belong to a later version.
- **OOS-2:** Region rendering, which belongs to a later version.
- **OOS-3:** Notifications and alerting on fog activity, which belong to a later version.
- **OOS-4:** Signature parsing, lifecycle and inference, which belong to sub-version 4.0.4.3.
- **OOS-5:** Observation scoring and serving.
- **OOS-6:** The final scope of an author-everything setting, which remains parked pending real usage and leans per-map because it would change shared data.

## 6. Hard constraints

- **HC-1:** Fog is derived presentation and stores zero collaborative documents.
- **HC-2:** Every client computes the same fog from the same synchronized facts, so fog never becomes a per-client truth.
- **HC-3:** Authoring every visited system remains forbidden; promotion is the single documented exception and fires only on the defined activity triggers.
- **HC-4:** Fog is visually unmistakable from authored fact.
- **HC-5:** Hole matching links only when exactly one candidate fits; ambiguity waits for a person.

## 7. Decisions the session plan must resolve

- **PD-1:** The promotion trigger set's exact mechanics — which activities promote, and how a promoted system carries its fog context.
- **PD-2:** The fog placement style relative to the deterministic layout, resolved by eye during the operator's review.
- **PD-3:** The default halo depth and the dial's range.
- **PD-4:** How hole matching behaves when signatures do not yet exist, so the capability degrades cleanly before sub-version 4.0.4.3 ships.

## 8. Acceptance criteria

- **AC-1:** A tracked pilot outside wormhole space produces a bounded halo at the default depth, and changing the dial changes the halo's extent — proving DC-1.
- **AC-2:** Two clients viewing the same map compute an identical halo, and an inspection confirms no document was written for any fog system — proving DC-2 and HC-1.
- **AC-3:** Fog systems render ghosted and dimmed, clearly distinct from authored systems — proving DC-3 and HC-4.
- **AC-4:** Making a note in a fog system promotes that system into the shared map for a second subscriber, with its fog context preserved — proving DC-4 and HC-3.
- **AC-5:** A resolved connection whose destination class matches exactly one unresolved signature links to it, while a case with two matching candidates links nothing — proving DC-5 and HC-5.
- **AC-6:** A promoted system appears using the surfacing vocabulary rather than snapping into place — proving DC-6.

## 9. Verification

- **V-2:** Evidence that fog writes no collaborative document and that two clients derive the same halo.
- **V-3:** Hole-matching coverage for the single-candidate and ambiguous cases, plus the no-signatures degradation case.

## 12. Close-out behavior

This session is the second and final session of sub-version 4.0.4.2, and the
sub-version ships one pull request per session. This session opens its own pull
request from the shared lifecycle branch, recreated from the trunk after the first

external review gate and merges, at which point the sub-version is complete. It
publishes no version record. On merge, the resolver advances to sub-version
4.0.4.3.
