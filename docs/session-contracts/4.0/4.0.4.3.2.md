## Session 4.0.4.3.2 — Inference engine, provenance and observation emission

**Sub-version:** 4.0.4.3
**Master plan:** `docs/VERSION_4_0_PLAN.md` §4.0.4.3
**UX gate:** Yes
**Execution profile:** Frontier autonomous coding agent
**Delivery unit:** One agent session, one shared sub-version branch, one PR per session
**Roadmap coverage:** §4.0.4.3 signatures — the constraint-solver inference engine, the provenance model, pick-list ranking, typed observation emissions, and the first real widget hosting
**Internal phases:** 1. Land the constraint solver that treats each wormhole signature as an unknown and each static as a constraint that must be satisfied; 2. **Split triggers:** The statics dataset is neither shipped nor able to run explicitly degraded, so inference would have to invent a system's constraints — which the honesty rules forbid

## 1. Objective

Deliver the version's flagship automation: a small constraint solver that
identifies wormhole signatures from what must be true about a system, with
provenance that never lets a guess overwrite a person, and the observation
emissions that make the dataset compound. This is the second and final session of
sub-version 4.0.4.3 and carries its visual review.

## 2. Current context and dependencies

- **DEP-1:** The first session of this sub-version shipped parsing, lifecycle, stub nodes, the ceiling and the two collapse triggers, and merged through its own pull request.
- **DEP-2:** Sub-version 4.0.1.6 must have shipped, or be explicitly running degraded with inference off and the pick list unranked; a static is never fabricated.
- **DEP-3:** Sub-version 4.0.1.3 shipped the sites widget export and the props contract this session hosts through, so a signature row can open the card; without it the row would degrade to opening the standalone page.
- **DEP-4:** Sub-version 4.0.3.3 shipped the window primitive the widget is hosted in.
- **DEP-5:** Decision D16 binds the attribution and anti-circularity rules: identification is directional, an observation attributes to a wormhole's origin side, the untyped far-side code is never an attributable type, inferred values never enter the stream, and accepting a suggestion weighs far less than overriding it.
- **DEP-6:** Elimination reasoning is only strictly sound for a complete scan, which cannot be verified, so provenance rather than certainty is the honesty mechanism.
- **DEP-7:** A static always exists and respawns under a new signature identifier when it collapses, which is what makes it a constraint rather than an observation.

## 3. Done conditions

- **DC-1:** Each wormhole signature is treated as an unknown, each of the system's statics is a constraint that must be satisfied, and every identification — typed, jumped or eliminated — propagates through the remaining unknowns.
- **DC-2:** A system with one static self-labels that static on paste, and a two-static system resolves by elimination where the evidence permits.
- **DC-3:** History narrows the solution: a confirmed static proves that later wormhole signatures in that system are not that static.
- **DC-4:** Every identification carries visibly distinct provenance — inferred, user-confirmed, or jump-verified — where user-confirmed outranks inferred, jump-verified outranks both, and a contradiction yields immediately.
- **DC-5:** Inference never silently overrides a person's identification.
- **DC-6:** The pick list is ordered by the merged per-system profile rather than by separate ranking logic: statics first from the community dataset, graduating toward observation-driven ordering as data accumulates.
- **DC-7:** A typed identification emits an observation weighted by whether the user accepted a suggestion or overrode it, and an inferred value provably never emits.
- **DC-8:** A signature row of a site type opens the sites card widget inside a window through the shipped props contract.
- **DC-9:** With the statics dataset unavailable, inference is off and the pick list is unranked rather than fabricated, and the rest of the signature surface still works.

## 6. Hard constraints

- **HC-1:** Inferred values never enter the observation stream, and a test proves it.
- **HC-2:** An observation attributes to the wormhole's origin side only, and the untyped far-side code is never recorded as an attributable type.
- **HC-3:** Provenance ordering is absolute: jump-verified outranks user-confirmed, which outranks inferred, and inference never silently overrides a person.
- **HC-4:** Without the statics dataset the system degrades honestly — inference off, pick list unranked — and never fabricates a static.
- **HC-5:** Ranking derives from the merged per-system profile; no separate ranking logic is introduced beside it.

## 7. Decisions the session plan must resolve

- **PD-1:** The solver's constraint model stated in plain terms, so the operator can review the reasoning rather than only the code.
- **PD-2:** How a contradiction is detected and what yielding immediately means for the displayed state.
- **PD-3:** The acceptance-versus-override weighting's exact values and how the distinction is captured at the point of identification.
- **PD-4:** How the merged per-system profile blends the community statics bootstrap with accumulated observations without letting inference feed itself.

## 8. Acceptance criteria

- **AC-1:** A single-static system self-labels its static on paste, and a two-static system resolves the second by elimination once the first is identified — proving DC-1 and DC-2.
- **AC-2:** After a static is confirmed, a later wormhole signature in that system is excluded from being that static — proving DC-3.
- **AC-3:** Identifications display their provenance distinctly, a user-confirmed value survives a contradicting inference, and a jump-verified value overrides a user-confirmed one — proving DC-4, DC-5 and HC-3.
- **AC-4:** The pick list orders by the merged per-system profile, and no second ranking path exists — proving DC-6 and HC-5.
- **AC-5:** A typed identification emits an observation whose weight differs between acceptance and override, and no inferred value ever produces an emission — proving DC-7 and HC-1.
- **AC-6:** An emitted observation attributes to the origin side, and a far-side untyped signature produces no attributable type, bounding the emissions DC-7 requires — proving DC-7 and HC-2.
- **AC-7:** A site-type signature row opens the sites card widget in a window using the shipped props contract unchanged — proving DC-8.
- **AC-8:** With the statics dataset made unavailable, inference is off and the pick list is unranked while parsing, lifecycle and stubs continue to work — proving DC-9 and HC-4.
