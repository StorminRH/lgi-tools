## Session 4.1.2.1 — What is on the system

**Sub-version:** 4.1.2
**Master plan:** `docs/VERSION_4_1_PLAN.md` §4.1.2
**UX gate:** Yes
**Execution profile:** Frontier autonomous coding agent
**Delivery unit:** One agent session, land each Ordered work step on development
**Roadmap coverage:** §4.1.2 disc glance marks, shared intel body, k-space region and trade-hub text
**Internal phases:** 1. Disc glance marks for identified harvestables, hacking, and combat; 2. Shared intel body with statics, category blocks, and ship names; 3. K-space region and closest-hub chrome, then the UX look
**Split triggers:** Showing identified content requires a new live intel feed or a second inspector outside the shared intel body

## 1. Objective

The chain shows where identified content is. The shared intel body shows
statics, identified site totals, and ship names. A mapped k-space exit shows
region and closest trade hub. This is the chrome half of 4.1; seats must
already hold still.

## 2. Current context and dependencies

- **DEP-1:** Session 4.1.1.1 has landed. Widgets and taller k-space frames sit
  on seats that no longer jump.
- **DEP-2:** Scanner grouping and site values already exist on the map
  (`scannerSectionForGroup`, harvestable live Jita, combat blue loot).
- **DEP-3:** Static slots already feed ghosts (`useSystemStaticSlots`); this
  session displays them under the wormhole title and does not change seat
  accounting.
- **DEP-4:** `shipTypeId` already rides on presence; the intel friendly list
  does not show a ship name yet.
- **DEP-5:** Stargate adjacency is already used for off-map pilot arrows; no
  trade-hub BFS exists yet.
- **DEP-6:** Standing decisions D4–D9 and the Trade hubs table in the master
  plan bind this session.

## 3. Done conditions

- **DC-1:** Three disc icons — Harvestables, Hacking, Combat — light only for
  identified rows in that bucket. Unknown and unidentified rows light nothing.
  Empty buckets omit.
- **DC-2:** Click card and current-system dock render one shared intel body.
- **DC-3:** Under the title on a wormhole system, each static shows as type
  code plus leads-to class. K-space cards omit that list.
- **DC-4:** Each present identified category is a collapsed block with count
  and total ISK from figures the scanner already has; expand shows names only.
  The list does not open the sites card.
- **DC-5:** Friendlies show the ship name next to the pilot.
- **DC-6:** Mapped k-space exits (security in the disc) may use a taller
  frame. Title text above the disc shows name, region, and closest hub with
  gate-jump count. The card lists all five hubs, closest first. No hub line.
  No hub widget.

- **OOS-2:** Opening the sites card from the intel list. Scanner still hosts

- **OOS-3:** Hub connection lines, route halo, waypoints, search bubble.

- **OOS-5:** A wormhole widget. Holes stay stubs and lines.

- **OOS-7:** New `src/features/*/widget.tsx` hosts for the glance marks.

## 6. Hard constraints

- **HC-1:** Identified only. Disc widgets and the intel card show a signature
  only when it has an identified group: Gas Site, Ore Site, Data Site, Relic
  Site, or Combat Site.
- **HC-2:** Three glance buckets only: Harvestables (gas + ore), Hacking
  (relic + data), Combat. Icon only.
- **HC-3:** One intel body for click card and dock. Do not leave a second body
  for the dock.
- **HC-4:** ISK sums only rows that already have a figure. A named combat site
  without a number still counts in `Combat ×N` and shows no ISK.
- **HC-5:** Extra title lines only on mapped systems whose chip is security
  (HS / LS / NS), not C1–C6, Thera, Drifter, or Pochven.
- **HC-6:** Widgets are mapper chrome in the existing node widget slot, not new
  feature-slice widget hosts. The sites card stays the scanner’s D15 widget.
- **HC-7:** Site values, hub jumps, region, and ship names come from
  already-held data. No new live feed.
- **HC-8:** Native chrome. Fit existing primitives, or create or expand one.
  No separate restyle pass.
- **HC-9:** Fallow zones stay deny-by-default. No new cross-layer exceptions.

- **AC-4:** Identified categories appear as collapsed count-and-ISK blocks that

- **AC-5:** Friendlies show ship name beside the pilot — proving DC-5.
- **AC-6:** A mapped k-space exit shows region and closest hub with jump count
  above the disc, lists all five hubs closest-first on the card, and draws no
  hub line — proving DC-6 and HC-5.

Each Ordered work step lands on `development`. The session plan may become
`Complete` after the last Ordered work step of this contract, including G-1
and the UX Ordered-work step. Promote starts at 80 app-facing files versus

version’s last session: after any due promote, the last Ordered work step
archives the master plan; the next Start Session then waits on product
direction for the next master plan.
