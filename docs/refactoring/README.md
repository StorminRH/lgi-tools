This is a living document. Update it in the same PR that lands, revises, or rejects an item.

## How to use this guide

- Each item has a stable ID (`P###`; gaps are candidates merged into another item or rejected). Its full write-up is in the wave file: problem, verified sites, home, boundary check, API sketch, migration steps, tests, and notes.
- Work in wave order and respect **Depends on**. Take one item, or one tightly coupled cluster named under [Conflicts](#conflicts-to-reconcile), per PR against `development`.
- Line ranges were correct at the audit commit and will drift. Re-open every listed site before editing, and grep for sites added since.
- Before writing code, run `docs-researcher` for any framework API the item touches (React, Next.js, Convex, Base UI, React Flow, Vitest). Run `repo-mapper` for the blast radius of the primitive and its consumers. Run `fallow guard <files>` to confirm the boundary rules for the home you pick.
- Preserve the behavior differences listed under **Notes**. Where copies drifted, the note says which copy is correct, and fixing the wrong copy is part of the item.
- Run `pnpm check` through `test-runner` before each commit. No threshold raises, overrides, baselines, or suppressions. If an item turns out larger than its estimate, stop and record the blocker in the item rather than landing a partial migration.
- When an item lands, tick its status box in the wave file and the roadmap table, and add the PR link. If implementation shows the item is wrong, move it to [Appendix A](#appendix-a-rejected-candidates) with the reason.
- Effort: **S** is under half a day, **M** is one to two days, **L** is more. Risk and payoff are `low`, `medium`, or `high`. A **revised** verdict means the verifier narrowed or changed the original proposal; the write-up reflects the revision.

## Summary

LGI.tools has a layered architecture. `.fallowrc.json` defines 23 zones, and the code mostly respects them. The 284 verified items show the same failure in every zone: a canonical primitive already exists, or is one small step from existing, and call sites re-implement it. The copies have started to disagree. Some of these disagreements are cosmetic: four tracking spellings, two chip hues, Chip and Pill used for the same label. Many have become real defects:
- The per-deploy auth backfill re-creates users for deleted characters (P296).
- An empty `BETTER_AUTH_SECRET` silently skips the `SESSION_SECRET` fallback (P268).
- Site detail caches never see an SDE re-ingest (P185).
- `formatRelativeTime` prints "0mo ago" for 28–29 days (P088).
- Owner-dataset writes serve the pre-sync value after a sync (P184), and a purge leaves `use cache` tags alive (P241).
- Stale map-access projections count as delivered (P164).
- User unlink never repairs `user.email` (P161).
- int4 and uuid ids reach Postgres and return 500 (P247, P248).
- Ops alerts swallow non-2xx webhook responses (P173).
- Four chevrons miss `aria-hidden`, and AccountDangerZone has a WCAG 2.5.3 label mismatch (P006, P021).

The largest themes:
1. **UI primitives with one owner.** A complete dialog kit, SectionPanel, CollapsibleChevron, HelpPopover, ActionForm, one chart shell, Pill instead of Chip, and type roles locked by a census.
2. **src/lib as the single home for generic helpers.** groupBy, idsKey, clamp/roundTo, mapConcurrent, retry/sleep, isoDay, formatCount/formatSigned/unresolvedName, web-storage, typed `excluded()`, executeRows, directDatabase, advisory-lock keys.
3. **Domain vocabularies derived instead of restated.** EVE scopes, ESI owner types, door sides, Convex validators built from data tuples, site class and type taxonomy, wormhole codex index, Convex door contracts.
4. **Routes and server writes through the existing pipeline.** runMutationRoute, parseFormBody with field lists, seeOther with failure stash, one after()-scheduled usage emitter, unlinkCharacter.
5. **Owner-sync and ESI.** Shared port bases, single-flight token vending, one sheet-row read per phase, reuse of fresh corp roles.
6. **Convex helpers.** takeIndexedOrThrow, deleteIndexedBatch, findLiveSystem, uniqueByUserCharacter.
7. **Test harness.** Seven or more shared helpers replace hand-rolled fakes in about 150 test files.

Expected payoff: most items remove more lines than they add. The plan removes thousands of lines across production and tests, cuts several fallow dupes groups, and shrinks the churn hotspots flagged by health/CRAP (the engine modules, the coverage pins, the admin and account routes). The efficiency items remove real I/O:
- 8 identical JSONB reads per character per sheet run (P292)
- 3K Neon HTTPS round trips per board view (P178)
- 50 Fuzzwork calls per degraded refresh (P295)
- 4 concurrent SSO refreshes per character (P189)
- live corp role probes on every corp sync pass (P297)
- the board read on every industry landing (P080)
- React Flow memo breaks on every ChainLive render (P279)

The plan has 16 waves of independent PRs:
- Waves 1–2 delete dead code and land the tooling and test-harness foundations.
- Waves 3–6 land the lib, format, persistence and vocabulary primitives that later items consume.
- Waves 7–15 adopt them zone by zone: UI kit, composition, routes, server and admin, owner-sync, client data, feature verticals, Convex, mapper.
- Wave 16 holds the four large or risky migrations: P219, P138, P046 and P246.

Where verifiers proposed competing homes or APIs for the same primitive, the Conflicts section picks one. About 50 such overlaps were found. Downstream items land only the residual scope.

**Counts.** 574 raw findings from 35 finders were consolidated into 303 opportunities. Of those, **284 were verified** (249 revised by the verifier) and 19 were rejected.

### Vocabularies and contracts derived, not restated
