## Delivered outcome

Every mutation, tool read, cron, and queued job now carries a stable capability
name and writes one durable outcome record, so a user-reported failure is
findable: the correlation id in the response body is the id recorded on the
server, alongside the stable error code, total and per-dependency durations,
retry result, and app version. Five owned service indicators read live from those
rows on the admin ops section, each naming who acts when it degrades and what they
do. A third test-only registry judges every re-runnable unit of work for duplicate
or loss risk. No application behavior changed.

## Divergences from plan

- **Plan interface for `sli-queries.ts` declared `getJobBacklog` in the telemetry
  slice.** Built in `src/app/admin/ops-view.ts` as `deriveJobBacklog` instead.
  Reading `@/data/esi-refresh-jobs` from `data/telemetry` is a peer-slice import
  that Fallow rejects; the admin page already owns both reads, so the composition
  belongs above them. Authority: discovered evidence (Fallow boundary violation).
- **Plan interface for `SliDefinition` declared a `query: SliQueryName` field.**
  Omitted. The panel wires the five queries explicitly because they differ in
  shape and arity, so the field always equalled `id` and nothing read it.
  Authority: discovered evidence (pre-PR design review).
- **Plan called for "one `addDependencyTiming` call at its existing single seam"
  for Upstash.** Required a client wrapper (`withCommandTiming` in
  `src/lib/upstash.ts`) instead. The SDK exposes no per-command completion hook
  and no injectable fetch, and the ESI scoreboard uses pipelines, whose cost lands
  entirely on `exec()`. Authority: discovered evidence.
- **Plan's ordered work 1 named four test importers of `problemResponse`.** Three
  of them (`api-client.test.ts`, `decode.test.ts`, `characterSync.test.ts`) define
  local helpers of that name and never imported the symbol; `service-auth.test.ts`
  did import it and was not listed. Authority: discovered evidence.
- **Rate limiting moved inside the mutation shell.** The plan left caller-owned
  rate limits ahead of the boundary. Four account routes therefore returned 429
  outside the capability scope, recording nothing, so a throttled surface would
  read as idle. Added a `preflight` stage that keeps the check ahead of identity
  but inside the scope. Authority: discovered evidence (PR review finding).

## Successor notes

- **A function covered only by a `*.db.test.ts` suite scores 0% in CI and can fail
  Fallow's CRAP cap while `pnpm verify` passes locally.** This session hit it on
  `sli-queries.ts` (CRAP 90/42/30 against a 30 cap). The fix is always off-database
  unit coverage in a sibling suite, never a suppression. Local green is not
  evidence for this class.
- **Fallow's vendor-rail census matches source text including comments.** A prose
  comment containing the literal `postgres()` failed `vendor-resilience.test.ts`.
  Reword the comment; do not weaken the rail.
- **postgres-js `Query` is lazy and `extends Promise` with `Symbol.species`
  returning `Promise`.** Timing it without executing a query the caller never
  awaited means patching the returned query's `then` in place. `handle()` is
  guarded by its own `executed` flag, and `catch`/`finally` need no patch because
  both delegate to `this.then`.
- **A required shell option is a cheaper coverage rail than a test.** Making
  `capability` required turned "is this route instrumented?" into a compile error
  for the 24 shell-owned operations; only the 13 outside the shells needed a census.
- **The cron capability row deliberately follows the shell's existing recording
  policy, not a per-run rule**, so an `idle` or `busy` no-op still writes zero rows
  and the `idle-silent` wake-class contract holds. This looks like a missed
  recording and is not.
- **`getDailyCounts` excludes `capability_outcome` by design.** Without it the
  admin traffic panel would blend server self-observation into user activity.
