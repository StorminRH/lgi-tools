## Delivered outcome

All 56 Neon tables now carry a machine-checked declaration of their owning
slice, cross-owner read and write contracts, database-enforced invariants,
transaction boundary, and data class, enforced by the existing
dataset-declaration census rather than a second governance document. The census
additionally fails on any production write to a table the writing slice neither
owns nor is declared against, and asserts row-level security is enabled nowhere
without a recorded per-data-class decision. The one invariant judged genuinely
race-exposed became a real constraint: concurrent owned-asset refreshes for a
single owner can no longer write duplicate natural-key rows into the ledger the
industry planner sums, and the losing refresh now stands aside cleanly. Racing
sets that share no natural key can still merge into their union; that residual
is recorded rather than fixed.

## Divergences from plan

- **Plan interface sketch for `SliceId` / `WriteSite.slice`.** The plan typed
  `WriteSite.slice` as `SliceId`. Built instead with `sliceOfPath` returning the
  structural slice string and `SliceId` as the closed vocabulary of table owners
  and declared writers only. Why: typing the scan result as a closed union would
  force this module to enumerate every directory under `src/`, duplicating the
  Fallow zone map that `AGENTS.md` names as the mechanical authority for
  file-to-zone ownership. The chosen shape fails closed — a slice matching no
  owner or declared writer is reported as undeclared. Authority: discovered
  evidence during implementation.
- **Plan detection sketch for the write scanner.** The plan specified matching
  `(db|tx|database).insert|update|delete(<ident>)`. Built receiver-agnostic
  instead: the operand must resolve to a reflected Drizzle table symbol, and the
  receiver name is not matched at all. Why: strictly more sensitive (a renamed
  handle cannot evade it) with no added false-positive risk, since a non-table
  operand can never match. Authority: discovered evidence.
- **`src/lib/module-path.ts` was not in the plan's owned surfaces.** Added when
  Fallow flagged the path-normalizer duplicated between `schema-reflection.ts`
  and `write-sites.ts`. Extracted for two real consumers rather than baselined.
  Authority: discovered evidence (mechanical gate pressure).
- **`collectProductionSources` and six registry types were exported in the
  implementation draft and un-exported at the design-review gate** as having no
  consumer. Authority: pre-PR design review.

## Discovered work

- Two per-user cap races found while declaring boundaries, both routed to
  `docs/backlog.md` under "Per-user cap races" with diagnosis, size, and trigger;
  contract HC-4 forbade fixing them here. Custom structures enforce their cap with
  a count-then-insert and no compensating recount. Saved plans do recount, but the
  compensation deletes the writer's own row, so two concurrent saves at the cap
  boundary can both be discarded and both users told the limit was reached.
- Eleven empty, untracked local directories exist in the working tree
  (`src/zzz/` and ten `* 2/` siblings such as `src/platform/auth 2/`). Machine-local
  cruft, invisible to git and to any `.ts` scan; reported to the operator, not
  actioned.

## Successor notes

- A `*.db.test.ts` proves nothing about a constraint unless `pnpm db:migrate` ran
  first. `createDbTestHarness` clones tables with `LIKE ... INCLUDING ALL` from the
  local `public` schema, so on an un-migrated database the clone silently lacks the
  constraint under test and the suite passes green.
- The write scanner's four blind spots are real and documented at the module: raw
  string-literal SQL naming no schema symbol (`src/scripts/backfill-users-if-empty.ts`
  writes `user` and `account` this way), Better Auth adapter-internal writes,
  variable-table helper calls such as `insertChunked(tx, eveRegions, rows)`, and
  non-import symbol aliases. The census pins a positive found-set — the four known
  cross-owner writes by file and table plus a floor on total detected sites — so a
  scanner that quietly stopped resolving symbols fails rather than reporting zero.
- `describeDbInvariants` must read `column.primary` and `column.isUnique`, not only
  `primaryKeys` and `uniqueConstraints`: in drizzle 0.45.2 the latter are empty for
  most tables because the schemas declare keys column-level. Index predicates render
  through `PgDialect.sqlToQuery(sql, 'indexes')`, whose `indexes` invoke source
  inlines values instead of emitting placeholders.
- The owned-assets constraint arbitrates duplicates, not winners. Two racing
  refreshes whose sets share no natural key still merge into their union; that
  residual is recorded in the table's registry note, as is the identical
  replace-all race on `owned_blueprints`, which has no natural key to constrain.
