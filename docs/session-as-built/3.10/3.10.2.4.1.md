## Delivered outcome

Every external service the app calls now has one declared resilience policy, and
no production call can be made without an explicit timeout. Three Upstash Redis
sites that previously ran with no request timeout and five silent retries now
fail fast into the degradation each already had; Neon HTTP queries carry a 30s
ceiling that cannot be mistaken for a cold start and retried; postgres-js states
its establishment bound from one owner at all eight construction sites; and the
last raw vendor `fetch` (Google Search Console) is bounded on both its API and
token legs. Lint rejects a bare `fetch`, a vendor SDK imported outside its owning
module, and a hand-written EVE SSO host.

## Successor notes

- `@upstash/redis` invokes a function-form `signal` once per `request()`, outside
  its retry loop, and rethrows immediately when that signal aborts. One declared
  timeout therefore bounds the whole attempt sequence, not each attempt, and a
  declared `retries: N` only ever covers transient non-abort errors. Do not
  reason about these values as if the timeout were per-attempt.
- `neonConfig.fetchFunction` is `NeonConfigGlobalOnly`; there is no per-client
  hook, and per-call `fetchOptions.signal` would freeze one signal for the
  client's lifetime. It is assigned inside `getClient()` on purpose, so
  `src/db/index.ts` stays import-side-effect-free. The census pins the
  single-`neon()`-consumer fact that justifies the global; adding a second
  consumer means revisiting that rationale, not just the test.
- The Neon driver wraps every fetch rejection as
  `NeonDbError: Error connecting to database: …` with `sourceError` set, which is
  indistinguishable by message from a real cold start. Any future bound on that
  path must keep the `TimeoutError` carve-out or one 30s hang becomes a ~123s
  retry envelope.
- ESLint flat config REPLACES a rule's options per matching block, so an
  exemption block that forgets a ban removes it silently while lint stays green.
  Reading the diff cannot detect this. Prove it instead by computing
  `calculateConfigForFile` for every source file under both the base and branch
  configs and diffing the resulting ban sets; that check found a real regression
  here. Place the baseline config at the repository root so its
  `eslint-config-next` imports resolve.
- A literal `[...all]` segment in an ESLint `files` glob is a minimatch character
  class and never matches the real path; glob its directory instead.
- The three coinciding 2000ms Upstash values are three independent policies that
  happen to share a number, not one constant awaiting extraction. The limiter
  retries once; the two hint writers do not.
