## Delivered outcome

The zone rules now draw themselves. A committed generator reads the `boundaries` block of
`.fallowrc.json` and emits both a GitHub-rendered Mermaid flowchart and a typed data
module, and a drift test byte-compares each against a fresh generation on every run, so a
boundary change that skips regeneration fails the build instead of leaving a stale diagram.
The public dev log's Fallow document renders that graph as a static permission matrix: 23
zones on both axes in layer order, 108 lit cells for declared permissions, a ringed cell
for the one reference-core exception, and a marked row for the one first-match carve-out.
Because both axes are layer-sorted, every lit cell falls on one side of the diagonal, so
the one-directional shape delivered by 3.10.1.1 and 3.10.1.2 is now visible rather than
asserted.

## Divergences from plan

- Plan `PD-4` specified Mermaid ids that "sanitize `/` to `__`", but its own worked example
  wrote `data__eve_data` for the zone `data/eve-data`, which also requires mapping `-` to
  `_`. Implemented the example's rule — `/` to `__`, every other non-word character to `_`
  — because a bare hyphen adjacent to Mermaid's `--` edge tokens is avoidable risk.
  Authority: discovered evidence, reconciled against the plan's own literal example.
- The plan's layout return shape listed `carveOutMarkers` carrying the covering zone, and
  an earlier draft also exposed a `litInset` field. Both were removed as unrendered state
  after review; the carve-out target stays pinned by the generator's taxonomy census
  instead. Authority: discovered evidence (design-review phase 2).
- The plan described a four-row legend. Shipped five: deny-by-default is true only between
  different zones, so the diagonal needed its own row rather than being folded into the
  "forbidden" claim. Authority: discovered evidence, recorded under Successor notes.

## Successor notes

- Fallow's `boundary-violation` rule constrains only cross-zone imports. A zone importing
  itself is entirely unconstrained — the `ui` zone declares `allow: []` yet its files import
  each other with the rule at `error`. Any prose about deny-by-default must therefore scope
  the claim to pairs of different zones; the shipped legend, SVG title, and devlog passage
  all do, and `zone-map-geometry.test.ts` pins that wording.
- `zoneId` is deliberately lossy, so `assertUniqueIds` is load-bearing rather than
  defensive: a collision would key both the layer map and the matrix row index to one zone
  and silently draw one zone's permissions against another.
- The drift test reads both artifacts as bytes through `node:fs` and must never import the
  generated module: a `scripts` to `features` import edge is absent from the very allow
  graph the map draws.
- `docs/**` is Fallow- and ESLint-ignored and sits outside the Tailwind `@source` scan, but
  `**/*.generated.ts` is ignored by Fallow only — the generated module still has to pass the
  full `src/**` lint rule set, including the contract-comment requirement.
- Editing any file invalidates its Istanbul coverage line-mapping, so a stale `coverage/`
  makes Fallow report untouched pre-existing functions at 0% and fail on CRAP. Regenerate
  coverage before believing a complexity finding.
