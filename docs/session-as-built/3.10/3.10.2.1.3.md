## Delivered outcome

Exactly one endpoint-contract system now owns every first-party programmatic
call. Convex reaches the two internal endpoints through a typed service
transport that shares the browser client's decode core, with runtime validation
and no response assertions; the three Better Auth seams call the library's own
typed client; query and path parameters are schema-derived and bound to the path
template at declaration; and the v1 model is deleted. New gates reject
contractless routes, orphaned contracts, template-literal same-origin URLs, and
asserted response bodies. This PR publishes sub-version 3.10.2.1.

## Divergences from plan

- Plan Interfaces (`ServiceCallInit`): the declared `timeoutMs?: number` was
  built, then removed at the pre-PR design review because no production caller
  needed it and only a test I had written exercised it. `serviceFetch` now leaves
  the shared outbound default in place, matching the bare-fetch call sites it
  replaced. Authority: design-review finding under the "no parameter without a
  current caller" rule; behavior unchanged.
- Plan Interfaces (`ServiceCallInit`, `ServiceBodyArgs`) and `EndpointCallInit`:
  declared as exports but unexported at the same review — zero external
  references. `src/platform/auth/service-client.ts` exports exactly `serviceFetch`.
- Plan Ordered work 3 (provider token proof): the plan located the
  null-on-error token proof in provider tests, but the src Vitest `include` glob
  covers only `*.test.ts`, so a `.tsx` provider suite would never run. The seam
  moved into `auth-client.ts` as `fetchConvexAccessToken`, proven in the existing
  `auth-client.test.ts` against the real client with a stubbed fetch — stronger
  evidence for AC-2 than mocking the library. Authority: discovered evidence.
- Plan Ordered work 1 (`decode.ts` interface): `decodeEndpointResponse` gained a
  generic overload pair and `networkFailure` an explicit return type, so both
  executors stay assertion-free under HC-3 while `apiFetch` keeps the single
  declaration SC-4 pins. Authority: discovered type-level constraint.

## Successor notes

- `convex/lib/characterSync.ts` imports contract *values* now, not only types, so
  Zod is bundled into the Convex isolate for the first time. The chain is
  `next/server`-free and free of `node:` builtins, but this whole failure class
  appears only in the post-merge production Convex push — never in `pnpm verify`
  or CI.
- Any stubbed first-party response in a test must derive its fixture type from
  the endpoint contract. Twelve `onlineStatusSync` tests failed the moment
  validation replaced the cast because their fixtures omitted `name` and
  `corporationId` and had only ever been valid under the cast.
- `PathParamKeys<string>` resolves to `string`, not `never`, so an endpoint whose
  `path` is widened away from a literal would force callers to pass `params`.
  Every contract goes through `defineEndpoint`, which keeps paths literal; do not
  annotate a contract with a widened type.
- The path-binding failure message arrives as a string-literal type on the
  `params` property, so a `@ts-expect-error` for it belongs directly above that
  property, not above the `defineEndpoint` call.
- The same-origin coverage inventories were deliberately left untouched for
  3.10.2.2.
