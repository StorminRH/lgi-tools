## Delivered outcome

A pilot can opt individual characters into tracking on individual maps; while a
tracked map is open, the platform follows each character's location and ship at
the ~5s ESI cache boundary through the existing sync engine, stores
docked/in-space state, writes nothing while the pilot is stationary, tears
tracking down on every revocation path, and classifies every observed movement
(gate placement, hole crossing, re-anchor, or noise) with a pure decision table
whose consumers are tests only. The shared chain tables are untouched.

## Divergences from plan

- **Plan statement:** Interfaces list continuity as derived "from the subject's
  bookkeeping (previous successful run covering this character within
  `JUMP_CONTINUITY_MS`)" with no dedicated field; `SYNC_DATASET_CONFIG` names
  only `chainOnSuccess`/`rateKeyScope` as engine extensions.
  **Built instead:** an optional `syncSubjects.coveredCharacterIds` stamp (the
  run's cleanly observed characters, 304s included) owned by the apply; both
  the `prevFresh` continuity decision and a new chain-on-success yield gate
  read it, so zero-yield "successes" no longer chain at the 5s floor.
  **Why:** the tracked-set proxy counted errored/unpolled characters as
  covered, producing invented paths on recovery — the exact case the plan's
  re-anchor rule exists to prevent.
  **Authority:** Evidence: Diff-mode adversarial review (three independent
  seats converged on the root cause; failure reproduced from the frozen diff).
- **Plan statement:** `mapTracking`/`forMap` specified without size bounds or
  durability labeling; purge contributor tier unspecified.
  **Built instead:** a per-(map, user) opt-in cap
  (`TRACKED_CHARACTERS_PER_MAP_USER_CAP`), a capped `forMap` read, the
  contributor moved to the `durable` tier, `mapTracking` documented as riding
  the sanctioned Convex durability exception (schema header,
  `convex/AGENTS.md`, `docs/CONVEX.md`), a tracking sweep in the
  purge-map-access door as the account-purge backstop, and non-2xx purge
  transport responses logged as missed deletes.
  **Why:** unbounded user-driven registry growth and uncapped hot reads
  violated the bounded-read invariant, and the registry's durability was
  mislabeled as regenerable in the schema header and purge tier.
  **Authority:** Evidence: Diff-mode adversarial review against
  `convex/AGENTS.md` bounded-read and regenerability invariants.

## Successor notes

- Continuity and the chain yield gate read `coveredCharacterIds`, never
  `syncedCharacterIds` (which keeps hint/park semantics); a dataset opting into
  `chainOnSuccess` must stamp the covered set or it never chains.
- Chain hops are jitter-free by construction (`computeChainBoundary`); adding
  jitter silently degrades cadence to the 30s scan.
- `observedAt` is last-change time (the HC-3 zero-write path never touches the
  document); freshness consumers read the subject's `lastFinishedAt`.
- `characterLocation.forViewer` deliberately ships before its consumer — the
  4.0.4.2.3 fog session reads it.
- Operator direction for 4.0.4.2.2, recorded during execution: visited k-space
  systems become authorable (reconcile with the successor contract's
  wormhole-exits-only wording at planning time, not by silent divergence);
  hole matching is signature-first with an informed confirmation question and
  never auto-asserts ambiguity; a `re-anchor` renders downstream as an
  orphaned anchor that regraphs and may reconnect, never an invented path;
  capsule/death fine-tuning stays deferred (non-adjacent capsule remains
  `re-anchor`).
