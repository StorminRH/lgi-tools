## Delivered outcome

Pasting probe-scanner output anywhere on the Atlas map applies it to the pilot's tracked current system: rows fill a permanent bottom-left scanner window (sectioned Signatures tab, Anomalies tab, signal fill, live age), wormhole rows live as unresolved connections rendered as ghosted stub nodes, and a jump through a stub resolves it into the real system on the same durable row. Re-pastes update in place with zero writes for unchanged rows; missing rows surface one bulk Dismiss/Remove prompt; every removal tombstones with a 24-hour undo backed by audit-log Restore entries; a right-click row editor hosts the shipped connection fields with a statics-first type picker, and typed codes show their destination class and anchor a first-seen lifetime ceiling whose grace-buffered cron sweep — like confirmed and confident removals — routes through the one extracted collapse core.

## Divergences from plan

- **Plan statement:** HC-3 implementation note — "a collapsed hole's tombstoned row is never revived by a new sig of the same ID (tombstoned rows are inert to paste)."
  **Built instead:** `applyScan` is signature-ID-first and revives a tombstoned row on re-paste, scoped to the SAME lifetime only: an unresolved stub inside its undo window with an unexpired ceiling and non-conflicting group revives in place; a collapsed resolved branch resurrects only through the ledger's branch undo; a passed ceiling, expired undo window, or conflicting group marks the pasted ID as a new lifetime that stays inert until the corpse purges.
  **Why:** Accidentally removed or dismissed rows reappearing on the next scan is the honest lifecycle; the close-out scoping preserves the contract's actual invariant that a signature ID is never an identity across lifetimes.
  **Authority:** Operator: G-1 direction for ID-first re-paste revive; the close-out adversarial round scoped the revive to one lifetime.
- **Plan statement:** PD-2 — per-row missing highlight with a Remove/dismiss confirmation affordance per row.
  **Built instead:** One frosted bulk prompt (Dismiss / Remove) above the scanner for the whole missing set, batch removal with a single undo toast, keyed to the paste-target system rather than the chain root; per-row confirm dialog removed.
  **Why:** Faster to act on real scans; the paste-target keying keeps the flow reachable when the pilot pastes away from the chain root.
  **Authority:** Operator: mid-session G-1 polish direction (2026-08-09); paste-target keying from close-out review findings.
- **Plan statement:** OW3 — signature window with counted kind tabs.
  **Built instead:** Sectioned Signatures tab (Unknown → Wormholes → Combat → Harvestables → Hacking) with per-section column recipes, a headerless 24rem dock, CCP security colors on Security Status readouts, and the typed code's destination class kept on the wormhole row.
  **Why:** Operator-directed presentation polish during the G-1 pause; the class label rode the retired Group column and was restored at close-out.
  **Authority:** Operator: mid-session G-1 polish direction (2026-08-09).
- **Plan statement:** Paste capture targets the paster's tracked current location (single-pilot wording).
  **Built instead:** Account-level target: any of the caller's covered ONLINE tracked pilots' system, with a truthful loading state during subscription warm-up; two-plus distinct systems refuse with an ambiguity toast (disambiguation in backlog). The server verifies tracked last-known location only — an accepted narrower check recorded on `requireTrackedSystem`.
  **Why:** Last-known location alone must not unlock paste for a logged-off alt.
  **Authority:** Operator: mid-session direction (2026-08-08); backlog entry for multi-system disambiguation.
- **Plan statement:** `by_death_latest` index on `deathLatestAt`; sweep batch 8 with `hasMore`.
  **Built instead:** Live-rows-only composite `by_deleted_death_latest` (`deletedAt`, `deathLatestAt`) read over both live representations (absent and explicit-null), a 64-row candidate window with 8 actions per run, per-row failure isolation with a per-map failure memo, and `failed` in the sweep result.
  **Why:** Tombstoned rows head-of-line-blocked the ascending range for their whole undo window, and one over-bound map's pre-write throw aborted the entire deployment-wide sweep.
  **Authority:** Evidence: close-out adversarial-review findings (reliability seat), probe-confirmed.
