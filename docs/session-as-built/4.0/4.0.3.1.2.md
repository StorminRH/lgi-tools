## Delivered outcome

The live Atlas canvas now draws its chain from the deterministic compass
kernel, computed in a route-scoped web worker behind the pure seam, through a
layout-then-merge pipeline: each chain change posts creation-ordered facts to
the worker and applies exactly one merge when that request's positions return,
with staleness decided by a posted-key/latest-wins model and drag protection
read at apply time. Systems render as circled class discs with names beneath;
connections render as straight segments clipped to each disc's rim through a
tested geometry module, with loop-closing (non-tree) connections dashed from
the kernel's own tree derivation. A whole-map lock (default locked) gates hand
dragging; re-lock clears every user stamp and the next merge snaps nodes home
through ordinary `system-moved` intents. The tuning panel exposes ring
spacing, separation, sibling fan, wedge posture, and direction-order dials
(local-only; every commit re-posts layout), plus a camera-follow toggle; the
viewport frames the chain once on first appearance and otherwise never moves
on its own. In-house deterministic trigonometry (`trig.ts`, fdlibm-class
minimax with exact-op reduction) replaced `Math.sin`/`Math.cos`/`Math.hypot`,
closing the recorded cross-engine float residual; browser probes confirmed
Chromium and Firefox render position-identical chains. The operator tuned
against paced replayed corpus chains and ratified the shipped defaults at the
G-1 gate (2026-08-02): ring 300, separation 150, sibling fan 3, `proportional`
wedge posture, compass-8 direction order, camera follow off. The determinism
fixture was deliberately regenerated twice (math swap; default bake). The
provisional grid assigner was deleted whole; `placement.ts` is now a pure
adapter from kernel results to the frozen `PlacementAssigner` seam. A paced
replay tool (`pnpm map:replay`, `src/scripts/`) seeds a disposable local map
and replays corpus timelines jump-by-jump, with `--loop` exercising the full
departure cascade; its degenerate-edge skip/defer policy is a tested plan
module.

## Divergences from plan

- **Plan statement:** owned surfaces place the replay tool at
  `scripts/map-replay.mjs`→`.ts` (repository root), and SC-1.3 expects
  `rg -l "mapper/layout" src --glob '!src/mapper/**'` to return no files.
  **Built instead:** `src/scripts/map-replay.ts` + `map-replay-plan.ts`, with
  an explicit `scripts → mapper` allowance in `.fallowrc.json`, a declared
  cross-owner `maps` seed write in the data-ownership registry, a `scripts`
  member in that registry's `SliceId` vocabulary, and the architecture-map
  census regenerated (24 zones / 117 permissions / 118 edges; zone-map cells
  117). SC-1.3's rg observable therefore returns exactly those two CLI entry
  files — declared tooling edges, not route bundles; the dev-server network
  capture still shows zero layout chunks on non-map routes.
  **Why:** root `scripts/` is boundary-`allowUnmatched`, so the planned
  location made a tooling→mapper-internals edge invisible to the mechanical
  boundary owner. The package script also gained `--conditions=react-server`
  because the projection's import chain carries `server-only`.
  **Authority:** Evidence: pre-PR ownership review demonstrated the invisible
  edge; the dataset-declaration and census suites enforced the rest.
- **Plan statement:** `kernel-requests.ts` includes a `die` transition routing
  later requests to the fallback.
  **Built instead:** the pure model owns only posted-key/latest-wins/
  terminal-reset sequencing; worker death is tracked by refs in
  `use-layout-kernel.ts`, which settles outstanding and subsequent requests
  through the in-process seam.
  **Why:** degradation belongs to the module that owns the worker; a `dead`
  flag in the sequencing model was one concept with two owners.
  **Authority:** Operator: directed correction of the identified dual
  ownership (2026-08-02); Evidence: pre-PR architecture review confirmed the
  split as two real concerns.
- **Plan statement:** SC-2.2's observable reads "all positions identical
  across the two browser engines".
  **Built instead:** the probes compare through a shared reader with a 0.01px
  tolerance (`docs/ux-check/lib/read-node-positions.mjs`).
  **Why:** engines serialize `style.transform` from float32 with different
  last-digit rules (measured: `40.9454` vs `40.9455` for an identical JS
  write), so the DOM witness carries ~1e-4px noise on byte-identical values;
  JS-side byte-identity remains pinned by the committed digest fixture.
  **Authority:** Evidence: measured CSSOM divergence on identical input.
- **Plan statement:** dial defaults ship as the 4.0.3.1.1 posture
  (ring 240 / separation 140 / fixed-slot) pending the gate.
  **Built instead:** the G-1-ratified `DEFAULT_LAYOUT_CONFIG`
  (300/150/3/proportional/compass-8); the fixed-slot guarantees (zero moves,
  zero tree crossings) are now gated under an explicit fixed-slot config, and
  the shipped default carries a pinned two-crossing corpus regression budget
  (down from five at the provisional dials).
  **Why:** the plan deliberately deferred final values to the live tuning
  gate; the operator's ratified dials measured better (fewer crossings) than
  the provisional posture at the wider spacing.
  **Authority:** Operator: G-1 ratification (2026-08-02).
- **Plan statement:** camera follow defaults on.
  **Built instead:** default off, with a one-time initial framing fit that
  ignores the toggle (policy in tested `camera-follow-model.ts`), and refits
  suppressed during drags.
  **Why:** the operator found automatic snapping intrusive; without an initial
  fit a fresh load left the layout origin under the chrome corner.
  **Authority:** Operator: default-off call (2026-08-02); Evidence: probe
  demonstrated the unframed first load.
- **Plan statement:** node/edge presentation unspecified beyond consuming
  positions; master-plan prose fences "edge styling" out of 4.0.3.1.
  **Built instead:** circled class discs with rim-clipped straight edges
  (tested `edge-geometry.ts`) and dashed loop closures classified from
  `deriveChainTree` re-run on the same facts object the worker laid out
  (~8µs at 60 systems — a deliberate main-thread exception). The
  drawing-feel mandate was judged to cover this structural presentation; the
  fence covers the later intel styling (mass/EOL color, hover), which stayed
  out, as did the library's default edge stroke color the operator ratified.
  **Why:** rectangles made center-aimed edges meet nodes at misleading angles
  and read as overlapping S-curves; circles give every connection a true
  radial terminus, and dashing loop closures restores the tree's readability —
  the exact drawing-feel concerns the gate exists to settle.
  **Authority:** Operator: in-session direction and G-1 sign-off (2026-08-02).
- **Plan statement:** the dial panel composes a segmented control for
  direction order.
  **Built instead:** a `Select` (four presets overflowed the panel's segmented
  track), plus a disclosure chevron on the dial group, an inline re-lock
  consequence sublabel, uppercase tracked label voice, corrected disc tokens
  (`border-border-idle bg-section` — the planned-era `border-line`/`bg-panel`
  classes had never existed as tokens), a px-bound disc size, and a `step`
  prop with disabled-state styling on the shared Stepper.
  **Why:** the review measured the four-preset segmented track overflowing the
  panel by 54px, found the disc's planned classes resolved to no tokens at all
  (transparent disc, fallback ring), and caught the dial steppers undoing
  their own clicks on the 10-unit grids.
  **Authority:** Evidence: pre-PR interface review measurements (overflow,
  missing tokens, clipped digits); operator's standing UI-conformance rules.

## Discovered work

- Replay `--map` reuse after an interrupted run accumulates duplicate
  connections (inserts are not idempotent); documented in the tool header —
  seed fresh with `--user`; replay maps are disposable.
- `use-layout-kernel.ts`'s degradation paths (worker death, postMessage
  failure, teardown) are inspection- and review-verified but carry no unit
  test — an evidence gap for a future session.
