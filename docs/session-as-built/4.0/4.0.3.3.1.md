## Delivered outcome

The Atlas map has one window system. A current-system dock stands on the left
rail hosting the shipped site-card widget, pops out to a freely dragged and
resized floating window whose rectangle survives reload on the same device,
and never closes from canvas click or Escape — only its close control hides
it in memory until a root click reopens it. Selecting another system shows a
summary card glued to that node through pan, zoom, and node drag. Typing and
scrolling inside any window leave the canvas transform untouched. The
character portrait sits beside the Atlas menu and map controls live
top-right, remaining operable beside the standing dock.

## Divergences from plan

- **Plan statement:** DC-1/AC-1 dock lifetime — selection-driven open and
  canvas-click close; Escape closes the topmost window including the dock.
  **Built instead:** dock presence is computed from the resolved chain root;
  canvas clicks and Escape never close it; close hides in memory only; a
  root click reopens (including when the root was already selected).
  **Why:** operator direction superseded both halves of DC-1 and bounded
  Escape reach for the dock only.
  **Authority:** Operator: plan hard-constraints (2026-08-02 / 2026-08-03).
- **Plan statement:** anchored dock on the right rail; map controls remain
  top-left; title-bar drag via a dedicated grip.
  **Built instead:** left-rail dock (`left-4 top-[4.5rem]`), controls
  `Panel position="top-right"`, portrait immediately beside the Atlas
  hamburger, floating drag from the entire title bar with controls excluded.
  **Why:** G-1 feel iteration on the live map.
  **Authority:** Operator: in-session G-1 direction and acceptance
  (2026-08-03).
- **Plan statement:** `MapWindowLayer` props include the host `nodes` array;
  `surfaceKind` is a separate prop; resize is a labeled button.
  **Built instead:** layer reads selection/titles through equality-stable
  React Flow store selectors; Escape kind derives from placement; resize is
  a pointer-only `data-map-window-resize` grip; summary target, dock modes,
  and minimum float size are owned once in `window-model` / persistence.
  **Why:** pre-PR and adversarial review — hot `nodes` re-rendered hosted
  content on every drag frame (PD-4), dual authorities for kind/target/mins,
  and a focusable dead resize button.
  **Authority:** Evidence: pre-PR architecture/ownership/interface and
  Diff-mode adversarial reviews (2026-08-03).
