## Delivered outcome

A collaborative wormhole chain can now be stored and reached safely, though
nothing renders it yet. Each map system, connection, signature and note is its
own indexed Convex document holding join keys and observed state only, and every
publicly callable map function authenticates the caller and checks a per-map role
claim before touching any of it. Scan observations merge monotonically — a later
scan enriches unknown fields, an identical one writes nothing, and two differing
values are reported as a conflict rather than overwriting shared state — while
last-seen bookkeeping lives on a separate row so it cannot invalidate a watched
payload. Signature deletion is reversible behind an absolute expiry, cleared in
fixed-size batches that cannot touch an active row. Map roles and the wormhole
code/size vocabulary now have single pure owners shared by both runtimes, with
compile-time bindings that turn a future divergence into a build failure.

## Divergences from plan

- **Plan statement:** `readMap({ mapId, cursors })` — one public query paginating
  systems, connections, signatures and notes together (plan §Interfaces and
  contracts, §Control and data flow, and SC-3's non-terminal-cursor observable).
  **Built instead:** `readMapCollection({ mapId, collection, cursor })` — one
  gated call per collection, each performing exactly one indexed `.paginate()`
  and returning Convex's real `{ page, isDone, continueCursor }`. Callers drain
  each collection's cursor independently.
  **Why:** Convex 1.42.3 permits exactly one `.paginate()` per function
  execution; a second call throws at runtime in a deployed backend, so the
  planned interface could not exist. Proven by probe before any implementation:
  `Only a single paginated query (.paginate()) is allowed per function
  execution.`

## Successor notes

- `mapAccess` has no uniqueness constraint, and `requireMapAccess` reads it with
  `.unique()`. A duplicate `(mapId, userId)` claim would make every gated call on
  that map throw indefinitely — 4.0.2.2.2's projection writer must guarantee one
  row per pair, not merely insert.
- The purge range keys on `purgeAfter` alone. Pairing with `deletedAt` is
  enforced only inside `setSignatureTombstone`; a future writer that sets
  `purgeAfter` without `deletedAt` would create a row that reads as active but
  purges. No defensive filter was added because that state is unreachable through
  this session's only writer.
- `readMapCollection('signatures')` returns tombstoned rows unfiltered. This is
  required — the payload must survive for restore — so the filtering obligation
  belongs to the consumer, and to 4.0.4.3.1 when it sets the undo window.
- `pnpm exec convex codegen --typecheck enable` exits 0 but reports
  `Found no convex/tsconfig.json … skipping typecheck`. Convex backend
  typechecking is covered instead by root `pnpm typecheck`, whose `**/*.ts`
  include reaches `convex/`. Adding `convex/tsconfig.json` was out of scope.
- Convex permits exactly one `.paginate()` per function execution. Any later
  multi-collection read must be per-collection calls, not one aggregate query.
- Draft PR #338 already exists for this sub-version and carries no version
  records; 4.0.2.2.2 completes and ships it.
