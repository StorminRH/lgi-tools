## Resolved implementation decisions

- **Contract PD-1 — acceptance-vs-override weights and capture point: the shipped tier capture stands; ranking does not consume tier.** Accept (jump-prompt confirm) records `confirmed`; override and independent typing record `human`; deductions record `assumed`; jump crossings record `jump-verified` — each emitted on its row. The pick list orders by statics-first only and never reads tiers. **Rejected:** re-weighting reads now (no volume to weigh); dropping the tier column (destroys the operator's analytics lens and future re-weighting option).
- **Contract PD-2 — provenance presentation: no user-facing provenance chrome.** The honesty mechanism is behavioral: human rows are `protected` from deduction, contradictions yield, and ambiguous multi-survivor jumps ask instead of guessing. Tiers stay in the database for the operator. **Rejected:** scanner-row badges, editor provenance lines, edge styling (operator: clutter users don't need).
- **Contract PD-3 — profile graduation: no graduation this session.** The merged profile remains its bootstrap state (Anoik.is statics-first, already shipped); statistics-driven ordering is deferred until observation volume exists, and flipping it is an explicit future operator decision. **Rejected:** building the statistics-driven ordering now (zero users → zero volume → nothing to compare against Anoik.is).
- **Plan — the signature viewer primitive.** One scanner-anchored panel host whose open-target is a connection edit or a site view; the body swaps, the chrome (hover arrow, bracket, leader line, dismissal, geometry) is shared. Site viewing is read-only and not gated on `canEdit`. **Rejected:** a separate site-popup pattern (violates the uniform-primitive direction).
- **Plan — site resolution by exact catalogue name.** The sites feature owns a name→`siteId` lookup over the deploy-static 69-site catalogue, with a drift test against the catalogue source; rows whose name misses the catalogue get no affordance. **Rejected:** fuzzy matching (fabricates matches); per-row network lookup (the catalogue is deploy-static and tiny).
- **Plan — standalone site-card presentation.** One always-expanded, non-collapsible, hover-free, narrowly-measured presentation shared by the atlas panel and `/sites/[id]`; the full page keeps its back link, freshness strip, and related sites. The exact measure is tuned at the G-1 pause, starting from the house reading measure (`max-w-reading`). **Rejected:** reusing `defaultOpen` collapsible (operator: collapse on a full page makes no sense) and the `hover={!centered}` conflation (alignment must not own hover behavior).
- **Plan — the 4.0.4.3.2 corrections (operator-directed).** Four fixes: carry `lifeStage`/`lifeStageObservedAt` in `linkKnowledgePatch`; cap the narrow-stack panel max-height to the space above its anchor; re-stamp probe freshness before the identical re-paste; assert static-ghost edges precisely in the automatic-jump probe. The stale-snapshot upsert race (`settleIdentity` + last-write-wins reconcile) is recorded as a known limitation — operator ruling: all input paths converge on the same identity, so a landed-first write is acceptable and the corpus heals on the next pass.

### Interfaces and contracts

- Panel open-target (mapper-owned; name settled in execution): `{ kind: 'connection', connectionId } | { kind: 'site', siteId, signatureId } | null` — one host state; the body resolves from the target kind. Draft comment: `/** The scanner panel's single open target: a connection edit or a read-only site view. */`
- `siteIdForSiteName(name: string): number | null` (sites-feature-owned) — exact-match lookup over the deploy-static catalogue; null means no affordance. Draft comment: `/** Resolves a scanned site name to its catalogue id; null when the catalogue has no such site. */`
- `SiteCard` standalone presentation (prop settled in execution) — renders header + full body inline; no `Collapsible`, no hover glow, no catalogue extras. Draft comment: `/** Standalone always-expanded presentation for the full page and embedded viewers. */`
- `MAP_SCANNER_EDITOR_CLASS` — narrow-stack max-height becomes `calc(100dvh - <anchor offset> - <top inset>)` so the panel never extends past the viewport top; the panel body scrolls internally.
- No changes to `SiteCardWidget`'s host contract (`siteId` + a box) and no new observation read API.

### Control and data flow

Row hover shows the arrow on wormhole rows (today) and on site rows whose name resolves to a catalogue id (new). Click sets the panel target. The host measures the bracket/leader from the same `data-signature-row` element. A connection target renders the editor (today's path, `canEdit`-gated); a site target renders `SiteCardWidget` fetching `siteDetailEndpoint?id=` and presenting the standalone card — available to any map viewer. Escape, outside click, and the close button dismiss through the shared machinery. The emission proof (OW-4) changes no runtime flow unless a gap is exposed.

### Edge and failure behavior

- Site row without a revealed name (low scan %) → no affordance; row unchanged.
- Name absent from the catalogue (k-space sites, future DED types) → no affordance; row unchanged; catalogue expansion later activates rows with no mapper change.
- Site detail fetch fails in the panel → the widget's existing error banner inside the panel; dismissal still works.
- Read-only map viewer opens a site → allowed (read-only card); the connection editor stays `canEdit`-gated.
- Short landscape viewport → capped panel max-height + internal scroll; header and close button stay on-screen (OW-1 fix).
- Human retype racing an elimination pass → known limitation: the corpus may hold the stale identity until the next pass heals it (operator-accepted).
- Anomalies (always named) → same affordance as named signature rows.
