## Bottom line (READ FIRST)

- **GOAL:** Maps become fully manageable end to end — created atomically from a
  dialog with a built-in access list, switched from a top-center chrome
  dropdown, access-edited through one shared editor, deleted through a 30-day
  undo trash with a bounded resumable purge, and discovered through an
  authorized landing catalogue whenever Atlas opens without a selected map.
- **DONE =** SC-1 through SC-8 below, plus: a signed-in user can create a map,
  share it, switch to it, un-share it, delete it, restore it, and let it purge —
  all from the Atlas surface, with no partial state anywhere.
- **OUT OF SCOPE:**
  - Removing the development wall or adding any public navigation link
    (post-audit work, Contract OOS-1 / DEP-8).
  - Resume-last-map behavior (Contract OOS-3 / DEP-9): the no-map entry always
    lands on the catalogue.

## Why now

Every prior 4.0 slice assumed a map already existed — seeded by a dev script,
addressed by a hand-carried URL. The chain canvas, signatures, tracking, and
access projection are all shipped and proven, but no user can create, find,
share, switch, or delete a map. This session closes that loop and is the final
roadmap session of v4.0: after it merges, every roadmap row is terminal and the
resolver directs version-audit planning.

## Scope (the destination)

A signed-in (dev-wall-admitted) user opens `/atlas` and, with no map selected,
sees the landing catalogue: three self-hiding sections — Your maps,
Corporation maps, Shared with you — of metadata cards (name, corp badge,
shared-by, plain-text access level, created date), a Create-new-map card always
present and pinned last, and a trash-barrel affordance in the bottom corner.
Creating a map is one dialog: name, a logo grid of the user's corporations, a
scoped ESI character typeahead with portraits (exact-name fallback), an
explicit read/write choice per selected principal (no defaults), empty list =
private. Create runs one Neon transaction (map row + grant rows), then projects
access to Convex behind a compass "Creating your map" interstitial (minimum
~5 s, retries to ~20 s, error + try-again with compensating rollback on
persistent failure), then lands on the shipped set-home prompt. Inside a map,
the map's name floats top-center in dock typography; clicking it opens a
frosted dropdown of the user's other maps (push navigation; the existing keyed
remount repopulates cleanly) with a settings cog per row opening the shared
access editor and delete/restore actions. The editor shows current grants (corp
logos, character portraits, names via public id→name resolution) with
viewer/editor/admin roles, inline role change, revoke-with-confirm; every write
is Neon-then-re-project, so revocation evicts live viewers within milliseconds.
Delete (any admin) starts a 30-day undo window: the map leaves every listing
instantly and its projection tears down; the trash window lists deleted maps
with multi-select Restore (no prompt) and creator-only Permanently-delete (one
confirm; fast-forwards grace via `purge_requested_at`). A daily cron sweeps
maps past grace in bounded 128-row batches across every map-keyed Convex table,
then tombstones the Neon row. Selected-map behavior, the wall, and the canvas
are unchanged. Contract §§3–6 are satisfied without widening: no settings-page
content beyond access/lifecycle, no chain intel on cards, no role tiers beyond
the renamed three, no public exposure.

## Resolved implementation decisions

- **Contract PD-1 — creation sequencing and projection-failure recovery:
  Neon-first, in-route bounded retry, compensating rollback.** The route
  commits the Neon transaction, then POSTs the projection with retries at
  0 s/+2 s/+5 s/+10 s inside a ~20 s budget while the client interstitial
  (minimum ~5 s) runs; on verified success the client navigates to the new map.
  On exhausted retries the route deletes the created Neon rows and returns a
  problem; the interstitial resolves to an error state with try-again (safe:
  rollback means retry is a fresh creation). Retry remains one-directional
  (Neon→Convex); the rollback is Neon-local. Residual: a delivered-but-
  unacknowledged projection can orphan Convex claims for a rolled-back map —
  invisible to all listings (Neon-derived) and healed by the existing teardown
  CLI; same accepted-residual class as the shipped projection drift notes.
  **Rejected:** keep-and-heal (map exists but its creator sees "lost access" —
  worst possible first-run); single-attempt rollback (a one-second blip kills a
  creation a retry saves).
- **Contract PD-2 — rate-limiter owner: Upstash `map-create`, 5/min, user-id
  key, route preflight.** The established owner for authenticated Neon-writing
  routes; a scripted burst trips in the first second, a human organizing maps
  never approaches it. The master plan's `@convex-dev/rate-limiter` mention
  predates the settled shape — creation never enters Convex as a mutation, so a
  Convex-side limiter cannot guard the durable boundary. **Rejected:** IP
  keying (shared-IP false trips); @convex-dev limiter (wrong side of the
  boundary).
- **Contract PD-3 — stale-flash-free retargeting: URL push + existing keyed
  remount.** Switching pushes `?map=<id>` (history entries per operator
  choice); `ChainHost key={mapId}` already remounts the entire subtree —
  subscriptions, reconciler, windows, tracking — from empty state, so prior-map
  content is structurally unreachable. Arrivals in one merge commit share one
  birth window (~1 s bloom), so large maps surface together, not sequentially.
  **Rejected:** in-place retarget with state reset (re-derives what the remount
  already guarantees, and reopens the cross-map diff risk).
- **Contract PD-4 — principal presentation: one shared access-list editor,
  three doors.** A single component (corp logo grid via `corporationLogoUrl` +
  `EveImage`; character typeahead with portraits; per-principal role select
  with no default — creation offers read/write, the editor offers
  viewer/editor/admin; explicit selection required to proceed) consumed by the
  creation dialog, the landing-card edit button, and the switcher-row cog.
  Operator direction supersedes the contract's page-settings-slot placement;
  the sole authority path (Neon write → re-projection) is unchanged. The
  creator never appears as a revocable row (ownership is the `maps` row).
  Non-admins see no access UI. **Rejected:** page-settings slot (the declarative
  enum/boolean control vocabulary cannot host a grant editor; the cog is always
  reachable); per-door bespoke editors (three implementations of one contract).
- **Contract PD-5 — grace period: 30 days.** Master-plan lean; survives
  vacations for corp-shared maps. UI vocabulary is Delete/Restore ("archive"
  appears nowhere user-facing) because deletion-with-undo is what it is.
- **Contract PD-6 — purge batching, ownership, recovery: daily Vercel cron,
  128-row batches, re-scan resumability.** A new `/api/cron/purge-maps` route
  (registered in `vercel.json`, following the cron registry pattern) selects
  maps with `archived_at` + 30 d elapsed (or `purge_requested_at` set) and not
  yet tombstoned, and drives a new bearer-gated Convex door that deletes one
  map's documents in 128-row batches per table with `hasMore` loops under a
  hard batch ceiling (the shipped `MAX_PURGE_BATCHES` pattern). Interruption
  recovery is structural: remaining rows are the progress; the next run
  re-scans and continues. Tombstone (`tombstoned_at`) and projection teardown
  happen only after a full clean sweep reports zero remaining. **Rejected:**
  Convex cron ownership (grace policy and tombstone are Neon-side facts; the
  sweeper needs both sides, and Vercel cron + bearer door is the shipped
  precedent); scheduler-chained continuation (adds state where re-scan is
  already safe).
- **Contract PD-7 — purge-census proof: a declaration test enumerating every
  map-keyed Convex table.** A census test (pattern:
  `src/app/api/cron/registry.test.ts`, `dataset-declarations.test.ts`) asserts
  the purge door's table list equals the set of map-keyed tables in
  `convex/schema.ts` — nine today: mapAccess, mapSystems, mapConnections,
  mapSignatures, mapNotes, mapSignatureActivity, mapEvents,
  mapJumpBookkeeping, mapTracking. A tenth map-keyed table without a sweep
  entry fails CI. **Rejected:** prose checklist (rots silently).
- **Contract PD-8 — bounded chain summary: cut by operator amendment.** Cards
  are metadata-only; the catalogue performs no Convex read, so no read budget,
  no degraded mode. DC-16/AC-16's summary-and-degrade clauses are recorded as
  operator-amended (the metadata card is the whole card); recency is
  `Created <date>` from the Neon row. **Rejected:** bounded per-card query
  (contract-faithful but permanent Convex coupling the operator declined).
- **Contract PD-9 — no-map branch mechanics: client-side branch on the
  existing `?map=` read inside the current Suspense composition.** The atlas
  page composes a client `AtlasEntry`: no `?map=` renders the catalogue
  (fetching the listing through the authorized-list read), a present `?map=`
  renders `MapCanvas` unchanged. Route classification stays `partial`
  (`instant = false` leaf untouched); the catalogue grid is its own scroll
  region (`overflow-y-auto`) inside the `100dvh` frame, so a
  taller-than-viewport grid scrolls honestly. No server-side collaborative
  preload is added to either branch. **Rejected:** server-rendered catalogue
  page split (a second route or server branch re-classifies the surface and
  buys nothing behind the wall).
- **Contract PD-10 — card affordance vocabulary: existing primitives, no
  pills.** `Card` primitive per map; corp badge = `EveImage`
  corporation-logo family; plain-text lines "Shared by <creator name>" (grant
  provenance only) and "Your access: Read-only / Write / Admin"; "Created
  <date>"; create card = `Card` with plus icon and "Create new map", always
  present, pinned last, alone-with-hint at zero maps. Switcher trigger wears
  the current-system dock treatment (`font-display text-h3 font-bold
  tracking-copy text-name` on `glass-panel-faint`), top-center; the dropdown
  is the Base UI Menu wrapper on the frosted map surface with a per-row cog.
  The trigger deliberately occupies `MapChrome`'s reserved top-center search
  slot — an operator decision with relocation explicitly deferred until the
  map search feature arrives (recorded so the search session reopens
  placement, not this plan). **Rejected:** role `Pill`s (operator prefers
  written-out access text).
- **Plan — role rename `owner` → `admin`: expand/contract across the two
  runtimes.** In this session: the Neon migration
  (`ALTER TYPE map_role RENAME VALUE 'owner' TO 'admin'`), the `MAP_ROLES`
  tuple, precedence, and capability record change together; the Convex
  validator (`convex/lib/mapEntityContracts.ts` `mapRoleValidator`, consumed
  by `convex/schema.ts`) **expands** to accept both `admin` and a legacy
  `owner` literal — Convex validates every existing document at schema push,
  and production claims store `owner`, so a hard rename cannot deploy — and
  the Convex access gate normalizes `owner` to `admin` at read. Delivery runs
  a one-shot projection resync over live maps to converge stored claims; the
  legacy-literal contraction is a recorded one-line follow-up (SCRATCHPAD
  next-agent note) once claims are converged. Known bounded window: during
  the single production deploy swap, old code reading renamed Neon rows
  fail-closes on the unknown `admin` value (`roleAllows` denies unknown
  roles) for seconds behind the dev wall — accepted and recorded. Map-admin
  copy never collides with site-admin (distinct type owners).
  **Rejected:** hard validator cutover (fails Convex push against existing
  documents); UI-only aliasing (permanent split vocabulary).
- **Plan — character search:** scoped ESI typeahead through `esiFetch`
  (`GET /characters/{id}/search?categories=character`, any linked character
  whose token carries the new scope, ESI-cached ~1 h), portraits via
  `characterPortraitUrl`; exact-name fallback through public
  `POST /universe/ids` when no token carries the scope; grant display resolves
  ids→names via public `POST /universe/names`. No Neon mirror — ESI exposes no
  bulk character feed, so there is nothing to ingest on a cron.
- **Plan — creation ownership (Contract DC-2 amended):** creation writes no
  owner grant row — `maps.user_id` is the ownership record, and the access
  rule already short-circuits creator → admin without consulting grants.
  The contract's "owner access row" wording predates the operator's
  user-keyed direction (no active-character concept anywhere); recorded as an
  operator amendment alongside the DC-16 cut.
- **Plan — delete semantics:** delete = `archived_at` set + projection
  teardown (live viewers get the existing lost-access state; the deleting admin
  is routed to the landing); restore = clear + re-project (undo, no prompt);
  permanent delete = creator-only `purge_requested_at` fast-forward with one
  confirm, map leaves the trash list immediately, next cron sweeps it.

### Interfaces and contracts

- `listAuthorizedMaps(userId, db?): Promise<AuthorizedMapRow[]>` — Neon-only;
  resolves principals via `resolveMapPrincipals` + `memberCorpIds`; returns
  every unarchived, untombstoned map the user created or reaches through a
  character/corp grant, each row carrying display fields and provenance;
  deterministic order (created first, then by recency). Never touches Convex.
- `POST /api/maps/create` — body `{ name, grants: [{ ownerType, ownerId,
  role }] }` (roles at creation: viewer/editor); preflight `map-create` 5/min;
  one transaction inserts `maps` + grant rows; then `projectMapAccess` with
  bounded retry; success `{ mapId }`; exhausted retry deletes the rows and
  returns a problem. Same-origin, session-authed, Zod-validated.
- `POST /api/maps/access` — admin-gated (via `getMapAccess`); upserts/removes
  grant rows and re-projects; viewer/editor/admin permitted.
- `POST /api/maps/delete` / `restore` — admin-gated; set/clear `archived_at`;
  teardown/re-project accordingly.
- `POST /api/maps/purge-now` — creator-gated; sets `purge_requested_at`.
- `POST /api/maps/search-characters` — session-authed; scoped ESI search when
  available, `universe/ids` exact fallback; returns
  `{ characterId, name, portraitUrl }[]` plus a `mode: 'typeahead' | 'exact'`
  marker the dialog uses to shape its hint.
- Convex door `POST /purge-map-chain` (bearer) → `internal.mapPurge.*` —
  deletes one map's rows per table in 128-row batches; response
  `{ remaining: boolean }`; census list is the single table registry.

### Control and data flow

Creation: dialog (client) → `POST /api/maps/create` → Neon transaction →
projection POST (retry ladder) → `{ mapId }` → client interstitial (min ~5 s)
resolves → `router.push('/atlas?map=<id>')` → keyed `ChainHost` mounts → access
subscription grants → empty map → home prompt. Failure after commit: Neon
delete → problem → interstitial error + try-again.
Switch: dropdown click → `router.push` → remount (same tail as above).
Access edit: editor → `POST /api/maps/access` → Neon write → `projectMapAccess`
→ Convex claim reconcile → revoked viewer's `watchMapAccess` flips →
`NoMapAccess` renders live.
Delete: `POST /api/maps/delete` → `archived_at` → `teardownMapAccessProjection`
→ all viewers (deleter included) hit lost-access / are routed to landing;
listings exclude the map immediately.
Purge: cron → select past-grace/purge-requested, untombstoned → door loops per
table until `remaining: false` → `tombstoned_at` → teardown (idempotent).
Catalogue/switcher/trash: server or client fetch of the single listing read —
no Convex anywhere in the read path.

### Edge and failure behavior

- Projection POST delivered but response lost during creation → Neon rollback
  leaves orphan Convex claims for a nonexistent map → invisible to listings;
  healed by existing teardown CLI; accepted residual (recorded).
- No linked token carries the search scope → typeahead degrades to exact-name
  entry with a clear hint; adding by exact name still works (public endpoint).
- Rate guard trips → 429 problem → dialog shows a calm "try again in a minute"
  message; no partial writes occurred.
- User deletes a map they are currently inside → projection teardown flips
  their own gate; the client routes them to the landing instead of stranding
  them on lost-access.
- Restore raced by the sweep (grace expired between listing and click) →
  restore route refuses when `purge_requested_at`/`tombstoned_at` is set or
  grace has elapsed; trash refreshes.
- Cron dies mid-sweep → nothing is tombstoned early (tombstone requires a
  clean zero-remaining pass); next run re-scans and continues.
- Convex unreachable during delete/restore → the Neon write stands; projection
  effect retries on the next mutation or resync (existing accepted-residual
  class); listings are already correct because they read Neon.
- Zero maps → catalogue renders the create card + one hint only (DC-19).
- Multi-corp user at creation → corp grid lists every `memberCorpIds` corp;
  one corp → preselected grid of one.
