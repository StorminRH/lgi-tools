## Why now

Last session made paste populate the map; without inference the map is
paperwork — every hole still needs manual identification even when the statics
already dictate the answer. This session delivers the flagship D11 reasoning as
a small, reviewable eliminator plus the always-on statics picture, and starts
accumulating the per-system identification log that 4.0.4.3.3's ranking will
consume. Deferring the editor consolidation would mean building the jump
prompt and deduction UX on top of input surfaces already ruled redundant.

## Resolved implementation decisions

- **Contract PD-1 — the eliminator's plain-language model: an answer-key
  crossing-off.** Each system's answer key = its anoik statics (multiset, so
  duplicate same-code statics hold two slots) plus every known connection
  touching the system that lacks a linked signature on this side. Every
  scanned wormhole sig must belong to exactly one key slot or be a wanderer.
  Crossing off: a sig identified as a key entry claims that slot; a sig
  identified as anything else (K162, wanderer code) leaves the key. When
  exactly one unidentified sig remains for exactly one open slot, the
  eliminator fills it (operator's worked example: statics B274+H296, three
  sigs; user types K162 and B274 → the third is the H296). Single-static
  systems self-label on paste; a previously confirmed static narrows every
  later scan (history narrowing falls out of slot-claiming, not a separate
  mechanism). Deductions are written with tier `assumed`, fill blanks only,
  and re-run after every paste, identification, and jump. **Rejected:** a
  general constraint solver / probabilistic scorer — unreviewable by the
  operator, unnecessary for a key this small, and a complexity hotspot the
  contract's §11 explicitly warns against.
- **Contract PD-2 — contradiction detection and yielding: quiet.** A system
  whose human-entered facts violate the key (more claimed statics than slots,
  a typed code no slot admits, zero possible assignments) yields: the
  eliminator writes nothing there, surfaces no error state, and never
  un-writes existing values. People always win; the map shows exactly what
  users entered. **Rejected:** contradiction badges/warnings — operator
  direction D-C (no special provenance/contradiction UI); the honest display
  is the users' own entries.
- **Contract PD-3 — the pure/presentation boundary.** The eliminator is a
  pure function (no I/O, no framework imports) returning typed deductions;
  the composition route owns every read (Convex state door, Neon statics),
  every write (tier-gated Convex door), and observation logging; the UI
  consumes stored state plus a toast. 4.0.4.3.3 consumes `wh_observations`
  distributions and the stored tiers; nothing in this session renders them.
  **Rejected:** running the eliminator inside `applyScan` — Convex cannot
  read Neon statics, and client-supplied answer keys would put map-shared
  deductions behind an unverifiable input.
- **Operator ruling D-A — account-level access, map-level data.** Nothing in
  this session gates on a specific character; paste and editing authority stay
  account-level as shipped; every drawn artifact (stubs, deductions, readouts)
  is identical for every map viewer by construction.
- **Operator ruling D-B — deduced identifications ARE logged.** Every
  identification logs to `wh_observations` tagged with its tier, including
  `assumed` deductions; the Drizzle migration drops the
  `wh_observations_verified_provenance` check; the K162 and hour-coarse
  checks stay; a human override corrects the same dedupe-keyed record in
  place. This supersedes the master plan's anti-circularity emission rule for
  deductions (authority: operator, 2026-08-10) — the tier tag preserves the
  ability to weight or exclude `assumed` rows wherever a wrong anoik entry
  could otherwise self-confirm; 4.0.4.3.3 planning must reconcile its HC-2
  with this ruling. **Rejected:** emit-only-human (prior rule) — discards
  real evidence the operator wants in the per-system distribution.
- **Operator ruling D-C — no provenance UI.** Tiers are stored bookkeeping;
  no badges, no visual distinction on rows or nodes; deductions announce via
  one toast to the acting user (e.g. `GHI identified: H296 - C3`).
- **Operator ruling D-D — stub accounting.** Canonical wording (carried as
  the rule's contract comment): **"One stub per hole we believe exists.
  Unidentified scanned wormhole sigs are presumed to be the statics first;
  only the surplus draws as Unknown."** Mechanics: unidentified sigs claim
  already-drawn holes first — open statics stubs, then connection lines
  without a linked signature on this side; only the surplus draws Unknown
  stubs. Worked cases: 2 statics + 4 pasted sigs → 2 statics stubs + 2
  Unknown (four drawn, four believed); 2 statics + 1 pasted sig → 2 statics
  stubs only; that sig later typed as a wanderer → it graduates to its own
  stub (3 drawn); jumped-in system (edge drawn) + 2 statics + 4 sigs → 2
  statics stubs + 1 Unknown.
- **Operator ruling D-E — identity readouts.** One shared rule
  (`systemIdentityReadout`) renders `<name> - <security>` (k-space, CCP
  security tones) or `<J-name> - C<class>` (J-space, C1→C6 light-green→deep-
  red ramp; C13 dangerous-end; Thera/Pochven/drifter existing tones) for both
  node labels and the current-system dock.
- **Operator ruling D-F — one editor, left-click scanner, right-click canvas.**
  Left-click a scanner wormhole row opens the Signature Editor; connection
  lines respond only to right-click (menu: Edit → same editor; Delete →
  sever). The edge left-click details card and the scanner-row right-click
  duplicate path are retired in the same change (parity-then-delete).
- **Operator ruling D-G — editor fields (final set, in order).** Title
  "Signature Editor". 1) Wormhole type (search, statics first) with the
  headerless stats block beneath (total mass, per-jump, regen, lifetime,
  size — no "Codex" heading); 2) **Size** (`Unset/S/M/L/XL`, auto-locked by
  code); 3) **Mass** — one section: dropdown with in-game wording (*More than
  50% remaining / Less than 50% remaining / Less than 10% remaining*, stored
  vocabulary `stable/reduced/critical` unchanged) plus one minimal tracked-
  estimate line; 4) **Reliable Lifetime** — in-game wording (*Less than 1 day
  remaining / Less than 4 hours remaining / Less than 1 hour remaining /
  Expired, closure imminent*) plus one minimal countdown line; 5) **Leads
  to** — one field, dropdown while unknown, locked to the destination's
  identity readout once known (click focuses that system); 6) **Delete**
  (renamed Sever; undo/Restore mode unchanged). Deleted: "Typed side",
  "Far side leads to", the "Auto-link" section, all "Origin/Far side"
  labels.
- **Operator ruling D-H — the jump prompt.** When a jump cannot resolve to a
  single signature, a scanner-overlay prompt (same affordance family as the
  shipped missing-sigs prompt) shows "You jumped into `<identity readout>` —
  Which signature did you jump through?". The candidate list is exactly the
  shipped `matchJump` `survivors` (its contradiction/hint/size filtering
  unchanged, per HC-1); the eliminator does not re-filter or extend this
  list, and `EliminationResult` carries no survivor field. Picking one
  resolves the connection through the existing reassociation path, links the
  sig, and cascades elimination. Replaces the editor's embedded Auto-link
  Q&A.
- **Plan decision D-I — elimination trigger and transport.** The acting
  client triggers `POST` to the new elimination route after `applyScan` or a
  type-entry mutation resolves; the jump resolver cascades in-route (it
  already holds statics and the bearer doors). The route mirrors the
  jump-resolver composition: Convex state read door + Neon statics read →
  pure eliminator → tier-gated Convex write door → observation upserts.
  Passive viewers never write. Deduced-observation emission (route and
  resolver alike) lands only in OW-5 together with the migration and the
  resolver's tier-filter change — OW-4's plumbing writes deductions without
  observation rows, so no `assumed` insert ever races the live DB check.

### Interfaces and contracts

- `eliminateSignatures(input: EliminationInput): EliminationResult` — pure.
  Input: statics codes (multiset), live wormhole sig rows (id, typed code,
  tier), connections touching the system (endpoint side, linked-sig state,
  typed code), codex entries. Output: `deductions` (each
  `{ signatureId, typeCode }` or `{ signatureId, connectionId }` far-side
  link) plus `quiet: boolean` (insufficient or contradictory evidence — the
  two are deliberately indistinguishable in output). Never proposes a write
  onto a non-`assumed`, non-null fact.
- `believedHoles(input): StubPlan` — pure; returns the per-system stub set
  (open statics stubs with `code`/`class`, Unknown-stub count) implementing
  D-D. Consumed only by `nodes.ts`.
- `systemIdentityReadout(facts): { label: string; tone: Tone }` — pure;
  k-space vs J-space rule per D-E; consumed by `SystemNode` and the dock.
- `POST` elimination route — body `{ mapId, systemId }` validated by the
  owning slice's `api-contract.ts`; session + map-access checked; responses:
  `{ status: 'applied', deduced: n }`, `{ status: 'quiet' }`,
  `{ status: 'statics-unavailable' }`; never 5xx on degraded statics.
- Convex deduction door (internal mutation, bearer-doored like the jump
  doors) — batch writes; per-item in-transaction gate: target field null or
  `typeProvenance === 'assumed'`; equality-skip; returns per-item outcomes
  for toast/logging.
- Observation upserts reuse `src/data/wh-observations/queries.ts` with the
  connection's `observationKey` dedupe key; `assumed` rows now admitted.
- Edge menu: `onEdgeContextMenu` handler mirrors the shipped
  `onNodeContextMenu` pattern in `ChainHost.tsx` (guard on edit authority and
  stub/halo edges, `event.preventDefault()`, store `{ connectionId, clientX,
  clientY }`, recompute `pointerAnchor` per render). Removing `onEdgeClick`
  does not disable React Flow's built-in click-to-select — edge
  selectability is governed separately and must be left as shipped.
- No public route or export outside the surfaces above changes shape. The
  scanner window's WORMHOLE-row `onClick` contract changes from "open row
  actions" to "open Signature Editor"; non-wormhole and unresolved rows keep
  the shipped `IdentifySignatureMenu` group-identification interaction
  unchanged. The edge `onEdgeClick` prop is removed.

### Control and data flow

Paste: `use-scanner-paste` → `applyScan` (unchanged) → on success the acting
client `POST`s the elimination route → route reads map state through the
Convex door and statics through `loadSystemStatics` (cached) → pure
eliminator → tier-gated Convex writes → `wh_observations` upserts → Convex
subscriptions fan the new facts to every viewer; the acting client toasts
from the route response. Manual identification: existing field setter
(`human` tier) → same client-side trigger → same route. Jump: doorbell →
jump-resolver route (unchanged entry) → after resolve/insert, the same pure
eliminator cascades with facts already in hand; unresolved ambiguity feeds
the jump prompt's survivor list; a prompt pick calls the existing
reassociation path then cascades. Statics stubs: client fetches per-system
statics via the cached statics route; `believedHoles` derives the stub set
from subscription state + statics; no persistence. Degraded: statics read
fails → route answers `statics-unavailable` with zero writes; client renders
zero statics stubs; nothing else changes.

### Edge and failure behavior

- Statics feed unavailable / system absent from dataset → no stubs, no
  deductions, `statics-unavailable` result; paste/edit/lifecycle unchanged.
- Contradictory human entries (over-claimed slots, inadmissible codes, no
  possible assignment) → `quiet`; zero writes; nothing un-written.
- Concurrent acting clients (two pastes racing) → per-item tier gate +
  equality-skip converge; a second identical deduction reports zero applied
  and shows no toast.
- Tombstoned signature rows and collapsed connections are invisible to both
  the eliminator and stub accounting (live rows only).
- Duplicate same-code statics → multiset slots; both must be claimed before
  history narrowing excludes that code.
- Human override of a deduced value → setter stamps `human`, observation
  corrected in place under the same dedupe key; the eliminator may later
  re-deduce only fields that are again null/`assumed`.
- Manually typed K162 → link candidates are the system's sig-less
  connections; unique candidate links, ambiguity does nothing.
- Matched connection collapses → accounting recounts; the static's ghost
  stub returns (the static respawned under a future new sig).
- Jump into a system with zero scanned sigs → resolver behaves as shipped
  (insert); the prompt never lists an empty candidate set — it simply does
  not open.
