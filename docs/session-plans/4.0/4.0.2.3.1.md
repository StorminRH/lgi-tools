## Scope (the destination)

The finished slice: a signed-in user opens `/atlas?map=<id>` and the canvas
renders immediately. Two gate-first Convex queries subscribe to that map's
systems and connections as independently paginated live feeds; a pure
reconciler merges each snapshot against the previous state and emits named
intents for what appeared, departed, or moved; the canvas applies those intents
as React Flow nodes and edges, labels nodes with real system names and classes
from the versioned client directory, and parks new arrivals on a deterministic
provisional grid. Dragging a node stores its position locally and permanently
protects it from the merge. Deleting the caller's access claim resolves the
watching client to a calm no-access state distinct from an authorized empty
map. Two internal removal fixtures join the insert fixtures so tests and the
demo can drive departure; no client-callable mutation ships. Contract §3 is
satisfied by the success criteria below; §4 by the surfaces above; §5 and §6
stay untouched per the coverage table.

## Resolved implementation decisions

- **Contract PD-1 — reconciler event contract: a five-kind discriminated union
  named `MapChainIntent`.** `{ kind: 'system-appeared'; systemId; position }`,
  `{ kind: 'system-departed'; systemId }`, `{ kind: 'system-moved'; systemId;
  from; to }`, `{ kind: 'connection-appeared'; connectionId; fromSystemId;
  toSystemId }`, and `{ kind: 'connection-departed'; connectionId }`. Kinds are
  renderer-neutral nouns so sub-version 4.0.3.2 can bind surfacing, exit, and
  glide animations to them without React Flow leaking into the motion
  vocabulary. `system-moved` is emitted only when the placement seam proposes a
  new position for an existing unprotected node — the grid assigner never does,
  but the layout engine will, and tests drive the seam to prove the emission
  path now. **Rejected:** reusing React Flow `NodeChange` objects as the
  vocabulary — it welds the motion contract to a renderer library the motion
  session does not own.
- **Contract PD-2 — protected-node identification: an explicit protection set,
  not a heuristic.** A node is protected when it is in the active-drag set
  (maintained by the canvas drag callbacks from drag start to drag stop) or its
  placement source is `user` (stamped permanently at drag stop). The reconciler
  receives the protection set as an argument and never emits `system-moved` for
  — nor writes the position of — a protected or already-placed node; positions
  are written at first appearance only. React Flow v12 keys drag state by
  stable node id, and drag positions flow only through `onNodesChange`, so an
  external update that adds or removes other nodes cannot move the dragged one.
  **Rejected:** recency timestamps ("recently moved nodes are safe") — an
  unprovable race window instead of a set-membership test.
- **Contract PD-3 — provisional placement: a deterministic next-free-grid-slot
  assigner behind a one-function seam.** The reconciler consults the assigner
  on every merge for every unprotected node, new or existing: the assigner
  returns a position per node, a changed position for an existing node becomes
  a `system-moved` intent, and an unchanged one is a no-op. This session's grid
  implementation assigns the next free cell in a fixed row-major sequence to a
  first appearance and always returns the existing position for an
  already-placed node, so no production reposition occurs — but the seam and
  emission path 4.0.3.1's layout engine needs are real and test-driven now.
  Deterministic: two identical arrival orders place identically and tests pin
  the sequence. Sub-version 4.0.3.1 replaces the assigner implementation behind
  the same seam; the reconciler and its intent contract do not change.
  **Rejected:** random scatter (non-deterministic, untestable), starting ELK
  now (owned and gated by 4.0.3.1), and a first-appearance-only assigner
  call-site restriction — it would make the repositioning emission path
  unreachable and force 4.0.3.1 to rework the reconciler.
- **Contract PD-4 — revoked versus empty: error identity, not row counts.** An
  authorized empty map is a successful subscription with zero rows and renders
  the plain canvas. Revoked or absent access surfaces as a query error carrying
  `ConvexError` data `{ code: 'FORBIDDEN' }` — the installed client throws it
  during render — and a dedicated boundary around the chain host catches
  exactly that code and renders the calm state ("access to this map is no
  longer held"), with no retry control per HC-4. Every other error rethrows to
  the existing map error surface. The two states are structurally disjoint, so
  the calm state is correct rather than merely quiet. Recovery is explicit: the
  boundary and chain host are keyed by the map id, so changing the `map` query
  param always remounts and re-subscribes fresh — a calm state for one map can
  never persist over another — while a re-granted claim on the same map is
  deliberately recovered by navigation only, because HC-4 bans a retry control
  and no access poller may exist; the calm state holds until the user navigates
  or reloads. **Rejected:** a separate "check my access" query or a re-grant
  poller — a second access-shaped surface the gate already owns, and a second
  subscription the contract does not ask for.

## Implementation blueprint

### Owned surfaces

- `convex/mapChain.ts` — owns the production chain read path: the two
  gate-first paginated queries and their page-size clamp.
- `convex/mapFixtures.ts` — additionally owns `removeSystemFixture` and
  `removeConnectionFixture`, the internal-only departure seams.
- `src/mapper/chain/intents.ts` — owns the `MapChainIntent` vocabulary the
  motion session consumes.
- `src/mapper/chain/reconciler.ts` — owns the merge: previous state plus
  snapshots in, next state plus intents out; the only producer of canvas nodes
  and edges.
- `src/mapper/chain/placement.ts` — owns the provisional grid assigner behind
  the seam 4.0.3.1 replaces.
- `src/mapper/chain/use-map-chain.ts` — owns the two subscriptions, the silent
  page drain, snapshot completeness, and directory-label resolution; mounted
  only behind the null-client gate.
- `src/mapper/chain/ChainBoundary.tsx` and the calm-state component — own
  FORBIDDEN identification, the calm no-access rendering, and the
  keyed-by-map-id remount that is the boundary's only reset path.
- `src/mapper/canvas/MapCanvas.tsx` — owns reading the `map` query param
  client-side and composing the chain host inside the existing canvas frame.

### Interfaces and contracts

- `watchMapSystems({ mapId, paginationOpts })` / `watchMapConnections({ mapId,
  paginationOpts })` — public Convex queries; `requireMapAccess(ctx, mapId,
  'view')` first; the `paginationOpts` argument is validated with
  `paginationOptsValidator` from `convex/server` (required — the client hook
  injects bookkeeping fields a hand-rolled validator would reject), with the
  `numItems` clamp to at most 100 applied in the handler body; one indexed
  `.paginate()` over the table's `by_map` range; return Convex's real page
  shape. Errors: `UNAUTHENTICATED` and `FORBIDDEN` from the gate, thrown
  before any chain read.
- `removeSystemFixture({ mapId, systemId })` — internal mutation; scans at most
  129 of the map's connections and fails closed (`FIXTURE_MAP_TOO_LARGE`) past
  128, refuses (`SYSTEM_IN_USE`) when any scanned connection touches the
  system, returns `removed` or `unchanged` (missing row, no write).
- `removeConnectionFixture({ connectionId })` — internal mutation; deletes one
  connection document by id, `removed` or `unchanged` (missing, no write).
- `MapChainIntent` — the PD-1 union; exported from `src/mapper/chain/intents.ts`
  with contract comments naming 4.0.3.2 as the consumer.
- `reconcileChain(previous, snapshot, protectedIds, assigner)` — pure; snapshot
  carries each collection's rows plus a per-collection `complete` flag;
  departures are emitted only from complete collections; the assigner is
  consulted every merge for every unprotected node and a changed proposal for
  an existing node becomes `system-moved`; returns `{ state, intents }` where
  state carries node positions, placement sources, and visible edges.
- `useMapChain(mapId)` — client hook; two `usePaginatedQuery` subscriptions
  (initial page 100) with an effect that keeps calling `loadMore` until each
  cursor exhausts; resolves labels through `loadUniverseAssets()`; returns the
  reconciled state and intents. It is only ever mounted behind the null-client
  gate below; within it, a null map id subscribes to nothing (the hooks'
  `'skip'` token).
- Null-client gate — the chain host renders its Convex-hook subtree only when
  the shared `convexClient` from `@/data/convex/client` is non-null, mirroring
  `src/components/OnlineStatusProvider.tsx`; with a null client the canvas
  renders empty and no Convex hook is called (the `'skip'` token alone is not
  sufficient — the installed hooks require a provider even when skipped).
- Remount keying — the chain host and its boundary carry `key={mapId}`, so a
  map-id change discards tripped-boundary and subscription state and
  re-subscribes fresh.
- No existing export changes shape; `MapCanvas` keeps its zero-prop signature.

### Control and data flow

`/atlas?map=<id>` → the static route renders `MapCanvas` (client) → it reads
the `map` query param via `useSearchParams` (under the existing map layout
Suspense, so the route classification is untouched) → `useMapChain` opens the
two gated subscriptions → pages stream in and silently drain → each snapshot
runs through `reconcileChain` with the current protection set → nodes and
edges render on the controlled React Flow canvas; drag events flow through
`onNodesChange`/`applyNodeChanges`, maintain the active-drag set, and stamp
`user` placement at drag stop. Server-side, every call enters through
`requireMapAccess` before touching a chain table. Failure boundary: the chain
host sits inside `ChainBoundary`; a FORBIDDEN query error renders the calm
state, anything else rethrows to `src/app/(map)/error.tsx`. No server-side
Convex read, no route mode change, no new environment variable.

### Edge and failure behavior

- Connection page arrives before its endpoint system → the edge is withheld
  with no intent; when the missing endpoint appears, `connection-appeared`
  fires then.
- A system departs while connection documents referencing it remain → those
  edges emit `connection-departed` (the documents persist server-side); the
  edges reappear if the system returns.
- Incomplete snapshot (pagination still draining or reset mid-drain) → arrivals
  and updates merge, departures are never inferred; a node leaves only on a
  complete collection missing it.
- Directory not yet loaded or load failed → labels fall back to the system id
  with no class chip, silently relabelled in place (no intent, position
  untouched) when the memoized loader — which resets itself on failure —
  succeeds on a later attempt.
- No `map` query param → today's empty canvas; no subscription is opened.
- `NEXT_PUBLIC_CONVEX_URL` unset (contributor without Convex) → the null-client
  gate keeps every Convex hook unmounted and the canvas renders empty,
  mirroring `OnlineStatusProvider`'s established null-client branch; the
  `'skip'` token is not relied on for this case.
- The `map` query param changes → the keyed chain host and boundary remount,
  discarding any tripped calm state and subscribing to the new map fresh.
- Claim re-granted while the calm state shows → deliberately no automatic
  recovery on the same map (no poller, no retry control per HC-4); the user
  navigates or reloads, and the remount subscribes normally.
- Access absent from the first result → the same FORBIDDEN path and calm state
  as live revocation; the copy does not pretend prior access existed.
- Transport disconnect → the canvas keeps its last reconciled state; the Convex
  client reconnects and resumes subscriptions silently; no indicator ships
  (OOS-5) and no user action is required.
