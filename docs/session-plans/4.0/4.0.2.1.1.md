## Why now

Nothing else in version 4.0 can be seen until there is a screen to see it on. The
route restructure this requires touches all 87 routes at once, so it must land as
its own revertable change before any map data, schema, or canvas content exists to
confound a rollback. Registering `src/mapper/` now also fixes the import direction
permanently while the zone is empty and the rule is free to enforce, rather than
after features have grown reasons to reach upward.

## Scope (the destination)

After this session the application serves one new URL, `/atlas`. Its route group's
layout renders a static full-viewport frame with the admin decision isolated in a
`<Suspense>` hole, matching every existing `/admin/*` route under Cache Components.
That hole resolves the viewer's admin authority through the existing Better Auth
session. A non-admin receives an under-development wall and no canvas markup at
all. An admin receives a container that fills the dynamic viewport with no page
scroll, inside which React Flow v12 renders an empty graph over a dot background;
the wheel zooms rather than scrolls, dragging pans, and zoom is clamped between
`0.2` and `2.5`. Resizing the window changes how much of the canvas is visible and
never moves the camera.

Three chrome elements float above that canvas, composed in the map layout and never
inside the mapper: a menu at the top left carrying a home/wordmark row plus the same
tools the site nav lists, every link opening in a new tab; an empty reserved slot at
the top centre; and the existing account control at the top right, given the session
it requires. A compact feedback affordance sits in the bottom-right corner.

`src/mapper/` exists as the 23rd configured Fallow zone, permitted to import
features, data, components, primitives, transport, lib and config, and denied
`platform/auth`, `components-composition`, `composition`, `db` and `api`. No zone
may import it, and `@xyflow/react` is confined to it by lint.

Every other route serves exactly the URL it served before, rendered by the same
files with unchanged content, wrapped by the same header and footer moved intact
into a `(site)` group layout. Contract §§3–6 are satisfied without widening: no map
data is read, no overlay framework is added, no search control ships, and no
existing route's markup is edited.

## Resolved implementation decisions

- **Contract PD-1 — Separability of the route restructure: the move is mechanical
  and reversible for the 13 route directories and `page.tsx`, but is _not_
  mechanical for `error.tsx` and `not-found.tsx`, which need explicit handling.**
  Live evidence: `src/app/error.tsx:9-15` documents that "the root `<html>/<body>`,
  header, and footer keep rendering — only the page body is replaced," which holds
  today only because the chrome is a sibling of `{children}` in the root layout.
  Next's installed `not-found.md:131` states the root `not-found.js` "handle[s] any
  unmatched URLs for your whole application," so it cannot move into `(site)`.
  Resolution: `error.tsx` moves into `(site)/` because layouts wrap error
  boundaries; the 404 body becomes `NotFoundContent`; `(site)/not-found.tsx`
  renders it bare and inherits chrome from the group layout, while the root
  `not-found.tsx` renders it inside `SiteFrame` for unmatched URLs. That split is
  correct whether or not a root boundary re-renders the group layout, removing the
  chrome-layering ambiguity instead of betting on one reading. `SiteFrame` has two
  real consumers, so the extraction is justified rather than speculative. The no-op
  is proven by the derived URL-key set, a rename-only `git diff`, and a both-paths
  404 chrome assertion. **Rejected:** multiple root layouts, one per group. Next's
  `route-groups.md:30` requires each to carry its own `<html>` and `<body>`, which
  would duplicate the entire provider stack and force the experimental
  `globalNotFound` flag to recover a 404 page.
- **Contract PD-2 — Administrator allow-list mechanism: reuse the existing
  session-resolved admin authority; add no new mechanism.** Live evidence:
  `src/platform/auth/auth.ts:44-48` computes `isAdmin` as
  `role === 'ADMIN' || characterId === SUPERADMIN_CHARACTER_ID`, projects it onto
  the session, and `src/platform/auth/route-guards.ts:36` exposes `checkAdmin()`,
  which returns a typed pass/fail rather than redirecting. A wall must render a
  page, so `checkAdmin()` is the correct guard and `requireAdminPage()` (which
  calls `redirect`) is not. Grants are already administered at `/admin/access`.
  Because `cacheComponents: true`, that call sits inside a `<Suspense>` hole and
  `/atlas` is classified `partial`, exactly like all four `/admin/*` routes.
  **Rejected:** an environment-variable character-id list for the map. It would be
  a second access path for the same question, contradicting the single-gate
  principle, and would need its own admin UI to be usable.
- **Contract PD-3 — Mapper zone permitted import directions: `features`, `data`,
  `components`, `ui`, `transport`, `lib`, `config`; `app` gains `mapper`.** Live
  evidence: `.fallowrc.json` `boundaries.rules` is deny-by-default, so omitting
  `mapper` from the `features` rule is the complete expression of HC-4, and
  `coverage.requireAllFiles: true` makes an unregistered mapper file fail outright.
  `platform/auth` and `components-composition` are both denied: `AccountMenu` lives
  at `src/components/composition/account/AccountMenu.tsx` in `components-composition`,
  so denying that zone — not merely `platform/auth` — is what mechanically forces
  the orb one layer up and converts HC-2 from convention into a rule. Fallow checks
  direct imports per statement, not transitively, so HC-2's mechanical guarantee is
  precisely "the mapper cannot import the account control or the auth slice
  directly"; a `components` leaf that internally uses auth is out of that model's
  scope and is accepted, because composition still happens at the app layer.
  `composition`, `db`, and `api` are denied because the mapper is a client
  presentation host with no server orchestration or persistence role. **Rejected:**
  granting the mapper `platform/auth` or `components-composition` for convenience.
  Either would let a future session render the orb inside the mapper, silently
  voiding HC-2 with no failing check.
- **Contract PD-4 — Resize and camera behavior: no resize-driven camera change and
  therefore no debounce; zoom clamped to `0.2`–`2.5`; no `translateExtent`.**
  Operator direction, 2026-07-28, supersedes the contract text. The contract's
  "re-fits on resize under a debounce" conflates two mechanisms: React Flow's
  built-in `ResizeObserver`, which keeps the canvas matched to its container and is
  on by default, and `fitView()`, which re-frames the camera around the nodes. Only
  the former is wanted. A debounced `fitView()` would rescale the whole picture on
  every window-edge drag, and with zero nodes it has no bounds to fit at all.
  Bounding pan is deferred because there is no graph extent to derive it from;
  numeric tuning is revisited in 4.0.3.1 when real nodes exist. `<Background>` dots
  ship so the operator can perceive pan and zoom on an otherwise empty canvas;
  they are canvas furniture, not a D11 placeholder control. **Rejected:** shipping
  fixture nodes so `fitView()` could be demonstrated. It would put map data on a
  production route that Contract OOS-1 excludes.

### Interfaces and contracts

- `routeKey(relPosix: string): string` (`scripts/route-presence.mjs`) — unchanged
  signature; segments matching `/^\(.+\)$/` are dropped before the key is built, so
  `(site)/sites/page.tsx` yields `/sites` and `(map)/atlas/page.tsx` yields
  `/atlas`. A grouped root `page.tsx` still yields `/`, and grouped metadata files
  keep their served paths.
- `SiteFrame({ children }: { children: React.ReactNode })` — Server Component.
  ```tsx
  /**
   * The site chrome frame: header, main region, footer, and feedback affordance.
   * Owned here rather than in the (site) layout because the root not-found file
   * must render identical chrome and cannot live inside the group — Next routes
   * every unmatched URL to the root file.
   */
  ```
- `NotFoundContent()` — Server Component, no props; the existing 404 markup with no
  chrome of its own.
- `MapCanvas()` — Client Component, no props.
  ```tsx
  /**
   * The map's full-viewport React Flow surface. Renders an empty graph over a dot
   * background with wheel-zoom, drag-pan and clamped zoom. Holds no node state and
   * reads no map data; later sessions supply both through this component's props.
   */
  ```
  Camera contract: `minZoom={0.2}`, `maxZoom={2.5}`, `nodes={[]}`, `edges={[]}`,
  default `zoomOnScroll` and `preventScrolling`, no `fitView` prop and no resize
  handler. The module imports `@xyflow/react/dist/style.css`.
- `MapChrome({ session }: { session: Session })` — Server Component. Receives the
  session resolved by the gate because `AccountMenu` requires it.
- `AccountMenu({ session, anchor }: { session: Session; anchor?: MenuAnchor })` —
  `anchor` defaults to today's `.app-header` lookup, so every existing route is
  unchanged; the map passes its own chrome root.
- `FeedbackButton({ compact }: { compact?: boolean })` — `compact` defaults to
  `undefined`, preserving today's labelled bottom-right button exactly.
- No export is removed. `src/mapper/index.ts` re-exports `MapCanvas` only.

### Control and data flow

A request to `/atlas` resolves `src/app/layout.tsx` → `src/app/(map)/layout.tsx` →
`src/app/(map)/atlas/page.tsx`. The map layout returns a static full-viewport frame
containing `<Suspense>` around an async gate. The gate awaits `checkAdmin()`, which
reads the Better Auth session from request headers. On `ok: false` it returns the
wall and never renders `children`, so the canvas subtree is absent from the
response. On `ok: true` it returns `MapChrome` with the resolved session plus
`children`; the page renders `MapCanvas`, a client boundary that mounts React Flow
after hydration. No database read, ESI call, Convex subscription, or cache lookup
occurs on this path. Existing routes are unchanged: their request path gains one
layout segment, `(site)/layout.tsx`, which renders `SiteFrame` and performs the same
two cached reads `AppHeader` already performed.

### Edge and failure behavior

- Unmatched URL anywhere in the app → root `not-found.tsx`, rendering
  `NotFoundContent` inside `SiteFrame`, visually identical to today.
- `notFound()` thrown inside a `(site)` route (`/changelog/[slug]`,
  `/devlog/[slug]`, `/sites/[id]`, `/industry/[id]`) → `(site)/not-found.tsx`,
  which renders `NotFoundContent` bare and inherits chrome from the group layout —
  exactly one header landmark on either path.
- Unhandled error in a `(site)` route → `(site)/error.tsx`, wrapped by the group
  layout, so header and footer keep rendering as its comment documents.
- Unhandled error in the map group → `(map)/error.tsx`, a viewport-filling message
  rather than an unstyled default page.
- Signed-out visitor at `/atlas` → `checkAdmin()` fails on the absent session and
  the wall renders; no redirect to sign-in, because the route is not advertised.
- Signed-in non-admin at `/atlas` → the wall. Zoom, canvas and chrome markup are
  never sent.
- Window resized to any size → the container tracks it and the camera transform is
  untouched; nodes, when later present, keep their positions.
- JavaScript disabled → the wall or an empty canvas frame renders; React Flow
  requires hydration and is not claimed to work without it.
