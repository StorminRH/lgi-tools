- **GOAL:** The map has its one window system — a persistent current-system
  dock panel (edge-anchored by default, pop-out to a freely draggable and
  resizable floating window with exact per-device geometry memory) and a
  node-anchored summary card that rides pan and zoom — both surfaces plus the
  floating mode on a single primitive rendered as a DOM sibling above the
  canvas, with typing and scrolling inside any window provably unable to move
  the map.
- **DONE =** SC-1 through SC-8 below, plus: on the live dev map the dock is
  standing for the current system hosting the shipped D15 widget, popping it
  out yields a floating window whose dragged/resized geometry survives a

  card glued to its node through pan and zoom, and the operator has recorded
  window sign-off at the browser gate.

## Why now

The shell (4.0.2.1), the live chain read path (4.0.2.3), and the widget-props
convention (4.0.1.3) exist, but the map still has no way to show detail over
the canvas: nothing can open, float, or anchor to a node. Every later surface
— signatures in 4.0.4.3, connection intel in 4.0.4.1, post-4.0 intelligence —
needs these windows, and a second window implementation appearing later would
be architecturally irreversible (HC-2). Building the container now, proven
against the shipped widget before any window-native content exists, is what
the master plan's phase ordering unlocks.

## Scope (the destination)

The finished slice is a window system private to the mapper zone. On a live
map with a resolved chain, the dock panel is a standing readout for the
current system — the chain root stands in for "current" until 4.0.4.2 ships
location tracking (operator ruling) — anchored to the right edge at a fixed
size with top clearance below the chrome control row, hosting the shipped
`SiteCardWidget` through the D15 props convention against a pinned fixture
identity. The right rail belongs to the standing dock: the shipped in-canvas
map-controls panel relocates from its top-right corner to top-left (a
one-prop placement change re-ratified at G-1), so the map lock, camera
settings, and dials stay fully visible and clickable for the whole session.
The dock is persistent by operator direction: presence is computed from the
resolved root, not selection; canvas clicks and Escape never close it; its
close control hides it for this page life only (never persisted — a reload
always shows it), and clicking the current system brings it back — a
per-click signal, deliberately not a selection edge, because clicking an
already-selected node emits no selection change in the installed canvas
library. Its pop-out toggle converts it to a floating window that drags by
its title bar, resizes freely from a corner handle, and remembers its exact
rectangle and mode per device: the persisted record carries `mode` and
retains the last committed floating rect across a re-anchor, so a reload
can never resurrect a float the user dismissed, a reload after floating
restores the float directly, and popping back out after a re-anchor returns
to the remembered rectangle. Selecting any non-root system shows a
node-anchored summary card with placeholder text that tracks panning,
zooming, node drags, and motion glides without per-frame React re-renders,
and dismisses on deselection, canvas click, Escape, or its close control —
every card dismissal routes through the host's deselect callback so the
derivation cannot instantly re-mount it. A canvas click deselects — React
Flow's own pane-click behavior — so the card closes with zero bespoke
dismissal wiring while the dock, whose presence is not selection-derived,
stands. Escape yields first to any open adopted-overlay popup (keyed on the
event's `defaultPrevented` flag, with a DOM presence check as the secondary
guard), then dismisses the card only — the dock is immune in both modes.
Pointer-down brings a window forward; the layer is inert everywhere a window
is not; card derivation is gated to settled single selections (no card
during box-select sweeps or multi-selection, and the card appears once a
sweep settles on exactly one non-root node). Everything renders in the host
layer as canvas siblings in the `z-sticky` band; the canvas library, its
pan/zoom behavior, and the `@/mapper` public surface are unchanged. Contract
§§3–6 are satisfied without widening — three surfaces, one primitive,
absolute isolation, local persistence, no window-native content — with the
dock-lifetime divergence from DC-1/AC-1 (both halves) and the dock's Escape
immunity under DC-5 recorded as operator-directed in the hard-constraints
block.

## Resolved implementation decisions

- **Contract PD-1 — pointer-event architecture: isolation by DOM-sibling
  topology, not suppression.** `MapWindowLayer` is a full-viewport
  `pointer-events-none` sibling rendered above the React Flow surface, each
  window a `pointer-events-auto` island — the exact `MapChrome` pattern, so
  the canvas stays live wherever no window covers it (HC-5 by construction).
  The version-matched documentation brief confirmed React Flow 12.11.2 binds
  wheel/pointer zoom-pan handlers to its own pane element only (window-level
  listeners exist solely during an in-flight pane drag, which cannot start
  from a sibling), so pointer and wheel events inside windows structurally
  cannot move the map. The keyboard hazards are global and split: React
  Flow's document/window key listeners skip `.nokey` subtrees for
  **non-modifier** keys (Space pan-activation is genuinely defeated), but a
  pressed modifier disables that gate in the installed source — therefore
  the window root also carries a keydown guard, pinned as a **React
  synthetic `onKeyDown`** that stops propagation: the synthetic handler
  runs inside React's document-delegated dispatch and its propagation stop
  halts the native event before it reaches the `window`-target listeners
  (Shift selection, Space pan-activation, multi-select), while keydown
  handlers inside hosted window content keep working — a native
  capture-or-bubble listener on the root would instead cut off React's own
  delegation and kill content handlers, the primitive's whole purpose from
  4.0.4.3 on. Recorded residual: the `document`-target zoom-activation
  watcher still arms on a held Meta/Ctrl inside a window, and is inert —
  zoom needs a wheel event on the pane, which the sibling topology denies.
  `keyup` deliberately bubbles so a key armed outside a window disarms
  wherever it is released. Wheel isolation inside windows rests on the
  sibling topology; the primitive's own contained scroll region (below)
  additionally stops scroll chaining. `deleteKeyCode={null}` and
  `disableKeyboardA11y` already ship on the surface. **Rejected:** rendering
  windows inside the canvas with `nowheel`/`nopan` suppression classes or
  React Flow portals (violates HC-3, inverts the isolation burden); a
  native keydown listener on the window root (kills hosted content's React
  handlers).
- **Contract PD-2 — separability: pure models plus a placement-variant
  primitive.** Every window decision lives in pure tested modules:
  `window-model.ts` owns surface presence (dock presence, hide/re-open
  transitions, card derivation from settled selection), the
  derivation-reconciled stack, bring-to-front, the keydown/Escape action
  decision, geometry, and clamp recovery; `follower-model.ts` owns
  node-anchored positioning and the follower subscription factory.
  `MapWindow` owns only chrome and isolation guards and takes placement
  (`docked` / `floating` / `node-anchored`) as an input with content as an
  opaque slot; `MapWindowLayer` is a thin applier of model output. The
  dock's content is the shipped `SiteCardWidget` passed as children — no
  sites type reaches the primitive's props, so the first consumer cannot
  shape the contract (D15), and the surfaces are thin variants, not
  implementations (HC-2). This split is also what makes the design provable
  at all in this repository's node-environment Vitest harness (no DOM, no
  effects — the shipped mapper pattern: `motion-host-model`,
  `camera-follow-model`, `map-controls-model`). **Rejected:** three sibling
  surface components sharing helpers (drifts into a second implementation);
  component-owned state machines (unreachable by the harness, and their
  0%-covered branches trip the repository CRAP cap at verify). **Also
  rejected:** building map windows on the Base UI overlay category — Base UI
  dialogs/popovers portal to `document.body` with dismissal, focus-trap, and
  anchoring semantics that HC-3 and HC-5 exclude, and they provide no drag,
  free resize, or moving-anchor follow; the map window is a deliberate
  non-overlay-category primitive confined to `src/mapper/windows/`, recorded
  here so a later session does not read the boundary as unsettled and reach
  for a Base UI surface (the second implementation HC-2 forbids).
- **Contract PD-3 — persistence: one Zod-validated mode-plus-rect record,
  exact pixels, rect retained across re-anchor, clamp on restore and on
  viewport resize.** The record under `lgi:map:windows:v1` is
  `{ v: 1, mode: 'docked' | 'floating', rect? }` — presentation is derived
  from `mode` alone, and `rect` is the last committed floating rectangle,
  RETAINED when re-anchoring writes `mode: 'docked'`: a reload can never
  resurrect a float the user dismissed, yet popping back out returns to the
  remembered rectangle instead of the default (the geometry DC-2 exists to
  remember). It follows the shipped `search-recents` pattern — safe-storage
  guard, Zod-parse of the untrusted blob (malformed or legacy shapes reset
  to defaults, never throw) — with one strengthening: the write path also
  swallows `setItem` failures (quota), which the reference's write path
  does not guard. Keyed per device and not per map (geometry is device
  presentation, DEP-3/HC-4). The in-memory hidden flag is deliberately NOT
  persisted — a reload always shows the dock (operator direction). A
  restored rect now off-screen is recovered by the pure `clampRect` so the
  title bar is always reachable — applied at restore AND re-applied on
  viewport resize while floating, because the map layout is
  `overflow-hidden` and OOS-3 ships no minimize/taskbar recovery
  affordance; the clamp is a no-op whenever the window is already
  reachable. **Rejected:** grid-slot/size-band quantization (the alternate
  draft's encoding — a quantized restore returns an approximation of where
  the user put it, with an undefined slot vocabulary); clearing the rect on
  re-anchor (destroys remembered geometry to enforce a rule `mode` alone
  enforces); account-scoped or Convex persistence (HC-4/DEP-3); persisting
  the hidden flag; clamping only at restore.
- **Contract PD-4 — node-anchored tracking without per-frame re-renders: one
  store subscription driving a pure follower model that writes CSSOM.** The
  positioning decision is a pure function in
  `src/mapper/windows/follower-model.ts`: given the previous baseline, the
  viewport transform triple, the anchor's `internals.positionAbsolute`, and
  measurement state, it returns the next transform string or `null` for "no
  write". Beside it lives the subscription factory —
  `createNodeFollower(store, anchorId, write)` returning `dispose()` —
  which subscribes to the shared React Flow store (a plain zustand
  subscription notified on every mutation: viewport frames, node drags,
  motion glides all flow through it; the transform triple is
  identity-replaced so `!==` is a valid guard) and applies model results
  through CSSOM with zero React re-renders. The factory takes the store as
  an argument, so its arm, diff, dispose-on-close, and dispose-before-
  retarget behavior is fully provable in the node harness with a fake
  store. The first write is defined, not diffed: on arm and on anchor
  change it performs one unconditional guarded read-and-write, and the diff
  baseline updates only when a write actually occurs — the card can never
  paint detached at the layer origin. Disposal is explicit: on card close,
  on retarget (dispose the old subscription before arming the new — stale
  callbacks must never move the new card), and on layer unmount. Screen
  position is computed as `position × zoom + viewport offset` directly;
  `flowToScreenPosition` is avoided because it calls
  `getBoundingClientRect()` (forced layout per frame). The follower guards
  the store's initially-null `domNode` and the anchor's not-yet-measured
  dimensions. **Rejected:** `NodeToolbar` / `ViewportPortal` (inside the
  flow renderer — HC-3); `useViewport`/`useStore` hook subscriptions for
  per-frame tracking (re-render every pan frame — this rejection does NOT
  cover low-frequency booleans like the box-select gate, which is read
  reactively); a rAF polling loop; follower logic inside the layer
  component (untestable, CRAP-capped).
- **Dock lifetime (operator direction, 2026-08-02, reaffirmed 2026-08-03):
  a persistent standing readout.** The dock renders whenever the chain has
  a resolved root and the in-memory hidden flag is clear — presence is
  computed, never selection-derived. Canvas clicks never close it; Escape
  never closes it in either mode; its close control sets an in-memory
  `dockHidden` that is never persisted (reload always shows the dock).
  Re-open is a PER-CLICK signal, not a selection edge: the installed
  canvas library emits no node change when an already-selected node is
  clicked, so "root became selected" is unreachable exactly when the user
  hid the dock while the root was selected — instead, `ChainHost`'s
  existing `onNodeClick` seam (which fires unconditionally on every node
  click and already stamps a monotonic token for the camera) passes a
  root-click signal `{ systemId, token }` into the layer, and a root click
  clears `dockHidden`, gated on the box-select flag being false. This
  supersedes DC-1/AC-1 in full (both the close-on-canvas-click and
  driven-by-selection halves) and bounds DC-5's Escape reach to the card;
  the divergence is recorded in the hard-constraints block for the
  as-built. **Rejected:** the contract's literal selection-driven dock (the
  operator ruled for a standing readout); observing a selection edge for
  re-open (unreachable when the root is already selected); persisting the
  hidden flag; a bespoke "re-open" control this session does not own.
- **Current-system stand-in (operator-ruled): the chain root, resolved as
  `rootSystemId`.** Until 4.0.4.2 ships location tracking, the root system
  plays "current" — the layout facts already resolve `rootSystemId` (the
  attach order is root-first, so this also matches the alternate draft's
  "first system" reading, with a precise source instead of an array-order
  assumption); `use-map-chain` passes it through to the host. If the root
  changes with the live chain, the dock's bound system follows; if the
  chain is empty (`rootSystemId === null`), the dock is absent and re-open
  is inert until a root exists. **Rejected:** every selection opening the
  panel (the summary card loses its trigger); deriving "first system" from
  an unspecified array order.
- **Chrome, controls, and window stacking: the window layer lives in the
  `z-sticky` band above base chrome; the right rail belongs to the dock, so
  the in-canvas controls panel relocates to top-left.** `MapChrome` is
  `absolute inset-0 z-sticky` (`--z-index-sticky: 10`) with
  `pointer-events-auto` islands; the window layer carries the same
  `z-sticky` token and, mounting inside the canvas subtree that follows
  `MapChrome` in document order, paints and hit-tests above the chrome row
  at equal z — a window dragged under a chrome control wins its own clicks
  (ordinary window behavior). Intra-layer stacking is the model's ordering
  applied through CSSOM as z-order **within** that band only.
  Body-portaled adopted-overlay surfaces (Base UI positioners at
  `z-dropdown`, dialogs at `z-overlay`) deliberately render above windows.
  The shipped `MapControls` panel currently occupies the top-right corner
  IN the canvas with an inline-expanding dial group — exactly where a
  persistent dock stands — so this session moves it to
  `Panel position="top-left"` (a one-prop placement change below the map
  menu's chrome island, re-ratified at G-1); the dock keeps top clearance
  below the chrome control row so the menu, search slot, and account
  control stay visible beside it. The G-1 review and the dock probe
  explicitly exercise the relocated controls (lock toggle, a dial open)
  while the dock stands. **Rejected:** an unbanded layer (hit-tests beneath
  `z-sticky` chrome); a new stacking token or the `z-overlay` band (buries
  open chrome popups); stacking the dock below the controls panel in the
  right rail (the dial group expands inline and would collide with or be
  buried by the standing dock all session).
- **Escape ownership: adopted-overlay popups first, then the card — the
  dock is immune.** Both Escape paths yield primarily on the event's
  `defaultPrevented` flag: Base UI's Escape handling on the popup's
  reference and floating elements runs as React synthetic handlers inside
  React's document-delegated dispatch — registered at hydration, BEFORE the
  layer ever mounts — and calls `preventDefault()` synchronously, with the
  popup unmounting in the same flush; a DOM presence check for an open
  adopted-overlay popup is the SECONDARY guard, covering the path where
  only Base UI's own later-registered document listener would handle the
  key (focus outside the popup) and the popup is still mounted when the
  layer's listener runs. One press therefore closes the popup, the next
  dismisses the card. In-window Escape is handled by the window root's
  synthetic keydown guard (card window → dismiss; dock window → ignore;
  then the propagation stop); the layer's document-level listener handles
  Escape only with focus outside every window and dismisses the card via
  the host's deselect callback so it cannot instantly re-derive; the card's
  close control routes through the SAME deselect callback for the same
  reason. With no card open, Escape does nothing — the dock never closes on
  Escape (operator direction). The keydown/Escape decision itself is a pure
  function in `window-model.ts`. **Rejected:** an unconditional document
  listener (double-close); a DOM-presence-only yield (races the synchronous
  popup unmount — the popup is already gone from the DOM when the layer's
  listener runs on the same event); Escape-closes-topmost across all
  windows (superseded by the dock immunity ruling).
- **Stack membership is derived, never separately registered.** Surface
  presence is a pure derivation in `window-model.ts` —
  `{ rootSystemId, dockHidden, mode, selectedIds, boxSelectActive,
  rootClick } → surfaces` — and the layer passes the currently-rendered
  surface ids into `reconcileStack` each commit: absent ids are pruned,
  newcomers append on top, and `topmost`/bring-to-front operate only on
  that reconciled order (the dock keeps one stable id across its
  docked/floating mode switch). Card derivation and dock re-open are gated
  on the store's `userSelectionActive` being false, and that flag is read
  REACTIVELY (a `useStore` boolean subscription — low-frequency, outside
  PD-4's per-frame rejection), because React Flow emits no node change when
  a box-select sweep ends: an imperative read would leave a settled
  single-selection card unmounted until an unrelated commit. **Rejected:**
  an imperative open/close registry beside the derivation (two owners for

  the owning effect's cleanup invokes it on mid-gesture teardown (access

### Interfaces and contracts

- `WindowPlacement` (window-model) — discriminated union:
  `{ kind: 'docked' }` (fixed-fit right edge, top clearance below chrome) ·
  `{ kind: 'floating'; rect: WindowRect }` ·
  `{ kind: 'node-anchored'; systemId: number }`. `WindowRect` is
  `{ x, y, width, height }` in layer pixels.
  Draft contract comment: `/** Where and how one window renders; the primitive never decides placement. */`
- `windowModel` pure functions (window-model) —
  `deriveSurfaces({ rootSystemId, dockHidden, mode, selectedIds, boxSelectActive, rootClick })`
  (returns the surface set: dock presence computed from root and hidden
  state, card from settled single non-root selection, hide cleared by a
  fresh root-click token), `keydownAction({ key, surfaceKind, popupOpen, defaultPrevented })`
  (returns `dismiss-card` | `ignore`, always followed by the propagation
  stop), `reconcileStack(stack, liveIds)`, `bringToFront(stack, id)`,
  `topmost(stack)`, `clampRect(rect, viewport, minVisible)`. All total; no
  DOM access.
  Draft contract comment: `/** Pure presence, stacking, keyboard, and geometry-recovery decisions for the map window system. */`
- `computeFollowerTransform(baseline, viewport, anchor, measured)` and
  `createNodeFollower(store, anchorId, write): () => void`
  (follower-model) — the pure transform decision plus the
  store-parameterized subscription factory; a null baseline or changed
  anchor id always produces a write when the guards (non-null `domNode`
  state, measured anchor) pass; `dispose` is idempotent and must run
  before a retarget arms the next anchor.
  Draft contract comment: `/** Decides and applies the node-anchored card's CSSOM transform; null means leave the DOM untouched. */`
- `readWindowRecord(): WindowRecord | null` / `writeWindowRecord(record): void`
  (persistence) — `WindowRecord` is `{ v: 1, mode: 'docked' | 'floating',
  rect?: WindowRect }`; presentation derives from `mode` only and `rect`
  is the last committed floating rectangle, retained across re-anchor;
  Zod-validated against the untrusted blob; unavailable or malformed
  storage reads as `null` (default docked) and BOTH read and write paths
  swallow storage exceptions (including `setItem` quota failures); never
  throws.
  Draft contract comment: `/** Per-device dock mode and last floating rect under lgi:map:windows:v1; local presentation only, never synchronized. */`
- `createPointerGesture({ onDelta, onEnd })` (drag-resize) — returns the
  `pointerdown` handler plus a `dispose()` for the owning effect's cleanup:
  natural release (`pointerup`/`pointercancel`) fires `onEnd` with the final
  deltas; `dispose()` releases capture and clears active state WITHOUT
  firing `onEnd` (the in-flight rect is discarded).
  Draft contract comment: `/** One capture-based gesture engine shared by window drag and window resize; dispose() aborts without committing. */`
- `MapWindow` props — `{ windowId, title, placement, onClose, onActivate, onPopToggle?, children }`;
  root carries `nokey` and the synthetic `onKeyDown` guard; only `floating`
  mounts drag/resize affordances; the card's `onClose` is bound by the
  layer to the host deselect callback (same path as Escape) so a closed
  card cannot re-derive.
  Draft contract comment: `/** The map's single window primitive: chrome and isolation only; content and placement are supplied. */`
- `MapWindowLayer` props — `{ nodes, rootSystemId, rootClick, onDeselect }`
  where `rootClick` is `{ systemId: number; token: number } | null` from
  the host's per-click seam; the layer owns no decisions.
  Draft contract comment: `/** Hosts every map window as a pointer-inert sibling above the canvas. */`

### Control and data flow

Selection originates in React Flow (pointer-down on a node emits select
changes; a pane click emits deselect-all) and flows through the existing
`onNodesChange` → `nodes` state in `ChainLive`; the existing `onNodeClick`
seam additionally stamps a root-click signal `{ systemId, token }` on every
node click (it fires even when the node is already selected — the selection
path does not). `MapWindowLayer` feeds `deriveSurfaces` with the nodes
state, `rootSystemId`, the root-click signal, the in-memory `dockHidden`,
the persisted `mode`, and the REACTIVE `userSelectionActive` boolean (a
`useStore` subscription, so a box-select sweep settling re-derives without
waiting for an unrelated commit). Dock presence: root resolved AND not
hidden → the dock renders in the recorded mode (floating restores the
retained rect through `clampRect`); a fresh root-click token clears
`dockHidden`. Card: settled single non-root selection → the card; zero or
multiple selected, or a sweep in progress → no card. Pane clicks deselect,
which closes the card and touches nothing else — the dock stands by
construction. The pop-out toggle switches the record to floating (writes at
gesture end and on mode change); re-anchor writes `mode: 'docked'` while
RETAINING the rect. Each commit the layer passes the rendered surface ids
to `reconcileStack` (the dock keeps one id across mode switches), so the
model stack always matches what is on screen. Keydown inside a window hits
the window root's synthetic guard first: `keydownAction` decides (Escape on
the card with no open popup and `defaultPrevented` false → dismiss via
`onDeselect`; Escape on the dock → ignore; everything else → ignore), then
propagation stops — React Flow's window-target key listeners and the
layer's document Escape listener never see in-window keys, while content's
own React handlers still run; `keyup` bubbles through. The document-level
Escape path fires only with focus outside every window: it yields when
`event.defaultPrevented` is already true (Base UI's synthetic popup
handlers ran earlier in the same delegated dispatch) or when an
adopted-overlay popup is still present in the DOM (its document listener
runs after the layer's), and otherwise dismisses the card via `onDeselect`;
the card's close control routes through the same callback. With no card
open it does nothing — the dock is immune. Pointer-down anywhere in a
window calls `onActivate` → `bringToFront` → intra-band stacking re-applied
via CSSOM. The card's follower is armed through `createNodeFollower`; on
arm and on anchor change it writes unconditionally (guards permitting),
afterwards only when the viewport triple or anchor position moved — no
React re-render on pan, zoom, drag, or glide frames; it disposes on card
close, retarget (dispose before re-arm), and layer unmount. Geometry writes
happen at natural gesture end (drag/resize release), never per delta and
never from a disposed gesture. No server, Convex, cache, or route boundary
is involved anywhere in this flow — the widget's own `apiFetch` is
feature-owned behavior this session does not touch.

### Edge and failure behavior

- `localStorage` unavailable, malformed, or throwing on write (private
  mode, quota) → the dock opens docked at defaults; reads fall back and
  writes are silent no-ops; nothing throws (persistence guard on BOTH
  paths).
- Persisted floating rect off-screen for the live viewport → `clampRect`
  pulls it back so the title bar is always grabbable (model unit coverage).
- Browser window resized while floating → the layer re-runs `clampRect`
  against the new viewport (a no-op while the window stays reachable), so
  the title bar can never be stranded outside the `overflow-hidden` map
  frame with no recovery affordance.
- Dock hidden while the root is ALREADY selected, then the root is clicked
  again → the dock re-opens: re-open rides the per-click signal, which
  fires without a selection change (the selection edge does not exist in
  the installed library).
- Re-anchor then reload then pop out → the floating window returns at the
  retained rect, not the default (rect survives `mode: 'docked'`).
- Access revocation or dock hide mid-drag/mid-resize → the owning effect's
  cleanup calls the gesture's `dispose()`: capture released, active state
  cleared, the in-flight rect discarded; the last committed record stands.
- Card's system removed live (revoked page, deleted system) → its node
  leaves `nodes`, the derivation finds no anchor, `reconcileStack` prunes
  the id, the card closes; the follower disposes. If the ROOT changes with
  the live chain, the dock's bound system follows the new root; if the
  chain empties (`rootSystemId === null`), the dock is absent and re-open
  is inert until a root exists.
- Box-select sweep crossing one node → no card mid-drag and no re-open;
  the sweep settling on exactly one non-root node mounts the card after
  release (the gate is reactive, so settle re-derives immediately).
- Multi-selection (box or modifier click) → no card; the dock is unaffected.
- Escape with an adopted-overlay popup open (chrome menus, the dial popup,
  future in-window Base UI controls) → both Escape paths yield — on
  `defaultPrevented` when the popup's own synthetic handlers ran first, on
  DOM presence when only its document listener will — so one press closes
  the popup and the next dismisses the card; the dock never closes on
  Escape (operator direction).
- Card close control → routes through `onDeselect`, so the derivation
  cannot re-mount the card on the next commit (a local hide would make the
  close button appear dead).
- Widget fixture unreachable (API error, missing site) → `SiteCardWidget`'s
  own error banner renders inside the slot; the window system is
  indifferent to slot content state.
- Store `domNode` still `null` or anchor unmeasured on first frame → the
  follower model returns `null` until real values exist; the first passing
  evaluation writes unconditionally (documented first-render gap, closed by
  the arm-write rule).
- Map switch (`ChainHost` keyed by map id) → the layer unmounts with its
  host; the persisted record is device-wide by design (HC-4, PD-3);
  `dockHidden` resets with the remount (in-memory only).
- Reduced motion → windows have no required animation (OOS-5), so no
  reduced-motion branch exists to diverge.
