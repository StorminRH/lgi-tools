## Scope (the destination)

At session end: every rendered system is a widget-frame primitive — an invisible frame whose bounds are the node box, the system name in the frame header, the visible disc centered inside, connection lines clipped to the frame boundary, and widget slots for at-a-glance indicators (pilot presence first; gas/anomaly readouts extend it in 4.0.4.3+). Tracked pilots render as a green presence indicator in their system's frame; clicking the system opens the existing summary card, whose placeholder body becomes real system intelligence with an operator-directed UI shape (2026-08-07): the system name and sensible static details up top, then a **friendlies-in-system readout as a minimal two-column table** — pilot name on the left, one single-word status on the right (`In space` / `Docked` / `AFK` / `Stale`), nothing more; statuses derive honestly (Stale from sync-subject feed freshness, AFK locally for your own characters); the click-through dock shares the same body. A pilot beyond the drawn map shows as a green arrow mounted on the last visible connection line along their gate path, pointing into the fog. From every authored k-space system, a deterministic BFS halo over the static gate adjacency draws two rings of neighbor systems and places a third ring under fog (`HALO_DRAWN_RINGS = 2`, `HALO_FOGGED_RINGS = 1`, `HALO_MAX_SYSTEMS_PER_EXIT = 60`, pinned constants tuned once at G-1; no user-facing configuration by operator direction — the contract's depth dial and toggle are superseded). J-space systems have no gate adjacency, so the halo acts only outside wormhole space by construction (DC-1's boundary). A world-anchored fog canvas sits above the backdrop and below the edges and nodes, covering everything except union reveals — soft noise-brushed discs around drawn nodes and strokes along fully-drawn edges — with smoky edges at rest, smoke-flavored reveal/return dynamics riding the motion layer's timing, a drag wake, and fog rolling back in as content despawns; edges whose far endpoint is fogged get no stroke reveal, so lines visibly run into the cloud and cut off. Everything derives client-side from authored truth plus the static asset: zero documents, identical on every client (DC-2/HC-1), no authoring of visited systems (HC-2), no new promotion triggers (HC-3 in superseded form). Chain authoring, sever/collapse, camera, and preferences behave exactly as before.

## Resolved implementation decisions

- **Contract PD-1 — Promotion triggers and preserved fog context: superseded; reveal-on-authoring is the successor.** The operator redefined fog in this planning session (2026-08-07): it is node-anchored canvas presentation (RTS fog-of-war), not per-system provisional state, so there are no "fog systems" to promote and the note/kill/pin trigger set is dropped — no note-authoring surface ships. The surviving intent lands as: when jump authoring (4.0.4.2.2's shipped path, untouched) creates a system already rendered in the halo, the node id is the system id, so the node upgrades in place — identity continuity, no duplicate — enters authored truth through the shipped `map-node-enter` vocabulary, and the fog reveal continues around it. **Rejected:** building the contracted note-promotes-fog mechanic (requires a net-new note surface for a concept the operator has explicitly withdrawn).
- **Contract PD-2 — Halo depth, dial range, placement style: pinned constants, no user configuration, compass-structural placement.** The halo anchors to **authored k-space systems**, not to tracked pilots — part of the same 2026-08-07 operator fog redefinition (the contract's and master plan's "around tracked pilots" wording is superseded; fog follows the drawn map). Defaults `HALO_DRAWN_RINGS = 2`, `HALO_FOGGED_RINGS = 1`, `HALO_MAX_SYSTEMS_PER_EXIT = 60`, `HALO_MAX_SYSTEMS_TOTAL = 150` (deterministic truncation: shortest depth first, then authored-exit creation order); values are exposed on the dev-only dial panel during G-1, the operator tunes by eye and performance, and the chosen values pin as constants — no page-settings entry, no user dial or toggle (operator direction supersedes the contract's dial/toggle wording). Placement is structural: halo systems and gate links append to `LayoutFacts` in deterministic BFS order and the compass kernel places them like every other node; each system places once at its shortest gate distance, extra adjacency draws as cross-link edges. **Rejected:** SDE-geometry placement (the client asset carries no coordinates, and real-space geometry fights the compass tree — operator explicitly declined); a user-facing depth dial (page-settings is Switch-only today and the operator ruled fog non-configurable).
- **Contract PD-3 — Large-chain cost boundary: memoized derivation, frame-bounded fog redraw, hard caps.** Halo derivation runs only when the authored-truth signature changes (never per render, never per frame) and is capped per exit with deterministic truncation; the fog canvas redraws at most once per animation frame, only when drawn content, positions, or motion phases change, with pan/zoom free via the viewport transform; reveal cost is linear in drawn nodes+edges (soft-brush sprite stamps, no SVG filter pipeline in the hot path). The 4.0.3.2 frame-budget probe at the 50–60-node ceiling is re-run with fog+halo active (SC-6). **Rejected:** per-frame halo recomputation (unbounded); SVG `feTurbulence` animation in the hot path (browser-expensive; the smoky look ships via canvas noise brushes with a static-smoky-edge degradation if any dynamic effect misses frame budget).
- **Plan — Frame primitive is the node box.** The React Flow node wrapper carries the frame dimensions (invisible bounds); the visible disc centers inside; the system name moves into the frame header; widget slots dock along frame edges; `chainLinkPath` in `src/mapper/canvas/edge-geometry.ts` swaps its disc-radius clip for a frame-box intersection using each endpoint's own frame dimensions. Icons and the frame scale with the map (world-space, operator-settled). **Rejected:** React Flow handles at frame edges (the shipped floating-edge approach already bypasses handles; reintroducing them would change edge anchoring semantics for no gain).
- **Plan — Presence details live in the existing summary card; the hover popover is cut (operator simplification).** The green frame icon is the at-a-glance signal; clicking the node opens the shipped node-anchored summary card whose `SystemIntelligencePlaceholder` body becomes `SystemIntelligenceBody` — operator-directed shape: system name + sensible static details, then the friendlies table (pilot name left, single-word status right: `In space` / `Docked` / `AFK` / `Stale`; precedence Stale > AFK > Docked > In space), minimal and clean, structured so future widget readouts (gas, anomalies) append as sibling sections; the click-through dock shares the body. No Base UI wrapper work. **Rejected:** a shared hover Popover over frame icons (extra wrapper surface, unresolved pan/zoom anchor-tracking behavior, and a redundant affordance beside the existing card).
- **Plan — Staleness honesty uses two signals.** `forMap` gains a read-only join: each tracked row carries `feedFreshAt` — the owner's `characterLocation` sync-subject `lastFinishedAt` (the field 4.0.4.2.1 established as feed freshness; `observedAt` is last-CHANGE and cannot distinguish a stationary pilot from a paused tracker). Model states: **live** (feed fresh) vs **stale** (feed old or subject row absent), with `lastMovementAt` retained as a model field feeding the status mapping and SC-3.1's unit matrix — the card *displays* only the operator-directed single-word status, never a movement-age column; own characters additionally show local AFK state from the shipped AFK gate. The card never claims online/offline knowledge it does not have. **Rejected:** age-of-`observedAt` staleness (marks every stationary pilot stale — dishonest); resurrecting online data (the `onlineStatus` dataset was deliberately retired in #368).
- **Plan — Fogged-ring nodes are placed but inert.** Ring-3 systems render under the fog: they enter layout (so fog recession reveals already-placed nodes) but carry the ghost precedent's inert style (`pointerEvents: 'none'` per node — a class cannot make a React Flow node inert), `selectable: false`, and are excluded from camera-fit bounds so the camera never frames invisible content. Drawn halo nodes are selectable (the summary card works for any rendered system) but not draggable — the kernel always owns derived positions and nothing persists them.
- **Plan — Outbound arrow mounts on the drawn boundary edge of the pilot's gate path.** A pure helper BFSes the gate adjacency from the drawn (non-fogged) set toward the pilot's system (bounded depth `PILOT_PATH_MAX_JUMPS = 15`); the arrow renders through React Flow's edge-label seam on the last drawn (visible) edge of that path, positioned parametrically in `edge-geometry.ts` (unit-testable), pointing outward. A pilot standing in a fogged ring-3 system is off-drawn-map by this definition: no badge under fog, arrow on the visible boundary line instead. No path → no arrow (pilot remains listed in tracking controls); J-space systems have no gate adjacency, so an unmapped J-space pilot simply is not drawn. Built as a single mount point that can grow into a fuller edge-frame later (operator's noted direction), not as a general edge-widget system now.

### Interfaces and contracts

- `deriveHalo(input: { authoredSystems: readonly { systemId: number; order: number }[]; neighbours: (id: number) => readonly number[]; securityClassOf: (id: number) => SystemSecurityClass | undefined }): HaloDerivation` — pure, deterministic; `HaloDerivation = { systems: readonly { systemId: number; ring: number; fogged: boolean }[]; links: readonly { a: number; b: number }[] }`; systems exclude everything already authored; identical inputs yield byte-identical output (order-stable); unknown system ids (absent from the asset) are skipped.
- `HALO_DRAWN_RINGS = 2`, `HALO_FOGGED_RINGS = 1`, `HALO_MAX_SYSTEMS_PER_EXIT = 60`, `HALO_MAX_SYSTEMS_TOTAL = 150`, `PILOT_PATH_MAX_JUMPS = 15` — exported pinned constants; G-1 tunes then pins; no runtime configuration surface; the aggregate cap truncates deterministically (shortest depth, then authored-exit creation order) so a many-exit chain's halo load has a hard bound, and the frame-budget proof runs at that bound combined with a ceiling-sized authored chain.
- `derivePresence(input: { tracked: ForMapTracked[]; now: number; ownCharacterIds: readonly number[]; ownAfk: boolean }): ReadonlyMap<number, SystemPresence>` — pure; `SystemPresence = { pilots: readonly { characterId: number; shipTypeId: number | null; docked: boolean; lastMovementAt: number; state: 'live' | 'stale'; ownAfk: boolean }[] }`; `state` derives from `feedFreshAt` age against `PRESENCE_FEED_STALE_AFTER_MS` (pinned; default 180000), never from `observedAt` age; absent subject freshness → `stale`.
- `mapTracking.forMap` — response rows gain `feedFreshAt: number | null` (owner's `characterLocation` subject `lastFinishedAt`); no argument change, no new index, read count stays capped by the tracked-rows cap; existing consumers unaffected (additive field).
- `derivePilotPath(input: { drawnSystemIds: ReadonlySet<number>; pilotSystemId: number; neighbours: (id: number) => readonly number[] }): readonly number[] | null` — pure bounded BFS; `drawnSystemIds` is the **non-fogged** rendered set (authored + drawn halo rings; fogged ring-3 systems are excluded, so a pilot standing under fog resolves to the arrow, never to an invisible badge); returns the system path from the nearest drawn system to the pilot (inclusive) or null past `PILOT_PATH_MAX_JUMPS`; the arrow mounts on the last **drawn** (visible) edge of that path.

- `deriveFogReveals(presentation: { nodes: readonly RenderedNode[]; edges: readonly RenderedEdge[] }): FogRevealSet` — pure; discs for every non-fogged rendered node (ghosts included, so despawn closes fog on the ghost timeline), strokes only for edges with both endpoints non-fogged; `FogRevealSet` feeds the canvas painter.

### Control and data flow

Render path: `useMapChain` reconciles authored truth → `factsFromSnapshot` builds layout facts → **new:** the memoized halo derivation (authored-truth signature key) appends halo systems/links to facts and contributes halo nodes/edges to the canvas node set before the motion layer → the compass kernel (worker, unchanged contract) places everything → `MotionLayer`/`derivePresentation` produces rendered nodes/edges (ghosts included) → `ChainSurface` renders frames and clipped edges; `FogLayer`, mounted beside the canvas layers inside the viewport transform, derives reveals from the same presentation output and paints once per frame when inputs changed. Presence path: the existing `forMap` subscription (now carrying `feedFreshAt`) → `derivePresence` → frame badges, the summary/dock intelligence body, and — for off-map pilots — `derivePilotPath` → the arrow mount on the boundary edge. Failure boundaries: universe assets not yet loaded → empty halo and chain-only fog reveals (no error, resolves when the memoized loader settles); adjacency lookup misses → system skipped; Convex subscription loss behaves exactly as today (fog/halo derive from the last reconciled truth). No server-side flow changes; the only Convex delta is the read-only `forMap` join.

### Edge and failure behavior

- Authored J-space system → no gate adjacency → contributes nothing to the halo; a pure-J-space chain shows fog with reveals around the chain only.
- Two authored k-space exits gate-adjacent or sharing neighbors → each halo system places once (shortest depth, first-claiming exit in authored creation order); discovered gate links between rendered systems draw as cross-link edges; no duplicate nodes by node-id construction.
- Halo system later authored by a jump → same node id upgrades in place: no duplicate, authored styling and interactivity apply, position may re-place under the kernel's authored ordering (motion glides per the shipped vocabulary), fog reveal persists through the transition (SC-4).
- Authored system severed/despawned → halo re-derives without its branch; departing nodes ghost through the motion layer and the fog closes on the ghost timeline.
- Ring-3 (fogged) node → placed, invisible under fog, inert (`pointerEvents: 'none'`, `selectable: false`), excluded from camera-fit bounds; its inbound line gets no stroke reveal, so it visibly cuts off under fog.
- Drawn halo node → selectable (summary card shows name/class; presence rows appear if a tracked pilot stands there), never draggable, position never persisted.
- Tracked pilot in a drawn (non-fogged) system → frame badge; in a fogged ring-3 system or any off-map k-space system within `PILOT_PATH_MAX_JUMPS` of the drawn set → outbound arrow on the last drawn (visible) edge of the gate path — never a badge inside an invisible node; beyond the bound, or in an unmapped J-space system (no gate path exists) → no canvas marker; tracking controls still list the pilot.
- Feed subject row absent, or `feedFreshAt` older than `PRESENCE_FEED_STALE_AFTER_MS` → the pilot's status renders `Stale`; a stationary pilot with a fresh feed honestly renders `In space` (or `Docked`).
- Own character AFK-gated locally → own row renders `AFK`; other viewers see `Stale` once the feed ages.
- `prefers-reduced-motion` → fog ships the static smoky edge with simple opacity easing; no smoke dynamics (mirrors the motion layer's reduced-motion handling).
- Fog frame budget missed at the 50–60-node ceiling → the dynamic smoke effects degrade to the static edge treatment (a pinned degradation path, not a tuning failure); the G-1 gate decides the shipped tier.
- Window/summary-card anchoring — the node-anchored follower tracks the node box, which is now the frame; existing window tests must stay green with frame dimensions (proven in OW 1).
