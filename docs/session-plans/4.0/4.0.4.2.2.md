## Why now

Tracking and pure jump classification shipped in 4.0.4.2.1 with deliberately test-only consumers: the platform can already see a scout cross a hole but does nothing about it. This session wires that knowledge into the map — automatic authoring is the master plan's heartbeat feature — and starts the D16 observation stream, which cannot be retrofitted (the dataset compounds from first emission). The fog/UX session (4.0.4.2.3) and the signature version (4.0.4.3) both consume the merged connection model this session establishes.

## Scope (the destination)

At session end: a wormhole-group signature is a `mapConnections` row from the moment it is known — scanned-but-unexplored rows carry an origin system, origin signature ID, optional type/size/leads-to knowledge, and a null destination; resolved rows carry both endpoints and both signature identities. A tracked scout's hole crossing rings a doorbell route from any open map client; the server verifies the transition against Convex truth, classifies it with Neon gate adjacency, and — for wormhole crossings touching J-space — authors idempotently in one Convex transaction: destination system upsert, connection resolve-into-slot or fresh insert, mass-odometer increment, and processed-transition stamp. Elimination (destination class, ship size, per-side leads-to hints) plus the statics census decide provenance: a lone consistent typed survivor with the census satisfied resolves as `jump-verified` and emits a D16 observation row to Neon; everything else resolves as `assumed` (never emits) with surviving candidates recorded; contradicted-or-empty candidate sets insert a fresh row. The pilot sees a non-blocking confirm/correct prompt; confirming records the accepted-suggestion tier (`confirmed`, which emits at its own D16 weight), correcting is an override (`human`) that re-associates the destination to the chosen row. Manual hole typing through the connection card now records provenance and emits at human tier through the same route. The connection card gains the closed-vocabulary leads-to field (K162/unidentified only) and shows mass regeneration only when nonzero. Gate travel, same-system noise, re-anchors, and pure k-space movement author nothing. Chain reads, collapse, sever, motion, and purge behave exactly as before because unresolved rows are filtered out of every shipped consumer.

## Resolved implementation decisions

- **Contract PD-1 — Idempotency and concurrent scouts: untrusted doorbell, server verification, one transactional Convex owner.** Any open map client whose session user holds `edit` access rings the doorbell on observing a tracked transition; the route authenticates the ringer (identity never from the body) and re-reads `characterLocation`/`mapTracking` server-side, so forged or repeated doorbells cannot fabricate movement. The mutation authorizes the ringer's `edit` access; the tracked scout's identity is payload — already-shared map state via `forMap` — never an authority claim. A per-(map,character) processed-transition stamp (`observedAt`-keyed, checked and written inside the authoring mutation) makes each transition exactly-once per map even under doorbell storms; system upsert converges on `by_map_system`; connection convergence checks both direction pairs and unresolved slots before inserting. Two scouts crossing the same hole are two real crossings: both stamp their own transitions, the second converges onto the existing connection and increments the odometer. **Rejected:** client-side direct authoring mutations (spoofable emission trigger, N-viewer duplicate writes); Convex-side classification (geography must not enter Convex); a `fetchQuery`/server-JWT Convex client seam (second seam beside the shipped bearer door, no server-side token mint exists, and stateless consecutive reads lack mutual consistency — the one-query evidence packet is strictly stronger).
- **Contract PD-2 — Observation shape: five-field Neon row, upsert by dedupe key.** `(solarSystemId of the typed side, whTypeCode ≠ K162, provenance tier, hour-coarse timestamp, random per-connection dedupe key)`; no map/user/character/destination columns exist. Emission is an upsert keyed on the dedupe key, so a later correction re-emits and repairs the row instead of poisoning history. A class-consistency check (typed code's target class vs verified destination) runs before every emit; mismatch → no emit. **Rejected:** append-only event log (corrections would accumulate contradictory rows) and emitting `assumed` matches (violates D16 anti-circularity).
- **Contract PD-3 — Matching proof interface before the parser: fixture-created unresolved connection rows + seeded statics.** `convex/mapFixtures.ts` gains an internal unresolved-hole fixture (origin, signature ID, optional type/hint); Neon db-test harness seeds `whSystemStatics`. The eliminator is pure and takes plain data, so the full matrix (single/ambiguous/absent, hint elimination, size elimination, census-short) runs as unit tests plus a route-level integration proof. **Rejected:** waiting for the 4.0.4.3 parser (blocks the heartbeat feature on a later session).
- **Plan — Merged signature/connection model (operator-settled; contract split trigger resolved in-session).** Wormhole-group signatures live in `mapConnections` as unresolved rows (null `toSystemId`, `fromSignatureId` set); `mapSignatures` keeps non-wormhole and unresolved-group rows. One row per hole from scan to resolution; both-side signature identities on the row; the uniform-editing requirement is satisfied by construction. The contract's DC-5 "links automatically" is realized as resolve-into-slot. **Rejected:** separate sig rows + link field (double-write mirroring, drift, unlink machinery, duplicate documents).
- **Plan — Never spawn a node while an eligible slot survives (operator rule).** Survivors ≥ 1 → resolve into the best-informed survivor (deterministic preference: typed-consistent, then hinted-consistent, then untyped, then K162). Zero survivors with candidates present (all eliminated — evidence conflict) or zero candidates → fresh row. Census shortfall never blocks slot resolution; it only downgrades provenance to `assumed`. Corrections re-shuffle identity between rows (`re-associate` mutation moves the verified destination; the vacated row returns to unresolved), never topology.
- **Plan — Authoring only when a side is J-space.** `hole-crossing` verdicts where both systems are k-space author nothing this session: k-space wanderer coverage was deferred with the k-space version, and this rule also suppresses the jump-drive/bridge false positive (a capital's non-adjacent k→k jump is not a wormhole). Recorded for the operator's later k-space version to revisit.
- **Plan — Authority: edit-capable watchers author.** The observed transition is shared map state; turning it into map fact is a map edit, so the authority that matters is the ringer's `edit` role — exactly the authority that could hand-author the same fact. Consequences, all recorded: a view-only scout's jumps still author whenever an edit-capable client is watching; a view-only ringer is `skipped`; and when no edit-capable client is open during the continuity window, the transition lapses to re-anchor honesty — nothing authored, nothing invented (accepted capture gap). **Rejected:** scout-identity authority (contradicts never-trusting body identity when the ringer is not the scout, and silently drops jumps whenever the scout's own map is closed while viewers watch).
- **Plan — Provenance vocabulary `['jump-verified','human','confirmed','assumed']` on connection identity fields.** D16's weighting rule ("accepting the suggested pick weighs far less than overriding it") is binding as written, so accepting is its own tier: popup **confirm** of an `assumed` resolution records `confirmed`; popup **correct** (choosing a different signature) is an override and records `human`, as does independent card typing; `jump-verified` is reserved for the eliminator's certain outcome. Human-tier values are never overwritten by inference; `jump-verified`, `human`, and `confirmed` emit — each carrying its tier on the observation row — and `assumed` never emits.
- **Plan — Leads-to hint vocabulary (closed buckets)** in `wormhole-contract.ts`: `hisec, lowsec, nullsec, unknown (C1–C3), dangerous (C4–C5), deadly (C6), thera, pochven, drifter`, stored per side (each side's show-info describes the space beyond it); card control only for K162/unidentified connections (D11: no manual field the codex can fill).
- **Plan — Regeneration display:** the codex panel/card renders the regeneration row only when `massRegen > 0` (14 real types); regenerating holes keep the shipped no-estimate rule while the odometer still accrues.

### Interfaces and contracts

- `WORMHOLE_DESTINATION_HINTS` / `WormholeDestinationHint` — closed bucket vocabulary; `hintAdmitsClass(hint, destinationClass): boolean` maps buckets to class sets (unknown → {1,2,3,13} — C13 show-info reads "unknown parts of space", dangerous → {4,5}, deadly → {6}, hisec/lowsec/nullsec → {7}/{8}/{9}, thera → {12}, pochven → {25}) and **fails open**: a destination class no bucket covers (drifter 14–18, future additions) or an unresolvable class admits every hint — the eliminator never falsely eliminates on vocabulary the game does not distinguish. K-space destinations with a null `wormholeClassId` derive hisec/lowsec/nullsec from the `securityStatus` banding (the `systemSecurityClass` sibling classifier); still-unknown → admit.
- `CONNECTION_PROVENANCES = ['jump-verified','human','confirmed','assumed']` — shared by Convex validators, the observation row's tier column, and UI display; `confirmed` is the accepted-suggestion tier D16 weighs below an override.
- `remainingMassAfterTravel(entry, massState, observedMassKg, observedMassAtStateKg): RemainingMassBounds | null` — shipped bounds minus since-anchor travel, clamped ≥ 0; null for regen holes (unchanged rule).
- `matchJump(evidence: JumpEvidence): JumpMatchOutcome` — pure; `evidence` = origin/destination class ids, observed ship mass (nullable), candidate rows (id, typed code, per-side hint, size class), statics codes, codex lookups; outcome = `{ kind: 'resolve'; candidateId; provenance: 'jump-verified' | 'assumed'; survivors: string[] }` or `{ kind: 'insert'; survivors: string[] }`. Survivor ordering and census rule live here and nowhere else.
- `resolveJumpAuthoring` (internal mutation behind the bearer door) — args: server-verified `userId`, map, character, transition (`fromSolarSystemId`, `toSolarSystemId`, `observedAt`), decided outcome + preconditions; authorizes `edit` access for `userId` via the access owner, re-validates preconditions transactionally (origin system live on this map, candidate still unresolved, stamp not yet written, no live duplicate pair, no tombstoned endpoint) and converges instead of failing on races; returns what it did (`authored | converged | stale`) plus emission facts (typed code, typed-side system, observation key) for the route.
- `reassociateJumpDestination` (internal mutation behind the bearer door, same `userId` authorization) — moves a verified destination between rows; vacated row returns to unresolved; provenance updates; ledger row written.
- `upsertUnresolvedHole` (internal fixture mutation) — seeds scanned wormhole rows for tests and the future parser.
- `insertWhObservation(db, row)` — Neon upsert by `dedupeKey`; hour-coarse `observedAt`; schema forbids map/pilot columns by construction.
- `POST /api/maps/jump` — body kinds `doorbell | confirm | typed-hole` (Zod contract); responses `processed | stale | skipped | retry`; the route authenticates the session user server-side, owns Neon reads (adjacency, statics, ship mass), `matchJump`, Convex-door calls, and post-mutation emission.
- Convex HTTP-action doors in `convex/http.ts` (bearer-gated via `bearerMatches`, Zod-validated, `userId` in body): `POST /jump-evidence` → one internal query returning a single-timestamp consistent evidence packet (transition, tracking row, `mapJumpBookkeeping` processed stamp, candidate rows, access verdict) — one query because consecutive stateless reads are documented as not mutually consistent; `POST /resolve-jump` → `ctx.runMutation(internal.mapJump.resolveJumpAuthoring, ...)` with the decided outcome; confirm/re-associate ride the same door. Next-side calls go through a `postProjection`-style helper (`deriveConvexSiteUrl`, `fetchWithTimeout`, typed unavailable error).
- Convex schema push discipline (docs brief): every new `mapConnections`/`mapTracking` field lands as `v.optional(...)` at push time (a bare `v.union(x, v.null())` addition fails validation against live documents); widening the existing `toSystemId` from `v.number()` to `v.union(v.number(), v.null())` is a safe pure widening; `ctx.db.patch(id, { field: undefined })` is the unset idiom, never a null write.
- No existing public export changes signature; `watchMapConnections` narrows semantically (resolved rows only) with its source-contract test updated in the same step.

### Control and data flow

Doorbell path: open map client observes a fresh location transition for a tracked character → `POST /api/maps/jump {kind:'doorbell', mapId, characterId}` → route authenticates the session user (identity is never taken from the body) → bearer-door `POST /jump-evidence` returns one single-timestamp evidence packet (transition + tracking row + processed stamp + candidate rows + edit-access verdict for the server-verified `userId`) → Neon reads: `eveSystemJumps` adjacency (classification), `eveSolarSystems` class ids, `whSystemStatics` (census), `eveTypes.mass` (odometer) → `classifyMovement` verdict gates: only `hole-crossing` with a J-space side proceeds → `matchJump` decides → bearer-door `POST /resolve-jump` runs `internal.mapJump.resolveJumpAuthoring`, which re-validates every precondition transactionally (serializable single mutation; OCC retries converge concurrent doorbells) and performs every Convex write → on `jump-verified` (or later `human`) typed identity, the route upserts the observation row in Neon after the mutation commits. Popup confirm/correct and card typed-hole notifications enter the same route with the same verification discipline. Failure boundaries: any Convex verification miss → `stale`/`skipped`, no writes; Neon unavailable → `retry`, nothing authored, the client observer re-rings on the next location update while the transition stamp is absent (a transition that goes stale before processing degrades to re-anchor semantics — authors nothing, honest); emission failure after a committed mutation → logged, non-fatal, and accepted as bounded loss for that instance unless a later identity event (confirm, re-associate, human typing) fires — each such event re-emits current knowledge through the upsert key, which is the only re-emission actor; the card typed-hole channel's dependence on a second client call after the Convex mutation shares the same accepted-loss bound.

### Edge and failure behavior

- Gate-adjacent k-space transition → `gate-placement` → route skips; nothing authored (SC-2).
- Same-system dock/undock/ship swap → `same-system-state`/`stationary` → skipped.
- First sample, stale continuity, capsule at non-adjacent destination → `re-anchor` → skipped; no invented path.
- Non-adjacent k→k crossing (jump drive, bridge, k-wanderer) → skipped this session (J-space-side rule; recorded for the k-space version).
- Origin system not live on the map (scout roamed past the authored exit, then jumped a wanderer) → lapses, nothing authored — consistent with gate-travel-authors-nothing; the chain never grows from an off-map anchor (route-level fixture).
- Return through a hole whose map system was severed/tombstoned while the scout was away → lapses, nothing authored and nothing auto-restored; restoration stays a human undo decision (mirrors the manual path's `DESTINATION_TOMBSTONED` refusal; route-level fixture).
- Wormhole exit into k-space → destination k-space system authored (the exit node only; HC-1 boundary).
- Return jump through the same hole → converges on the existing connection (both direction pairs checked); odometer increments; observation upsert refreshes, no duplicate row.
- Two scouts, same hole, near-simultaneous → both transitions stamp independently; second converges; odometer counts both crossings.
- Doorbell storm from N viewers → first mutation stamps the transition; the rest return `converged`/`stale`; no duplicate writes.
- All candidates eliminated (evidence conflict: stale paste, mistyped sig) → fresh row, no identity asserted, survivors recorded empty.
- Census short (scanned wormhole rows < statics count) → slot still resolves, provenance `assumed`, no emission.
- Popup dismissed → `assumed` association stands; popup state remains answerable from the connection card later.
- Ringer's session user lacks `edit` on the map → route `skipped`; the scout's own access level never gates authoring (edit-capable-watcher authority).
- No edit-capable client open when a tracked jump lands → transition lapses within the continuity window to re-anchor semantics; nothing authored, nothing invented (accepted capture gap).
- A sever/collapse removes a system carrying live unresolved rows → those rows are stamped into the same shared tombstone set as their anchor (one undoable pathway); a later re-placement of the same system id must not resurrect stale candidates into the match pool (tested).
- `shipTypeId` null (ship fetch failed at sample time) → authoring proceeds; odometer increment skipped.
