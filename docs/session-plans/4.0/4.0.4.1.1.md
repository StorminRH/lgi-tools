## Bottom line (READ FIRST)

- **GOAL:** A blank map is hand-authorable from one root — home selection,
  add-from-node, and live connection detail editing — through gated,
  field-scoped, equality-skipping, optimistic mutations, with reversible
  tombstone/restore foundations that 4.0.4.1.2's collapse pathway reuses
  unchanged.
- **DONE =** SC-1 through SC-7 below: an editor authors home/adds/edits
  live across two clients, a viewer can neither see nor use any mutation
  affordance, tombstone/restore round-trips identical state, and no
  destructive connection surface exists anywhere.
- **OUT OF SCOPE:**

    countdown/estimates, and mass presentation — all owned by 4.0.4.1.2,

    map-event audit log (future, see End of session notes).

## Why now

The read path, deterministic layout, motion, and window framework shipped
through 4.0.3.3, but no production mutation exists — a map can only be seeded
by admin fixtures. This session turns the read-only canvas into an authorable
map and establishes the gated, field-scoped, reversible mutation foundations
that every later writer — 4.0.4.1.2's collapse pathway, 4.0.4.2's auto-mapper,
4.0.4.3's signature flows — builds on, unlocking the master plan's "living
chain" phase.

## Scope (the destination)

A signed-in **editor** opening an empty map sees exactly one centered prompt —
"Set your home system" — with two options: a system search (the shared
platform system search, the same one the industry planner's location slots
use) and a visible-but-disabled "Use current system" option annotated as
requiring live tracking (4.0.4.2). Picking a system creates the map's first
system; the layout derives it as the root by creation order. A **viewer**
opening the same blank map sees only the empty canvas.

Right-clicking any node opens a menu bound to that node with "Add
connection…": a system search whose selection writes the destination system
and its connection **in one Convex transaction**, so the reveal is whole on
every client (no "nowhere, then hop"). Loops back to systems already on the
map are legitimate and simply insert the connection.

Clicking a connection line opens a small details card anchored to that line
(following it through pan/zoom/drag, via the shipped window primitive and an
edge-midpoint extension of the follower model). The card holds the
human-authored facts: wormhole type (search scoped to the wormhole-type codex,
K162 included), size (S/M/L/XL), stability (unset until observed, then
stable/reduced/critical), and life stage (the four current in-game Reliable
Lifetime buckets). Every pick saves immediately as its own field-scoped
mutation — optimistic locally, equality-skipping, fanning out to every
subscriber. No codex-derived auto-fill, no estimates, no EOL math renders this
session (4.0.4.1.2 owns that intelligence, on this same card); the codex is
used only as the type search's vocabulary.

The access subscription answers `{ granted, canEdit }` from the same claim
row; every authoring affordance renders only for `canEdit`. A live rights
change unmounts affordances immediately and shows one quiet toast; a rejected
in-flight mutation relies on Convex's automatic optimistic rollback with no
bespoke feedback (operator-directed).

Systems and connections gain reversible tombstones (fields, mutations,
bounded cleanup, live-row filtering) with a 24-hour undo window — plumbing
and tests only, no UI. Contract §§3–6 are satisfied without widening: every
done condition maps to SC rows below, both in-scope items land as described,
out-of-scope items are protected by inspection-backed criteria, and all three
hard constraints are enforced server-side, not just visually.

## Resolved implementation decisions

- **Contract PD-1 — field mutation granularity and optimistic rejection: one
  named mutation per editable field, optimistic through the existing merge
  pipeline, edge identity preserved.** Mutations: `setHomeSystem`,
  `addSystemFromNode`, `setConnectionWormholeType`, `setConnectionShipSize`,
  `setConnectionMassState`, `setConnectionLifeStage`, and the tombstone/restore
  pairs. Each is gated first (`requireMapAccess(ctx, mapId, 'edit')`),
  validates with the shared validators, and equality-skips before patching.
  Client-side, each uses `useMutation(...).withOptimisticUpdate(...)` against
  the paginated chain subscriptions and the access value (current API
  confirmed for convex 1.42.3: `OptimisticLocalStore` get/set, official
  paginated helpers, automatic rollback when the mutation completes or
  fails). Optimistic rows enter the same `chainSignature → layout → merge`
  pipeline as server rows, so rejection reconciliation is by construction:
  rollback changes the signature and the next merge removes the node/edge.
  Edge identity stays `connectionId` (`_id`) — it is load-bearing for the
  shipped intent/motion vocabulary (`connection-appeared`/`-departed`,
  ghost capture) and endpoint pairs are not unique (parallel connections are
  legitimate). The optimistic temp-id → confirmed-id swap is reconciled at
  the merge: a departure and appearance in the same merge sharing endpoints
  is treated as an identity swap — the edge id updates in place and no
  intent pair is emitted, so nothing blinks and motion surfaces stay
  untouched. (A concurrent parallel add by another client inside that same
  merge window could match the swap to the wrong twin; the consequence is
  one suppressed birth animation, accepted as cosmetic and rare.)
  **Rejected:** one generic `updateConnection(fields)` mutation — a wide
  argument surface that invites multi-field clobbering, weakens per-field
  validation, and couples concurrent editors' write sets. **Rejected:**
  re-keying edges by endpoint pair — breaks edge uniqueness under parallel
  connections and silently kills the 4.0.3.2 motion layer's id-keyed
  birth/exit animations. **Rejected:** no optimistic layer — the contract
  explicitly requires optimistic-local behavior with rejection
  reconciliation.
- **Contract PD-2 — home and add-from-node composition: canvas overlay +
  node-bound context menu + edge-anchored card on the shipped primitives.**
  Home prompt renders as a centered overlay from the chain host when
  `canEdit && systems complete && zero live systems`; both options render,
  "Use current system" disabled with its tracking annotation until 4.0.4.2.
  Add-from-node hangs off React Flow's node context-menu event, presents the
  Base UI menu wrapper at the pointer, then the shared system search. The
  connection details card mounts through the `MapWindow` primitive anchored
  to the edge midpoint via an edge extension of `follower-model.ts` (node-pair
  anchor; same CSSOM transform approach). Viewers get none of these
  affordances (`canEdit` false), and the server gate holds regardless.
  Composition note recorded for 4.0.4.1.2: its contract reserved
  "edge-anchored editing composition" as its PD-1; this session pulls that
  composition forward by operator direction, and .2 enriches this card rather
  than re-deciding its shape. **Rejected:** a separate dialog/page for
  connection details — breaks the map-native interaction the sub-version is
  built around. **Rejected:** a new local prefix search over the universe
  directory — the platform search engine with the `systems` source already
  owns exactly this ("one search path", 3.7.13.2), and the operator directed
  reuse.
- **Contract PD-3 — tombstone contract 4.0.4.1.2 uses without migration:
  mirror `mapSignatures`, optional-with-normalization fields, hook-level
  filtering upstream of the content signature, 24-hour window, indexed
  liveness proof.** `mapSystems` and `mapConnections` gain
  `deletedAt`/`purgeAfter` declared `v.optional(v.union(v.number(), v.null()))`
  — optional because existing rows (live demo maps) predate the fields and
  Convex validates existing documents at schema push, so a required field
  cannot land before a backfill that cannot run first; one shared predicate
  (`isTombstoned`, owned in `src/data/maps/chain-contract.ts`) normalizes
  `undefined` to active so the optionality never leaks past its single owner.
  Tombstone = stamp both fields (`purgeAfter = deletedAt +
  MAP_CHAIN_UNDO_WINDOW_MS`, 24h, same owner); restore = clear both on the
  same document (identity preserved); repeated tombstone/restore of an
  already-target-state row writes nothing (watched-table no-op discipline).
  New `by_purge_after` indexes and a bounded expiry cleanup mirror
  `mapSignatureCleanup` (cap + look-ahead; active null/undefined rows can
  never enter the range). `mapConnections` also gains `by_map_from` and
  `by_map_to` indexes so "does any live connection still reference this
  system?" is two exact indexed per-system lookups with a small fail-closed
  cap — the production negative proof `tombstoneSystem` and .2's collapse
  both use (the map-wide 128-row fixture scan stays a dev seam). The read
  path is untouched server-side: tombstoned rows still flow (the payload must
  survive for restore, and .2's undo UI needs the rows client-side). The
  chain hook filters live rows **upstream of `chainSignature`** — the
  signature fingerprints only ids and completeness, so the filtered row set
  must change for a tombstone patch to trigger the merge that removes the
  row; filtering anywhere downstream would leave a ghost on canvas until an
  unrelated change. Root derivation therefore only ever sees live systems:
  tombstoning the root re-roots to the next-oldest live system on every
  client identically, and restore re-roots back (creation order preserved by
  identity-preserving restore). 4.0.4.1.2's collapse consumes this contract
  with no migration: a collapse is tombstone-connection +
  tombstone-orphaned-system in one transaction. **Rejected:** hard delete
  with an audit copy — breaks document-ID links (notes today, signature links
  in 4.0.4.3) and re-roots the layout through creation-order loss.
  **Rejected:** server-side filtering — hides rows .2's undo UI needs and
  adds a second read shape to the pinned one-read chain handler.
- **Consequential — shared vocabularies live in `src/data`:** the mapper zone
  imports `data` and never `convex/` (Fallow), so every vocabulary both the
  card UI and the Convex validators need is data-owned:
  `CONNECTION_MASS_STATES` moves from `convex/lib/mapEntityContracts.ts` to
  `src/data/eve-data/wormhole-contract.ts` (joining the size classes it
  already owns), and the new `WORMHOLE_LIFE_STAGES` vocabulary lands there
  too. `mapEntityContracts` keeps its validators, re-bound to the data-owned
  vocabularies with the existing `satisfies` drift guards. The tombstone
  predicate and undo window live in the new pure
  `src/data/maps/chain-contract.ts`.
- **Consequential — mass state gains an unset value:** `massState` widens to
  `stable | reduced | critical | null` (schema, validator, and
  `ConnectionInput`), because stability is a human observation and a freshly
  added connection has none yet — the card must not fabricate "stable". A
  null mass state is honest input to .2's estimate model (no clamp basis).
  Existing rows all carry explicit values, so no data migration is needed.
- **Consequential — access answer widened:** `watchMapAccess` returns
  `{ granted, canEdit }` computed from the same single claim row
  (`rolesAllow(roles, 'edit')`); read set unchanged, so live revocation
  semantics are identical. The client surfaces a quiet toast on a rights
  *transition* (using the existing sonner wrapper) and unmounts affordances;
  no per-mutation rejection feedback exists (operator-directed).
- **Consequential — life stage fields:** `mapConnections` gains `lifeStage`
  (union of four literals matching the current in-game Reliable Lifetime
  buckets — less than 1 day / less than 4 hours / less than 1 hour / expired —
  plus null-unset; vocabulary confirmed against the Version 23.02 patch notes
  and current show-info wording) and `lifeStageObservedAt` (server-stamped at
  set time, so 4.0.4.1.2 can compute bounded remaining-life estimates without
  migration). Both optional-with-normalization like the tombstone fields.

### Interfaces and contracts

- `watchMapAccess(mapId) → { granted: boolean; canEdit: boolean }` — same
  single claim-row read set; `canEdit = rolesAllow(roles, 'edit')`; answers
  `{ granted: false, canEdit: false }` for identity-less callers.
- `setHomeSystem({ mapId, systemId })` — gate `edit`; refuses when any live
  system exists (`MAP_NOT_EMPTY`) or `systemId` invalid; inserts the first
  system; OCC converges the two-editor race to one winner and one refusal.
- `addSystemFromNode({ mapId, fromSystemId, toSystemId })` — gate `edit`;
  refuses when the origin is not a live system on the map
  (`UNKNOWN_ORIGIN`), when ids are invalid or equal (`SELF_LOOP`), or when
  the destination exists but is tombstoned (`DESTINATION_TOMBSTONED` —
  restore is the sanctioned path back); upserts the destination system and
  inserts the connection in one transaction with `wormholeTypeCode: null`,
  `massState: null`, `shipSize: null`, `eolAt: null`, `lifeStage: null`,
  `lifeStageObservedAt: null`; returns both ids.
- `setConnectionWormholeType / setConnectionShipSize / setConnectionMassState
  / setConnectionLifeStage ({ mapId, connectionId, value })` — gate `edit`;
  connection must belong to the map and be live; value validated by the
  owning validator; equality-skip (no write, no fan-out) when unchanged;
  `setConnectionLifeStage` also stamps `lifeStageObservedAt` from server time
  (skipped entirely when the stage is unchanged).
- `tombstoneSystem({ mapId, systemId })` — gate `edit`; refuses while any
  live connection references the system, proven by two exact indexed
  per-system lookups (`by_map_from`, `by_map_to`) reading up to a small
  fail-closed cap of rows each and filtering live; stamps
  `deletedAt = now`, `purgeAfter = now + MAP_CHAIN_UNDO_WINDOW_MS`;
  idempotent.
- `tombstoneConnection({ mapId, connectionId })` — gate `edit`; same stamps;
  idempotent.
- `restoreSystem / restoreConnection ({ mapId, id })` — gate `edit`; clears
  both stamps on the same document; restoring a connection refuses when an
  endpoint system is tombstoned (`ENDPOINT_TOMBSTONED`); idempotent.
- `purgeExpiredChainTombstones` — internal, bounded batch over
  `by_purge_after`, reporting `hasMore`; never touches active
  (null/undefined) rows.
- `src/data/maps/chain-contract.ts` — `MAP_CHAIN_UNDO_WINDOW_MS`
  (24 hours) and `isTombstoned(row): boolean`, the single owner of
  undefined/null normalization; consumed by `mapEntityContracts`,
  `mapAuthoring`, the cleanup owner, and the chain hook.
- `src/data/eve-data/wormhole-contract.ts` — `CONNECTION_MASS_STATES`
  (`stable | reduced | critical`) and `WORMHOLE_LIFE_STAGES` (the four

  CSSOM discipline as the node follower.

### Control and data flow

An edit pick flows: dropdown/search selection → mutation call with
`withOptimisticUpdate` (local store patches the exact paginated pages /
access value) → live-row filter → `chainSignature` changes → worker layout
(if topology changed) → `reconcileChain` merge → canvas. Server-side, the
mutation runs gate → ownership/liveness validation → equality check →
patch/insert → Convex fans out to every subscriber's affected read sets; the
confirmed rows replace the optimistic layer when the mutation completes, and
the same-merge endpoint-matched swap rule updates the edge id in place with
no intents. On rejection (FORBIDDEN or validation), Convex rolls the
optimistic layer back automatically; the filtered row set reverts and the
next merge removes any optimistic node/edge — the same departure path as a
real removal. A tombstone patch changes the filtered row set (not just a
field), which is exactly what lets it trigger the removal merge. An access
change re-runs `watchMapAccess` (its read set is the claim row), flipping
`granted`/`canEdit` live: affordances unmount, the transition toast fires
once, and the calm no-access state continues to own full revocation.

### Edge and failure behavior

- Two editors race `setHomeSystem` on an empty map → OCC re-runs the loser
  against the winner's row; loser receives `MAP_NOT_EMPTY`; its optimistic
  root rolls back; one root exists.
- `addSystemFromNode` with a tombstoned or absent origin → `UNKNOWN_ORIGIN`
  refusal; optimistic rollback; nothing written.
- Add targeting a system already live on the map (loop closure) → destination
  upsert converges on the existing document; the connection inserts; the
  canvas draws it as a loop edge (dashed), never a second node.
- Add targeting a tombstoned destination → `DESTINATION_TOMBSTONED` refusal
  (an add must not silently resurrect a removed system).
- Repeated tombstone / restore to an already-current state → no write, no
  fan-out.
- Tombstoning the root system → hook filtering re-roots the layout to the
  next-oldest live system on every client identically; restore re-roots back.
- Optimistic temp-id connection confirmed → same-merge endpoint-matched swap:
  edge id updates in place, no departure/appearance intents, no blink; a
  concurrent same-endpoints parallel add in the same merge may suppress one
  birth animation (accepted, cosmetic).
- System-search index unavailable → pickers degrade exactly as the planner's
  do (empty suggestions until the memoized loader heals); no error state; the
  wormhole-type search reads the session codex with the same null-degradation.
- Rights revoked mid-session → affordances unmount from the live value; an
  in-flight mutation rejects server-side and rolls back silently; one
  transition toast.
- Convex backend restart mid-edit → existing reconnection behavior holds
  (proven in 4.0.2.3.1); unconfirmed optimistic state resolves with the
  reconnected subscription truth.
