## Why now

The layout engine (4.0.3.1) computes deterministic targets and the reconciler
(4.0.2.3) announces every arrival, departure, and forced move — but today the
canvas teleports: births pop, shifts snap, and the camera jumps. Motion is how
the map communicates change (decision D8), and it is the last presentation
layer the overlay framework (4.0.3.3) and auto-mapping (4.0.4.2, whose fog
reveals will arrive as bursts of ordinary arrivals) build on. The inputs are
live in production for the first time, so the tuning loop tunes against real
behavior.

## Scope (the destination)

When this session ends, the Atlas map at `/atlas` behaves as follows. A system
arriving on initial load or live insertion surfaces in place at its
kernel-computed position: it starts slightly small, dim, and soft — softness
being exactly the low-opacity, sub-scale start state, never a blur — scales
through a small overshoot, and settles sharp, with zero positional travel. A
forced layout shift (kernel reposition, re-lock snap-home) glides each moved
node from the intent's `from` position to its `to` target along the spring
family, with every edge tracking its endpoints frame-by-frame because the
rendered nodes and edges derive from one state in one commit. A departing
system plays a brief exit (its heavier chain-collapse variant is a tuning
dial) and its edges either fade with it or shrink toward the parent (a flavor
dial that preserves the loop-closure dash semantics — dashed loop edges always
take the fade flavor so the tree/loop distinction never lies mid-animation).
Hover produces a glow and a subtle breathing on the hovered node only; the map
is otherwise completely still, with the animation loop unregistered at rest.
The camera always eases: initial-frame and follow fits gain slow-tier duration
and easing with their bounds computed from reconciled kernel targets (never
from mid-glide displaced positions), a drag start aborts any in-flight camera
transition, a newer fit or focus supersedes an older one, and a new
click-to-focus setting — its own toggle beside camera follow, default chosen
at the gate, kept as a user option either way — eases the camera to a clicked
system at the current zoom (explicitly overriding the library's max-zoom
default). A node under the user's own drag renders raw pointer positions with
every transition suppressed. A reduced-motion preference collapses position
changes to instant placement and scale/opacity vocabulary to gentle fades, and
zeroes camera duration. Drag-performance hardening lands as the measured light
fix: memoized node and edge components and containment of the per-frame
re-render cascade, tuned for the operator-set realistic ceiling of 50–60
nodes. The tempo tiers, overshoot, and flavor dials join the existing tuning
panel, and the operator's replay-driven sign-off ratifies the shipped
defaults.

Contract §3 is satisfied by the behaviors above; §4's six in-scope items map
below; §5's exclusions stay untouched by design (no window/overlay animation,
no layout influence, no sound, no dependency, no reconciler change); §6's
constraints are carried in the hard-constraints block.

## Resolved implementation decisions

- **Contract PD-1 — production-like performance evidence: dev-mode frame-time
  series in-session, production feel-check after merge (operator ruling
  2026-08-02).** React dev mode carries strictly more per-frame overhead than
  the production build, so dev-mode measurement that holds frame rate is a
  pessimistic bound on production. Evidence is numeric: in-page
  requestAnimationFrame timestamp deltas collected over the drag and glide
  windows on a replayed 50–60 node chain, reported as p50/p95 frame times
  against stated thresholds with a required non-zero sample count;
  long-animation-frame entries are a supplementary signal only (their 50 ms
  threshold alone proves too little). The map on production sits behind the
  admin wall, so the operator confirms feel there informally after merge, and
  any surprise is ordinary out-of-bound bugfix work riding a later session.
  **Rejected:** a Vercel preview deployment — EVE SSO cannot complete on
  preview hosts (callback registration requires a stable pre-registered
  address; previews get per-deploy addresses), and building that
  infrastructure is not worth this session's evidence; a local production
  build — forbidden by repository rule; long-animation-frame absence as the
  primary observable — a 28 fps cascade produces zero such entries.
- **Contract PD-2 — tween scheduler design: one pure model, one thin
  requestAnimationFrame host, one position authority.** `ChainHost`'s
  controlled nodes state remains reconciled truth with its two existing
  writers (`syncNodes` on merge, `applyNodeChanges` on drag) — `syncNodes`'
  drag-only hold rule and membership semantics are unchanged. `tween-model.ts`
  owns tween bookkeeping as pure data: origins taken from each
  `system-moved` intent's `from` field (so a merge that has already committed
  the target into truth cannot zero the glide), retarget-from-current on
  supersession, cancel-on-drag, time-based progress so hidden-tab resume
  completes correctly, ghost lifetimes, and idle detection. `use-motion.ts`
  owns the single requestAnimationFrame loop for all movers and the motion
  state (displacement map, entering flags, ghosts); each frame it advances
  displacement and the presentation derivation recomputes in the same commit:
  rendered nodes and edges are derived from truth plus displacement plus
  ghosts, with identity preservation — a node with no displacement or flag
  passes through as the same object reference, so React Flow's equality
  checks and the memoized wrappers keep reconciliation proportional to actual
  movers. `ChainSurface` renders only the derived arrays. Frame budget:
  per-frame arithmetic is linear in movers (~60 at the operator's ceiling —
  microseconds); the real cost is the React commit, which the identity
  discipline bounds to changed nodes; the frame-time series proves the budget
  and the contract's split trigger is not expected to fire. **Rejected:**
  the scheduler writing displaced positions into `ChainHost`'s nodes state —
  that array is reconciled truth with two writers already, and a third
  per-frame writer either snaps glides on every merge (`syncNodes` holds only
  dragged ids) or forces a second commit per frame; React Flow's
  `useReactFlow().setNodes` per frame — its batch queue diffs every node per
  flush; CSS transitions on node position — forbidden by the first hard
  constraint because edges would desynchronize.
- **Contract PD-3 — chain-collapse departure weight: shipped as the
  `collapseWeight` dial, decided at the gate.** The scheduler distinguishes a
  departure batch that removes a connected subtree (collapse) from a single
  removal; the dial selects whether collapse plays the heavier exit. The
  operator decides the default from feel during the tuning loop, per the
  contract's own deferral. **Rejected:** fixing the answer at planning time —
  the contract explicitly reserves this for the tuning loop.
- **Contract PD-4 — edge departure flavor: shipped as the `edgeFlavor` dial
  (`fade-with-child` or `grow-from-parent` for arrivals and the mirrored
  shrink for departures), decided at the gate.** The grow/shrink presentation
  drives `stroke-dashoffset` over a `pathLength`-normalized path and applies
  only to solid tree edges; dashed loop-closure edges always take the fade
  flavor, preserving the dash channel's structural meaning (`LOOP_DASH_CLASS`
  owns it). **Rejected:** picking one flavor now — the contract makes this a
  tuning dial; animating dash properties on loop edges — the one visual
  distinction between structure and shortcut must never lie mid-animation.
- **Contract PD-5 — duration tiers: fast 200 ms, mid 600 ms, slow 1000 ms as
  the starting dial values around the contract's fixed ~600 ms middle
  anchor.** Fast drives hover/micro feedback, mid drives births, exits, and
  position glides, slow drives camera moves. All three are dials with
  clamped ranges in `motion-controls-model.ts`; the gate ratifies the final
  defaults into `DEFAULT_MOTION_CONFIG` exactly as 4.0.3.1.2 ratified the
  layout dials. **Rejected:** a single duration for everything — the
  contract fixes three tiers; unbounded dial ranges — every dial commit
  routes through a tested clamp per the panel's established pattern.
- **Camera focus (consequential choice settled with the operator
  2026-08-02): click-to-focus ships this session as a user setting.**
  Clicking a node eases the camera to center it: `setCenter` with slow-tier
  duration, the family's no-overshoot variant, and the current viewport zoom
  passed explicitly — the installed library defaults to `maxZoom` when the
  zoom option is omitted, which would read as a lunge. `focusOnClick` is its
  own `ChainHost` state with a prop pair beside the camera-follow switch in
  the always-visible control group — deliberately not a `MotionConfig` field,
  because the dial group is the operator tuning surface that a later
  wall-removal session may re-gate (4.0.3.1.2 handoff), while this is a
  shipped user setting; it is also a boolean with no clamp semantics. The
  operator picks the default at the gate and the setting remains available
  to users regardless. Focus is additive to selection semantics — it never
  swallows or alters the click's selection behavior that 4.0.3.3 will build
  on. **Rejected:** easing only the existing fits and leaving focus to a
  later slice — the acceptance wording covers focus, and feel cannot be
  judged without building it; `focusOnClick` inside `MotionConfig` — two
  owners and two panel homes for one user decision.
- **Camera transition lifecycle (new consequence of leaving zero-duration
  snaps): a drag start aborts any in-flight fit or focus, and a newer fit or
  focus supersedes an older one.** Today's `duration: 0` fits complete
  instantly, so no in-flight camera move has ever coexisted with a drag; the
  eased camera creates that overlap (click-to-focus, then grab the same node
  200 ms later — the viewport must not keep panning under a live drag). The
  rule lives in `camera-follow-model.ts` where fit policy already lives, and
  fit bounds are computed from reconciled kernel targets (`state.systems`)
  rather than rendered positions, so the initial framing during a mass glide
  frames the settled chain, not a mid-tween scatter. **Rejected:** letting
  in-flight transitions run out — it recreates exactly the camera-moves-on-
  its-own behavior the operator's follow-off ruling exists to prevent.
- **Realistic performance ceiling (operator ruling 2026-08-02): optimize and
  evidence at 50–60 nodes.** A realistic large chain is ~10 systems; 50–60
  nodes is deliberate headroom, and the future fog halo (4.0.4.2) caps drawn
  k-space nodes by construction, so no 200-node design case exists.
  **Rejected:** designing for hundreds of nodes — not a real user scenario,
  and it would push toward the heavy restructure this session deliberately
  defers.
- **The tuning loop runs on replayed chains (operator ruling 2026-08-02,
  matching 4.0.3.1.2 precedent).** Live location tracking does not exist
  until 4.0.4.2, so "live mapping" for this gate means `pnpm map:replay`
  drawing paced corpus chains into a real local map while the operator
  watches and tunes. **Rejected:** literal in-game mapping — hours of
  scanning per run makes iteration unrealistic, and the machinery it would
  exercise is not built yet.
- **Departure rendering: the motion derivation keeps brief ghosts.** A
  departed system (and its edges, per flavor) stays in the presentation
  arrays flagged `departing`, non-interactive, for exactly one exit duration
  on the scheduler's clock, then drops — removal is clock-scheduled, never
  dependent on `animationend` delivery. A ghost is dropped immediately if its
  id re-appears in truth (supersession), and the motion state resets when
  map access flips to false, so no ghost set animates behind the calm
  no-access panel and none survives a re-grant. **Rejected:** instant removal
  (the contract's departure presentation requires an exit);
  DOM-event-driven cleanup (a missed event would leak ghosts); letting
  revocation's full-map departure batch play as ghosts — the calm state must
  be still.

### Interfaces and contracts

- `MotionConfig` (exported from `motion-contract.ts`) —
  `{ tempo: { fast: number; mid: number; slow: number }; overshootPct: number; edgeFlavor: 'fade-with-child' | 'grow-from-parent'; collapseWeight: 'ordinary' | 'heavy' }`;
  durations in ms, overshoot an integer percent (the shared Stepper is
  integer-only by contract); all values clamped by `motion-controls-model.ts`
  commits; consumed by the scheduler, the stylesheet bridge, and the camera.
  `focusOnClick` is deliberately not a member.
- `springFamily(overshootPct)` (from `motion-contract.ts`) — returns the
  easing as both `(t: number) => number` and a CSS `linear()` stop-list
  string sampled from the same function; a unit test pins JS/CSS agreement at
  the sample points; the no-overshoot variant serves the camera.
- `tween-model.ts` exports pure functions over an opaque `MotionState`
  (create, `adoptIntents(state, intents, now, config)` reading each move's
  `from`/`to` from the intent itself, `step(state, now)` returning displaced
  positions plus done-ness, `cancelForDrag(state, ids)`, ghost supersession
  on re-appearing ids); no DOM, no React, no clock reads — timestamps are
  arguments.
- `useMotion(truth, merge, access, config, seams)` (from `use-motion.ts`) —
  `truth` is `ChainHost`'s current `{ nodes, edges }` (reconciled positions
  plus raw drag positions); `access` is the live boolean the read path
  already answers; returns the derived presentation `{ nodes, edges }` that
  `ChainSurface` renders. Contract: consumes each distinct `merge.intents`
  array exactly once by identity; empty or repeated arrays cause no
  scheduling; dragging nodes (read through the ref-backed seam) pass through
  untouched; nodes with no displacement or flag keep their input object
  reference; while any tween, ghost, or entering window is active it drives
  re-render through state it owns; when idle it holds no frame callback;
  resets wholly when `access` is false.
- `camera-follow-model.ts` — fit plans gain `{ duration, ease }` from the
  slow tier and compute bounds from reconciled `state.systems` positions
  (plus disc radius padding), never from rendered arrays; new pure rules:
  a drag start aborts the in-flight transition, a newer fit/focus supersedes
  an older one; new pure `decideFocus(click, enabled, dragging)` returning a
  center action carrying the current zoom or nothing. Callers
  (`use-camera-follow.ts`, `ChainHost`) pass results to
  `fitBounds`/`setCenter` (both accept `{ duration, ease }` and return
  promises in React Flow 12.11.2).
- No production export changes outside `src/mapper/**`; `src/mapper/index.ts`
  is unchanged (the route consumes `MapCanvas` as today).

### Control and data flow

Convex subscriptions → `useMapChain` merge (`{ state, intents }`) →
`ChainHost` keeps its truth pipeline exactly as today (`syncNodes` on merge,
`applyNodeChanges` on drag) and hands truth, merge, and `MotionConfig` to
`useMotion`. On a new intents array (identity check, the `decideCameraFit`
discipline): `system-appeared` marks entering ids (birth presentation at the
final kernel position — never a positional tween); `system-moved` enqueues or
retargets a tween using the intent's own `from`/`to`;
`system-departed`/`connection-departed` create clock-bounded ghosts;
connection arrivals take the flavor presentation. The requestAnimationFrame
loop steps the pure model with the frame timestamp; the presentation
derivation recomputes in the same commit, overlaying displacement on movers,
appending ghosts, and passing every other node through by reference; React
Flow re-renders exactly the changed nodes, and each `ChainLinkEdge`
recomputes from the same rendered state in the same commit — edges cannot
desynchronize because there is no second position channel. Drag events flow
unchanged into truth; drag start cancels that node's tween and aborts any
in-flight camera transition; drag stop still emits an empty intent batch
(pin), and the snap-home moves arrive one merge later as ordinary
`system-moved`. Camera: fit bounds derive from reconciled targets; fit and
focus ease through the viewport API; reduced motion zeroes their duration.
Failure boundaries are unchanged — worker death, access loss, and reconnect
all resolve upstream of the merge; on access loss the motion state resets
(no ghost storm behind the calm panel), and motion holds no state that
outlives its map (`ChainHost` remounts per map key).

### Edge and failure behavior

- Initial load (or a future fog reveal) delivering many arrivals at once →
  every node surfaces in place simultaneously; no positional tweens are
  created, so the frame budget is untouched; the birth window is one mid-tier
  duration.
- A `system-moved` intent for a node already mid-tween → retarget from the
  tween's current displaced value to the new `to` (no jump, no
  restart-from-origin).
- A merge commits new reconciled positions mid-glide (the tuning loop's dial
  commits do this constantly) → truth updates in that commit, but the
  presentation derivation still overlays the active tweens' displaced
  positions in the same commit, so no teleport-and-return frame can paint;
  the accompanying `system-moved` batch retargets the tweens.
- Drag starts on a tweening node → that tween is cancelled the same frame and
  any in-flight camera transition is aborted; the node renders raw pointer
  positions; on drop, the pin's empty intent batch schedules nothing, and any
  later kernel move animates from the intent's `from`.
- Reduced-motion preference (live toggle included) → `step` resolves every
  tween to its target immediately, births and exits render as opacity-only
  fades via the media-query gates, camera calls receive duration 0; the
  predicate is read through the injected seam so tests drive both values.
- Tab hidden through a glide → progress is computed from timestamps, so the
  first resumed frame completes or advances tweens correctly; ghosts expire
  by the same clock.
- A departure batch that removes the map's whole visible subtree (chain
  collapse via replay `--loop`) → ghosts play the dial-selected exit; the
  scheduler drains and the loop unregisters (proven idle afterward).
- A departed id re-appears while its ghost is still playing → the ghost is
  dropped in the same derivation that admits the arrival (supersession); one
  id never renders twice.
- Access revocation (the read path serves an empty complete snapshot, so the
  reconciler emits a full-map departure batch) → the motion state resets
  instead of playing ghosts behind the calm no-access panel; a re-grant
  starts clean with ordinary arrivals.
- Worker-death fallback layouts and map switch → motion consumes whatever
  merge arrives; no tween or ghost survives a remount; the host's effect
  teardown cancels its frame callback.
