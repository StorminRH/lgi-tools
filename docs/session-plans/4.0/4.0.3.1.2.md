## Why now

The kernel exists and is fully proven, but the live map still parks systems on
the provisional grid — the sub-version's product outcome (every client drawing
the same compass tree) is unrealized, and 4.0.3.2's motion layer binds to
`system-moved` intents that today never fire in production. This session wires
the proven kernel into the live canvas, closes the recorded cross-engine
determinism residual before the first live client depends on it, and completes
sub-version 4.0.3.1 with the operator-tuned defaults and the single PR the
master plan requires.

## Scope (the destination)

When this session ends, opening `/atlas?map=<id>` mounts one web worker that
owns every layout computation for that map. Each chain update flows: Convex
snapshot → creation-ordered `LayoutFacts` → worker → positions → one reconciled
merge — so a system appears exactly once, already in its computed place, and
the main thread never runs kernel geometry. The provisional grid is gone;
identical clients draw byte-identical pictures on any browser engine because
the kernel's transcendental math is now in-house and deterministic.

The map is locked by default: nodes cannot be dragged. An unlock control turns
free drag on; every hand placement is local presentation only. Re-locking
clears all hand placements and the next layout pass snaps nodes back to
computed positions. A camera-follow toggle (local, default on, revisited at the
gate) refits the viewport with zero duration when nodes appear or move. A
tuning panel on the canvas exposes the ring, sector, sibling, and direction
dials; changing a dial re-runs layout live for this client only. After the
operator signs off, the chosen values are baked into `DEFAULT_LAYOUT_CONFIG`
(with the determinism fixture regenerated) so every client ships the tuned
feel; the panel remains as a tuning tool whose only wall today is the map
route's own admin gate — whichever future session removes the atlas
development wall owns re-gating or removing the dial group.

A paced replay tool feeds a generated corpus chain into the dev map through the
existing access-gated fixture surface, one event at a time at watching speed,
standing in for real mapping until 4.0.4.2 ships tracking. Contract §§3–6 are
satisfied without widening: no motion, no location data, no synchronized
presentation, and the seam remains the only position authority.

## Resolved implementation decisions

- **Contract PD-1 — Worker mounting, cancellation, and stale results:
  layout-then-merge with a posted-key guard and request-id staleness.** The
  worker mounts once per live map (composed inside `useMapChain`, which calls
  `useLayoutKernel` itself), via the documented
  `new Worker(new URL(...), import.meta.url)` Turbopack pattern, and terminates
  on unmount. The merge pipeline becomes async: when the posted key
  (`chainSignature` plus the layout revision) changes, derive `LayoutFacts`
  from the snapshot's server-ordered rows and post to the worker with a
  monotonic request id; apply `reconcileChain` only when that request's
  positions return — a few milliseconds, below perception (operator-selected:
  nothing ever appears at a wrong position first). The posted key advances
  eagerly at post time (exactly as today's guard does), so re-renders with
  fresh-but-equal subscription objects — including every pointer move of an
  active drag — never cancel or repost in-flight work; staleness is decided by
  comparing a reply's request id against the latest posted id, never by effect
  cleanup identity; and a request that terminates without applying (kernel
  rejection or fallback failure) resets the posted key so the next change
  retries. The drag-protection set is read from the existing ref at apply
  time, not captured in the posting closure, so protection can never go stale
  across the async window. Worker degradation has two named paths: a
  construction throw falls back immediately, and a post-construction failure
  (`error`/`messageerror` events — a chunk that fails to load or evaluate
  never rejects the constructor) logs once, marks the worker dead, and settles
  the outstanding and all subsequent requests through the same in-process
  `compassKernel` seam — identical deterministic output either way, so the
  map can never sit silently empty behind a healthy subscription.
  **Rejected:** merge-immediately-reposition-later (flashes arrivals at the
  origin before the worker answers — the exact first-appearance artifact the
  operator declined), effect-cleanup cancellation (fresh subscription object
  identities re-run the effect every render, so cleanup would cancel work
  nothing superseded and starve merges during a drag), and a persistent
  request queue (the kernel computes ~1 ms per 60-system chain; queueing is
  complexity with no observable win).
- **Contract PD-2 — Dial ranges and the operator-review fixture: clamped
  ranges over the ratified defaults, plus a paced corpus replay.** Dials and
  ranges: ring spacing 140–480 step 10 (default 240); minimum separation
  80–240 step 10 (default 140), committed values clamped to keep the standing
  invariant ring spacing ≥ separation; sibling fan 1–6 step 1 (default 3);
  wedge posture segmented `fixed-slot`/`proportional` (default fixed-slot);
  direction order as preset constants (compass-8 default, cardinal-4,
  diagonals-first-8, rotated-45) rather than a free-form array. The review
  fixture is `scripts/map-replay.ts`: it seeds a Neon map owned by the
  operator (claim derived by the existing access projection), then replays a
  proof-kit corpus timeline into the dev Convex deployment through the
  internal fixture mutations at a paced interval (`--interval-ms`, default
  1500, operator-adjustable) with fixed connection metadata defaults, one
  event at a time (serial await-then-delay, preserving system-before-connection
  order). It is a TypeScript script run through `tsx` with a `package.json`
  script entry (`map:replay`, which also makes it a Fallow entry point): plain
  `.mjs` cannot import the Drizzle schema, the access projection, or the
  proof-kit corpus, and the Neon `maps` table has no production writer — the
  script seeds the map row for the operator's user via the schema and derives
  the claim with the existing `projectMapAccess`, or reuses an existing map
  via `--map`. One small committed addition to `convex/mapFixtures.ts` — an
  internal, CLI-callable system placement with `upsertSystem`'s exact id
  validation and idempotent `by_map_system` upsert but no access gate
  (internal mutations are admin-key-only via `convex run`, matching
  `insertConnectionFixture`) — completes the internal family the replay
  drives. **Rejected:** free-numeric direction editing (an arbitrary radian
  array is not a dial and invites invariant-breaking states) and an
  uncommitted throwaway driver (the fixture is contract-named, and 4.0.3.2's
  motion tuning needs it again).
- **Contract PD-3 — How a pinned node rejoins its deterministic target: a
  whole-map lock whose release is a pure state transition.** The map is locked
  by default (`nodesDraggable` off). Unlocking enables React Flow's native
  drag; drag stop stamps positions `user` via the existing `applyUserPlacement`
  path, which excludes them from layout (reconciler protection) and never
  synchronizes (no mutation surface exists). Re-locking calls the new pure
  `clearUserPlacements` (every `user` stamp reverts to `assigner`, positions
  untouched) and bumps the layout revision, so the next merge applies kernel
  proposals and emits ordinary `system-moved` intents — the node snaps home
  without any special-case movement path, and shared layout never changed
  because the kernel never saw the pin. Operator-selected shape (2026-08-01):
  one global lock control, not per-node pins; hand arrangements are
  deliberately discarded on re-lock. **Rejected:** per-node unpin affordances
  (more bookkeeping and UI noise for the same outcome, and the operator
  explicitly chose the global model) and preserving hand placements across
  re-lock (contradicts "returns to its computed position").
- **Cross-engine determinism (closing the recorded 4.0.3.1.1 residual):
  in-house deterministic math.** A new `src/mapper/layout/trig.ts` owns
  deterministic `sin`/`cos` (argument normalization to the quadrant plus a
  fixed minimax polynomial, using only IEEE-754-exact `+ - * /` operations) and
  a `distance` helper built on `Math.sqrt` (correctly rounded per spec, hence
  deterministic). `geometry.ts` and `overflow.ts` drop their `Math.sin`/
  `Math.cos`/`Math.hypot` calls for these; `proof-kit.ts` follows for
  consistency. Positions become bit-identical across JavaScript engines by
  construction, which the browser digest probe then demonstrates. The
  determinism fixture is regenerated once here, deliberately. **Rejected:**
  output quantization (shrinks but cannot close the window — a value at a
  rounding boundary still flips discrete placement choices) and computing
  layout in one place then syncing (synchronizing presentation violates the
  local-layout constraint).
- **Camera follow: a local toggle, default on, zero-duration refit,
  suppressed during gestures.** When enabled, a mapper-owned follow hook calls
  React Flow's `fitView` with duration 0 after a merge that adds or moves
  nodes, so new arrivals are always in frame; when disabled the camera never
  moves on its own. The refit is additionally skipped while the drag set is
  non-empty — a viewport jump mid-gesture would drop the node somewhere
  unintended and stamp that accident as a user placement. Default revisited by
  the operator at the gate. **Rejected:** always-on refit (the operator wants
  it optional per user) and animated glide (motion belongs to 4.0.3.2).

### Interfaces and contracts

- `trig.ts`: `/** Deterministic sine: identical bits on every JS engine; only IEEE-exact ops. */ export function detSin(radians: number): number` (and `detCos`); `/** Euclidean distance via exactly-rounded sqrt; the layout zone's only length op. */ export function distance(a: ChainPosition, b: ChainPosition): number`. Precondition: finite input; accuracy within a documented small bound of true value (pinned by tests against reference values).
- `layout.worker.ts` message shapes: request `{ requestId: number, facts: LayoutFacts, config: LayoutConfig }`, response `{ requestId: number, positions: ReadonlyMap<number, ChainPosition> }` (structured clone carries the Map). The worker never posts for a request it did not receive; a kernel rejection posts an error variant the hook logs and drops.
- `kernel-requests.ts`: pure exported transition functions over a small request-state value — post (assign the next monotonic id and posted key), accept (a reply applies only if its id is the latest posted id), fail (terminal without apply resets the posted key so the next change retries), and die (all later requests route to the fallback). Every branch is a node-environment unit test.
- `use-layout-kernel.ts`: `/** Worker-backed LayoutKernel with in-process fallback; stable identity per mount. */ export function useLayoutKernel(): LayoutKernel`. Consumed by `useMapChain` internally (callers never construct workers). Construction throw → immediate fallback; `error`/`messageerror` after construction → log once, mark dead via `kernel-requests.ts`, settle outstanding and subsequent requests through the in-process seam.
- `placement.ts`: `/** Adapts one kernel result to the assigner seam; omitted ids keep their current position. */ export function assignerFromPositions(positions: ReadonlyMap<number, ChainPosition>): PlacementAssigner`.
- `reconciler.ts`: `/** Reverts every user-owned placement to assigner ownership, positions untouched (re-lock). */ export function clearUserPlacements(state: ChainState): ChainState`.
- `use-map-chain.ts`: `useMapChain(mapId, draggingIds, config: LayoutConfig)` — the added `config` is the live dial state; returned `MapChain` gains `releasePlacements: () => void` (clears user stamps and forces a fresh layout merge). The hook mirrors `draggingIds` into its own ref and reads that ref at apply time (the `draggingRef` pattern `ChainLive` already uses), so the protection set a merge applies with is the gesture's current one, never the one captured when the request was posted. Other returned fields keep their contracts.
- `map-controls-model.ts`: pure exported clamp and preset functions (commit-time clamping keeps ring spacing ≥ separation from either direction; presets resolve to the `DIRECTION_PRESETS` constants exported by `layout-contract.ts`).
- `MapControls.tsx` props: `{ locked, onLockedChange, follow, onFollowChange, config, onConfigChange }` — controlled, stateless, domain values only; commit handlers apply `map-controls-model.ts` clamping so invalid configs cannot leave the panel.
- `ChainSurface.tsx` adds optional `nodesDraggable?: boolean` (default true preserves the empty-canvas contract) and optional `children` rendered inside `<ReactFlow>` beside `<Background>`, the mount point for `MapControls` and the follow hook's host component.
- `convex/mapFixtures.ts`: `placeSystemFixture` internal mutation, args `{ mapId, systemId }`, `requireSystemId` plus the `by_map_system` idempotent upsert, no access gate (internal, admin-key `convex run` only).
- `scripts/map-replay.ts` CLI (`pnpm map:replay`): `--map <id>` to reuse an existing map (otherwise it seeds a map for the operator's user and projects the claim), `--chain <corpus-seed>`, `--interval-ms` (default 1500); dispatches serially (await, then delay) and prints each event as it lands; a rejected event stops the replay loudly.

### Control and data flow

Changed path: `watchMapSystems`/`watchMapConnections` pages land →
`chainSignature` changes → the pipeline derives `LayoutFacts` from the
snapshot's rows in server (creation) order — never from reconciled arrival
order — and posts them with the current dial config to the worker → that
request's positions return and its id is still the latest posted id →
`reconcileChain(previous, snapshot, dragSet, assignerFromPositions(positions))`
produces the next state and intents → `syncNodes`/`buildEdges` render, and the
follow hook refits the camera if enabled and no drag is active. The posted key
is signature plus a layout revision that dial commits and `releasePlacements`
bump, advanced eagerly at post time, so config changes and re-lock re-merge
without a server change while re-renders (fresh subscription object
identities, pointer moves during a drag) never repost or cancel in-flight
work; stale replies lose the request-id comparison and are dropped; the drag
set is read from the existing ref at apply time so protection cannot go stale
across the async window. Unlock/drag keeps today's flow (drag set →
protection → `user` stamp at stop). Re-lock: `clearUserPlacements` then
revision bump → kernel proposals apply → `system-moved` intents snap nodes
home. No Convex write path changes; the replay tool drives the existing
fixture mutations from the CLI only.

### Edge and failure behavior

- Worker construction throws (unsupported environment) → one logged error,
  in-process kernel through the same seam; behavior and output identical.
- Worker fails after construction (`error`/`messageerror` — a chunk that
  fails to load or evaluate never rejects the constructor) → one logged
  error, the worker is marked dead, and the outstanding plus all subsequent
  requests settle through the in-process seam — the map can never sit
  permanently empty behind a healthy subscription.
- Worker reply for a superseded request (newer signature, config, or unmount)
  → loses the request-id comparison and is dropped; the newest request's
  reply applies.
- Kernel rejection (engine failure) → logged, that merge is skipped, the
  posted key resets so the next change retries, canvas keeps previous state
  (never a loading state).
- Incomplete (draining) snapshot → facts carry only the snapshot's rows;
  retained-but-draining systems get no proposal and keep their positions;
  the complete snapshot then converges every client to the identical picture.
- Facts with no systems (empty map) → kernel returns an empty Map; merge
  yields the empty state; the canvas stays the calm empty surface.
- Re-lock with nothing hand-placed → `clearUserPlacements` returns state
  unchanged; the forced merge proposes identical positions; zero intents.
- Dial commit violating the invariant → the panel clamps (separation is
  capped at ring spacing; ring spacing floor is separation), so the kernel
  never receives an invalid config.
- Replay endpoint not yet on the map (connection before both systems) → the
  tool orders each timeline event system-first, matching the fixture
  mutation's own endpoint check; a rejected event stops the replay loudly.
