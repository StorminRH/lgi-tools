## Why now

The Atlas shell is shipped but deliberately has no collaborative data. The
reactive reader and every later authoring surface need stable entity, index, and
authorization contracts first; landing this fixture-backed foundation now lets
Session 4.0.2.2.2 connect durable authority without simultaneously deciding
payload shape or creating a second access path.

## Scope (the destination)

The finished slice has one Convex document per map system, connection,
signature, and note, plus the minimal access-claim and signature-activity rows
those payloads depend on. Authorized fixture reads are map-scoped; authorized
system upsert is atomic and idempotent; unauthorized calls fail before touching
the database. Connections store only endpoint IDs and mutable observation
state. Signatures retain their payload during a reversible tombstone window and
carry an absolute purge boundary; nullable knowledge fields can be enriched by
later partial observations without being downgraded by less-resolved input.
Notes are user-authored documents with map, system, or signature targets, while
the eventual first UI may remain system-only. Last-seen observations update a
separate, stale-gated activity document without a running timer. No production
browser, Next route, durable writer, paste parser, or mapper UI consumes the new
API in this session.

## Resolved implementation decisions

- **Contract PD-1 — Stable wormhole type representation: store the canonical
  wormhole code as `wormholeTypeCode: string | null`.** Move the existing code
  and size vocabulary into a pure `src/data/eve-data/wormhole-contract.ts`
  owner consumed by the codex, its wire validator, and the Convex boundary.
  Codes are the stable vocabulary used by typed observations, while SDE
  `typeId` remains a versioned lookup inside the client codex. A signature whose
  group is known to be `wormhole` but whose type is still unidentified stores
  `wormholeTypeCode: null`; `K162` remains its own real far-side code rather
  than standing in for unknown. **Rejected:** persisting
  `typeId`, which couples collaborative documents to one SDE build and forces
  later observation consumers to translate the stored identity.
- **Contract PD-2 — Reversible signature tombstone and bounded cleanup:
  retain the document and set `deletedAt` plus `purgeAfter`, both absolute
  timestamps.** Active rows hold both fields as `null`; restore clears both,
  recovering the unchanged payload. `by_purge_after` supports an internal
  oldest-first cleanup mutation capped at 128 rows per call; its range is
  explicitly `purgeAfter > null && purgeAfter <= now`, so active rows can never
  enter the cleanup batch. The caller-owned
  undo duration remains deliberately unset until Session 4.0.4.3.1 resolves
  that session's explicit undo-window decision. **Rejected:** a boolean-only
  tombstone, which cannot drive bounded expiry, and immediate deletion with a
  copied undo payload, which creates a second state owner.
- **Contract PD-3 — Minimum projected role claim: one row
  `{ mapId, userId, roles }`, where `roles` is the non-empty, de-duplicated
  effective set of existing `viewer | editor | owner` values.** Extract
  `MAP_ROLES`, `MAP_ROLE_PRECEDENCE`, `MAP_ROLE_CAPABILITIES`, and the
  capability-union predicate into `src/data/maps/access-contract.ts`; keep the
  existing re-exports so current callers do not change. Extract
  `resolveMatchedMapRoles(...)` inside the maps
  access owner and make the existing `resolveMapRole(...)` consume it, preserving
  current output while exposing the exact capability-preserving set Session
  4.0.2.2.2 must project. `requireMapAccess` accepts required capability
  `view | edit`, reads one `by_map_user` claim after JWT identity, and grants
  only when any projected role carries that capability through the shared
  record. It returns `{ userId, roles }`; it never chooses a display role,
  resolves principals, or decides durable authority. **Rejected:** projecting
  only the precedence-selected display role, which loses capabilities when
  future non-linear roles match through different principals; duplicating
  `canView`/`canEdit` flags in Convex, which can drift from the durable rule; and
  ordinal role comparisons, which break the shipped non-linear-role extension
  seam.
- **Contract PD-4 — Keyed monotonic observation merge, followed by a 60-second
  activity staleness check with no timer.** A Convex-local pure
  `mergeSignatureKnowledge(existing, incoming)` contract owns normalized field
  comparison. Blank/unresolved incoming values normalize to `null`; `null`
  never clears stored knowledge, equal values are unchanged, a non-null value
  fills a stored null, and differing non-null values return `conflict` without
  a patch so a later explicit correction path must resolve them. A non-null
  wormhole code is valid only with `group: 'wormhole'`. The internal
  `upsertSignatureObservation` fixture queries the exact
  `(mapId, systemId, signatureId)` row, inserts new knowledge, applies only an
  `enriched` result, and skips `unchanged`, `conflict`, or `tombstoned` results.
  The later paste mutation must load one indexed system slice, apply this same
  merge contract in memory, and batch only inserts/enrichments; omitted IDs are
  never passed to the merge. Separately, a new observation inserts
  `mapSignatureActivity`; an existing activity row is patched only when the
  server observation time is at least 60 seconds newer than `lastSeenAt`.
  Nothing schedules or delays a user-visible change: the one-minute boundary
  controls invisible bookkeeping only and keeps every activity write outside
  `mapSignatures`.
  **Rejected:**
  writing `lastSeenAt` onto the signature payload, which invalidates watched
  rows even when debounced, and a zero-threshold activity row, which preserves
  payload bytes but needlessly amplifies write/fan-out cost.

### Interfaces and contracts

- `MAP_ROLES`, `MapRole`, `MAP_ROLE_PRECEDENCE`,
  `MAP_ROLE_CAPABILITIES`, `MapCapability`,
  `roleAllows(role, capability)`, and `rolesAllow(roles, capability)` — pure
  shared access contract. Existing exports from maps schema/access continue to
  resolve to these exact values so no current caller changes semantics, and
  both runtimes use the same precedence only for deterministic serialization
  and display, never for capability grants.
- `resolveMatchedMapRoles(input)` — maps-access-owned principal/grant
  resolution returning a precedence-sorted, de-duplicated effective role set.
  Existing `resolveMapRole(input)` consumes that set to preserve its reported
  role and independently unioned capabilities; the projection writer in the
  next session consumes the set directly.
- `WORMHOLE_SIZE_CLASSES`, `WormholeSizeClass`,
  `FAR_SIDE_WORMHOLE_CODE`, and `isWormholeTypeCode(value)` — pure codex/chain
  vocabulary. A code is `K162` or an uppercase letter followed by three digits;
  Convex fixture boundaries reject other strings rather than storing an
  unresolvable reference.
- Convex-local `CONNECTION_MASS_STATES`, note-target validators, and
  `validateConnectionInput(...)` — authoritative fixture/schema boundary for
  `stable | reduced | critical`, positive distinct endpoint IDs, canonical or
  null wormhole codes, finite absolute timestamps, and typed note targets.
  `insertConnectionFixture` additionally requires both endpoint systems to
  exist in the same map. `insertNoteFixture` accepts a map target only when its
  target ID equals `mapId`, and accepts system/signature targets only after one
  typed `db.get` proves that document belongs to the same map.
- `mapAccess` — `{ mapId: string, userId: string, roles: MapRole[] }`, indexed
  `by_map`, `by_map_user(mapId, userId)`, and `by_user(userId)`. `roles` is
  non-empty, unique, and stored in `MAP_ROLE_PRECEDENCE` order so equality/no-op
  comparison is deterministic. It is a non-authoritative claim table; Session
  4.0.2.2.2 owns every writer.
- `mapSystems` — `{ mapId: string, systemId: number }`, indexed `by_map` and
  `by_map_system(mapId, systemId)`.
- `mapConnections` — `{ mapId, fromSystemId, toSystemId,
  wormholeTypeCode: string | null, massState: stable | reduced | critical,
  shipSize: S | M | L | XL | null, eolAt: number | null }`, indexed `by_map`.
  Endpoint IDs must be positive safe integers and distinct; remaining lifetime
  is always derived from `eolAt - now`.
- `mapSignatures` — `{ mapId, systemId, signatureId,
  group: string | null, typeName: string | null,
  wormholeTypeCode: string | null, deletedAt: number | null,
  purgeAfter: number | null }`, indexed `by_map`,
  `by_map_signature(mapId, systemId, signatureId)`, and
  `by_purge_after(purgeAfter)`. `deletedAt` and `purgeAfter` are both null or
  both finite absolute timestamps with `purgeAfter > deletedAt`; cleanup ranges
  the index with `q.gt('purgeAfter', null).lte('purgeAfter', now)` before
  `.take(129)`, so null active rows are excluded by construction and the 129th
  row supplies exact look-ahead truth without increasing the 128-row delete
  cap. The nullable
  group/type fields hold the map's best shared knowledge: a later observation
  may enrich them, but an unknown or less-resolved paste never erases a known
  value. A non-null `wormholeTypeCode` requires `group: 'wormhole'`. Exact
  additional clipboard fields remain for live-sample resolution in Session
  4.0.4.3.1 and can be added as optional fields.
- `mapNotes` — `{ mapId, targetKind: map | system | signature,
  targetId: string, body }`, indexed
  `by_map` and `by_map_target(mapId, targetKind, targetId)`. A map-wide note has
  `targetKind: map` and repeats the stable map ID as its target; system and
  signature notes carry the matching Convex document ID. Later authoring uses
  one typed target constructor to validate that the target kind and ID agree
  and that the target belongs to the same map before insertion. Note text is
  user-authored primary payload. The first UI may expose only system notes,
  while the stored shape already admits the two known follow-ons.
- `mapSignatureActivity` — `{ mapId, systemId, signatureId, lastSeenAt }`,
  indexed `by_map` and `by_map_signature(mapId, systemId, signatureId)`. No
  payload query reads this table.
- `mergeSignatureKnowledge(existing, incoming)` — a pure keyed-field merge
  returning `unchanged | enriched | conflict`. Incoming nulls preserve stored
  values; exact equality no-ops; null-to-non-null enriches; differing non-null
  values preserve the stored row and report a conflict for an explicit later
  correction path. It never decides absence or deletion.
- `upsertSignatureObservation({ mapId, systemId, signatureId, knowledge })` —
  internal fixture mutation that requires a positive existing same-map system,
  normalizes a non-empty signature ID, queries
  `by_map_signature(...).unique()`, inserts when absent, refuses tombstoned
  rows, and otherwise writes only the pure merge contract's `enriched` result.
  Concurrent identical inserts converge through the same indexed read and
  Convex transaction retry behavior.
- `requireMapAccess(ctx, mapId, requiredCapability)` — authenticate first,
  query `mapAccess.by_map_user(...).unique()`, throw
  `ConvexError({ code: 'UNAUTHENTICATED' })` for no JWT identity and
  `ConvexError({ code: 'FORBIDDEN' })` for a missing/insufficient claim, then
  return `{ userId, roles }`.
- `readMap({ mapId, cursors })` — public query whose first handler call is
  `requireMapAccess(..., 'view')`. `cursors` carries independent nullable
  cursors for systems, connections, signatures, and notes. Each corresponding
  `by_map` range calls `.paginate({ cursor, numItems:
  MAP_FIXTURE_PAGE_SIZE })` and returns `{ page, continueCursor, isDone }`;
  callers iterate each collection until `isDone`, so a map above one page is
  explicitly incomplete until its own cursor finishes. The query never reads
  activity rows or another map.
- `upsertSystem({ mapId, systemId })` — public mutation whose first handler call
  is `requireMapAccess(..., 'edit')`; validate a positive safe integer, query
  `by_map_system(...).unique()`, return the existing ID without a write, or
  insert and return the new ID. Convex transaction retry semantics make
  concurrent/repeated calls converge on the same indexed lookup path.
- Internal fixture seams `insertConnectionFixture`, `insertNoteFixture`,
  `upsertSignatureObservation`, `setSignatureTombstone`,
  `recordSignatureSeen`, and `purgeExpiredSignatureTombstones` — make every
  round-trip invariant executable instead of relying on unrestricted test
  setup. Signature observation validates its owning system, uses the pure
  merge result, server time for stale activity, and no missing-row scan.
  Tombstoning deletes the one indexed
  activity companion in the same mutation, restore clears both tombstone
  fields, observations no-op while tombstoned, and cleanup reads at most 129
  expired rows, deletes at most 128, and returns
  `{ deletedCount, hasMore: rows.length > 128 }` without any per-tombstone
  companion lookup. The cleanup core lives in
  `convex/lib/mapSignatureCleanup.ts`; source-contract coverage proves it
  contains exactly one indexed `mapSignatures` query and no
  `mapSignatureActivity` query or `db.get`.
- Every new or moved exported production surface receives a concise `/** */`
  contract comment; no public interface remains implicit.

### Control and data flow

For a public fixture call, Convex validates the argument shape, the handler
immediately calls `requireMapAccess`, and the gate resolves Better Auth JWT
identity before its single indexed access-claim read. Denial throws before a
chain table is touched. An allowed read then performs separate cursor-based,
fixed-size `by_map` pages for systems, connections, signatures, and notes;
because the map key is the leading equality constraint, map B cannot enter map
A's result, and each collection reports whether more rows remain.
An allowed upsert performs one `by_map_system` unique lookup and writes only
when absent. Internal connection/note fixtures validate through their named
contracts before inserting, including endpoint existence and same-map target
ownership. An internal signature observation performs one exact indexed
identity lookup, applies the pure merge result, and writes the payload only for
an insert or enrichment; missing IDs are never enumerated. Signature payload
changes and signature activity use different tables and read sets.
Tombstoning deletes the activity companion once, before cleanup; a later
observation of a tombstoned signature reports `tombstoned` and writes nothing.
Expiry cleanup therefore ranges only the signature expiry index oldest-first,
reads one look-ahead row beyond the delete cap, deletes the first fixed batch
with no companion lookup, and reports whether another call is required.

No path in this session reads Neon from Convex, writes Neon, calls an external
service, schedules a new engine, exposes data to the mapper, or creates a
production subscription. Session 4.0.2.2.2 will populate `mapAccess` from the
durable side and prove that the gate's indexed access read participates in live
subscription invalidation.

### Edge and failure behavior

- Signed-out caller → `UNAUTHENTICATED` before any database lookup.
- Signed-in caller with no claim or viewer attempting `upsertSystem` →
  `FORBIDDEN` before any chain read/write.
- Authorized request for map A when map B has rows → only map A index ranges
  are read and returned.
- Repeated/concurrent `(mapId, systemId)` upsert → one system document; the
  later caller receives the existing ID and performs no patch.
- Invalid system/endpoint ID, self-loop connection, invalid wormhole code,
  non-finite timestamp, or unpaired tombstone timestamps → boundary error and
  no write.
- Unidentified wormhole → preserve its stable signature ID and `wormhole`
  group with `wormholeTypeCode: null`; never invent a generic type code. K162
  remains the real far-side code with nullable size until later knowledge
  resolves it.
- Same signature ID with stronger normalized information → the merge contract
  fills only previously null fields; identical or less-resolved rows no-op.
  Differing non-null knowledge returns `conflict` without changing the stored
  row, reserving corrections for an explicit later override path.
- Existing signature absent from an ordinary paste → no write and no
  tombstone. The later signature-session plan must reconcile the operator's
  required explicit missing-item review with that session's frozen
  automatic-removal wording before implementation; absence alone is not
  evidence of despawn because the EVE client can hide ignored results.
- Connection with an unknown code, absent/cross-map endpoint, or self-loop →
  reject before insertion. A map note whose target ID is not its own map, or a
  system/signature note whose typed target is absent or belongs to another map
  → reject before insertion.
- Signature restore before expiry → payload and identity remain on the same
  document; only `deletedAt`/`purgeAfter` clear, and the next valid observation
  recreates its activity row.
- Observation while a signature is tombstoned → return `tombstoned` and make
  no activity write.
- Cleanup backlog above 128 rows → one call reads the oldest 129, deletes the
  oldest 128, and returns `hasMore: true`; exactly 128 returns `false`, and
  later calls drain a larger remainder. Active
  rows with `purgeAfter: null` never enter the bounded index range and survive
  every cleanup call, and cleanup performs no per-tombstone activity lookup.
- Any payload collection above one fixture page → `readMap` returns that
  collection's non-terminal cursor; iterating its cursor returns every row
  without increasing the fixed transaction page size or implying a complete
  result early.
- Activity observation while its separate row is still fresh → return
  unchanged and perform no patch; at/after 60 seconds → patch only the activity
  row. No background timer runs and no displayed signature update waits on the
  staleness gate.
- Missing durable projection writer → production claims remain absent, so
  fixture APIs fail closed until Session 4.0.2.2.2 connects authority.
