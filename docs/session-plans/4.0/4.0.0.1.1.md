## Resolved implementation decisions

- **Contract PD-1 — capture mechanism home: a checker-owned transition rule plus a read-only reporter, documented in the owning schema.** The freeze already lives in `check_baseline_claims.py` (`_version_start_findings` errors on any `Version-start` drift from `origin/main`), so capture and freeze are one rule with one owner: the checker recognizes exactly one legal transition, keyed on the new `Version-start ref` Snapshot row. `capture_version_start.py` is a pure reporter (the `fold_pending_changelog.py` precedent): it reads `origin/main`'s committed baseline via `git show`, promotes `Current` → `Version-start` for schema-registered shared rows, fills new rows from the live measurement functions, and prints the table; it never writes. The schema documents the rule (satisfying DC-5); `plan-version.md` gains one invocation step at topology approval. At adoption the promotion ref is the committed baseline's own Code ref — the ref its `Current` values were actually measured at — which for 4.0 is `c60a44e6e35efaadbb6ed1d7d3a36bd69fe896dd`; the audit that produced those values is the only pass that ever measures every row (coverage, Fallow health, and breadth rows are not derivable by script), so promotion is the only honest capture. **Rejected:** a procedure-only documented step (no mechanical enforcement — exactly the gap that let v3.10 run on v3.9's column), and a baseline-writing capture script (breaks the read-only-reporter convention every `.agent-local` tool follows, and would create a second writer of a checker-owned document).
- **Contract PD-2 — registered rows, units, and commands: six bare-integer rows resolved against live code, with the operator's 2026-07-27 drop rulings applied in the same change.** New rows and their measurement owners in `repo_measures.py`: `Fallow boundary zones (configured)` = entry count of `boundaries.zones` in `.fallowrc.json` (22); `Vendor-resilience integrations` = record-key count in `src/composition/vendor-resilience-registry.ts` (14); `Instrumented capability operations` = record-key count of `CAPABILITIES` in `src/data/telemetry/capability.ts` (38); `Owned service-level indicators` = entry count of `SLI_IDS` in `src/data/telemetry/sli.ts` (5); `UI adoption exemptions` = summed entries of the five exemption families in `src/composition/ui-adoption-registry.ts` (16); `Retained legacy CSS families` = `retainedCssFamilies` entry count (8). Bare integers keep `Delta` derivable and the live check exact. The backlog's "15 declared integrations" is stale — registry record, type union, and census test all agree on 14 — so the plan pins commands, not remembered numbers, and the executor must not reconcile toward 15. Dropped by operator ruling: `Auth query-hub exports`, `PricingContextValue` fields, `usePricing()` call sites (tombstones), `Telemetry query breadth`, `ESI refresh-job query exports` (duplicates of the live-checked `src/data/telemetry/queries.ts` and `src/data/esi-refresh-jobs/queries.ts` rows, which survive; the hand-counted fan-in figures retire with them). The registry's empty `temporaryCssFamilies` gets no row per the same ruling; its own census test already pins it. **Rejected:** compound multi-value rows for the four surfaces (em-dash deltas, weaker machine checks), and evidence-only registration without live measurement (contradicts the operator's explicit mechanical-measurement direction).
- **Contract PD-3 — suppression split boundary: a `@ts-expect-error` occurrence in a `*.test.ts` or `*.test.tsx` file is a test contract suppression; every other marker the current scan counts is a diagnostic suppression.** The rule is purely mechanical over the existing `suppression_count` scan (same file set, including checked-in Convex `.js`/`.jsx` headers; same three markers), so the two new counters partition the old count exactly: at the current ref, test contracts 24 and diagnostics 18 (12 production `eslint-disable`, 5 test-file `eslint-disable`, 1 `fallow-ignore`), summing to the pre-split 42. An `eslint-disable` in a test file stays diagnostic — it silences a linter, it asserts nothing that self-invalidates. Both rows join the checker's required live-measured set. The backlog's remembered 22/20 split was measured at an older ref; the rule, not the numbers, is what this session ships. **Rejected:** classifying all test-file suppressions as contract assertions (would hide real test-file lint debt), and per-site annotation-based classification (requires editing production and test sources, violating OOS-1 and adding a manual step where a mechanical rule suffices).
- **Contract PD-4 — the fidelity check reuses the existing bundle-list mechanism unchanged: `"session-as-built"` joins the directory tuple in `_active_bundle_files`.** As-built records being per-session files needs nothing new — the mechanism already rglobs every file under each named directory and SHA-256-compares each copy, and its existing "archive source set is missing or empty" error covers a version whose as-built directory was never created. Fixture updates seed `docs/session-as-built/9.9/` and extend `copy_bundle`; a new test proves post-phase failure on a corrupted and on a missing as-built copy. **Rejected:** a distinct per-session comparison path (a second owner for byte-fidelity with no behavioral difference to justify it).
- **Operator rulings (2026-07-27), recorded as binding decisions:** drop the five rows named under the second decision; wire live measurement for every new and split row; add a backlog entry "Revisit the version-audit lifecycle for bloat" triggered before the next version audit; the drops are explicit operator authorization against the contract §11 no-silent-drop expectation and are restated in the as-built record's divergence section.

### Interfaces and contracts

- `repo_measures.diagnostic_suppression_count(root: Path) -> int` and `repo_measures.test_contract_suppression_count(root: Path) -> int` — partition the exact file-and-marker set of the retired `suppression_count`; each raises `MeasureError` on unreadable input; `suppression_count` itself is removed with its last caller (no dead export remains). Contract comment: `"""Count <partition> suppression markers; the two partitions sum to the old total."""`
- `repo_measures.fallow_zone_entry_count(root) -> int`, `vendor_integration_count(root) -> int`, `capability_operation_count(root) -> int`, `sli_count(root) -> int`, `ui_adoption_exemption_count(root) -> int`, `retained_css_family_count(root) -> int` — each parses its named file with an anchored pattern and raises `MeasureError` when the anchor is missing or the count is zero, so a silently moved literal fails loud instead of measuring 0. `vendor_integration_count` must scope to the `vendorResilienceRegistry` object body (brace-depth or anchored span) and accept both quoted (`'eve-esi':`) and bare-identifier (`convex:`, `fuzzwork:`) top-level keys — the live registry mixes both forms, and a quoted-only pattern silently counts 12 instead of 14; `test_repo_measures.py` must include a mixed-key fixture proving this.
- `check_baseline_claims`: the Step-1 claims map becomes the required live-measured row set (existing five minus `Source suppressions`, plus the eight new/split rows); `frozen_version_start`/`_version_start_findings` gain the transition: same `Version-start ref` → exact key-and-value freeze (today's behavior); differing or newly introduced ref → shared-row promotion equality against `origin/main`'s `Current`, ref equality against `origin/main`'s Code ref SHA, additions and removals permitted; a working baseline lacking the ref row once `origin/main` has one is an error.
- `capture_version_start.py` CLI — `--root` only, prints the promoted Snapshot identity rows and complete Metrics table as Markdown to stdout, exit 0 on success, exit 1 with a message when `origin/main`'s baseline or a live measurement is unavailable. Before measuring, it verifies ref fidelity: the promotion Code ref must exist as a git object and `git diff --quiet <promotion-ref> -- src convex .fallowrc.json` must be clean (those paths are the complete input set of every live measurement), so new-row values are provably the promotion ref's values; a differing or dirty tree is an exit-1 failure, never a silent capture. No `--check`, no writes.
- `verify_archive._active_bundle_files` — tuple becomes `("session-contracts", "session-plans", "session-as-built", "version-audits")`; error text and comparison semantics unchanged.
- `docs/workflows/schema/code-health-baseline.md` — Snapshot gains `| Version-start ref | <full lowercase commit SHA> |`; the capture rule is stated in the prose that already owns the `Version-start` freeze sentence.

### Edge and failure behavior

- `origin/main` baseline unreadable during capture or claims check → `MeasureError`/existing "anchor unavailable" error; both tools fail loud, never fall back to the working copy.
- Promotion Code ref missing as a git object, or `src`/`convex`/`.fallowrc.json` differing from that ref at capture time → `capture_version_start.py` exits 1 naming the drift; it never captures values the recorded ref cannot reproduce.
- A mid-version attempt to re-run the transition → unreachable by construction: the transition requires the working `Version-start ref` to equal `origin/main`'s Code ref while differing from `origin/main`'s recorded `Version-start ref`, a state that only exists in the adoption window after a version-close audit advances the Code ref.
- A registry literal moves or is renamed (e.g. `CAPABILITIES` restructured) → the anchored parser raises `MeasureError`; the checker reports "cannot measure" as an error on that row rather than warning with a fabricated 0.
- Ordinary 4.0 session edits `Version-start` or drops a row without a ref change → existing freeze error, unchanged.
- Adoption transition with a shared row's `Version-start` not equal to `origin/main`'s `Current` → new transition error naming the row.
- Archive bundle missing its `session-as-built` directory or containing an altered as-built copy → post-phase error via the existing "missing or empty" / "differs from active source" paths, proven by the new failing-case tests.
- The five dropped rows reappearing in a later working baseline → "metric key is not registered" schema error, unchanged mechanism.
