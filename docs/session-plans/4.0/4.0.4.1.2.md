## Why now

Session 4.0.4.1.1 made the map authorable but left it append-only and dumb:
every fact is hand-entered, nothing can be removed, and the tombstone
foundations sit unused. This session completes sub-version 4.0.4.1 — the codex
makes typed holes self-describing, lifetime and mass become honest shared
estimates, and the one collapse pathway that 4.0.4.2's tracking enriches and
4.0.4.3's automatic triggers reuse goes live with its audit ledger — then
opens the sub-version PR that ships the whole write path to production.

## Scope (the destination)

An editor who types a wormhole code on the connection card sees the hole know
itself: a read-only codex panel (total mass, per-jump limit, regeneration,
lifetime, size) fills in, and the ship-size select locks to the derived size
class — it stays editable only for K162/untyped connections (Contract §3
DC-1, §6 HC-1). The four-bucket life-stage picker gains consequences: each
report intersects a persisted death window server-side, so every client
derives the same honest range ("~4–16h") with a live countdown on hover, and
the SDE ceiling shows even before any report on typed holes. A contradictory
report resets the window rather than wedging it (DC-2 under the superseding
operator direction: no separate mark-EOL action exists; the stage report is
the input and `eolAt` stays null-deprecated). Mass renders as a bounded
remaining-mass interval — state thresholds clamp the codex budget, widened by
±10% spawn variance, suppressed for regenerating holes — always a range,
never a number (DC-3, HC-2).

Severing goes live: the card's sever control acts immediately — no
confirmation prompt anywhere (operator direction 2026-08-04) — with the
computed outcome announced afterward in a keyed undo toast and recorded in
the map-event ledger. The pure decision core retains a cut branch only when
something known is inside it — a mapped k-space system, or (tri-state input,
always `unknown` this session) a friendly — otherwise the branch tombstones
whole (its systems and every connection incident to them) with the severed
connection in one transaction, undoable for 24 hours (DC-4, DC-5). A retained
branch keeps its exact shape: the dead connection renders as a red pulsing
line (reduced-motion: steady dim red) that is clickable and restorable
in-window, then becomes an invisible skeleton tie — a structural layout edge
that never renders and never moves the compass. Tombstoned systems still
vanish immediately. The purge is production-scheduled this session and gains
two rules: a tombstoned connection with two live endpoints leaves the purge
range permanently (skeleton retention), and a system tombstone re-arms its
incident tombstoned connections so ties still purge once they dangle.

The map gains its first audit surface (operator-directed pull-forward of the
backlogged map-event log, basic version): a bottom-edge "Log" text control
that expands into a small line-by-line ledger — timestamp, actor, event —
backed by a new `mapEvents` table written in the same transaction as each
despawn or restore, with 7-day retention (the Wanderer-proven window) and a
bounded newest-first read. In-window removal entries carry a Restore action,
making undo persistent beyond the transient toast on every client (DC-4).
Contract §§3–6 are satisfied without widening: both IS items land as
described, OOS items are protected by the tri-state parameter and by
shipping no signature surface, and the three .1-review riders (rejection
swallow, temp-id-scoped swap suppression, memoized live filtering) land
inside the client-plumbing step.

## Resolved implementation decisions

- **Contract PD-1 — edge-anchored editing composition: enrich the shipped
  card; no new window shape.** 4.0.4.1.1 pulled the composition forward by
  operator direction (recorded in its plan PD-2); this session adds sections
  to `ConnectionDetailsCard` — codex panel, lifetime row, mass row, sever
  control — and one new mode: clicking a dying (in-window tombstoned)
  connection opens the card in restore-only mode (restore action plus
  read-only facts; field setters refuse tombstoned rows server-side already).
  Skeleton ties render nothing and are not clickable. The ledger is its own
  bottom-edge surface, not a card section. **Rejected:** a separate sever
  dialog or map-level destructive menu — breaks the map-native card
  composition and adds a second authoring surface.
- **Contract PD-2 — collapse decision inputs: one pure core over synced
  facts with a tri-state pilots input.**
  `decideCollapse({ cutConnectionId, systems, connections, isKnownSpace,
  pilotsPresent })` in pure `src/data/maps/chain-collapse.ts`: evaluates
  **per cut-endpoint component** — the live topology is a forest once any
  island has been retained, so root-reachability is not the question. Remove
  the cut edge, take the two components containing its endpoints (one
  component when the edge was a loop), and retain each component that holds
  the map root, a k-space system, or present pilots; every non-retained
  component returns in `{ kind: 'remove', systemIds, connectionIds }` — its
  systems plus every connection incident to them, so the remove transaction
  leaves no live connection referencing a tombstoned system. A loop edge
  (one component) is always `{ kind: 'retain' }`. A sever inside a retained
  island evaluates that island's two halves by the same rule, and a sever
  elsewhere never re-examines pre-existing islands (only the cut edge's own
  components are considered). Everything non-retained removes, including
  `pilotsPresent === 'unknown'` (operator direction 2026-08-04:
  retention is earned, not default; the only trigger this session is a human
  sever, and by the time 4.0.4.3's automatic triggers call this core,
  4.0.4.2's tracking supplies a real `present`/`absent`). The four shipped
  public tombstone/restore mutations are re-scoped so no second destructive
  path exists: `tombstoneSystem` and `tombstoneConnection` become internal
  helpers of the pathway (no public export, no client hook),
  `restoreSystem` internalizes likewise, and `restoreConnection` stays
  public for the dying-edge restore but writes its ledger event; the .1
  test suites retarget the internal helpers. Space
  classification uses `isKnownSpaceSystemId` (id `< 31_000_000`), a pure
  `src/data` predicate drift-guarded by a pinned census db test against the
  SDE mirror: id `< 31_000_000` ⇔ `whClassId ∈ {null, 7, 8, 9, 25}`
  (unclassed k-space, HS, LS, NS, Pochven) and id `≥ 31_000_000` ⇔
  `whClassId` a J-space class (C1–C6 and the special J-class ids 12–18) —
  so Convex needs no directory access. The server is the enforcement owner:
  `severConnection` recomputes the decision over its own documents inside
  the mutation and executes it in one transaction; this supersedes the
  master plan's "dead-empty offers removal, ambiguity keeps" prose by
  operator ruling (recorded for the as-built). **Rejected:**
  client-computed decisions passed to the server — unverifiable removal
  sets. **Rejected:** retain-by-default with manual cleanup —
  operator-rejected as a chore.
- **Contract PD-3 — shake-state representation and clamp: the shipped
  `massState` vocabulary plus threshold-interval bounds co-owned with the
  future roll engine.** No new observation state ships; the clamp is
  `remainingMassBounds(entry, massState)` in
  `src/data/eve-data/wormhole-contract.ts`: remaining fraction intervals
  stable `(0.5, 1]`, reduced `(0.1, 0.5]`, critical `(0, 0.1]`, unset
  `(0, 1]`, applied to true total mass `M ∈ [0.9, 1.1] × totalMass`, giving
  kg bounds `(fracMin × 0.9 × totalMass, fracMax × 1.1 × totalMass]`;
  `massRegen > 0` returns `null` (regenerating holes get codex facts only, no
  interval). The threshold and variance constants
  (`WORMHOLE_MASS_STATE_THRESHOLDS`, `WORMHOLE_MASS_VARIANCE`) are exported
  from this one owner — the roll-calculator engine (planned standalone
  feature, 2026-08-04) consumes the same constants and formalizes the same
  table as its feasible-region inequalities, so the two models can never
  disagree. **Rejected:** a mapper-local mass model — creates the competing
  vocabulary the master plan's "roll calculator substrate" note forbids.
- **Consequential — lifetime is a persisted death window, not a mark-EOL
  stamp.** `mapConnections` gains `deathEarliestAt`/`deathLatestAt`
  (optional-normalized absolute timestamps, per the house absolute-end-stamp
  rule); `eolAt` stays null and documented as superseded. The pure module
  `src/data/maps/connection-lifetime.ts` owns the algebra: bucket remaining
  intervals under_1_day `[4h, 24h)`, under_4_hours `[1h, 4h)`, under_1_hour
  `(0, 1h)`, expired `[0, 0]`, capped by the typed lifetime; a report at `t`
  implies death in `[t + rMin, t + rMax]`; a typed hole with no report yet
  has ceiling `_creationTime + lifetime` (first sighting is a spawn lower
  bound); windows intersect monotonically across reports — including a
  repeated same-bucket report at a later time, which strictly narrows — and
  a contradiction (empty intersection) resets to the new report's own window
  (mispick correction). The life-stage and wormhole-type setters accept the
  client-computed window and the server enforces shape and
  monotonic-narrowing-or-reset before stamping; the setters' equality-skip
  therefore skips only when the value AND the resulting window are both
  unchanged, and `lifeStageObservedAt` stamps on any accepted change —
  editors are already the trusted authors of every other connection fact.
  Display: bounded range with hover countdown; ceiling-only before any
  report; "expired" at zero. **Rejected:** computing windows server-side —
  Convex has no codex access and shipping the full type table into the
  bundle duplicates a Neon-owned dataset. **Rejected:** persisting only the
  latest report — loses the compounding precision that is the whole point.
- **Consequential — the connection presentation lifecycle is
  live → dying → skeleton.** The client filter changes from "live rows only"
  to: systems live-only (unchanged), connections live + tombstoned
  (structural). The chain signature fingerprints connection liveness
  (`id:deletedAt-bit`) so a tombstone patch triggers the merge; reconciled
  connections carry the stage; `buildEdges` styles dying edges (red,
  20–75% opacity pulse via CSS custom property + stylesheet keyframes;
  `prefers-reduced-motion` renders steady dim red) and drops skeleton edges
  from rendering while both remain layout facts. Root derivation stays
  live-systems-only. The dying→skeleton flip is client-clock driven; a
  coarse 60-second ticker while dying edges exist bounds the lag. Tombstone
  state becomes three-valued in `src/data/maps/chain-contract.ts`: active
  (`deletedAt` null/absent), dying (both stamps finite), skeleton
  (`deletedAt` finite, `purgeAfter` null). The purge
  (`purgeExpiredChainTombstones`) is production-scheduled this session via
  the Convex cron registry and applies two rules: an expired tombstoned
  connection with two live endpoints has its `purgeAfter` cleared (skeleton
  retention — it permanently leaves the `by_purge_after` range instead of
  clogging the batch head), and any transaction that tombstones a system
  re-arms `purgeAfter` on that system's incident tombstoned connections
  (via `by_map_from`/`by_map_to`) so ties still purge once they dangle.
  **Rejected:** letting expired ties purge and re-laying-out islands — the
  kernel parks unreachable systems in the overflow cluster, destroying
  island shape (verified in `src/mapper/layout/overflow.ts`); the skeleton
  tie is what keeps a trapped mapper's world stable. **Rejected:** skipping
  live-endpoint rows in place without clearing `purgeAfter` — permanently
  clogs the bounded purge batch.
- **Consequential — sever UX is act-then-announce with a persistent
  ledger.** `severConnection` returns the executed outcome (`retained` or
  `removed` + counts); the card fires one keyed sonner toast from the result
  ("Severed — N downstream systems removed · Undo" / "Severed — branch
  kept"); Undo calls `restoreSeveredBranch({ mapId, connectionId })`, whose
  restore set is derived server-side (every row carrying the sever
  transaction's exact `deletedAt` stamp plus the connection itself), so
  undo works from any client, after reload, and from the ledger — the
  toast is a convenience, not the affordance of record. The sever
  transaction guarantees stamp uniqueness (bump the millisecond on
  collision with any existing tombstone stamp on the map, checked within
  its bounded read) so two severs can never share a restore set. The
  sonner owner `src/components/ui/toast.tsx` gains `actionButton` styling —
  today's `unstyled` classNames map has no action slot and this is the
  first action-bearing toast. No ConfirmDialog
  anywhere in the flow (operator direction 2026-08-04). "Never destroy
  silently" is satisfied by the announcement, the ledger entry, and the
  24-hour undo, not by a gate.
- **Consequential — the map-event ledger is a new primitive with despawn
  events as its first consumer (operator direction 2026-08-04).** Concept
  research (Wanderer map-audit guide + audit module; Nexum jump/kill log
  panels — read 2026-08-04, concepts only per the D10 clean-room rule):
  typed events with actor and timestamp, newest-first bounded reads, short
  auto-cleaned retention (Wanderer: 7 days), display fields resolved at
  write time. Ours: `mapEvents` table (`mapId`, `at`, `kind`, `actor`,
  `payload` per kind), indexed `by_map` and a `by_purge_after`-style
  retention stamp; written in the same transaction as the mutation it
  records (sever retained/removed, branch restored, connection restored);
  `MAP_EVENT_RETENTION_MS` (7 days) owned in pure
  `src/data/maps/chain-events.ts` beside the event-kind vocabulary and
  payload types; retention rides the scheduled purge with the same bounded
  batch pattern; `watchMapEvents` is one bounded newest-first indexed read.
  Actor sourcing is resolved, not assumed: the Convex-facing Better Auth
  JWT deliberately carries only the role today
  (`src/platform/auth/auth.ts` `definePayload`), so this session widens
  that payload with the account's display `name` (updating its contract
  comment); event writes capture `identity.name ?? 'unknown'` — display
  fields resolved at write time with no user directory in Convex. UI: the
  ledger presentation lives in `src/mapper/log/` (bottom-edge "Log" control
  + timestamped line rows) composing the existing `Collapsible`
  details/summary primitive and house tokens — deliberately NOT extracted
  to `src/components/ui/`, per the extract-only-for-a-real-second-consumer
  rule; the backlogged full history is the promotion trigger. Rows show
  timestamp, actor, and event text; in-window removal rows render the
  Restore action wired to `restoreSeveredBranch`. Viewers see the ledger
  (visibility is not a mutation); only `canEdit` rows show Restore. The
  `docs/CONVEX.md` + `convex/AGENTS.md` durability-exception wording is
  amended in the same change to enumerate map events beside
  systems/connections/signatures/notes — the operator direction authorizes
  the product, and the guides must not drift. **Rejected:** deferring all

- **Consequential — the three .1-review riders land in client plumbing

### Interfaces and contracts

- `severConnection({ mapId, connectionId }) → { outcome: 'retained' } |
  { outcome: 'removed', systemIds: number[] }` — gate `edit`; refuses unknown
  or already-tombstoned connections; bounded map-wide read (fail-closed
  `MAP_TOO_LARGE` at the .1 cap pattern); recomputes `decideCollapse`
  server-side with `pilotsPresent: 'unknown'`; tombstones the connection
  (retain) or the connection plus the decision's `systemIds` and
  `connectionIds` in one transaction sharing one `deletedAt` stamp — made
  unique against every existing tombstone stamp on the map by millisecond
  bump (remove) — re-arms `purgeAfter` on incident tombstoned connections
  of removed systems, and writes the matching `mapEvents` row in the same
  transaction. After this session the public destructive/restorative
  surface is exactly `severConnection`, `restoreSeveredBranch`, and
  `restoreConnection`; the .1 tombstone/restore mutations are internal
  pathway helpers.
- `restoreSeveredBranch({ mapId, connectionId }) → { restored: true }` —
  gate `edit`; derives the restore set server-side (the connection plus
  every map row whose `deletedAt` equals the connection's stamp), restores
  all rows in one transaction, writes the restore event; idempotent per
  row; degrades to whatever rows still exist after window expiry.
- `setConnectionLifeStage({ mapId, connectionId, value, deathEarliestAt,
  deathLatestAt })` — as shipped plus the window pair (nullable); server
  validates the pair shape (both null or ordered finite) and
  narrowing-or-reset against the stored window; skips only when value and
  resulting window are both unchanged; stamps `lifeStageObservedAt` on any
  accepted change.
- `setConnectionWormholeType({ mapId, connectionId, value, deathEarliestAt,
  deathLatestAt })` — as shipped plus the same window handling (a type pick
  caps the ceiling).
- `watchMapEvents({ mapId }) → newest-first bounded page` — view-gated like
  the chain watches; one indexed read; no continuation (the basic ledger
  shows the retained window only).
- `decideCollapse(input) → { kind: 'retain' } | { kind: 'remove',
  systemIds, connectionIds }` — pure; documented as the single decision core
  for the manual trigger and 4.0.4.3's two automatic triggers;
  `pilotsPresent: 'present' | 'absent' | 'unknown'`.
- `connectionLifetime` module — `deathWindowForReport(bucket, observedAt,
  lifetimeMinutes | null)`, `intersectOrReset(stored, next)`,
  `lifetimeDisplay(window, now)`; all total and pure.
- `remainingMassBounds(entry, massState) → { minKg, maxKg } | null` — null
  for `massRegen > 0` or missing type.
- `isKnownSpaceSystemId(systemId) → boolean` — `systemId < 31_000_000`;
  census-drift-guarded both directions against the SDE mirror
  (`whClassId ∈ {null, 7, 8, 9, 25}` below the line; J-space classes at or
  above it).
- `chainTombstoneState(row, now) → 'active' | 'dying' | 'skeleton'` — the
  three-valued owner in `chain-contract.ts`; `now`-aware so a past-window
  row not yet swept already reads skeleton (dying requires a finite future
  `purgeAfter`); `isTombstoned` remains (`deletedAt` finite).
- `filterChainConnections(pages)` replaces the connection-side
  `filterLivePages` call — keeps live and tombstoned rows, memoized;
  `chainSignature` connection tokens become `${id}:${liveBit}`.
- `ConnectionDetail` gains `deletedAt`/`purgeAfter`, `_creationTime` (the
  no-report ceiling and type-pick cap both need it), and the death window;
  `MapChain` gains the events read; codex resolution stays card-side.
- No other production export or public interface changes.

### Control and data flow

A sever click flows: card action → `severConnection` with an optimistic
tombstone patch on the connection only (branch removal is server-computed and
arrives with the confirmed result) → server gate → bounded topology read →
`decideCollapse` → transactional stamps + event write → result returns →
keyed outcome toast with Undo → subscription patches flow through the
liveness-bearing signature → merge restyles the edge (dying) or removes
branch nodes, and the ledger row appears on every client. Undo — from the
toast or the ledger — calls `restoreSeveredBranch`, whose server-derived
restore set reverses the same path and logs the restore. A life-stage or
type pick computes the death window client-side from the pure module and
codex entry, sends it with the mutation (optimistically patched), and the
server persists after narrowing validation; every client renders the
countdown from the same persisted window. Window expiry changes rendering
only (dying → skeleton via the 60-second ticker); the scheduled purge later
deletes dangling ties, expired system tombstones, and expired events, and
converts live-endpoint ties to permanent skeletons by clearing `purgeAfter`,
so layout facts for retained islands are permanent.

### Edge and failure behavior

- Sever a loop edge (branch still reachable) → `retained`; connection dies
  red; no system touched; quiet toast; ledger entry.
- Sever cutting a branch that contains a k-space system → `retained`; island
  keeps shape through dying and skeleton stages; positions byte-identical
  after window expiry (tested).
- Sever cutting a wormhole-only branch → `removed` with the full downstream
  system set and every incident connection in one transaction; toast and
  ledger Restore both undo it; restore round-trips identity.
- Undo after toast dismissal, reload, or from the second client → the ledger
  row's Restore action performs the same server-derived restore.
- Two editors race sever/restore on one connection → OCC serializes;
  second writer's operation is an idempotent no-op or a clean refusal;
  no partial branch state can persist (single transaction each).
- Contradictory life-stage report (window intersection empty) → reset to the
  new report's own window; never a refusal, never a wedged countdown.
- Repeated same-bucket report later → strictly narrower window accepted and
  stamped (not equality-skipped).
- Life-stage report on an untyped connection → bucket-only window (no
  ceiling cap); typing it later tightens the window monotonically.
- Regenerating hole (massRegen > 0) → codex facts render; mass interval
  suppressed with a "regenerates" annotation.
- Client with a stale window proposal (raced report) → server narrowing
  validation intersects or resets deterministically; both clients converge
  on the persisted window.
- Reduced-motion user → dying edges render steady dim red, no opacity
  animation (`prefers-reduced-motion` media rule in the stylesheet).
- Purge with a mixed batch → dangling ties, expired system tombstones, and
  expired events delete; live-endpoint ties have `purgeAfter` cleared and
  permanently leave the candidate range (tested cap, skip, and re-arm
  behavior).
- Ledger on a map with no events → the collapsed "Log" control renders; the
  expanded panel shows an empty state; viewers see rows but no Restore
  actions.
