## Why now

Sub-versions 3.10.2.1–3.10.2.2 hardened the request path (typed contracts,
same-origin enforcement), but below it data ownership is convention only: the
census proves growth/purge/ESI declarations yet says nothing about who may
write a table, what the database itself enforces, or what happens under
concurrency — and the request path runs on the transaction-free neon-http
driver, so a Postgres constraint is the only atomic guard it has. This session
turns those conventions into one machine-checked registry on the existing rail
and closes the one silent-corruption race it surfaced, completing the
data-layer leg of the master plan's production-flow contract before 3.10.2.4
addresses vendor resilience.

## Scope (the destination)

When this session ends, `src/composition/data-ownership-registry.ts` declares,
for each of the 56 reflected tables: the owning slice (closed vocabulary
derived from the file path, with `src/db/auth-schema.ts` aliased to its
semantic owner `platform/auth`); the permitted cross-owner read contract
(`'open'` for the global-reference tables, an explicit reader list with
purposes otherwise); the exact database-enforced invariant list (primary key,
unique constraints/indexes with partial-index predicates, foreign keys,
checks) as normalized strings the census diffs two-way against live Drizzle
metadata — including column-level `.primaryKey()`/`.unique()` flags; a
transaction-boundary statement (closed kind + required note); and a data class
whose authorization decision lives in `DATA_CLASS_DECISIONS` (five classes,
all application-authorization-only today, each with justification and review
trigger). The census test gains exact-cover, invariant-match, RLS-absence, and
cross-owner-write checks; a filesystem scanner
(`src/esi-datasets/write-sites.ts`) attributes every Drizzle-symbol and
`${symbol}` raw-template write in production sources to a slice using
whitespace-tolerant matching, the census asserts the four known cross-owner
writers are actually found (so a degraded scanner fails loudly), and any write
outside the owner + declared-writer set fails the census naming the file and
table. The owned-assets natural key becomes a unique index (migration `0050`
with a defensive dedup guard), `saveOwnedAssets` reports
`'saved' | 'superseded'` so its sync caller cleans up the loser's snapshot and
skips the false domain event, and a new real-Postgres suite proves the race,
the coalesce, and the cleanup. The `resolveAllTrees` handle type tightens from
`AnyPgDb` to `PostgresJsDb` so the transaction boundary this registry declares
for the SDE tables is truthful in types. Contract §§3–6 are satisfied without
widening: no RLS is enabled, no schema redesign occurs, Convex placement rules
are untouched, and no vendor-resilience work begins.

## Resolved implementation decisions

- **Contract PD-1 — Registry home: a sibling registry module read by the same
  census test.** `src/composition/data-ownership-registry.ts`, a peer of
  `table-growth-registry.ts`, exporting `DATA_OWNERSHIP` (56 entries keyed by
  `PgTable` reference, reusing the growth registry's key function),
  `DATA_CLASS_DECISIONS`, the `SliceId` closed vocabulary with
  `sliceOfPath()`, and `describeDbInvariants(table)` (normalizes live
  `getTableConfig` metadata into comparable strings).
  `dataset-declarations.test.ts` consumes it exactly as it consumes the three
  existing registries. **Rejected:** extending `TABLE_GROWTH_STORIES` with
  ownership fields — it would overload a registry whose single purpose is
  growth stories, force all 57 entries through a shape change, and tangle two
  change axes (growth policy vs ownership policy) in one declaration.
- **Contract PD-2 — Race-exposed invariants: exactly one warrants a
  constraint; the rest are recorded judgments.** The full candidate set from
  the live survey, with per-item resolution recorded in registry notes:
  - **Constraint (ships):** `owned_assets` natural-key uniqueness
    `(owner_type, owner_id, type_id, location_id, location_flag,
    location_type)`. The ESI projection aggregates by exactly this key before
    every write (`esi-projection.ts` `aggregateAssets`), yet two concurrent
    `saveOwnedAssets` for one owner (on-view refresh racing the drain worker)
    can interleave delete/insert and silently double the ledger the planner
    sums. Race-exposed, cleanly expressible, invalid-writes-only — the only
    candidate meeting all three tests. Honest residual: two racing sets that
    share no natural key can still merge into a union; recorded in the
    registry note.
  - **Not expressible as plain constraints (recorded, no change):** the
    per-user caps on `custom_structures` and `saved_plans` (cardinality needs
    a trigger or counter — out of contract scope) and the "≥1 linked
    character" invariant (a minimum-child rule). Recorded as
    application-enforced with their honest residual races; the
    `custom_structures` missing compensating recount and the `saved_plans`
    over-correcting compensation (two concurrent saves at 49 can delete both
    rows) are routed to `docs/backlog.md` as application-behavior defects this
    contract forbids fixing here. `owned_blueprints` shares the identical
    replace-all race but has no natural key (raw per-item rows are legitimate
    duplicates), so no constraint can express it; recorded as a residual, not
    a non-issue.
  - **Not race-exposed (recorded, no change):** `tax_pct` bounds and
    rig-array length are Zod-enforced on every write path; concurrency cannot
    produce an out-of-range value, so they fail the contract's
    "genuinely race-exposed today" test. Recorded as application-validated.
  - **Deliberate absences preserved (recorded, no change):**
    `user.active_character_id` stays FK-less (documented write-ordering
    rationale at `auth-schema.ts`, plus a self-healing resolver);
    `user_preferences.key` stays JS-validated by documented design; admin
    merges keep their compare-and-swap + `account_provider_account_idx`
    backstop.
  **Rejected:** shipping the `CHECK` constraints for tax/rig bounds anyway —
  defense-in-depth beyond the contract's race-exposure test, and it would
  widen the migration surface for zero concurrency payoff.
- **Contract PD-3 — Data-class taxonomy: five classes mapped to the runbook
  role model.** `global-reference` (SDE/universe/wormhole catalogue/market/
  indices/GSC/meta), `identity-credential` (`user`, `session`, `account`,
  `verification`, `jwks`, `characters`, `corp_access_audit`), `personal`
  (skills, character jobs, owned assets/blueprints + syncs, saved plans,
  custom structures, preferences, usage logs), `corp-shared` (corp jobs +
  syncs, corp structures/syncs/sharing/rigs), `operational`
  (`esi_snapshots`, `esi_refresh_jobs`, `domain_events`). Every class resolves
  to `application-authorization-only`: the live role model is one shared
  runtime role (today `neondb_owner`; post-cutover `lgi_runtime`) with no
  per-request database identity, so RLS policies would bind to nothing until
  the identity-propagation campaign (backlogged, XL) runs; each decision
  records that justification and the campaign as its review trigger.
  **Rejected:** a per-table decision without classes — 56 near-identical
  records obscure the actual decision axes; and any `application-plus-rls`
  grant today — it would violate DEP-4/HC-3 with no enforcement identity to
  bind to.

### Interfaces and contracts

- `DataOwnershipEntry` — `{ table: PgTable; owner: SliceId; reads: 'open' |
  readonly { by: SliceId; purpose: string }[]; writers?: readonly { by:
  SliceId; reason: string }[]; invariants: readonly string[]; boundary: {
  kind: 'single-statement' | 'transactional-batch' | 'ordered-sequence' |
  'adapter-managed' | 'read-only'; note: string }; dataClass: DataClassId }` —
  `writers` lists scanner-visible permitted writers beyond the owner;
  scanner-invisible writers (Better Auth adapter, raw string-literal script
  SQL) are named in `boundary.note`. Draft contract comment: `/** One table's
  ownership, access, invariant, boundary, and data-class declaration; the
  dataset-declaration census enforces exact cover and truth against live
  schema metadata. */`
- `DATA_CLASS_DECISIONS: Record<DataClassId, { decision:
  'application-authorization-only' | 'application-plus-rls'; justification:
  string; reviewTrigger: string }>` — every current value is
  `application-authorization-only`; the census rejects an
  `application-plus-rls` value while migrations contain no policy (keeping the
  vocabulary honest without enabling RLS).
- `describeDbInvariants(table: PgTable): string[]` — normalized, sorted forms:
  `pk(col,…)`, `unique(col,…)`, `partial-unique(col,…) where(<normalized
  predicate>)`, `fk(col→table.col)`, `check(name)`. Sources: `getTableConfig`
  `primaryKeys`, `uniqueConstraints`, `indexes` (where `isUnique`, including
  the `.where` predicate rendered to a normalized string), `foreignKeys`,
  `checks`, **and the `columns` array** — `column.primary` and
  `column.isUnique` are how column-level `.primaryKey()`/`.unique()` surface
  in drizzle 0.45.2 (`primaryKeys`/`uniqueConstraints` are empty for most
  tables). Pinned unit assertions: `describeDbInvariants(ownedAssets)`
  contains `pk(id)`; `describeDbInvariants(user)` contains `unique(email)`;
  `describeDbInvariants(esiRefreshJobs)` contains the partial-unique form with
  its predicate.
- `scanProductionWriteSites(rootDir: string): WriteSite[]` with `WriteSite =
  { file: string; slice: SliceId; table: string }` — walks production `.ts`
  under `src/` (excluding `*.test.ts`, `*.db.test.ts`, `test-support/`,
  `*.tsx`), resolves schema imports through `reflectedSchemaExports()`,
  detects `(db|tx|database).insert|update|delete(<schemaIdent>)` with
  **whitespace/newline-tolerant matching** (the dominant live form is a
  multi-line chain: `await db\n  .delete(ownedAssets)`), and `sql`-template
  writes interpolating `${<schemaIdent>}` whose template contains a
  word-boundary, statement-leading insert/update/delete/truncate keyword (so
  `updated_at` never matches). Contract comment states the four documented
  blind spots: raw string-literal SQL without a schema symbol
  (`backfill-users-if-empty.ts`), adapter-internal writes (Better Auth),
  variable-table calls (`universe.ts` `insertChunked`), and any future write
  through the `drizzle-schema` barrel namespace (mitigated by resolving barrel
  re-exports in `reflectedSchemaExports()`).
- `findUndeclaredCrossOwnerWrites(sites: readonly WriteSite[], registry:
  readonly DataOwnershipEntry[]): string[]` — pure; a site passes when its
  slice equals the entry's owner or appears in `writers`; failures name file,
  table, and the declaration that would sanction them.
- `saveOwnedAssets(owner, rows, etags, snapshotId?): Promise<'saved' |
  'superseded'>` — `'superseded'` means a concurrent refresh won the insert
  race (unique violation caught): no stamp, no revalidate, and the caller must
  discard its snapshot and emit no domain event. The sync caller in
  `owned-assets-sync.ts` is the only consumer; its snapshot-cleanup `catch`
  path extends to the `'superseded'` return.
- No production route, API contract, or schema-export-to-consumer changes.

### Control and data flow

Request-path runtime flow changes only inside the owned-assets save chain:
delete → insert → stamp stays sequential on neon-http; a unique violation on
the insert (concurrent refresh already replaced the set) returns
`'superseded'` without stamping or revalidating; the sync caller then deletes
the snapshot row it inserted for this attempt and skips `esi_snapshot_pulled`,
so no orphan snapshot and no false event survive — the winner's rows, stamp,
snapshot, and event stand. All census flow is test-time: reflection enumerates
tables, the registry supplies declarations, the scanner walks the source tree
once per run, and checks diff pure values. Migration flow: `0050` runs inside
the standard build-time migrator (schema-owner credential), dedup guard before
index creation; the plain `CREATE UNIQUE INDEX` (the migrator's transaction
rules out `CONCURRENTLY`) briefly write-locks `owned_assets` — accepted:
the table holds per-owner aggregated holdings (thousands of rows at current
scale, not millions), so the lock window is sub-second on the deploy path.

### Edge and failure behavior

- Concurrent `saveOwnedAssets` for one owner → loser hits `23505`, returns
  `'superseded'`; caller deletes the loser's snapshot and emits no event;
  winner's set, stamp, snapshot, and event stand; proven by the new db suite.
- Racing sets that share no natural key → the index cannot arbitrate; the
  union outcome is the recorded residual in the registry note (same class as
  the `owned_blueprints` replace-all residual).
- Production duplicates found by the SC-4 gate → the split trigger fires:
  stop, report to the operator, return through the lifecycle. The migration's
  dedup guard exists only for a duplicate created between the check and the
  deploy (keeps the highest-`id` row per natural key); it is expected to
  delete zero rows.
- Undeclared cross-owner write added later → census fails naming file + table
  + required declaration; the seeded fixture keeps the red path proven, and
  the positive found-set assertion (the four known cross-owner writers, by
  file + table, plus a total-count floor) keeps a degraded or empty scan from
  passing silently.
- Registry drift (table added/renamed/dropped, or a constraint changes) →
  exact-cover or invariant two-way diff fails with the exact table and the
  stale/missing string.
- Scanner blind spots (the four documented ones) → named in the contract
  comment and `boundary.note` prose so the limitation is visible, not silent.
- Postgres-less CI → the db suite skips via `describe.skipIf`; the census and
  scanner remain database-free and always run; `saveOwnedAssets` keeps
  cyclomatic ≤ 4 so the CI-side 0%-coverage CRAP stays far under the cap.
- Local dev without `pnpm db:migrate` → the harness clones the un-migrated
  `public` schema and the constraint tests would fail; the suite's header
  comment and SC-3 name the migrate-first requirement.
