## Why now

Version 3.10's thesis was that intended design becomes enforced design, and its
close audit found exactly the residue that thesis predicts: committed documents
describing a system the repository no longer is. Because the readers of this
repository are coding agents, those documents are not prose — they are
instructions. `CONTRIBUTING.md:34` currently tells an agent to import `@/lib`
from a UI primitive, which the `ui` zone's empty allow-list turns into a Fallow
`boundary-violation` and a failed gate; `README.md:139` sends a new schema to a
feature slice when ten of nineteen belong under `src/data/`. Correcting them is
the last thing standing between v3.10 and a clean cycle-2 audit, and the same
sweep exposed *why* the residue collected in these particular files: the
doc-reference checker never reads them. Fixing the claims closes the finding;
extending the checker stops the class from recurring silently.

## Resolved implementation decisions

- **Contract PD-1 — exact replacement wording for every claim: specified verbatim
  below as C1–C13, C16, and C17.** Each is a minimal in-place restatement built from a re-run
  live observation. `README.md`'s schema sentence names the three *owners* (feature
  slices, `src/data/` slices, `src/db/auth-schema.ts`) and the aggregator, and
  deliberately carries **no counts**, so it cannot restale when the nineteenth
  module becomes the twentieth. **Rejected:** a file inventory or a count ("19
  modules, 8 in features…") — it restales on the next schema and reproduces the
  exact defect being fixed.
- **Contract PD-2 — `docs/CONVEX.md`: drop the path, state archived status, name
  the live authority.** The checker already maps this token via `_ARCHIVE_REDIRECTS`
  to `../LGI Tools Document Archive/SCALING_AUDIT_FINDINGS.md`, so it emits a
  warning, not an error — the mechanical layer was never failing. The defect is
  that an agent reading a backticked repo path will attempt to read it, fail, and
  either waste a turn or reconstruct the content from memory. Dropping the path
  removes that, and the `_ARCHIVE_REDIRECTS` entry remains the durable record of
  where the document went. **Rejected:** citing `../LGI Tools Document Archive/…`
  directly — it resolves on no CI machine and invites the same failed read;
  **rejected:** keeping the backticked repo path with an "archived" label — still
  dangles a repo-shaped path that resolves nowhere.
- **Contract PD-3 — placement and wording of the two admitted observations: three
  separate README bullets (operator ruling) and two CONTRIBUTING invariant
  bullets.** README's three layer bullets insert between the existing `src/data/`
  and `src/app/api/` bullets, preserving the list's layer-descending order and its
  one-path-per-bullet form; the operator ruled on 2026-07-27 for three separate
  bullets over one combined bullet. CONTRIBUTING's two bullets append to the
  existing five-item "Architecture invariants" list, matching its bold-lead form.
  Neither document gains a section or loses a line elsewhere. **Rejected:** a new
  README "Responsibility layers" section — that is the document reorganization
  `OOS-5` forbids.
- **Contract PD-4 — the corrected generator line requires no test change, and the
  `ZoneMap.tsx` comment needs none.** `architecture-map.test.ts:49` byte-compares
  `renderMermaid(liveMap())` against the committed artifact, so regenerating makes
  it pass and *skipping* regeneration makes it fail — the rail already works in
  both directions. Its other pinned strings (`:150-153`) are edge forms and the
  fence marker, none of which is the legend line; the legend text is pinned
  nowhere. `architecture-map.generated.ts` carries no legend line at all
  (verified: zero matches for `forbidden`/`deny-by-default`/`%%`), so it
  regenerates byte-identical, satisfying `DC-4`'s "otherwise unchanged". The
  `ZoneMap.tsx` header is a comment with no assertable output; its behavior-bearing
  siblings at `:185` and in `zone-map-geometry.ts` already carry the coverage
  `HC-3` protects. **Rejected:** adding a legend-text assertion to the drift test —
  it would duplicate the byte-compare that already covers it.
- **Contract PD-5 — changelog: one `### v3.10.5.1 — 2026-07-27` entry with a

### Interfaces and contracts

- `_source_paths(root: Path) -> list[Path]` (`check_doc_refs.py:234`) — gains four
  repository-root entries. Its docstring stops saying "markdown surfaces", because
  `.env.example` is plain text. Return contract (a sorted, de-duplicated list of
  existing files) is unchanged, so `collect_findings` needs no adjustment.
- `_normalized_path_claim(token: str) -> str | None` (`:248`) — gains one
  placeholder rejection: a token containing a `path/to/` segment returns `None`,
  alongside the existing `X.Y`/`X_Y`/`vX.Y` template guard. This is what keeps
  `docs/workflows/schema/code-health-baseline.md:72`'s
  `exports(src/path/to/owner.ts)` fixture from becoming a false finding.
- **New** `_bare_path_claims(line: str) -> list[str]` — returns repository-root-prefixed
  path-shaped runs found *outside* backticked spans on one line, so bare and
  backticked claims share one resolution path. Preconditions: caller strips
  backticked spans first (reuse `_INLINE_CODE.sub`). **It must strip trailing
  sentence punctuation (`.,;:)`) from each candidate**, because live comments write
  paths as `src/scripts/migrate.ts,`, `src/proxy.ts).` and
  `docs/security/db-privilege-runbook.md):`; without stripping, truthful
  `.env.example` paths report as unresolved and `SC-8` cannot reach zero. A verified
  prototype of this exact design over all 127 live sources returns exactly one error
  before the C9 fix (`.env.example:20`) and zero after, with the seven pre-existing
  archive warnings unchanged and no duplicates. The checkers run on Python 3.9, so
  the helper uses `from __future__ import annotations` (already present) and no
  3.10+ syntax. Outputs feed the same
  `_path_exists` / `_declared_ignored` / `_ARCHIVE_REDIRECTS` / `_ALLOWLIST`
  pipeline, so a bare claim and a backticked claim of the same token produce the
  same verdict and the same `Finding` severity. Error behavior: no separate
  severity — an unresolved bare claim is an `error`, matching backticked claims.
- No production export in `src/` or `convex/` is added or changed. `ZoneMap.tsx`
  and `src/scripts/architecture-map.ts` change a comment and a string literal
  respectively; every exported signature, and `renderGeneratedModule`'s emitted
  content, stays identical.

### Control and data flow

No runtime data flow changes. One build-time flow changes:
`.fallowrc.json` → `buildArchitectureMap` → `mermaidSource` (the corrected legend
line) → `renderMermaid` → `docs/architecture-map.md`, executed by
`pnpm generate:architecture-map` and then byte-compared by
`architecture-map.test.ts:49`. The parallel `renderGeneratedModule` →
`src/features/devlog/architecture-map.generated.ts` path is unaffected because the
generated module emits no legend, so that artifact must come back byte-identical.

The checker's flow gains one branch: for each scanned line, backticked spans are
extracted as today, then the line with those spans removed is scanned for bare
claims; both streams converge on the existing resolution pipeline before any
`Finding` is emitted.

### Edge and failure behavior

- A bare path inside a fenced example (`exports(src/path/to/owner.ts)`) → **not** a
  claim, via the `path/to/` placeholder guard. Proven by a `test_doc_refs.py`
  fixture and by `SC-8` returning zero findings repository-wide.
- A bare path that is also archive-redirected or allowlisted → resolved by the
  existing tables, not re-reported, because both streams share one pipeline.
- Regeneration skipped after editing the generator → `architecture-map.test.ts:49`
  fails with a byte mismatch. This is the intended rail, not a defect to route
  around; re-run `pnpm generate:architecture-map`.
- A correction that cannot be made truthful without changing behavior,
  configuration, a boundary rule, or a rendered string → **stop and report**
  (contract split trigger and `G-1`); do not change the system to fit the prose.
- A source correction that cannot hold its current line count → refresh only that
