## Why now

3.10.2.1 finished the typed problem/endpoint contract system, so a mid-pipeline
rejection can finally be emitted through one mapper instead of inventing an
error path. The same-origin check has observed production traffic since
2026-07-13 without changing any response, which is exactly the evidence base the
enforcement flip was waiting on. Flipping now closes the last observe-only
security gap (backlog LGI-03) as the movement's single intentional production
behavior change, isolated in its own sub-version for independent rollback.

## Resolved implementation decisions

- **Contract PD-1 — rollout shape: direct flip, no reject-log-then-enforce
  window.** The observer has produced exactly the data a reject-log window
  would produce (route, offending origin, source) since 2026-07-13, so a window
  adds a second production behavior change and a second ships-alone cycle for
  zero new information. The evidence is read honestly: the observation point
  sits *after* the auth gate on 21 of 22 routes (only `feedback/route.ts:94`
  observes without a session gate), and SameSite=Lax already strips cookies
  from cross-site POSTs — so zero rows confirms *no authenticated cross-origin
  mutation was attempted*, which is precisely the full population the flip can
  newly reject: any request the flip would newly 403 must have carried a
  mismatched Origin/Referer and reached that same observation point. The flip
  is gated on the Ordered-work-1 review (HC-1). **Rejected:** a reject-log
  window — it duplicates the already-collected evidence and doubles the
  rollback surface.
- **Contract PD-2 — missing-provenance classification: allowed (proceed to auth
  gates), documented.** Every modern browser attaches `Origin` to cross-site
  `POST` (fetch, XHR, and form submissions), so a real browser CSRF attempt is
  caught by the mismatch branch; and Better Auth session cookies default to
  `SameSite=Lax` with no repo override, so cross-site `POST`s arrive without
  credentials and already fail `authorize`. A missing-both request is therefore
  a non-browser client or a privacy-stripped same-origin browser, and rejecting
  it breaks those legitimate callers for no modern-browser CSRF gain. Honesty
  notes recorded in the doc block: (a) the observer never logged
  missing-provenance requests (`same-origin.ts:38` returns before logging), so
  this decision rests on the platform guarantees above, not telemetry counts;
  (b) seven guarded routes accept form encodings
  (`parseFormBody`, `src/transport/route-body.ts`), so their defense rests on
  SameSite=Lax plus the enforced mismatch branch — not on content type.
  **Rejected:** rejecting missing-both — it would 403 privacy-proxy users and
  scripted personal use, and would invalidate every existing route test that
  builds header-less requests, all to defend against a vanishing legacy-browser
  population.
- **Contract PD-3 — Fetch-Metadata / content-type policy: deferred, recorded.**
  With mismatches enforced, missing-provenance allowed by the PD-2 rationale,
  and Lax cookies denying credentials to cross-site POSTs, a `Sec-Fetch-Site`
  or content-type gate adds marginal defense now. The deferral, its rationale,
  and its revisit triggers (a trusted sibling subdomain, a new class of
  cookie-authenticated mutation surface, or observed missing-provenance abuse)
  are recorded in the doc block, and the deferred policy becomes its own
  backlog entry so the remainder of the original LGI-03 text has a home.
  **Rejected:** shipping the policy now — it widens the only-behavior-change
  boundary (HC-6) and its main beneficiary population is already covered.
- **Contract PD-4 — coverage discovery mechanism: extend
  `same-origin-coverage.test.ts` to enumerate every `src/app/api/**/route.ts`
  whose source exports a mutating HTTP method (`POST`/`PUT`/`PATCH`/`DELETE`,
  detected as `export async function <M>` / `export function <M>` /
  `export const <M>`), and assert that set equals the union of three declared
  lists: `PIPELINE_MUTATIONS` (17), `DIRECT_MUTATIONS` (5), and a new
  `EXEMPT_MUTATIONS` map (12 entries, each with a recorded reason matching the
  route's live `// authz:` marker): service-auth internal (2:
  `internal/eve-characters`, `internal/eve-token`, `authz: service`); public
  rate-limited read-through refresh (2: `market-history/refresh`,
  `market-prices/refresh`, `authz: public`); public stateless compute (2:
  `eve/names`, `industry/build-location`, `authz: public`); authenticated
  stateless compute (1: `account/custom-structures/parse-fit`, `authz: auth`);
  public telemetry beacon (1: `telemetry`); Better Auth library-owned CSRF (1:
  `auth/[...all]`); authenticated personal-data refresh triggers (3:
  `industry/owned-assets`, `industry/owned-blueprints`,
  `industry/skill-levels`, `authz: auth`).** A new mutating route in none of
  the lists — or a listed route that stops matching its list's source
  assertions — fails. Cron routes export `GET` only and never enter the set.
  **Rejected:** a separate registry file — DEP-4 fixes the existing test as the
  rail, and a sibling registry would be a second owner of the same truth.
- **Contract PD-5 — documentation home: a single doc block at the top of
  `src/app/api/mutation-route.ts`.** That file is the pipeline owner the master
  plan names ("where `runMutationRoute` lives"); the block carries the intended
  order, threat model, live-order mapping (pipeline and direct positions),
  PD-2 classification, and PD-3 deferral, so the contract and its rationale
  live where the code changes. **Rejected:** a `docs/` page — it would decouple
  the contract from the owner and add a second place to keep true.
- **Plan — `requireSameOrigin` interface: return
  `{ ok: true } | { ok: false; failure: AppFailure }` (the pipeline's existing
  result grammar) with the failure built as
  `forbiddenFailure('cross_origin', 'Cross-origin requests are not allowed')`.**
  The telemetry write stays fire-and-forget inside the check on the mismatch
  path, so monitoring continuity survives the flip (post-flip events mean
  "rejected"). **Rejected:** throwing — the repository's boundary grammar is
  typed failures, not exceptions.

### Interfaces and contracts

- `requireSameOrigin(request: Request): { ok: true } | { ok: false; failure: AppFailure }`
  — draft contract comment: `/** Enforces browser same-origin on mutations:
  explicit Origin/Referer mismatches return a forbidden 'cross_origin' failure

  semantics are unchanged from the 3.9-era observer. */` Preconditions: none;

- Each of the 15 declared guarded endpoints — response union gains

  `runMutationRoute`'s signature is untouched.

### Control and data flow

Entry: a browser mutation hits a route → (pipeline) `runMutationRoute` runs
`authorize`; on success `requireSameOrigin(request)` — mismatch now returns the
failure and the pipeline responds `problemResponse(failure)` (403,
`application/problem+json`, correlation id) without invoking `parse` or
`handle`; otherwise flow is unchanged. Direct routes call the check at their
current positions and return their mapper's 403 on mismatch. The mismatch path
still fire-and-forgets `logUsageEvent('cross_origin_mutation')` to Neon
`usage_logs`. Cron (GET-only), service, and the 12 exempt routes never enter
this path. No cache, external-service, or persistence boundary changes.

### Edge and failure behavior

- Same-origin request (Origin or Referer matches request/canonical origin) →
  proceeds; no telemetry.
- Explicit mismatch (including `Origin: null` and malformed/unparseable
  provenance, both normalized to non-matching) → 403 problem
  (`forbidden`/`cross_origin`) + telemetry event; handler never runs.
- Missing both headers → proceeds to auth gates (PD-2, documented); no
  telemetry (unchanged).
- Preview deployments → canonical-origin resolution via `VERCEL_ENV`/
  `VERCEL_URL` and request-origin matching are byte-identical to today.
- Telemetry write failure → swallowed with the existing console error; the 403
  is still returned.
- Unauthenticated cross-origin request → still 401 (authorize runs first;
  order unchanged per HC-6).
