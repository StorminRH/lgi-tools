## Why now

Phases 1–3 hardened the data and architecture layers; Phase 4 is the
presentation system, and its first half is adoption. The 3.8 component arc
built the primitives but only `select` ever got a real rail, so bypasses
accumulated (37 action/toggle sites, 16 `title=` hints, ~1,145 page-scoped CSS
lines). This session makes adoption universal and mechanically enforced while
the "nothing changed visually" claim is still provable; 3.10.4.2's deliberate
restyling becomes safe to review only after this diff proves visually inert.

## Scope (the destination)

Every A1-dispositioned bypass surface consumes its owning primitive: ghost/text
action buttons wear `Button`, the two cockpit toggle groups wear compact
`SegmentedControl`, the sites filter rail wears pressable `ChipToggle` +

`scripts/audit_ui_system.py` retires. Contract §§3–6 are satisfied without

## Resolved implementation decisions

- **Contract PD-1 — rail form per family: strongest-reliable, two-tier.**
  Tier 1 (ESLint `no-restricted-syntax`, unambiguous): raw elements
  (`button`, `input` — with a selector-internal `:not(:has(JSXAttribute
  [name.name='type'][value.value='hidden']))` carve-out for the twelve
  server-action inputs — `textarea`, `table`, `details`), HTML-only `title=`
  (`JSXOpeningElement[name.name=/^[a-z]/] > JSXAttribute[name.name='title']`),
  `role="button"` in both JSX-attribute and object form — the object selector
  is `Property[key.name='role'][value.value='button']` (the value filter keeps
  `banner.tsx`'s `role: 'status' | 'alert'` map legal), `aria-pressed` on
  lowercase elements only
  (`JSXOpeningElement[name.name=/^[a-z]/] > JSXAttribute[name.name='aria-pressed']`,
  so migrated `Button`/`ChipToggle` consumers that forward it stay legal),
  extended class-const names
  (`/([aA]ction|[bB]utton|[hH]ead(ing)?)Class$|_(BTN|BOX)$|^SECTION_HEAD$/`
  added beside `inputClassSelectors` — `SECTION_HEAD` is the live legal-page
  const AD-023 names), and token-scope literals (`text-empty`,
  `(bg|text|border)-(pill|chip)-`, `--pct`, `industry-bar-fill`,
  `progress-fill`, `animate-pulse`, `skeleton-shimmer`, `toast.loading`).
  All spread into the existing 9 production scope blocks. Exemptions are
  narrow per-file flat-config blocks: one per owning primitive (e.g.
  `button.tsx` lifts only the button-element ban; `static-table.tsx` the table
  ban; `collapsible.tsx` + the two `content-browser*` files the details ban;
  `banner.tsx`/`pill.tsx`/`chip.tsx`/`chip-toggle.tsx`/`tones.ts` the
  pill/chip-token ban; `skeleton.tsx`, `progress-bar.tsx`, `empty-state.tsx`,
  `toast.tsx` their own token bans), one block for the two CCP-imagery files
  (`LoginButton.tsx`, `character-strip.tsx`) lifting the button-element and
  `aria-pressed` bans, and one block for the five disabled-control account
  forms lifting `title=`. Four further live `title=` sites have explicit
  dispositions (all recorded in the survey per HC-3): `NavTools.tsx:35` sits
  on the A2 `.nav-tool` surface — it joins the title exemption block as a
  declared temporary entry the census pins in `TEMPORARY_TITLE_SITES` and
  3.10.4.2 clears; `character-strip.tsx:85` and the `LoginButton.tsx` flat
  portrait link migrate their hints onto `Tooltip` like every other AD-018
  site; the AdminChip anchor's title is dropped (its restyled visible "Admin"
  label self-describes). The CCP block's census pin fixes each file's raw
  `<button>` count at exactly 1 (LoginButton's ghost Log-out button migrates
  in the same work item as the lift). Tier 2 (census, judgment-grade): loading literals,
  row grid signatures, card-surface strings, ad-hoc dot shapes,
  `role="alert|status"` placement, plus pinned rosters for every Tier-1
  exemption so a widened `files` glob or a new site inside an exempted file
  fails the census (the vendor-census "pin the exemption list itself" model).
  CSS families' rail is deletion + the census CSS-family checker + zero-
  reference sweeps. **Rejected:** ESLint `warn`-level loading-literal rules —
  `--max-warnings 0` makes any warn a failure, so judgment-grade patterns
  cannot ride lint; and a single broad `src/components/ui/**` exemption block
  — it would let any primitive use any other primitive's tokens, wider than
  "narrowly encoded".
