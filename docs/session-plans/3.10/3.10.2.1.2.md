## Why now

Session .1 shipped the typed primitives with one route proving them; every
other route still emits hand-built errors and every caller still receives an
opaque failure arm. Migrating the guards and the full route/caller surface now
— while the primitives are fresh and the wrapper seams still exist — turns .3
into pure deletion and unblocks 3.10.2.2's rejecting 403 and 3.10.3.1's
telemetry codes, which both consume the mapper and stable codes this session
spreads across the tree.

## Scope (the destination)

After this session, one typed chain serves every first-party surface:

- **Guard layer.** `route-guards.ts` gains zero-argument failure-returning
  cores (`checkSession`, `checkUserId`, `checkAdmin` — the session guards
  read `next/headers` internally, exactly like the wrappers they underpin;
  no `Request` parameter). The existing `require*` wrappers are re-expressed
  on the cores and now serialize through `problemResponse` (401
  `unauthenticated`; 403 `forbidden` — always `forbidden` for the admin
  guard, anonymous included). `requireBearerSecret` gains a request-taking
  core; its 401 stays `unauthenticated` and its unconfigured 500 becomes an
  `unexpected`-category problem with code `not_configured` and today's exact
  detail text. `stationManagerGate` returns `forbiddenFailure` values;
  `rejectUnknownSystemPin` returns
  `validationFailure('unknown_system', 'unknown system')`. `requireAdminPage`
  keeps its redirect. The Upstash unconfigured production throw keeps 500ing
  unshaped (unchanged .1 decision).
- **Parsers.** `parseFormBody` is re-typed to the failure contract:

  route-owned `invalid` callback now mapping `z.ZodError → AppFailure`
  (today's exact copy as `detail`). `ParsedBody` and the `Response`-carrying
  parse path disappear with `parseJsonBody` (DC-1/IS-1: body parsers return
  typed failures, no exceptions).
- **Mutation pipeline.** `runMutationRoute`'s `authorize` and `parse` slots
  both take failure unions; the pipeline maps `{ ok: false, failure }`
  through `problemResponse` — the only translation point it owns. All 17
  pipeline routes update their callbacks in the same step. Order (authorize →
  same-origin observe → parse → handle) is untouched.
- **Contracts.** The 11 v1-object modules redeclare 33 endpoints as v2; five

## Resolved implementation decisions

- **Contract PD-1 — migration batching: ten checkpointed steps, guard layer
  before routes, families in dependency order, deletions ride with their last
  consumer.** Endpoint-model prep → guard cores/wrappers (+ the full
  cross-family test sweep those bodies break) → parser/pipeline re-typing
  including the complete form-route error conversion (+ its test sweep) →
  five family steps → gates → final sweep. Each step ends in `pnpm verify`
  green; a step owns every test its wire changes break;
  `rateLimitGuard`/`parseJsonBody`/`ParsedBody` die in step 8 with their last
  consumers, so no checkpoint carries a dead export. **Rejected:** per-route
  checkpoints (52 verify cycles, no added safety) and one big-bang commit
  (violates HC-5).
- **Contract PD-2 — 429 body transition: flip directly; one characterized
  exception.** Zero first-party callers read an error body (verified across
  all 23 caller files, the 3 seam runners, Convex, and `RateLimitedBody`'s
  importers — comment-only). The one true body reader is the Better Auth
  client transport (better-fetch JSON-parses non-OK bodies) behind the auth
  catch-all's rate limiter; the app voids every `authClient` result, and the
  problem body is JSON exactly like today's `RateLimitedBody`. Because
  better-fetch does not surface response headers, characterization splits:
  a route-level test asserts status 429 + `Retry-After` + problem body; an
  authClient-level test asserts the parsed problem fields on `error` and
  no-throw. **Rejected:** a compatibility window serving both bodies — the
  only reader is characterized instead.
- **Contract PD-3 — cron responses: documented framework-owned delegation.**
  No client calls cron routes; Vercel's invoker branches on status only. The
  shell keeps `Response.json(outcome.body)`; the delegation is documented at
  `defineCronRoute` and pinned as a named exemption set (count 7) in the
  hardened classifier. Cron auth denials change shape only through the shared
  bearer guard. **Rejected:** 7 v2 cron contracts — declarations with no
  consumer that would still need a shell-level bypass for the lock/idle
  machinery.
- **Contract PD-4 — guard gate: a type-aware TS-AST classifier suite
  extending the `api-contracts.test.ts` precedent (which is AST +
  type-checker based).** Two layers: (a) exported cores (`check*`,
  `readJsonBody`, `parseFormBody`, `stationManagerGate`,
  `rejectUnknownSystemPin`, the sites query parser) must have
  typed-failure-union return types containing no `Response` arm — a core
  returning `problemResponse(...)` fails on its return type, closing the
  constructor-evasion hole; (b) the named modules may construct no `Response`
  by any spelling (constructor, alias, `globalThis`, imported helper), with
  the delivery-wrapper allowlist pinned exactly
  (`requireSession`/`requireAdmin`/`requireUserId`/`requireBearerSecret`/
  `requireCronAuth`), and a reverse sweep over `src/platform/auth`,
  `src/lib`, `src/transport`, `src/composition` failing any new
  Response-returning export outside the allowlist. Seeded fixtures: direct
  constructor, alias, `globalThis`, helper-wrapped, `problemResponse`-
  returning core, and a new-file fixture. **Rejected:** a constructor-only
  regex gate — evadable by aliasing and by typed cores returning mapped
  responses.
- **Contract PD-5 — same-origin coverage tracking: no assertion changes.**
  The test pins route inventory and guard-presence call text
  (`runMutationRoute(request`, `requireSameOrigin(request);`), not body
  shapes; the migration preserves both strings verbatim in all 22 routes.
  The enforcement flip stays in 3.10.2.2. **Rejected:** extending it to
  assert problem bodies — that duplicates the status-matrix suite's job
  inside a structural test.
- **Operator — internal service routes migrate route-side now.**
  `convex/lib/characterSync.ts:84-88` branches on `res.status === 404/409` and
  `!res.ok` and never reads an error body; the 200 body is unchanged. The
  routes get v2 contracts and problem errors; the Convex caller keeps its raw
  fetch until .3. This closes DC-5's 404/409/502 route-level proof on
  `internal/eve-token`. **Rejected:** deferring to .3 (operator overrode: no
  invented 404 elsewhere, no gap).
- **Operator — feedback path validation: one enforcement point, disclosed.**
  The schema regex re-created main's duplicate-validation defect (dead route
  check, unreachable declared code). It is removed; the route check owns the
  rule; the ordering assertion flips to `toHaveBeenCalledOnce()`; the PR body
  and as-built record disclose the accepted delta. **Rejected:** keeping both
  checks — dead code plus a lying contract vocabulary.
- **Plan — sites routes migrate response-side now with authored schema
  authority; builders stay .3.** The .3 contract's DEP-1 assumes every route
  and contract migrated; OOS-2 defers only the query/path builders. No
  runtime response schemas exist today — the wire shapes are hand-written
  interfaces (`types.ts`) that HC-4 classifies as duplicated wire interfaces
  once a schema exists. Decision: author `sitesListResponseSchema` and
  `siteDetailSchema` (non-transforming, full nested coverage) in the
  wormhole-sites contract module as the single authority; re-derive
  `SiteDetail`/`SiteListApiItem` via `z.infer`; delete the superseded
  hand-written interfaces; convert `sites-query.ts` to
  `validationFailure('invalid_query', <today's issue text>)`; prove nested
  validation with fixture tests parsing a real site payload. **Rejected:**
  a permanent classifier exemption (contradicts DC-2/DC-3 and .3's starting
  state) and `jsonBody(z.unknown())` (a contract that validates nothing).
- **Plan — `parseFormBody` re-types to the failure contract; the pipeline
  parse slot is a single failure union.** Contract DC-1/IS-1 require body
  parsers to return typed failures — a retained `{ response }` arm would be
  an unauthorized exception. `parseFormBody(request, pick, invalid)` keeps
  its field-picking shape but `invalid` becomes
  `(error: z.ZodError) => AppFailure` (today's copy as `detail`);
  `runMutationRoute` performs the sole `problemResponse` translation; the
  three direct form routes early-return `problemResponse(parsed.failure)`.
  **Rejected:** the `ReadJsonBodyResult | ParsedBody` union — it preserved a
  `Response`-typed parser arm the contract forbids.
- **Plan — structures wire type: schema-inferred, cast deleted.**
  `AvailableStructuresResponse` becomes
  `z.infer<typeof availableStructuresResponseSchema>` (string-keyed attribute
  maps — the runtime shape JSON always had); numeric-index coercion keeps
  consumers compiling (verified by a strict in-memory probe during planning).
  If any consumer genuinely requires `number` keys, the executor adds one
  pure tested boundary projection — never a cast. A negative type test pins
  the cast's absence. **Rejected:** keeping the `as unknown as` cast (HC-4)
  or re-keying the domain model (planner-internal churn out of scope).
- **Plan — problem `code` vocabularies: category defaults for guards, named
  codes for route-owned domain errors.** Guards emit `unauthenticated` /
  `forbidden` / `rate_limited` defaults; bearer unconfigured emits
  `not_configured`; every body-consuming endpoint's 400 declares at least
  `invalid_json`/`invalid_body`; all route-owned codes and preserved details
  are pinned in the code matrix below. **Rejected:** a global code registry —
  codes stay endpoint vocabulary per the brief.

### Control and data flow

Pipeline mutation (post-migration, e.g. saved-plans create): `POST` →
`runMutationRoute` → `checkUserId` (failure → `problemResponse` 401) →
`requireSameOrigin` observe (unchanged) → `readJsonBody` (failure →
`problemResponse` 400) → handler → domain failure → `apiResponse(endpoint,
409, conflictFailure('template_limit', …))` | success →
`apiResponse(endpoint, 201, body)`.

Form mutation (e.g. active-character): `POST` → `runMutationRoute` →
`checkSession` (failure → 401 problem) → observe → `parseFormBody` (invalid →
failure → pipeline `problemResponse` 400) → handler → domain failure →
`problemResponse(validationFailure('not_linked', …))` | success → 303
redirect (unchanged Location).

Service route (eve-token): `POST` → bearer wrapper (failure → 401/500
problem) → `readJsonBody` → lookup → `apiResponse(endpoint, 404|409|502,
failure)` | `apiResponse(endpoint, 200, body)`; Convex's status-only branching
observes identical statuses.

Browser caller: v2 `apiFetch(endpoint, …)` → closed union; callers branch on
`ok`/`status` exactly where they branched before. Cron and sites flows keep
their entry points; only error serialization changes.

### Edge and failure behavior

- Guard denial on any surface (browser, cron, service, form) → problem JSON
  with unchanged status; anonymous admin callers keep 403 (`forbidden`
  always). Verified consumers: zero first-party error-body readers; Vercel
  cron and Convex branch on status.
- Auth catch-all 429 → problem JSON; better-fetch (the one real body reader)
  JSON-parses it exactly as it parsed `RateLimitedBody`; the app voids
  `authClient` results. Characterization: route-level test asserts 429 +
  `Retry-After` + `problemBodySchema` parse; authClient-level test asserts
  the parsed problem fields on `error` and no-throw (better-fetch exposes no
  headers).
- Bearer secret unconfigured → 500 `not_configured` problem, detail
  `<ENV> not configured` (today's bytes as detail; status preserved).
- Upstash unconfigured in production → unchanged unshaped 500 throw.
- Cron work-stage throw → unchanged rethrow (framework 500); shell outcomes
  stay JSON.
- Form invalid field or domain error → 400/404 problem per the form code
  matrix; success redirects stay 303 with unchanged Location targets.
- Sites invalid query / unknown id → 400 `invalid_query` / 404 `not_found`
  problems; statuses, the closed-catalogue proxy boundary, and the 200 bytes
  unchanged (schema authored from the live wire shape; fixture test parses a
  real payload).
- Non-`/` feedback path → schema passes, rate-limit token consumed, route
  returns 400 `path_invalid` (`path must start with /`); over-limit callers
  see 429 first — the disclosed operator-accepted delta.
- v2 route returning an undeclared status is impossible at compile time via
  `apiResponse`; drifted wire bodies reach clients as `kind: 'protocol'`
  (unchanged .1 policy).
- 404/409/502 on eve-token serialize as problems with codes
  `not_found`/`reauth_required`/`upstream_error`; Convex maps them by status
  to skip/reauth/unavailable exactly as today.
