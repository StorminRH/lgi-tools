## Resolved implementation decisions

- **Contract PD-1 — rendering path: owned server-side JSX SVG, in permission-matrix form.** The generator emits a semantic graph; the tested pure helper `zone-map-geometry.ts` computes the matrix layout; dumb `ZoneMap.tsx` maps it to SVG elements. JSX SVG is the only lint-clean path: `dangerouslySetInnerHTML` is banned repo-wide with zero exemptions (so a committed `.svg` asset cannot be embedded), raw `<img>` and out-of-wrapper `next/image` are lint-banned, and the repo already ships this pattern server-side (`static-sparkline.tsx`, `stacked-share-bar.tsx`). The matrix form is the measured answer to graph density (23 nodes, 108 edges, ~21% density, 11 longest-path layers with six singleton rows, 90/108 edges spanning multiple rows): a node-link drawing is a hairball at this density, and drawing only the 25-edge transitive reduction would falsify semantics because Fallow permissions are not transitive — an unlisted direct edge is forbidden even when a path exists. The matrix shows all 108 edges with zero crossings, and its layer-sorted triangular shape makes acyclicity visible. The sub-version's flowchart deliverable is the committed, GitHub-rendered Mermaid intermediate the passage links to. Zero new dependencies, zero client-bundle bytes, so the contract's split trigger does not fire. **Rejected:** a client Mermaid runtime (heavy client dependency, presumed rejected by OOS-4); build-time Mermaid rendering (needs a DOM/headless-browser dependency against HC-2, and its output would still need a raw-HTML sink); a bus-routed schematic node-link (operator-declined: substantially more complex geometry for a worse legibility floor).
- **Contract PD-2 — artifact homes: split by consumer.** The Mermaid intermediate lives at `docs/architecture-map.md` beside its prose owner `docs/architecture-boundaries.md`: `docs/**` is Fallow- and ESLint-ignored and outside the Tailwind `@source "../"` scan (which covers only `src/`), and the fenced `mermaid` block is what GitHub actually renders (a bare `.mmd` file displays as plain text — verified against GitHub's diagram docs). The typed graph lives component-owned at `src/features/devlog/architecture-map.generated.ts`, matching the `**/*.generated.ts` Fallow ignore, imported only by the devlog feature. **Rejected:** a `content/devlog` asset — that tree is an assembled historical record deliberately excluded from living-path sweeps, the wrong home for living derived state, and its loader concatenates markdown rather than serving data modules.
- **Contract PD-3 — no embedded copy-paste Mermaid block.** The introducing passage links to the committed `docs/architecture-map.md` on GitHub, where the fenced flowchart renders and the raw source is one click away. **Rejected:** embedding the source in the devlog — it creates a second committed copy the drift test would also have to police and grows the locked excerpt census for no reader value.
- **Contract PD-4 — edge distinctness is derived, three classes, exact rules.** The generator classifies mechanically. *Allow*: every listed allow target that is a declared zone → `from --> to` in the flowchart, a filled ISK-green cell in the matrix. *Exception*: an allow target that is not a declared zone but is a child path of an `autoDiscover` group — today exactly the `data` band's `data/eve-data` reference core → `data -.->|reference core| data__eve_data` in the flowchart (ids sanitize `/` to `__`; labels keep the real name), a visually distinct ringed/hollow cell in the matrix. *First-match carve-out*: an ordered zone pair where every glob of the earlier zone is matched by some glob of a later zone, under stated semantics (`**` matches any depth; `*` matches exactly one segment) — today exactly `api` carved out of `app` → the arrowless dotted `api -. first-match carve-out .- app` in the flowchart, and an annotated marker on the carved-out zone's row label plus a legend entry in the matrix (it is a classification-precedence relation, not a permission cell). The flowchart carries no style directives — distinctness lives in link types plus the comment legend — and the matrix legend also states that an empty cell means forbidden (deny-by-default). The taxonomy census in the drift test pins today's derived sets so a config change updates them consciously. **Rejected:** hand-tagged edge lists (violates HC-1) and Mermaid `classDef`/`linkStyle` color styling (an ad-hoc palette in the intermediate).
- **Contract PD-5 — host: extend `content/devlog/06-rails/03-fallow.md`.** The Rails-chapter Fallow document already explains zones and boundaries in prose, so the map lands beside the text that explains it; the nav tree and document census stay unchanged. The passage (placed after the existing boundaries paragraph, followed by the marker line, date stamp updated) keeps these required elements — derived-not-drawn, the drift test, deny-by-default cell reading, visible acyclicity, the two special classes, and the GitHub link to the rendered flowchart — with this draft wording: *"That configuration is now also the diagram. The grid below is generated straight from `.fallowrc.json` — never drawn by hand — and a test fails whenever the committed map no longer matches the live rules. Each lit cell is a declared permission: the row zone may import the column zone, and an empty cell is forbidden — the map is deny-by-default. Every cell sits on one side of the diagonal because the dependency graph is one-directional. The ringed cell is the data band's single sanctioned reference-core exception, and the marked row is the one first-match pattern carve-out, where route handlers classify ahead of the page tree. The full flowchart source is committed alongside the rules"* with the link on the final clause. Exact wording may be polished in execution without dropping any element. **Rejected:** a new Rails document — it splits the map from its explaining prose and churns the locked nav census for no structural gain.

## Implementation blueprint

### Owned surfaces

- `src/scripts/architecture-map.ts` — owns parsing/validating the `boundaries` slice, edge classification, longest-path layering, the cycle guard, and deterministic rendering of both artifact texts; every function at or under cyclomatic 8 / cognitive 8.
- `src/scripts/generate-architecture-map.ts` — entry point (runs at import, like its siblings): reads `.fallowrc.json`, writes both committed artifacts; registered as `generate:architecture-map` in `package.json` scripts and appended to the Fallow `entry` array.
- `src/scripts/architecture-map.test.ts` — owns the drift lock (byte-compare of both committed artifacts, read via `node:fs`, against fresh regeneration — the generated module is never imported), double-run determinism, seeded-allow-edit divergence, seeded-cycle throw, malformed-config throw, and the pinned edge-taxonomy census.
- `src/features/devlog/architecture-map.generated.ts` — committed generated module: `architectureMap` const (`nodes` with `id`/`label`/`layer`/`kind`, `edges` with `from`/`to`/`kind`), no imports, no colors; lint-clean under the full `src/**` rule set (TSDoc-valid contract comment, no banned comment substrings, repo-relative literals only).
- `src/features/devlog/zone-map-geometry.ts` (+ co-located test) — owns the pure matrix layout: one layer-descending order (config declaration order as tiebreak) shared by rows and columns; cell coordinates from index math; label measurements from a fixed mono character-width constant; rotated column-header transforms; legend entries; viewBox. Small single-purpose functions (order, cells, labels, legend), each directly unit-tested.
- `src/features/devlog/components/ZoneMap.tsx` — dumb server component mapping the layout to `<svg>`/`<g>`/`<rect>`/`<text>` with token classes; emits `data-zone-map` plus node/cell counts as data attributes for the probe; wrapped in an `overflow-x-auto` figure with a minimum width so narrow viewports scroll the figure, never the page.
- `src/features/devlog/types.ts`, `parse.ts`, `components/DocumentView.tsx` — the `zone-map` block variant, its marker, and its renderer entry; `parse.test.ts` gains the marker assertions plus a negative census that no rendered block anywhere in the real tree contains a residual `uth:` comment literal.
- `content/devlog/06-rails/03-fallow.md` — the introducing passage, the marker, and the refreshed date stamp.
- `docs/architecture-map.md` — the committed Mermaid intermediate (fenced `mermaid` block, GitHub-rendered).
- `docs/ux-check/probes/devlog-zone-map.mjs` — structural probe for `/devlog/fallow`.

### Interfaces and contracts

- `buildArchitectureMap(config: unknown): ArchitectureMap` — validates the `boundaries` shape (throws a named `Error` on a missing/malformed block, an allow target that is neither a declared zone nor an `autoDiscover` child, or any cycle in the allow graph, naming both ends of the back edge); returns nodes (declaration order; `autoDiscover` groups flagged; `data/eve-data` appended as the referenced child) and classified edges with layer numbers. Contract comment: /** Derive the zone-level dependency graph from a parsed `.fallowrc.json`. */
- `renderMermaid(map: ArchitectureMap): string` and `renderGeneratedModule(map: ArchitectureMap): string` — pure text emitters, LF, trailing newline; each output carries a header comment naming the generator and regeneration command with repo-relative paths only; Mermaid ids sanitize `/` to `__` while labels keep the real zone name; `renderGeneratedModule` emits a TSDoc-valid /** */ contract comment directly above `export const architectureMap` so the generated file passes the `jsdoc/require-jsdoc` and `tsdoc/syntax` rails without any exemption. Both emitters carry their own /** */ contract comments.
- `architectureMap` (generated const, `as const`) — the devlog's only data source for the map; its type is derived via `typeof` in `zone-map-geometry.ts`, so the generated file imports nothing.
- `layoutZoneMap(map): ZoneMapLayout` — pure; returns `{ width, height, order, cells: [{ x, y, from, to, kind }], rowLabels, columnLabels, carveOutMarkers, legend }`. Contract comment: /** Deterministic matrix layout for the zone map SVG; no color decisions. */
- `ZoneMap(): JSX` — server component; renders the figure, overflow wrapper, the SVG with `<title>`, and the legend. No props (the committed module is its single source).
- `Block` union gains `{ type: 'zone-map' }`. The marker seam is pinned: `parseProse` recognizes the exact trimmed line `<!-- uth:zone-map -->` as a block boundary — it flushes any accumulated paragraph and emits the `zone-map` block directly, so a marker adjacent to prose cannot be silently absorbed into a joined paragraph. `BLOCK_RENDERERS` is the single compiler-enforced consumer; `documentSummary`, `eachExcerpt`, and `rebuildTree` narrow at runtime and correctly ignore a text-free block (verified, not compiler-guaranteed).
- No production API route, schema, or env surface changes.

### Control and data flow

Generation time (developer/CI only): `pnpm generate:architecture-map` → read `.fallowrc.json` → `buildArchitectureMap` → write `docs/architecture-map.md` + `src/features/devlog/architecture-map.generated.ts`. Render time: `/devlog/fallow` → `loadDevlog()` (`'use cache: remote'`, unchanged) → `parseDevlog` resolves the marker into the `zone-map` block → `DocumentView` → `ZoneMap` → `layoutZoneMap(architectureMap)` → static SVG in the RSC payload. No client JS is added, no runtime IO changes, and route classification (`/devlog/[slug]` = `partial`) is unaffected because the component uses no dynamic API.

### Edge and failure behavior

- Cycle introduced in a future config → `buildArchitectureMap` throws naming both ends of the back edge; generation and the drift suite fail loudly rather than rendering a wrong map.
- Allow target that is neither a declared zone nor an `autoDiscover` child → named throw (no silently dropped edge).
- Malformed or missing `boundaries` block → named throw; the drift suite covers one seeded malformed case.
- Config drift without regeneration → the drift test's byte-compare fails in `pnpm verify` and CI.
- Marker not recognized (regression in the parse seam) → the `parse.test.ts` negative census fails on the residual `uth:` literal in a rendered block; nothing renders silently as prose.
- Narrow viewport → the figure wrapper scrolls horizontally (`overflow-x-auto` + minimum width); the page body never gains horizontal scroll.
- Devlog marker present but renderer missing → impossible to ship: the `BLOCK_RENDERERS` mapped type makes it a compile error.
