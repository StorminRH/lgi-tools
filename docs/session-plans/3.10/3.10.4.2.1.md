## Why now

Sub-version 3.10.4.1 made primitive adoption universal and railed it, which is the precondition that lets a change to one shared primitive land everywhere instead of chasing hand-rolled stragglers. The site still reads as instrumentation because JetBrains Mono is the page default and uppercase with wide tracking is the default treatment for buttons, tabs, nav cells and menu rows; every page wears the same 1280px frame, the same 30–42px title and the same bordered card; and mobile is the desktop composition narrowed rather than a designed mode. This session spends that adoption dividend: it moves the remaining refinement decisions into tokens and primitives, retires the last four page-scoped CSS families the adoption bundle parked on a temporary allowlist, and turns the observed breakpoint set into a declared ladder — completing outcome groups B and C and closing outcome group A's final debt.

## Resolved implementation decisions

- **Contract PD-1 — Type-role assignment and surviving uppercase: three roles, with uppercase reserved for the eyebrow.** `--font-mono` is set to `initial` so the utility and the key both disappear; `--font-ui` (Geist) becomes the `html, body` default and `--font-data` (JetBrains) is stated explicitly on data surfaces; `--font-display` (Barlow) is unchanged; `--font-jb` and `--font-body` are deleted. Because a retired token makes its class compile to nothing rather than error, a `no-restricted-syntax` ban covering the three legacy font classes *and* the four retired tracking steps is the mechanical detector; it lands in the pull request with the migration it governs, at all eleven places `eslint.config.mjs` spreads `textSizeSelectors` **plus** the `src/app/preview/**` block at line 1327, which re-states its bans without them. Tailwind preflight points bare `code`, `kbd`, `samp` and `pre` at `--default-mono-font-family`, which resolves through `--font-mono`, so a `code, kbd, samp, pre { font-family: var(--font-data) }` base rule is added or code blocks silently fall to the browser monospace stack. The tracking scale goes from eight steps to five: the four retired steps map onto their nearest survivor, `copy`, `label`, `wide` and `eyebrow` survive unchanged, and one new `--tracking-optical: 0.01em` step absorbs the thirteen `[0.01em]` and four `[0.02em]` arbitrary escapes. Class-string assignment is mechanical, first match wins: a class string containing `tabular-nums`, a chart or SVG source file, a `break-all` or `truncate` identifier, field, stepper or terminal text, or membership of the enumerated identity-and-status list takes `font-data`; inside `src/components/ui/**` everything else takes an explicit `font-ui`; elsewhere the class is deleted and the element inherits. `Card`'s own `font` prop is part of this migration: its value vocabulary moves from the deleted face names to the role names, with one call site to update. The rule alone is insufficient, because elements carrying no font class inherit mono today and would silently flip; step 5 of the ordered work is the enumerated sweep that closes that gap. Uppercase survives on the eighteen label-bearing primitives and on the two Barlow titles; it is dropped from Button, Segmented, Tabs, the header tool cells, account-menu rows and hamburger rows. **Rejected:** keeping mono as the page default and opting primitives in one by one — it leaves every unconverted surface mono forever and forfeits the propagation the whole version exists to buy.
- **Contract PD-2 — Route-to-mode mapping, Card classification and glow: a required mode, a conservative Card rule, and a recorded glow audit.** `PageShell` takes `mode: 'workspace' | 'reading' | 'detail'` as a required prop, because all twenty consumers are page or layout default exports under `src/app/**`, neither `error.tsx` nor `not-found.tsx` uses the shell, and a required prop makes `npx tsc --noEmit` the migration checklist. `workspace` is the frame plus a bottom region gap; `reading` adds a centred 760px measure; `detail` adds a top region gap and is the set of routes whose primary content titles itself. Mapping: `detail` for `/`, `/sites/[id]`, `/industry/[id]`, `/admin/access/[userId]`, `/preview/cards`; `reading` for `/industry/templates`, `/jobs`, `/skills`, `/structures`, `/characters`, `/settings`, `/contact`, `/legal`; `workspace` for `/sites`, `/industry`, `/changelog`, `/devlog`, `/admin`, `/admin/access`, `/preview/primitives`. `/admin/access/[userId]` is the one `detail` route that also wants the narrow measure — its own four `max-w-[760px]` wrappers and its not-found `PageHead` all stay, because inventing a fourth mode for a single route is worse than one call-site wrapper. Cards keep their border when the populated state is an object, control group or data region; a Card whose only child is an already-bordered Callout or Banner loses the Card; a Card standing in for a sibling or successor data region while loading, empty or unavailable keeps its shell so the panel does not materialise when data lands. Applied honestly the rule fires on exactly three of the twenty-one candidate sites, so the survey's "twenty-one spacing wrappers" reads more accurately as three redundant wrappers and eighteen state-dependent surfaces; that re-reading is listed for operator ratification. Glow is audited and recorded rather than changed wholesale: the four `Card hover` sites are genuinely clickable surfaces, the banner dot, `Dot`, `.status-led` and `.industry-bar-fill` glows are live status, the planner's ME ring drop-shadow is value-driven, and the only two findings are the declared-but-unreferenced `--shadow-home-live`, which is deleted, and the changelog timeline node's single arbitrary decorative shadow, which is recorded for the punch list. **Rejected:** a defaulted mode, which would let an unmigrated route look correct and silently skip the decision; and a new borderless `Section` primitive, because after the rhythm token lands the pattern's entire hand-roll is one bottom margin on nine sites.
- **Contract PD-3 — Surviving header seams: cluster borders only, no sticky treatment.** The per-cell `border-right` between tool links, the strip's own leading hairline and the 0.13em tracking are removed; the bottom active rule survives as an `after:` pseudo-element on the cell, and the brand cell's trailing border and the status/account cluster's leading borders survive. The header is not made sticky and gains no translucency or backdrop blur — the operator ruled it out on 2026-07-26 after the upstream implementation was shown to depend on a Framer Motion scroll fade this repository has no equivalent for, and no done condition asks for it. The header's responsive block is *not* dissolved into utilities: `.nav-host` and `.nav-search` are un-layered rules with a `!important` width, and un-layered declarations outrank Tailwind's layered utilities, so one `@media (width < 64rem)` block survives in `globals.css` owning exactly those two retained families. - **Contract PD-4 — Mobile contents affordance and settings placement: a bottom drawer and an in-popup settings group.** A new `src/components/ui/drawer.tsx` wraps Base UI's `Drawer`, entering from the bottom with `max-h-[75dvh]` and internal scroll, uncontrolled with a real `Drawer.Trigger` so Base UI owns focus restore, and with `swipeDirection="down"`. - `src/app/globals.css` — owns the three font roles, the type ladder including the navigation and title tiers, the retuned five-step tracking scale, the rail state colors, the four-step rhythm ladder, the reading and frame containers, the declared breakpoint ladder, and exactly one surviving responsive block for the two retained navigation-host families.
- `src/components/ui/cn.ts` — owns the class-merge registration for every named token family, including the spacing scale and container namespace it has never covered.
- `src/components/ui/page-shell.tsx` and `page-head.tsx` — own the page frame with per-mode rhythm and the reading measure, and three title sizes with the size-dependent subtitle plus the exported title recipe the one bespoke entity header consumes.
- `src/components/ui/navigation-menu.tsx` — owns the navigation cell recipe for the desktop strip and the hamburger rows. `src/components/ui/dropdown-panel.ts`, re-exported through `menu.tsx` — owns the full-width menu row, separator, section, section label and control row. `src/components/ui/type-roles.ts` — owns the eyebrow recipe.
- `src/components/ui/content-browser.tsx` and `content-browser-nav.tsx` — own the desktop rail layout, the layered state model, the mobile chapter bar and drawer composition, and the `data-*` probe hooks. `src/components/ui/drawer.tsx` — owns the bottom-sheet surface and its swipe, focus and reduced-motion behavior.
- `src/composition/ui-adoption-census.ts` and `ui-adoption-registry.ts` — own the pure stylesheet scan and the now-empty temporary allowlist. `eslint.config.mjs` — owns the legacy font and tracking class ban and the Base UI wrapper allowlist.
- `scripts/ux-capture-args.mjs`, `scripts/ux-capture.mjs`, `docs/ux-check/run-probes.mjs`, `docs/ux-check/README.md` and the probe files `nav-menu.mjs`, `content-browser-scroll.mjs` and `changelog-browser.mjs` — own the width matrix, the per-viewport browser-context mapping, the reduced-motion context option, the collapsed-header capture at every viewport that shows the hamburger, the durable definition index rows for the three new probes, and the migration from retired class selectors to `data-*` hooks.

### Interfaces and contracts

- `PageShell({ mode, className, children })` — `mode: 'workspace' | 'reading' | 'detail'` is **required**. Draft comment: *"The ONE shared page frame. `mode` declares what kind of page this is and is required so a new route cannot silently inherit someone else's rhythm: `workspace` fills the frame, `reading` centres the article measure, `detail` adds the top rhythm a self-titling page would otherwise hand-roll. Purely presentational, so wrapping a page tree in it never flips a route's render mode."*
- `PageHead({ crumb, title, subtitle, meta, size })` — `size?: 'hero' | 'page' | 'compact'` defaults to `page`. Title tokens are the display, title and 26px tiers respectively; the subtitle renders as Geist sentence case for `hero` and `page` and keeps today's mono uppercase label treatment for `compact`, which is exactly the split between call sites passing sentences and call sites passing terse data. Also exports `PageTitle({ size, className, children })`. Draft comment on the export: *"The page-title recipe on its own, for the entity headers that cannot use the full scaffold — the same carve-out `Breadcrumb` already makes, so a portrait header still wears the one title treatment."*
- `Drawer({ title, trigger, triggerClassName, className, children })` and `DrawerClose` — deliberately minimal: a bottom sheet, uncontrolled, with a real trigger. No side variants, no controlled open state, no focus refs and no description, because this session has exactly one consumer and the repository forbids speculative configurability. Draft comment: *"The edge-anchored sheet: a bottom drawer with swipe-to-dismiss, for the small-screen composition a centred Dialog cannot serve. Uncontrolled by construction — the trigger is real, so Base UI owns focus movement and restore."*
- `titleForSlug(model, slug)` in `content-browser-view.ts` — pure and server-safe, returning the display title for a slug or `null`. Draft comment: *"The active document's title for the compact chapter bar. Pure so the bar's server fallback and its live client value share one lookup."*
- `navigationMenuLink({ surface, state })` in `navigation-menu.tsx` — `surface: 'bar' | 'panel'`, `state: 'rest' | 'active' | 'soon'`. Draft comment: *"The one navigation cell recipe, worn by the desktop strip and the hamburger's restacked rows. `panel` replaces the old descendant rule so the popup no longer reaches into the cell; `soon` omits hover rather than excluding it."*
- `eyebrow({ size, tone, weight, emphasis })` in `type-roles.ts` — draft comment: *"The eyebrow role: the micro-caps label above or beside content. One owner for the treatment that had drifted across six tracking steps, composed into whatever element the caller already owns."*
- `unexpectedFamilies(css, allowed)` and `deadAllowlistEntries(css, allowed)` in `ui-adoption-census.ts` — pure functions over stylesheet text so the census can be seeded with synthetic CSS. Draft comment: *"The page-family census as pure functions, so the gate proves both directions — an unrecorded family and an allowlist entry nothing needs any more — and can be seeded rather than only run against the live stylesheet."*
- `Callout({ label, children, className })` — gains the optional `className` its in-card callers now need; its base string loses the margins that assumed a Card parent.
- `Card({ hover, font, as, className, ...rest })` — the `font` prop's value vocabulary changes from the two deleted face names to `'ui' | 'data'`, still defaulting to the page face, because the old values emit classes that no longer compile. One call site passes it today. Draft comment addition: *"`font` names the semantic role, not the face — a card whose body is prose stays on the interface face, a card that is a readout states the data face."*

### Control and data flow

No runtime data flow changes. The one flow that matters is the render-mode contract, and it is preserved exactly. `ContentBrowser` stays a server component and authors both Suspense boundaries itself: the existing one around `ContentBrowserNav` with its `activeSlug` null fallback, and a new one around `LiveChapterTitle` whose fallback is the same bar with an empty title slot. Within the ContentBrowser family, `usePathname` is read by exactly three client components — `ContentBrowserNav`, `LiveChapterTitle`, and the drawer's close-on-navigation effect. The first two sit inside those boundaries. The third is rendered inside `Drawer.Portal`, whose `keepMounted` defaults to false, so that subtree does not exist during prerender at all. Close-on-navigation is primarily a delegated click handler on the sheet's nav wrapper driving the root's `close()` action, with the pathname effect as the back-and-forward backstop, because the layout persists across soft navigation. Nothing about where request-time data is read moves, so `scripts/route-classification.json` is not edited, `pnpm assert:routes-present` stays green, and the binding render-mode assertion runs inside Vercel's production build after merge — which is the only place repository policy allows a production build to run.

### Edge and failure behavior

- A route added later without a PageShell mode → `npx tsc --noEmit --incremental false` fails. This is the rail for the mode migration.
- A stale legacy font or tracking class left behind → the class compiles to nothing and the element silently inherits. The ESLint ban is the mechanical detector, covering plain literals and template elements, at twelve insertion points including the preview block that re-states its bans without the shared list.
- An element that carries **no** font class today → it inherits mono now and Geist after the flip, and no lint rule can see it. The step-5 sweep is the detector: every call site of the value, currency, duration, countdown and identifier formatters is checked for an explicit data-face ancestor, with the live job status column, the sites table's value cells, the skill-queue timers and the planner readouts named as known members of the set.
- A retired token name written inside a surviving stylesheet comment → the census retired check uses substring matching over the whole file including comments, so comment text mentioning a retired class fails the gate. Comments are rewritten, not preserved.
- The reduced-motion user → every new transition carries the motion-reduce guard, including the drawer's enter and exit; the rail's only transition is a colour cross-fade with nothing positional to animate, which also fixes today's unguarded raw duration literal on the nav item. The swipe-follow transform is deliberately unguarded and is listed for ratification.
- The rail's first paint on the static document routes → the server fallback renders with no active slug, so the guide is present but the marker and group wash appear only once the client boundary resolves. This is today's behavior made slightly more visible by the wash; it is called out in the sweep and shown to the operator rather than hidden.
- A route with no registered page-settings spec → the menu control resolver returns empty and the section renders nothing, so the hamburger shows tool rows then the login footer with no orphan divider, exactly as today.
- The mobile drawer's group folders reset to open each time the sheet opens, because the portal subtree unmounts on close while the desktop rail's disclosure state survives soft navigation. Accepted and recorded.
- A ux-check probe or capture script selecting a retired class → the capture helper fails silently and the probe fails loudly. Both are migrated to `data-*` hooks in the same commit, and the two selectors already dead since 3.10.4.1 are repointed so this session's evidence is not built on false confidence.
