## Bottom line (READ FIRST)

- **GOAL:** Every production external dependency has one declared resilience
  policy in a single typed registry, every external call site routes through its
  declared wrapper with an explicit timeout, and lint plus a census test fail on
  any direct vendor call made outside its registered adapter.
- **DONE =** SC-1 through SC-7 below, plus this observable result: the registry
  module and its census pass listing every integration, the whole-tree sweep
  shows no bare `fetch(` and no vendor-client construction outside sanctioned
  files, and a seeded direct vendor call turns lint red.
- **OUT OF SCOPE:**
  - Circuit breakers or any new resilience infrastructure (contract OOS-1) — an
    executor noticing repeated failures must record the observation, not build
    breaker machinery.
  - Telemetry emission (contract OOS-5) — the registry only *records* each
    integration's existing telemetry field names; no new pipeline, metric, or
    logging is built.
  - Code-review-bot configuration and any docs/lifecycle git-tracking change —
    an operator-considered rider that was explicitly withdrawn on 2026-07-25;
    it is deferred to the planned doc-system discussion, not absorbed here.

## Why now

Sub-versions 3.10.2.1 through 3.10.2.3 closed the typed error contract, the
mutation pipeline, and data ownership; resilience is the last Phase 2
correctness gap. Today only ESI has the full pattern (wrapper + explicit
timeout + host ban); three Redis sites and the Neon drivers run on implicit SDK
defaults — no timeout at all, with five silent exponential retries on Redis —
and one raw vendor `fetch` sits outside any wrapper. A hung vendor call
currently stalls a serverless function toward the 300-second platform limit
instead of failing fast into the degradation paths the code already has. This
session closes those gaps and hands Phase 3 (3.10.3.1 telemetry) the declared
retry/rate-limit vocabulary its outcome fields need.

## Scope (the destination)

The finished slice has one typed registry —
`src/composition/vendor-resilience-registry.ts` — recording, for every live
external integration, the eight contract fields: wrapper entry point, timeout,
retryable error classes, backoff/jitter policy, rate-limit behavior,
idempotency stance, degradation behavior, and telemetry fields. The one
integration with no programmatic call surface (the Vercel platform, whose only
src artifact is the build-injected Speed Insights beacon component) records
that fact explicitly instead of a fabricated policy; the client-side CCP image
CDN records its real client-side policy (browser-owned fetch with no
app-controlled timeout or retry, broken-image degradation) rather than a
false absence. A census test in `src/esi-datasets/vendor-resilience.test.ts`
binds the registry to reality: declared wrapper modules exist and export the
declared symbols, vendor-client construction inventories match pinned
found-sets, and every `urllib` call in `.agent-local/*.py` carries an explicit
timeout. ESLint rails make the registry enforceable: a bare-`fetch` ban outside
the two sanctioned transport modules, a vendor-package import rail
(`@upstash/redis`, `@upstash/ratelimit`, `@neondatabase/serverless`,
`postgres`, `better-auth`, `convex/react`, `google-auth-library`) allowlisted
to each wrapper home, and a `login.eveonline.com` host-literal ban mirroring
the existing ESI host rail with `src/proxy.ts`'s CSP source list as a named
exemption.

Runtime behavior changes only where the contract mandates resilience: the three
unwrapped Redis sites gain explicit 2000 ms timeouts with declared retry counts
(zero for fire-and-forget hints, one for the request-path rate limiter, which
covers transient non-abort network errors — a timeout abort rethrows
immediately by SDK design), the Neon HTTP driver gains a 30 000 ms per-query
bound through the global `neonConfig.fetchFunction` hook (assigned lazily; the
lone `neon()` consumer is `src/db/index.ts`), the cold-start classifier gains a
timeout-abort carve-out so the new bound cannot multiply through the retry
envelope, the postgres-js clients make their 30-second establishment bound
explicit, and the Google Search Console calls gain the shared 10-second
outbound bound (analytics fetch via `fetchWithTimeout`, token fetch via the
SDK's `transporterOptions` timeout). Vendor types stop leaking at the database
boundary: `src/db/index.ts` exports owned `Sql` and `ReservedConnection`
aliases and the four production type importers repoint to them. Every
degradation path, return type, and caller contract is otherwise preserved.
Contract sections 3 through 6 are satisfied without widening: no circuit
breakers, no vendor change, no ESI-gate rewrite, no neighboring Phase 2 scope,
no telemetry pipeline, and no UI/schema/dependency changes.

## Resolved implementation decisions

- **Contract PD-1 — Registry form: typed module consumed by a census test.**
  `src/composition/vendor-resilience-registry.ts` exports a closed
  `VendorIntegrationId` union and a `vendorResilienceRegistry` record; the
  census in `src/esi-datasets/vendor-resilience.test.ts` is its sole consumer.
  This copies the proven 3.10.2.3 pattern (`data-ownership-registry.ts` +
  `dataset-declarations.test.ts`): the type system enforces field completeness
  (HC-4) at compile time and the census enforces reality-binding at test time.
  `src/composition/` is the sanctioned cross-slice home, `src/esi-datasets/`
  the sanctioned test-only registry-check zone, and the `esi-datasets →
  composition` Fallow edge is already allowed; a test-only consumer satisfies
  the unused-export gate exactly as the data-ownership registry does today.
  **Rejected:** a Markdown document plus parser — weaker completeness
  guarantees, a second document system to keep truthful, and no compile-time
  closure over integration ids.
- **Contract PD-2 — Explicit-timeout gap set: fix all of them in-slice; all are
  Floss-sized.** The sweep found exactly these gaps: (1) three Redis sites on
  SDK defaults; (2) the Neon HTTP driver (one `fetch` per query, no bound);
  (3) postgres-js establishment bounds inherited silently (the SDK default is
  30 s — the gap is implicitness, not absence; `src/db/index.ts` directClient,
  the dev-only postgres-js request path, and six operator CLI scripts under
  `src/scripts/`); (4) `src/data/gsc/source.ts:53` raw fetch and the
  `google-auth-library` token fetch. Values: Redis 2000 ms (sibling of the
  scoreboard's tuned 1500 ms; these are hint writes and one request-path
  limiter). Neon HTTP 30 000 ms per query via the **global**
  `neonConfig.fetchFunction` — the driver has no per-client injection point
  (`fetchFunction` is `NeonConfigGlobalOnly`; per-call `fetchOptions.signal`
  would freeze one signal for the client's lifetime) — assigned inside the
  lazy `getClient()` so `src/db/index.ts` stays import-side-effect-free, with
  the global's blast radius recorded in the registry (exactly one `neon()`
  consumer exists). The bound is paired with a classifier carve-out in
  `src/lib/neon-cold-start-retry.ts`: the driver wraps every fetch rejection
  as `NeonDbError: Error connecting to database: …`, which the current
  prefix match would classify cold-start and retry into a ~123 s envelope —
  so `isNeonColdStartError` learns to return false when the wrap's
  `sourceError` chain carries a `TimeoutError`. That carve-out is unreachable
  today (no abort signal exists on the neon path) and becomes load-bearing
  with the bound; a new classifier test proves both directions (abort-caused
  wrap → single attempt, genuine `fetch failed` wrap → still retried).
  postgres-js `connect_timeout: 30` stated explicitly at every construction —
  the current effective value made visible, establishment-only, deliberately
  not tightened because the direct unpooled endpoint used by lock holders is
  exactly where a suspended-compute wake is slowest, and deliberately no
  statement timeout because lock holders and ingest run legitimately long.
  Google Search Console 10 000 ms via the shared `OUTBOUND_FETCH_TIMEOUT_MS`
  for the analytics fetch and `transporterOptions: { timeout: 10_000 }` on the
  `JWT` constructor for token acquisition (both options verified against the
  installed packages). **Rejected:** deferring the Neon/GSC bounds to a later
  slice — it would ship the registry with recorded gaps and leave DC-2
  unsatisfied; and shipping the Neon bound without the classifier carve-out —
  it would convert a hang into a retry storm, the exact opposite of the
  contract's intent.
- **Contract PD-3 — Upstash wrapper: extend `src/lib/upstash.ts` into the
  single client factory.** Two exports join the existing resolver:
  `createUpstashClient(config)` (explicit url/token plus required
  `timeoutMs`/`retries` and optional `automaticDeserialization`, preserving
  the SDK default of automatic deserialization when the field is omitted) and
  `resolveUpstashClient(options)` (env-resolved via `resolveUpstashRest`,
  returning `null` when unconfigured so every caller keeps its exact
  degradation). The portable signal factory (`AbortController` + `setTimeout`,
  Convex-runtime-safe) moves here from the scoreboard; the SDK invokes a
  function-form `signal` once per request, outside its retry loop, so the
  bound spans each attempt sequence. A type re-export (`UpstashRedis`) lets
  consumers type fields without importing the vendor package. Consolidation:
  `rate-limit.ts` builds its `Ratelimit` over
  `resolveUpstashClient({ timeoutMs: 2000, retries: 1 })`; `pending-signal.ts`
  and `exhaustion-marker.ts` use `{ timeoutMs: 2000, retries: 0 }`;
  `createRedisScoreboard` constructs through `createUpstashClient` with its
  identical current values. All four sites keep their null-checks, swallows,
  and verdict types byte-compatible. Stated plainly for the operator: the SDK
  rethrows immediately on signal abort and skips its retry loop, so `retries:
  1` covers only transient non-abort errors, and the rate limiter's Redis-
  outage failure mode changes from an unbounded multi-second retry stall
  (then throw) to a throw at roughly the 2 s bound — same fail-closed
  production semantics, now bounded; this is the timeout/retry routing HC-1
  explicitly mandates. **Rejected:** a new `src/platform/redis/` capability
  module — `src/lib/upstash.ts` already owns the credential seam, is already
  imported by all three consumer zones, and is already proven safe in the
  Convex bundle chain; a platform move would churn imports for zero ownership
  gain.
- **Contract PD-4 — Gate: lint rails for everything ESLint can see, census
  checks for the rest.** (a) A new shared `no-restricted-syntax` selector set
  bans bare `fetch(` calls (`CallExpression[callee.name='fetch']` — the same
  accepted altitude as the existing `apiFetch`/ESI-host selectors, with the
  known `globalThis.fetch` indirection gap documented in the config comment)
  across production `src/**` and `convex/**`, with only
  `src/lib/fetch-with-timeout.ts` and `src/transport/api-client.ts` exempted.
  (b) A new shared `vendorImportPatterns` const bans `@upstash/redis`,
  `@upstash/ratelimit`, `@neondatabase/serverless`, `postgres`, `better-auth`
  (and subpaths), `convex/react`, and `google-auth-library` everywhere
  (type-only imports included — the core rule does not distinguish them, which
  is why step 2 introduces the owned database type aliases), with per-home
  exemption blocks that re-list retained bans: `src/lib/upstash.ts`
  (@upstash/redis), `src/lib/rate-limit.ts` (@upstash/ratelimit),
  `src/db/index.ts` and `src/scripts/**` (Neon/postgres drivers),
  `src/platform/auth/**` plus `src/app/api/auth/[...all]/route.ts` plus
  `src/app/industry/active-job-character-ids.ts` (better-auth),
  `src/data/convex/**` plus `src/components/OnlineStatusProvider.tsx` plus
  `src/platform/auth/components/ConvexClientProvider.tsx` (convex/react),
  `src/data/gsc/**` (google-auth-library), and three named non-production
  vendor seams — `src/db/test-support/db-test-harness.ts`,
  `src/db/advisory-lock.concurrency.test.ts`,
  `src/app/industry/active-job-character-ids.test.ts` — each exempted as an

  `login.eveonline.com` literal/template ban outside
  `src/platform/auth/eve-sso-constants.ts`, `src/platform/auth/eve-sso.ts`,

### Interfaces and contracts

- `src/lib/upstash.ts` — new exports beside the existing `resolveUpstashRest`:

  ```ts
  /** Upstash Redis client type, re-exported so wrapper consumers never import the vendor package. */
  export type UpstashRedis = Redis;

  /** Explicit per-client resilience config; timeout and retries are required so no construction ships an implicit SDK default. */
  export interface UpstashClientConfig {
    url: string;
    token: string;
    timeoutMs: number;
    retries: number;
    automaticDeserialization?: boolean;
  }

  /** Constructs the app's only Upstash Redis client shape: portable abort-signal timeout, explicit bounded retries. */
  export function createUpstashClient(config: UpstashClientConfig): UpstashRedis;

  /** Env-resolved variant of createUpstashClient; null when Upstash is unconfigured so callers own their degradation. */
  export function resolveUpstashClient(
    options: { timeoutMs: number; retries: number },
  ): UpstashRedis | null;
  ```

  Error behavior: a timed-out command rejects with the SDK's `TimeoutError`
  `DOMException` (rethrown immediately, bypassing SDK retries by SDK design);
  callers' existing catch/swallow paths handle it unchanged.
- `src/db/index.ts` — new owned type aliases; every other export keeps its
  exact shape:

  ```ts
  /** Owned alias for the postgres-js client handle; downstream modules type against this, never the vendor package. */
  export type Sql = ReturnType<typeof postgres>;

  /** Owned alias for a reserved direct connection (advisory-lock holders); see resolveLockConnectionUrl. */
  export type ReservedConnection = Awaited<ReturnType<Sql['reserve']>>;
  ```

  (`Sql` is today a module-private alias and `ReservedConnection` lives in
  `advisory-lock.ts`; both become `src/db`-owned exports and
  `advisory-lock.ts` re-exports its name for existing callers.)
- `src/composition/vendor-resilience-registry.ts` — new module:

  ```ts
  /** Closed set of external integrations this app talks to; adding a vendor means adding its policy here. */
  export type VendorIntegrationId =
    | 'eve-esi' | 'eve-sso' | 'better-auth' | 'convex' | 'upstash-redis'
    | 'neon-postgres' | 'vercel-platform' | 'github-tooling'
    | 'google-search-console' | 'discord-webhooks' | 'fuzzwork'
    | 'ccp-static-data' | 'eve-news-feed' | 'ccp-image-cdn';

  /** One integration's declared resilience policy — the contract's eight fields, each a recorded fact about live behavior. */
  export interface VendorResiliencePolicy {
    wrapper: { module: string; symbol: string };
    timeout: string;
    retryableErrors: string;
    backoff: string;
    rateLimit: string;
    idempotency: string;
    degradation: string;
    telemetryFields: string;
  }

  /** An integration with no programmatic call surface records that fact instead of a fabricated policy. */
  export interface NoProgrammaticSurface {
    noProgrammaticSurface: true;
    fact: string;
  }

  /** The vendor resilience registry: every external integration's declared policy or recorded absence. */
  export const vendorResilienceRegistry:
    Record<VendorIntegrationId, VendorResiliencePolicy | NoProgrammaticSurface>;
  ```

  The census is the sole consumer; Fallow's zero-unused-export gate holds
  because the census imports every export (the proven data-ownership pattern).

- The session adds no other production export and changes no public interface,

### Control and data flow

Request-path flows are unchanged in shape; only bounds are added. A
rate-limited API request now flows: route → `checkRateLimit` →
`resolveUpstashClient` (memoized limiter) → Upstash REST with a 2000 ms abort
signal and one non-abort retry → allow/deny verdict unchanged, or throw
(production) / bypass (dev) exactly as today — a Redis outage now surfaces at
roughly the bound instead of after an unbounded retry stall. ESI refresh
enqueues and drains touch the pending-work signal through the same three
functions with a 2000 ms bound and zero retries; every failure path still
degrades to the durable Neon queue. The ESI scoreboard's go/no-go path is
byte-identical in behavior (same 1500 ms / zero retries, now constructed via
the factory). Neon HTTP queries flow drizzle → `neon()` client → the global
`fetchFunction` (assigned on first client construction) wrapping each query's
fetch at 30 000 ms → on timeout, the driver wraps the abort as `NeonDbError`,
the narrowed classifier sees the `TimeoutError` in its `sourceError` chain,
declines the cold-start match, and `withColdStartRetry` rethrows on the first
attempt — no envelope multiplication. Lock holders connect through postgres-js
with the now-explicit 30-second establishment bound and run unbounded
statements while holding advisory locks, as required. Google Search Console
cron reads acquire a token (SDK transporter, 10 s bound) and call the API
through `fetchWithTimeout`; failures surface to the cron's existing outcome
handling. No new persistence, cache, or external service enters any flow.

### Edge and failure behavior

- Upstash unconfigured (local dev, tests) → `resolveUpstashClient` returns
  null; rate limiter bypasses in non-production and throws in production,
  hints no-op, scoreboard falls back exactly as today — owned by each call
  site, asserted by their existing unit tests.
- Upstash command timeout → `TimeoutError` rejection (immediate, no SDK
  retries) takes each site's existing catch path (swallow / `'unknown'` /
  throw-bounded); no new outcome category is introduced.
- Neon compute scaled to zero at prerender → first query is slow but far under
  30 s; genuine connection-class failures (`fetch failed`, HTTP 5xx, SQLSTATE
  08/57P03) still retry through the cold-start envelope; a genuine 30 s hang
  now aborts, is declined by the narrowed classifier, and fails the build
  loudly on the first attempt instead of hanging toward the platform kill —
  evidence: the new classifier test plus the existing retry tests staying
  green.
- Advisory-lock holder mid-work → `connect_timeout` bounds only establishment
  at the current effective value; session statements and lock hold time are
  unbounded by design (recorded in the registry rationale).
- Convex isolate build → `src/lib/upstash.ts` gains no `next/server` or
  Node-builtin import; the exhaustion-marker chain stays portable. The
  post-merge production Convex push is the only surface that can prove this —
  named as a delivery watch item in End of session.
- Seeded gate probe → a temporary production file with a direct
  `new Redis(` import or bare `fetch(` turns `pnpm lint` red with the rail
  message; removing the seed restores green; the permanent fixtures in
  `scripts/vendor-rail.test.mjs` assert the same through virtual paths.
