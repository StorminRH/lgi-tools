## Why now

Sessions .1 and .2 built the typed primitives and migrated every first-party
route and browser caller; the seams left — two casting Convex calls, three
hand-pinned Better Auth shapes, two unwired parameter schemas, and the live v1

master plan's §3.10.2.1 outcome (one error vocabulary and one contract system,

the old path is gone and the gates make regression impossible. This is the
sub-version's final session; its PR publishes the planned version records.

## Resolved implementation decisions

- **Contract PD-1 — service transport home: `src/platform/auth/service-client.ts`,
  reusing a decode core extracted inside `src/transport/`.** Evidence:
  `.fallowrc.json` allows `convex → platform/auth` and
  `platform/auth → transport`; the consumed contracts and their schemas already
  live in `src/platform/auth/api-contract.ts`, which Convex already imports; the
  full chain is `next/server`-free so the Convex production bundle stays clean.
  The response-decode logic currently private in `api-client.ts`
  (`decodeEndpointResponse` and helpers) moves to `src/transport/decode.ts`,
  imported by both executors. **Rejected:** adding a `convex → transport` edge —
  needs operator approval per HC-2 and buys nothing; `src/lib` — it may import
  only `config`, so it cannot see the contract types without inverting the
  transport dependency.
- **Contract PD-2 — Better Auth disposition: official typed client for all
  three seams.** `authClient.signOut()` (core), `authClient.signIn.oauth2()`
  (genericOAuthClient, already installed in `auth-client.ts`), and
  `authClient.token()` (jwtClient, added to the plugin list; server `jwt`
  plugin already active) — each verified against the installed 1.6.15 package
  and current v1.6 documentation. `commands-source.ts` (composition zone,
  client-shell-only) legally imports `@/platform/auth/auth-client`;
  `ConvexClientProvider.tsx` is same-slice. Executable proof: updated unit
  tests mock `authClient` and pin success/failure navigation semantics, and
  fresh `tsc` compiles the typed calls against the installed library.
  **Rejected:** exported-type binding or contract tests against hand-kept REST
  shapes — strictly weaker than consuming the official API, and the comment
  claiming the auth client was unreachable predates the responsibility-layer
  restructure (composition may import platform/auth today).
- **Contract PD-3 — route-presence checking: no generated manifest.** The
  existing AST-based gate in `api-contracts.test.ts` gains a derivation:
  endpoint `path` → expected route file (`/api/sites/[id]` →
  `sites/[id]/route.ts`, template segments passed through verbatim, matching
  `scripts/route-presence.mjs` key derivation), asserting the file exists, the
  file imports that endpoint identifier, and the file exports the endpoint's
  method. An endpoint whose derived route file is missing or non-importing is
  an orphan and fails. Deterministic, no committed artifact, no drift checker
  needed. **Rejected:** a generated manifest — a second source of truth
  requiring its own drift gate, explicitly warned against by the brief.
- **Contract PD-4 — AST-versus-regex split and gate reuse.** Rebuilt/extended
  AST gates (in `api-contracts.test.ts`, which already parses route files with
  the TS AST): route↔contract association (PD-3), the existing contractless
  and `satisfies`-pin checks, and the input-marker rule with vocabulary
  `{'none','query','path'}`. New deterministic sweep tests (regex over
  repository sources, following the existing `guard-emissions` sweep pattern):
  (a) template-literal first-party fetch — reject `fetch`/`fetchWithTimeout`
  whose argument contains `/api/` in a template literal across `src/` and
  `convex/`, with no allowlist: both executors fetch variables
  (`endpoint.path`, `baseUrl + endpoint.path`), never `/api/` template
  literals, so the live tree passes clean and any future match is a genuine
  bypass; (b) first-party response-assertion — reject `.json()) as` /
  `.json() as` across `src/` and `convex/`, excluding the sanctioned
  `as unknown` widening idiom, allowlist exactly the external untrusted
  boundaries (`src/data/eve-data/station-names.ts`,
  `src/data/eve-data/entity-names.ts`, `src/data/gsc/source.ts`), pinned by
  exact path and count so growth fails. ESLint keeps its existing selectors;
  the inline-endpoint selector's v1-era message is updated to name the v2
  contract model. Each new gate carries a seeded red fixture (SC-5).
  **Rejected:** extending ESLint overrides into `convex/` — the sweep tests
  cover both trees in one deterministic place, and lint-config surgery would
  duplicate the same ban in two grammars.
- **Contract PD-5 — deletion order (every checkpoint compiles).** (1) decode
  core + service transport + tests; (2) Convex call-site migration; (3) Better
  Auth migration and deletion of the three v1 declarations; (4) query/path
  builders and sites wiring; (5) Next→Convex seam validation; (6) v1 model
  deletion from `api-client.ts` and superseded-test removal; (7) gate rebuild
  and count re-pin; (8) inventory re-run, records, PR. Steps 1–5 leave the v1
  model present but unreferenced; step 6 removes it; step 7 pins the world
  that remains. **Rejected:** deleting the model first — it would break the
  three auth callers and force a mid-session compatibility shim, violating
  HC-3's spirit.

### Interfaces and contracts

- `src/transport/decode.ts` — `/** Decodes one endpoint response into its declared, protocol, or network outcome. */`
  `export async function decodeEndpointResponse(endpoint: EndpointContract, response: Response): Promise<unknown>`
  plus the moved `protocolFailure`/`networkFailure` helpers; unchanged
  semantics, callers own typing via `OutcomeOf`.
- `src/platform/auth/service-client.ts` —
  `/** Server-to-server call context: trusted base URL, service secret, optional timeout override. */`
  `export interface ServiceCallInit { baseUrl: string; secret: string; timeoutMs?: number }`
  `/** Executes a first-party endpoint contract server-to-server with service auth and runtime validation. */`
  `export async function serviceFetch<const TEndpoint extends EndpointContract>(endpoint: TEndpoint, init: ServiceCallInit & ServiceBodyArgs<TEndpoint>): Promise<OutcomeOf<TEndpoint>>`
  — joins `init.baseUrl + endpoint.path`, sends
  `Authorization: Bearer ${secret}` and `Content-Type: application/json` for
  body endpoints, calls `fetchWithTimeout` (default timeout preserved), decodes
  via `decodeEndpointResponse`. Network rejection returns the network outcome;
  it never throws.
- `src/transport/endpoint.ts` additions —
  `/** Query-parameter schema slot; keys own the wire parameter names. */`
  `query?: z.ZodObject` and
  `/** Path-parameter schema slot bound to the path template's [segments]. */`
  `params?: z.ZodObject` on `EndpointContract`; a type utility
  `ExtractPathParams<TPath>` (recursive template-literal type) making
  `defineEndpoint` reject a `[segment]` path without a matching `params` key
  set and vice versa;
  `/** Builds the concrete request URL from an endpoint's declared path, params, and query. */`
  `export function endpointUrl<const TEndpoint>(endpoint: TEndpoint, input: UrlInputOf<TEndpoint>): string`
  — substitutes `[key]` with `encodeURIComponent`, appends declared query keys
  via `URLSearchParams`, omitting `undefined`;
  `/** Parses request query parameters through an endpoint's declared query schema. */`
  `export function parseQueryInput<const TEndpoint>(endpoint: TEndpoint, searchParams: URLSearchParams): z.ZodSafeParseResult<...>`
  — reads exactly the schema's keys (`null → undefined`), then `safeParse`.
- `sitesEndpoint` gains `query: sitesQuerySchema`; `siteDetailEndpoint` gains
  `params: siteIdParamSchema`. `parseSitesQuery(searchParams: URLSearchParams)`
  changes signature to consume `parseQueryInput(sitesEndpoint, …)` internally
  and keeps its exact `"Invalid ${field}. Must be one of: ${expected}"` detail
  and `invalid_query` failure — it remains the guard-emissions core.
- `apiFetch` v2 call args gain `params`/`query` members when declared,
  resolved through `endpointUrl`; endpoints without the slots are unchanged.
- `convex/lib/characterSync.ts` — `fetchEnumeratedCharacters` and
  `vendCharacterToken` keep their exported signatures and return types
  exactly; only their bodies change.
- Deleted exports: `ApiEndpoint`, `ApiResult`, the two v1 `apiFetch` overloads
  (`api-client.ts`), `signOutEndpoint`, `signInOauth2Endpoint`,
  `tokenEndpoint` (`api-contract.ts`).
- New Zod schemas (module-local, not exported): sweep response
  `{dispatched, retired, deleted}` in `sync-sweeper/declaration.ts`; inbound
  purge body `{userId, characterId}` in `convex/http.ts`.

### Control and data flow

Convex sync entry (`onlineStatusSync`/tracker actions) → `requireSyncEnv` (env
unchanged) → `serviceFetch(eveCharactersEndpoint | eveTokenEndpoint, {baseUrl: env.siteUrl, secret: env.secret, body})`
→ `fetchWithTimeout` → Next route (unchanged) → `decodeEndpointResponse`
validates status + problem/JSON body → closed outcome → call-site mapping
(enumeration: ok→characters, else throw; vend: ok→token, 404→skip, 409→reauth,
other→unavailable). Browser auth flows: command palette → `authClient.signOut()`
/ `authClient.signIn.oauth2()` → Better Auth catch-all route (library-owned,
rate-limit precheck unchanged — same paths, same POST method); Convex bridge →
`authClient.token()` → jwt plugin `/api/auth/token`. Sites API: request →
`parseQueryInput`-backed `parseSitesQuery` or endpoint-declared
`siteIdParamSchema` → unchanged queries → `apiResponse`. No other runtime data
flow changes.

### Edge and failure behavior

- Convex enumeration non-2xx (declared or undeclared status, invalid body) →
  thrown `Error` naming the failure → Action Retrier retries — preserved; a
  drifted 200 body now also throws (was: silent garbage propagation) —
  disclosed refinement, unit-tested.
- Token vend 404 → `{kind:'skip'}`; 409 → `{kind:'reauth'}`; other declared or
  undeclared non-2xx → `{kind:'unavailable'}` — preserved; a drifted 200 body
  now maps to `unavailable` (was: garbage token) — disclosed refinement,
  unit-tested. Network/timeout failures rethrow their cause so retrier
  semantics are byte-equivalent.
- `authClient.signOut()` failure → no navigation, user stays put — preserved;
  success → `window.location.href = '/'` kept at the call site.
- `authClient.signIn.oauth2()` success → library redirect plugin navigates to
  the SSO URL (replaces the manual assignment, same destination); failure → no
  navigation — preserved.
- `authClient.token()` error or network failure → `null` returned to Convex's
  auth bridge — preserved (try/catch retained).
- `endpointUrl` with a params value needing encoding → `encodeURIComponent`
  output; query keys with `undefined` values → omitted from the query string.
- Invalid `/api/sites` query → same `invalid_query` 400 problem with
  byte-identical detail (the `sites-query` unit tests are rewritten for the
  `URLSearchParams` signature while preserving the exact detail-string
  assertions).
- Invalid `/api/sites/[id]` id → same `invalid_query` 400; missing site → same
  `not_found` 404.
- Sweeper `/sweep` response drift → `{status:'failed', reason:'sweep_invalid_response'}`
  telemetry row (was: silent garbage) — within the declared response type,
  unit-tested.
- `/purge-online` well-formed JSON with wrong-typed fields → 400 (was: 500 via
  Convex validator throw) — a wire-visible status change on bearer-gated
  service traffic, explicitly flagged for and sanctioned at plan approval;
  aligns with the route's documented clean-400 intent; purge remains
  best-effort either way; convex-test covered.
