## Why now

Atlas 4.0 draws a chain that jumps. The kernel is deterministic but its input is not: `watchMapConnections` is served from the `by_map_to` index, so a resolved stub sorts by destination system id and shifts every sibling after it; stubs are renumbered on every paste; ghosts are recomputed from universe data and blink on every system add. 4.1.2 puts widgets and taller k-space frames on those seats, so the seats have to stop moving first. The operator has also ruled that statics are real facts about a system and belong in Convex as rows, so the seat work is built on rows rather than on a client memory that would be thrown away when ghosts are redesigned.

## Scope (the destination)

When this session is complete, a system landing on a map brings its statics with it as unresolved connection rows. A pasted wormhole sig is an unresolved connection row too. Identifying that sig as the static merges the two rows into one; a hole that is jumped first and typed later merges the same way. Every viewer orders a system's children by when each connection first existed, so a new hole always appears after the ones already drawn, a stub that becomes real stays in its slot, and a deleted hole leaves its slot empty for the undo window. Auto layout and dragging are gone from settings, canvas, code, and the preference table. Overlap after first paint is left alone.

## Resolved implementation decisions

- **Contract PD-1 — how a stub's first seat is remembered: it is not remembered, it is derived from shared facts in a stable order.** Every child of a system (authored connection, sig stub, static row, tombstoned connection) sorts by `seatOrderAt ?? _creationTime`, ties by `_id`. A new connection is newest and lands last; the fixed-slot kernel already leaves earlier claims alone for appends (`stability.test.ts`). A stub that resolves is the same row, so the same slot. Two rows that merge carry the earliest `seatOrderAt`. Tombstoned connections stay in the list as hidden slot holders for the 24-hour undo window. Every viewer computes the same picture, including a late joiner. **Rejected:** a per-tab seat ledger fed into the kernel as pinned positions. It guarantees a watcher never sees a move, but a late joiner computes a different picture after any deletion or ghost claim, and the operator ranked "everyone sees the same map" first. **Rejected:** positions stored in Convex. Violates HC-1 and is the contract's split trigger.
- **Contract PD-2 — leftover Auto layout preference rows: deleted.** `drizzle/0060_retire_atlas_auto_layout.sql` runs `DELETE FROM "user_preferences" WHERE "key" = 'atlas.autoLayout';` and ships with the drizzle journal and snapshot. `src/lib/preferences.ts` drops the definition so the PUT route rejects the key (`validatePreferenceValue`) and `reconcilePreferences` ignores any stale GET row. `RETIRED_PREFERENCE_KEYS = ['atlas.autoLayout']` is exported and `PreferencesProvider` removes `lgi:pref:<key>` for each on load. **Rejected:** leave rows inert. The table-growth registry (`src/composition/__tests__/table-growth-registry.ts:316-319`) says `user_preferences` is bounded by registered keys; orphan rows break that promise for no gain.
- **Plan — statics are Convex rows (operator directive).** A static placeholder is a `mapConnections` document: `fromSystemId = P`, `toSystemId = null`, `from.typeCode = <code>`, `from.signatureId = null`, `identity = { kind: 'typed', provenance: 'assumed' }`, `staticCode = <code>` (the code the row was born as; `from.typeCode` may later be corrected by a human, `staticCode` never changes), `seatOrderAt = <insert time>`. **Rejected:** keep ghosts as a client calculation with a slot rule. The operator will redesign ghosts as rows regardless, so building seat rules on the calculation would be thrown away.
- **Plan — who creates static rows: the server, one seam.** `ensureStaticPlaceholders(ctx, mapId, systemId)` is called inside `upsertLiveDestination` (`convex/mapAuthoringHome.ts:77`) on its insert and its un-tombstone branches, which covers add-from-node and jump authoring (`convex/mapJumpAuthoring.ts:361`); after the `ctx.db.insert('mapSystems', …)` in `insertHomeSystem` (`mapAuthoringHome.ts:33-58`); and in `restoreSystem` (`convex/mapAuthoringTombstone.ts`). The early return for an already-live system schedules nothing. It schedules `internal.mapStatics.fetchSystemStatics` (internal action) which reads `${SITE_URL}/api/universe/statics/<systemId>` and calls `internal.mapStatics.applyStaticPlaceholders` (internal mutation) once with the code list. Apply inserts only the codes with no live row carrying that `staticCode` for that system. **Rejected:** the browser passes codes into every add mutation. Four call sites, and jump authoring would have to fetch statics for a system the browser has not drawn yet.
- **Plan — existing maps: a one-time backfill action.** `internal.mapStatics.backfillStaticPlaceholders` improves on the `mapHallwayBackfill.ts` `.take(HALLWAY_BACKFILL_BATCH)` pattern by being resumable: it takes `{ cursor?: string; batch?: number }`, reads at most `STATIC_BACKFILL_BATCH = 32` live systems per run through `.paginate`, fetches statics for each inside that loop, calls `applyStaticPlaceholders` per system, and returns `{ systems, inserted, cursor, hasMore }`. The operator reruns `pnpm exec convex run mapStatics:backfillStaticPlaceholders '{"cursor": "<cursor>"}'` until `hasMore: false`. Run on dev during step 2, on staging at promote, on prod at release. Recorded in the as-built and the close-out checklist.
- **Plan — claiming: the survivor inherits `staticCode` and the earliest `seatOrderAt`.** `claimStaticPlaceholder(ctx, row, side)` runs after the three mutations that set a door `typeCode` on a row whose `side` system is `P`: `setConnectionWormholeType` (`mapAuthoringFields.ts:318`), `stampIdentifiedWormholeType` (`mapScanApply.ts:490-521`), and `applyTypeDeduction` (`mapScanElimination.ts:170-190`). Jump authoring never sets a `typeCode` (`mapJumpAuthoring.ts:295-305` patches destination and resolution only), so it has no hook. A row that already carries `staticCode` is never a claimant. It looks for a live placeholder on `P` where `placeholder.staticCode === row.from.typeCode` (the birth code, not the placeholder's possibly retyped door), `placeholder.from.signatureId === null`, and `placeholder._id !== row._id`. When the claimant is an unresolved sig row, the placeholder survives: it takes the sig's `from.signatureId`, `signalPct`, `leadsTo`, `lifetime`, `observationKey`, `firstSeenAt`, identity provenance, and the sig row is deleted. When the claimant is a resolved connection (jump-created), the resolved row survives and takes `staticCode` and `seatOrderAt` from the placeholder, which is deleted. Both branches use one merge function. `applyLinkDeduction` and `absorbLeftoverOriginStub` also set `seatOrderAt = min(...)`. **Rejected:** flip the jump path's survivor to the older row. `resolution.candidateIds` and jump bookkeeping reference the jump row; `seatOrderAt` makes the survivor choice irrelevant to seats.
- **Plan — static death respawns the placeholder in the same slot.** After `tombstoneConnectionRow` (scan selection), `severConnection`, or the expiry sweep tombstones a row with `staticCode`, `respawnStaticPlaceholder(ctx, deadRow)` inserts a fresh placeholder for the same code with `seatOrderAt = deadRow.seatOrderAt ?? deadRow._creationTime`, unless a live row with that `staticCode` already exists. The layout groups children by seat key (`static:<P>:<code>` for rows with `staticCode`, otherwise `_id`), so the tombstone and the respawn share one slot. Restoring the tombstoned row deletes the unclaimed respawn for that code first (hard delete; it was never claimed and needs no undo).
- **Plan — drawing from rows.** Stubs are the live unresolved rows on live authored systems. Rows with `staticCode` draw as `PlacedStaticStub` (code from `from.typeCode`; `className` and `whClassId` from the client codex); rows with a signature draw as `PlacedStubConnection`. `believedHoles` keeps only the hide rule: an unidentified sig row (`typeCode === null`) on `P` is hidden while the count of unidentified sigs does not exceed unclaimed static rows plus return slots (`isRoot ? unlinkedLines : max(unlinkedLines, 1)`). `staticStubs` and `staticsBySystem` leave the accounting input. `useSystemStaticSlots` becomes `useWormholeCodex` (codex only). Ghost nodes stay inert as today: `draggable: false`, `selectable: false`, no edge menu.
- **Plan — the mover stays for the purge case.** The reconciler keeps following the kernel; user placement and the drag-protection set are deleted; `system-moved` and its tween remain because a tombstone purge after 24 hours closes a gap for every viewer at once. Operator accepted: a deleted or purged node that comes back takes the newest slot, not its old one.
- **Plan — unresolved query returns tombstones.** `watchUnresolvedHoles` drops its server-side `isTombstoned` filter. `unresolvedHolesFromRows` keeps filtering live rows for the scanner and jump resolution; a new `slotHolderRows(rows)` returns tombstoned unresolved rows for layout only.

### Interfaces and contracts

- `mapConnections.staticCode?: string` — present only on rows that are, or were claimed from, a static placeholder; the wormhole code the placeholder was born with. Survives merges, retyping, and tombstones.
- `mapConnections.seatOrderAt?: number` — epoch ms. Set at insert for placeholders and respawns; set to `min(a.seatOrderAt ?? a._creationTime, b.seatOrderAt ?? b._creationTime)` on every merge. Rows without it sort by `_creationTime`. Never a coordinate.
- `ensureStaticPlaceholders(ctx: MutationCtx, mapId: string, systemId: number): Promise<void>` — schedules `fetchSystemStatics` at 0 ms. No throw; callers do not await the fetch.
- `fetchSystemStatics` (internalAction, `{ mapId, systemId }`) — `GET ${SITE_URL}/api/universe/statics/${systemId}`; on non-2xx or missing `SITE_URL` logs `static placeholders skipped` and returns; on success calls `applyStaticPlaceholders` once.
- `applyStaticPlaceholders` (internalMutation, `{ mapId, systemId, codes: string[] }`) — requires a live system row; inserts a placeholder for every code with no live row carrying that `staticCode` on that system; returns `{ inserted: number }`. No map event.
- `backfillStaticPlaceholders` (internalAction, `{ mapId?: string }`) — loops live maps (or one), loops live systems with `.take()` paging, fetches statics per system, applies per system; returns `{ systems: number, inserted: number }`.
- `claimStaticPlaceholder(ctx, row: Doc<'mapConnections'>, side: 'from' | 'to'): Promise<'claimed' | 'none'>` — preconditions: `hallwayDoor(row, side).typeCode !== null` and `row.staticCode === undefined` (returns `'none'` otherwise); finds a live placeholder on that system with `staticCode === hallwayDoor(row, side).typeCode`, `from.signatureId === null`, `_id !== row._id`; merges per the survivor rule; returns `'none'` when no placeholder matches.
- `optimisticClaimStaticPlaceholder(localStore, { mapId, connectionId, typeCode })` in `src/mapper/chain/optimistic-authoring.ts` — mirrors the sig-claimant branch inside `optimisticSetConnectionWormholeType`: when the local `watchUnresolvedHoles` page holds a live placeholder on the same system with that code and `from.signatureId === null`, it patches the placeholder with the sig row's `from.signatureId`, `signalPct`, `leadsTo`, and identity through `optimisticallyUpdateValueInPaginatedQuery`, and removes the sig row from the `watchUnresolvedHoles` page (the only page an unresolved row is on; `watchMapConnections` serves resolved rows) through a new `removeFromPaginatedQuery(localStore, query, args, predicate)` in `src/data/convex/use-mutation.ts` (convex-react exports insert and update helpers but no removal; the wrapper iterates `localStore.getAllQueries(query)` and `setQuery` with the filtered page, the same shape the update helper uses). Removal, not a local tombstone, because step 4 makes tombstoned unresolved rows slot holders. No placeholder → the existing type patch only.
- `respawnStaticPlaceholder(ctx, dead: Doc<'mapConnections'>): Promise<Id<'mapConnections'> | null>` — preconditions: `dead.staticCode !== undefined`, `dead` tombstoned, and `dead.fromSystemId` is a live system on `mapId` (returns `null` otherwise, so a branch-removal collapse in `mapAuthoringCollapse.ts:210-247` that tombstones systems and their connections together never leaves an orphan placeholder on a dead system); inserts a placeholder for `dead.staticCode` with `seatOrderAt = dead.seatOrderAt ?? dead._creationTime` unless a live row with that `staticCode` exists on that system.

- `seatOrderOf(row: { readonly seatOrderAt?: number; readonly _creationTime: number }): number` — `row.seatOrderAt ?? row._creationTime`. Typed on the document-shaped row (`Doc<'mapConnections'>`, `ConnectionEditorDetail`), not on the `ConnectionHallway` value object, which has no `_creationTime`.

### Control and data flow

1. Editor adds a system (home, add-from-node, jump authoring, restore). The mutation inserts or restores the `mapSystems` row and calls `ensureStaticPlaceholders`, which schedules `fetchSystemStatics`. The action fetches `/api/universe/statics/<id>` and runs `applyStaticPlaceholders`, inserting one unresolved typed row per static with `seatOrderAt = now`. Browsers subscribed to `watchUnresolvedHoles` receive the rows and draw ghosts at the newest slots of that system.
2. Editor pastes a scan. Unchanged: each wormhole sig becomes an unresolved row with `typeCode = null`. Browsers hide unidentified sig stubs up to the unclaimed static plus return-slot count.
3. Editor identifies a sig as C247 (or a typed paste, or assumed typing, or types an already-jumped connection). After the type patch, `claimStaticPlaceholder` finds the unclaimed C247 placeholder on that system and merges. For a sig claimant the placeholder survives with the sig's fields and the sig row is deleted. For a resolved claimant the resolved row survives with `staticCode` and the placeholder's `seatOrderAt`, and the placeholder is deleted.
4. Editor resolves a stub to a system (scanner destination or jump). Same row, `toSystemId` set. When the jump path merges two rows, `applyLinkDeduction` sets `seatOrderAt = min`.
5. Any connection is tombstoned. `watchUnresolvedHoles` and `watchMapConnections` both deliver the tombstoned row. If it had `staticCode`, `respawnStaticPlaceholder` inserts a fresh placeholder with the dead row's `seatOrderAt`.
6. Browser layout. `useMapChainPages` builds `stubRows` (live unresolved rows on live systems, minus hidden unidentified sigs) and `slotHolders` (tombstoned unresolved rows). `useMapChainMerge` builds `seatOrderedFacts`: one connection list sorted by `seatOrderOf`, seat-key collapsed, slot holders as hidden negative children, then halo facts. `compassKernel` runs unchanged. The reconciler follows the kernel for authored systems; `stubPositionsFromLayout` keys ghost and sig stubs by seat key.
7. Purge after 24 hours removes tombstones; slot holders leave the list; later siblings move; `system-moved` glides them. Every viewer sees the same move at the same time.
8. Settings: `atlas.autoLayout` is not in `PREFERENCES`; the Map settings section shows Camera follow and Click focus. `ChainSurface` renders `nodesDraggable={false}`; no drag handlers exist; the `SystemNode` disc chrome carries `nopan`, so a pointer-down on the disc neither drags nor pans; the frame padding pans through as it does today.

### Edge and failure behavior

- `SITE_URL` unset or the statics route unreachable → `fetchSystemStatics` logs `static placeholders skipped` and returns; the system draws without ghosts; a later restore or the backfill fills them. Evidence: `convex/mapStatics.test.ts` with fetch mocked to fail.
- Statics route returns `[]` (k-space, Thera, unknown id) → `applyStaticPlaceholders` inserts nothing.
- Two editors add the same system → only the inserting mutation schedules; apply is idempotent on `(system, staticCode)` among live rows, so a second schedule inserts nothing.
- Sig identified as a code with no placeholder on that system (wandering hole, K162) → `claimStaticPlaceholder` returns `'none'`; the sig row stays its own newest child.
- A row that already holds `staticCode` gets a type set again or resolves → not a claimant; its slot never changes. If a human retypes a claimed static row to a different code, the row keeps its `staticCode` and slot; no placeholder respawns until that row dies.
- A human retypes an unclaimed placeholder's door (C247 to Z971) → the row keeps `staticCode: 'C247'` and its slot and still draws as a ghost showing the human's type; a later sig identified as C247 still claims it (lookup is on `staticCode`), and the survivor keeps the human's `from.typeCode`.
- Placeholder already claimed (`from.signatureId !== null`) → not a claim target; a second sig identified as the same code becomes its own row (the static is already accounted for).
- Jump through an untyped door → new resolved row; placeholder stays; a later type set on that row claims it.
- Restore of a tombstoned row with `staticCode` while an unclaimed respawn exists → restore hard-deletes the respawn, then restores. If the respawn was claimed in the meantime, restore proceeds and both rows live; the layout collapses them to one slot by seat key and the second draws over the first (overlap accepted, DC-6).
- Removing a system, or a branch-removal collapse → connections tombstone as today; each with `staticCode` respawns nothing because `respawnStaticPlaceholder` requires a live `fromSystemId` system and returns `null`.
- Convex page drain → `systems.complete` and `connections.complete` behave as today; the reconciler retains systems from an incomplete snapshot; ordering is by `seatOrderOf`, so a late-arriving page cannot reorder earlier children except through a genuinely earlier connection, which is initial load, not a post-paint move.
- Tombstone purge (24 h) → later siblings close the gap on every viewer; `system-moved` glides them; stubs snap.
- Layout worker teardown or kernel rejection → unchanged (`LAYOUT_KERNEL_TEARDOWN` path).
- A user with `atlas.autoLayout = false` stored in Neon or localStorage → row deleted by migration `0060`; localStorage pruned on first load; `usePreference` never asked for the key again.
- A stale client on the old bundle after the schema change → new optional fields are ignored by the old validators; the old `watchUnresolvedHoles` consumer receives tombstoned rows it did not before, and `unresolvedHolesFromRows` already filters `!isTombstoned`, so the old bundle draws nothing new. That client-side filter is load-bearing for backward compatibility and stays; `slotHolderRows` is a separate reader of the same page.
