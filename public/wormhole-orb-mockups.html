Wormhole orb studies

Five ways to read an Atlas system as the in-game hole: a dark, reflective ripple-orb with class-colored wisps — without making the node transparent. The disc stays opaque so names, class chips, and connection lines still read. Hover a large specimen (or turn on preview wisps) to see the motion. The small discs are the real Atlas size: 55px.

Hover also works. Reduced-motion freezes the spin and keeps the static glow.

2. SVG ripple rings

inline SVG cheap Concentric strokes do the “pond ripple / gravitational lens” read from the screenshots. The core circle is a solid fill — not a see-through hole. Wisps are blurred path streaks that spin on hover. Scales cleanly at 0.2–2.5 zoom.

3. Canvas painter

Canvas 2D medium One paint function: sphere lighting, ripple rings, and bezier wisps. Idle map paints once. Hover (or the preview toggle) starts a frame loop on that canvas only — same idle contract as Atlas fog. More organic than CSS; still no WebGL context.

4. Liquid-metal CSS

CSS cheap Closer to the amber screenshot: two speculars (hot top-left, soft opposite fill), a deep inset core, and a conic “sheen” that stands in for the glassy ripple bands. Wisps are a blurred conic wash, not blades. No JS.

5. WebGL fresnel

WebGL 1 shader heavier A disc treated as a sphere: fake normal, fresnel limb, animated ripple rings, and angular wisp streaks. This is the “true 3D feel” without pulling Three.js into the app. I only mount a few contexts here (browsers cap them). On a real map I would not give every node its own WebGL context — one shared canvas, or CSS/SVG instead.

What I would actually ship

Start with study 1 or 4. Both are CSS, stay inside the existing SystemNode disc, keep the idle-map contract, and already have class tokens (--color-wh-c1…c6). Study 1 is the clearer “orb.” Study 4 is closer to the reflective amber screenshot.

Add SVG wisps (study 2) on hover only if the CSS blades feel too geometric. Concentric SVG rings are the cheapest way to get the ripple-orb silhouette at 55px.

Canvas (study 3) is the next step, not the first. Use it if CSS/SVG cannot get the liquid grain. One paint on idle, requestAnimationFrame only on the hovered node.

Skip per-node WebGL / Three.js for Atlas. The shader is here so you can see the ceiling. A shared WebGL overlay (the fog pattern) could do always-on ripples later; it is a new layer, not a drop-in to NodeDisc.

Transparency stays off on purpose: the in-game hole is a lens over space, but a map node has to hide the edge that runs under it and keep the class chip readable.
