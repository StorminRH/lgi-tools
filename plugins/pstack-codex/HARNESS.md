# Codex runtime

Upstream Task examples express delegation intent, not Codex API syntax. Use the session's native spawn/send/wait tools and actual parameter schema. `generalPurpose` means a normal worker with the supplied workflow prompt. Resolve the MODELS.json role to its `agent` TOML in `.codex/agents/`: pstack-worker (Sol/high), pstack-reviewer (Astra/high), or pstack-fast (Terra/medium). These pins avoid depending on a model override parameter that some Codex surfaces do not expose. Comment cleanup uses comment-sicko. If named roles are unavailable but explicit model/effort overrides are supported, apply the same configured pair; otherwise report the gap.

For a poteto-agent task, use the chosen pinned role and include the full poteto-agent routing instruction in its prompt: read this edition's poteto-mode SKILL.md in full, including its Principles index, then follow the assigned scope. The unpinned poteto-agent role is also available when inheritance is intentional. Do not use the wrapper for how/why/arena/reflect reviewers whose own prompt templates define their work.

`readonly` denotes task scope; enforce it using supported sandbox settings and instructions. It does not imply MCP is unavailable. Native children run concurrently without a Cursor background flag. Use native wait/resume rather than Cursor Task IDs. Respect the actual concurrency and nesting limits; process additional independent work in waves when necessary.

`environment: "cloud"`, Cursor's `/loop`, sticky mode, cloud-sleeper and Cursor agent-store schemas have no assumed Codex equivalent. Start cloud work in an already-configured Codex cloud session, or use native workers in the current session. Use a supported goal/scheduling facility only if exposed and requested. Otherwise work to the next bounded checkpoint and report what remains, without claiming background persistence. Poteto-mode remains the user's chosen workflow until they opt out; this is a conversation convention, not a registered Codex mode.

For recall/reflect/eval/automate-me/session-pickup/show-me-your-work, use an explicitly exposed current-workspace transcript or a user-supplied export. Do not reconstruct Cursor paths or search global Codex history. If unavailable, use the current conversation digest plus relevant GitHub and Linear records and label the missing transcript evidence. Transcript examples below are upstream formats, not a promise about Codex storage. Use the native skill-creator when authoring skills, and standard Codex skill metadata rather than Cursor mode fields. Different GPT roles do not establish different-provider diversity; report that limitation when an upstream review asks for it.

Read [LGI workflow](LGI.md) once before executing an entry skill, and [model choices](MODELS.json) before delegating. These repo adaptations replace conflicting upstream defaults in every linked playbook, reference and agent prompt. Skill names remain upstream names.

Resolve `references/`, `playbooks/` and `scripts/` relative to the skill that owns them, not the shell's working directory. Run tools with absolute paths while keeping the working directory at the target repository. The bundled watcher and orchestrator need Bun and authenticated GitHub CLI. Their bootstrap installs locked dependencies next to the scripts. If an installed plugin cache is read-only, execute the repository edition's script at the same pinned revision; do not disable sandboxing or change permissions to make a cache writable.

Model configuration is scoped to this plugin. Every entry in a panel list is one worker; the default is two. Reflect keeps its three distinct lenses. Never expand to upstream's four-model defaults when a configured slug fails. Check the session's tool schema, model picker or runtime metadata first. An unavailable model is a reported gap requiring a replacement choice, not permission to select an expensive fallback. A child's claim about its model is not runtime evidence.

The three Team Kit dependencies, deslop/control-ui/control-cli, are bundled at this same source revision. Native skill authoring support is a harness prerequisite when using the authoring workflows; report its absence instead of inventing a missing skill. No bundled automation is enabled by installation.
