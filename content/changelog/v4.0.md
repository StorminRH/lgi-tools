## v4.0 — Atlas of Worlds

v4.0 ships Atlas, a shared wormhole map that updates live for everyone watching.
Paste scanner results, jump through holes, track mass and lifetime, manage who can edit, and see pilots and fog on one canvas.

### v4.0.5.1 — 2026-09-02

Atlas is now in the public header and on the home tools list. Signed-out visitors see the map catalogue and can still reach login from a shared link. Maps that are being deleted for good stay gone, and staging runs at its lasting address.

#### Added
- Atlas in the public site header and on the home tools list.

#### Changed
- A map that is being deleted for good cannot be restored or put back online.
- Development pushes no longer open a preview deploy.
- Staging uses its lasting address and talks to the staging live services.
- In-app feedback requires a title and opens a Linear issue.
- Each end of a wormhole connection is either a class hint or a known system, never both.
- Harvestable site prices use the best Jita sell order.
- Stored Jita buy figures ignore very low hub bids.
- Signed-out Atlas shows the map catalogue instead of an admin wall.
- Background EVE data sync jobs no longer run on a fixed fifteen-minute Vercel schedule.

#### Fixed
- Old sharing access can no longer come back after it was removed.
- A delayed access update can no longer bring a map back after it was deleted for good.
- Restore shows as pending when a newer empty map already took its place.
- A blank database setting no longer turns off safety locks.
- Named wormhole types show in the scanner even when the first stored end is a K162.
- Re-identifying the same wormhole type no longer leaves a jump prompt behind.
- Corp Structures opens on first visit.
- Presence pins no longer vanish when a tracker turns tracking on or off.
- Removing an unused system from a large map no longer fails.
- An unscanned wormhole placeholder no longer stacks on a static.
- A shared Atlas link no longer hides login for signed-out visitors.
- A deleted map no longer looks live when its deletion date is missing.
- Pressing Enter in the scanner on a named return hole links that door instead of creating a second destination.

#### Removed
- The Under the Hood pages and their footer link.
- The Under the Hood walkthrough link on the privacy page.

### v4.0.4.4 — 2026-08-12

You can create maps, share them, switch between them, and send them to trash from Atlas. Access roles are viewer, editor, and admin.

#### Added
- A catalogue of your maps when none is selected, grouped into your maps, corporation maps, and maps shared with you, with create and trash in the header.
- Create a map from one dialog: name it, optionally share it, wait briefly, and land on the empty map's set-home prompt.
- Switch maps from the current map name at the top of the canvas. Admins can manage access from a gear on each row.
- Share a map with characters and corporations as read-only, write, or admin. Removing access drops a live viewer without a reload.
- Deleted maps move to trash for thirty days and can be restored. Only the map's creator can delete one for good.

#### Changed
- Map access roles are now viewer, editor, and admin. Older owner access still acts as admin until it is refreshed.
- Atlas uses the same site frame as the other tools. Opening a map covers the header and navigation with the full canvas.
- Release checks wait on the production deploy, and browser tests use the host browser cache.

### v4.0.4.3.1 — 2026-08-09

Paste probe-scanner results onto the map. Signatures land in a scanner window, wormholes appear as placeholders, and removals stay undoable.

#### Added
- Paste probe-scanner results anywhere on the map. Signatures and anomalies land in a bottom-left scanner window with grouped sections, signal strength, and a live age column. The paste applies to the system your tracked online character is in.
- Scanned wormhole signatures appear as ghosted placeholder nodes. Jumping through one turns the placeholder into the real destination without a duplicate.
- A right-click editor on wormhole rows covers type, life stage, mass, and leads-to, with the origin system's known statics sorted first. Typing a wormhole code shows its destination class and starts the remaining-lifetime estimate from first sighting.
- Wormholes past their maximum lifetime collapse automatically after a safe grace period. A live hole is never removed early, and a branch holding a tracked pilot is always kept.
- Every signature removal is undoable for 24 hours. Bulk removals show an undo toast, quiet expiries write an audit-log Restore, and re-pasting a removed signature brings it back in place.
- A managed Cloud agent development environment that sets up a local database, secrets, migrations, and EVE static data without Docker.

#### Changed
- Re-pasting a scan updates rows in place. Better information enriches a row. A contradicted row is refused and counted. Rows missing from a re-paste ask once before delete, so a filtered paste never deletes on its own.
- The audit log and feedback controls moved to compact bottom-right chips. The audit log expands leftward inside the screen.
- The current-system dock and System Info card show security status in CCP colors with the system's class, plus a scanner summary.
- Page navigation is faster. Routes share a ready loading layout so headers and placeholders paint while account data loads.
- The changelog and development log keep their contents list in place while switching documents. Unknown document links show a not-found page that search engines should skip.
- Atlas fog, halo, presence, and sync tests were folded into fewer longer workflow tests.

#### Fixed
- The development log's server cache no longer exceeds the shared remote cache size limit in production.
- Production deployments build again after the navigation pass. The social preview image is served as a static asset.
- Historical wormhole site data loads cleanly on a fresh database.

### v4.0.4.1 — 2026-08-04

A blank map asks for a home system. From there you grow the chain by right-clicking, with mass, lifetime, and undo built in.

#### Added
- A blank Atlas map opens with one centered prompt. Type your home system's name and it becomes the root of the chain.
- Right-click a system to add a connection, pick the wormhole type, and the discovered system fans out live for everyone watching. Adds always grow from an existing system.
- Picking a wormhole type fills mass budget, per-jump limit, size, and lifetime from the type catalog. The ship-size control locks when the type already decides it. Unidentified holes keep the manual size control.
- Reporting a connection's observed life stage narrows a remaining-life window that every watching client shows the same way. Later reports narrow it. A contradictory report resets it.
- Mass estimates show as honest ranges from the type's catalog budget, tightened when the hole has been shaken and mass has clearly been used.
- Removing a connection offers one-click cleanup for a dead empty branch, keeps k-space exits or a loop home marked as removed, and always offers an immediate Undo toast.
- The map keeps an event log of remove and restore entries with an inline Restore action within a one-day undo window.
- Expired leftovers are cleaned up on a schedule every fifteen minutes.
- Every map change requires the editor role. Viewers' writes are rejected by the server. Editors see their own change instantly, and everyone else receives it live.

#### Changed
- Dying connections pulse red. Follower cards stay inside the screen with green leader lines. Map panels share one frosted look.
- Platform announcements from the update-watch digest were recorded in the acknowledged baseline.

#### Fixed
- The map's data client logs through a plain console logger so server page builds no longer trip over the vendor logger.
