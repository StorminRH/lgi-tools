## v4.0 — Atlas of Worlds

v4.0 lays the groundwork for a collaborative wormhole mapper while keeping its delivery records and measurement baseline trustworthy from the first shipped slice.

### v4.0.4.1 — 2026-08-04

#### Added
- A blank Atlas map now opens with a single centered prompt: type your home system's name and it becomes the root of the chain. No tutorial, no empty-state art.
- Chains grow from the map itself: right-click a system to add a connection, pick the wormhole type from a type-ahead, and the discovered system fans out live for everyone watching the map. Adds always grow from an existing system, so a floating system can never be created.
- Picking a wormhole type fills the connection card from the codex on its own: mass budget, per-jump limit, size, and lifetime appear without typing, and the ship-size control locks whenever the type already decides it. Unidentified holes keep the manual size control.
- Reporting a connection's observed life stage narrows a bounded remaining-life window stored as absolute timestamps: every watching client renders the same countdown range, later reports narrow it, a contradictory report resets it, and a computed honest ceiling built from the type's lifetime and when the hole was first seen rides alongside.
- Mass estimates are presented as honest ranges: the type's catalog budget with per-hole variance, clamped tighter when an observed shake state proves mass has been consumed.
- Severing a connection runs a computed collapse decision: a truly dead, empty branch offers one-click removal, a branch holding k-space exits or a loop home stays on the map marked severed, and nothing is ever destroyed silently. Every removal offers an immediate Undo toast.
- The map keeps an event log: newest-first sever and restore entries with an editor-gated Restore action inline, so a removal can still be walked back within its one-day undo window after the toast is gone.
- Expired remnants — collapsed connections past their retention window and dangling events — are cleaned up by a scheduled purge every fifteen minutes.
- Every map mutation requires the editor role — a viewer's writes are rejected by the server — while editors see their own change instantly and everyone else receives it reactively.

#### Changed
- The map chrome was polished under operator review: dying connections pulse red (a steady dim red under reduced motion), follower cards stay inside the viewport with green leader lines, chrome surfaces share one frosted look, docked site cards center correctly, and the canvas dots and library attribution were tidied.
- Absorbed the 2026-08-03 update-watch digest's informational Vercel AI Gateway announcement into the acknowledged baseline.

#### Fixed
- The map's data client now logs through a plain console logger so server prerendering no longer trips over the vendor logger's random identifier generation.
- Raised the PostCSS floor to the patched release that clears the incomplete sourceMappingURL advisory.

- Typing and scrolling inside any window leave the map's pan and zoom alone, and Escape closes only the summary card — never the current-system dock.

### v4.0.3.2 — 2026-08-02

#### Added
- The Atlas map now moves like water. A system arriving on the map surfaces in place — starting slightly small and dim, swelling through a soft overshoot, and settling sharp — the same way whether it arrives on first load or live while you watch.
- When the layout engine shifts systems to make room, they glide to their new places along a spring curve with their connection lines tracking them every frame of the way; nothing teleports and no line tears loose from its system.
- A departing system plays a brief exit, and its connections leave with it — either fading alongside the removed system or shrinking back toward the chain, a selectable flavor. A wormhole collapse — a connection dying and taking its unreachable system with it — can play a heavier farewell than a bare system removal, and that weight is selectable too.
- Hovering a system makes it glow and breathe gently. That is the map's only cursor response: at rest the canvas runs no animation and does no rendering work at all.
- The camera always glides now — the initial framing and follow moves ease over a moment instead of snapping — and a new click-focus switch centers the view on any system you click, keeping your current zoom.
- Motion dials join the tuning panel: three tempo tiers (quick feedback, births and glides, camera moves), overshoot amount, edge flavor, and collapse weight.
- The map honors a reduced-motion system preference: position changes become instant placement, births and exits become gentle fades, and camera moves complete immediately.

#### Changed
- Dragging stays raw: a node you are holding follows the pointer one-to-one with every animation suppressed on it, and node rendering was hardened so a large chain stays smooth under drag.
- Chain reveals and collapses are now written as single atomic events, matching how mapping really works: a jump records the discovered system together with the connection that found it, and a collapse removes the severed connection together with the system it had discovered. Nodes are born directly on the tree and leave with their connection — never orphaned off to the side — and the development replay tool exercises both shapes.

### v4.0.3.1 — 2026-08-02

#### Added
- The Atlas map now lays out the chain automatically as a compass tree: home sits at the center, every jump lands one ring further out, and branches claim compass directions in the order they are found. Every pilot watching a map sees the identical picture, even across different browsers.
- Systems draw as circled class markers with the system name beneath, and connections draw as straight lines meeting each circle at its edge. Shortcut connections that close a loop draw dashed so the chain structure stays readable, and duplicate links never draw as structure twice.
- A map lock keeps the layout in charge: unlock to drag nodes around freely on your own screen, then re-lock to snap everything back to its computed place. Hand arrangements are never visible to anyone else.
- A tuning panel exposes the layout dials — ring spacing, separation, sibling fan, wedge posture, and direction order — and changing one re-draws the chain live on that screen only. The shipped defaults are the values tuned and signed off against live replayed chains.
- A camera-follow toggle brings new arrivals into frame when enabled. The view frames the chain once when a map opens and otherwise never moves on its own.
- A developer replay tool feeds realistic generated chains into a local map at watching pace, with a loop mode that repeatedly grows and tears down the chain to exercise arrivals and departures.

#### Changed
- Chain layout is computed by a deterministic compass-sector engine selected over ELK radial after a measured bake-off, and the computation runs in a background worker loaded only on the map route, keeping the page responsive and other pages free of layout code.
- The layout engine computes its own trigonometry instead of using the browser's, making node positions identical on every JavaScript engine by construction.
- The provisional placement grid is gone; the layout engine is now the only thing that has ever placed a node on the live map.
- The map library's default corner attribution stays visible for now; a styled credit that can replace it is planned for a future footer pass once Pro eligibility or an equivalent credit home is settled.
